# 审计表的租户列、行键与唯一写入方属于对外接口面

## 状态

已接受

## 背景

本模块不交付查询面（[ADR-audit-scope-2026-09-21](adr-audit-scope-2026-09-21.md)），宿主要读某个租户的审计轨迹，只能自己读这张表。表自己不内嵌租户模块的受约束模型约定，租户列可空，键只有 `id` 一列（[ADR-audit-sink-2026-09-21](adr-audit-sink-2026-09-21.md)），读它的语句不被租户插件加条件。

按租户读的那一方，其隔离全靠表里几件事实：租户列叫什么、存的是什么、没有租户的行存什么；行键是否跨租户唯一；表里的行是否都是本模块写的。这张表列进对外接口面的只有表名，这几件事随时可以变，而它们一变，读的一方不报错地读错：租户列改存别名，以标识为条件的读漏掉那个租户的全部行；没有租户的行改存空串，就与一个取值域之外的标识混在一起；键改成按租户分段，一个 `id` 就不再只指一行，跨租户按 `id` 取出的那一行可能属于任何一个租户。

## 考虑过的选项

### 仍然只把表名列进对外接口面

**否决**：读的一方的隔离所依的事实没有一处列进对外接口面，本模块改动其中任何一件，读的一方越界或漏行，全程不报错。

### 交付一个按租户读的查询面

**否决**：查询要先回答谁可以查谁，那是授权判定，归属权限模型（[ADR-audit-scope-2026-09-21](adr-audit-scope-2026-09-21.md)）。只按租户过滤的查询面仍要替读的一方回答「这个租户里谁能读」，本模块没有这个概念。

### 把整张表的每一列都列进对外接口面

**否决**：每一列都随之列进对外接口面，而明细的编码、来源与结果的取值这些是本模块要能演进的；读的一方的隔离并不依赖它们。

### 审计表自己内嵌租户约定

**否决**：跨租户操作与系统级操作的行没有租户，非空约束会让它们写不进去（[ADR-audit-sink-2026-09-21](adr-audit-sink-2026-09-21.md)）。

### 把隔离所依的三件事列进对外接口面

**采纳**，见决策。

## 决策

采纳：**审计表的租户列、行键与唯一写入方属于对外接口面，与表名同在。**

- **租户列是 `tenant_id`，存受理那一刻上下文里的租户标识的字符串形式**，与租户模块的约定在那一列里存的是同一种文本。上下文里没有租户、或落在跨租户标记下时，事件级的行存事件携带的那个标识；两者都没有时存 NULL，不存空串。
- **行的键是 `id`，在整张表里唯一**，由表生成。
- **这张表只由本模块写入。**

其余列的形状仍不在对外接口面内。读的一方借租户模块的过滤来读时，内嵌约定的那个模型要守的义务由租户模块裁定，不由本记录裁定。

## 后果

以租户列等于某个标识为条件的读，读到的恰是那个租户的行，读不到任何一行没有租户的行；在这个条件下按 `id` 取一行，取到的是那个租户的那一行，或者什么也没有。

**接受的代价：**

- **这三件事的任何改动都是跨模块的破坏性改动。** 改租户列的名字或取值、改键的形状，每一个读这张表的宿主都要跟着改，而本模块看不到它们。
- **其余列的同步仍然没有一处校验。** 读的一方读明细、来源、结果这些列时，本模块改它们照旧只在读的一方那里暴露。
- **「只由本模块写入」本模块验不了。** 宿主写进去的行与本模块记下的事实在表里分不出来，经模型写这张表的语句按自指判据也不产生审计行；这一条只能写成对宿主的要求。
- **授权面仍在读的一方。** 本记录只把隔离所依的事实列进对外接口面，谁能读哪个租户由读的一方自己判定。

## 失效条件

若审计表需要按租户分区存放、或租户列要改存别的文本，则读的一方所依的事实要重新裁定，本记录随之失效。
