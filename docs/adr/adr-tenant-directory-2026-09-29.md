# 名册自己的语句经数据库模块的 Connection 取交付连接，取不到、表不在与其余失败分开作答

## 状态

已接受

## 背景

名册的语句跑在交付句柄上：整张名册的读、进入方法在快照要拒绝时按标识的那一读、登记与改状态的写，每一条都从交付连接池里取一条连接（[ADR-tenant-directory-2026-09-21](adr-tenant-directory-2026-09-21.md)）。名册功能的方法只收调用方的上下文，调用方的事务不在上下文里；名册的写各自开一个事务，合不进调用方的事务。

数据库模块把只属于一条连接的库——SQLite 的内存库——交付成只有一条连接的池。调用方在交付句柄上开着一个事务时，那条连接由它占着，要到它自己的调用返回之后才放开。名册的一条语句这时去取连接，等的是调用方自己：上下文没有期限就一直等下去，调用方的事务与进程里唯一的那条连接一起被占着，别的语句也跟着停住。调用方的事务占着的也可以是锁：SQLite 文件库上写过的事务占着整个库的写锁，SQLite 的等锁不随上下文结束，按忙等时限结束；PostgreSQL 上写过名册表某一行的事务占着那一行的锁。

这个形状是常态而不是误用。进程内的事件总线在发布方的协程上、以发布方的上下文同步调用订阅者，发布可以就在发布方的事务里；订阅者按事件的租户标识经 `Enter` 进入那个租户，而快照要拒绝时——一个停用的租户，一个快照里没有的标识——进入要读表（[ADR-tenant-scoping-2026-09-28](adr-tenant-scoping-2026-09-28.md)）。停用期间仍属于一个租户的清除与导出在事务里做、并发布事件，订阅者进入的正是那个停用的租户（[ADR-tenant-scoping-2026-09-29](adr-tenant-scoping-2026-09-29.md)）。连接池被占满时形状相同：占着连接的调用方各自在等名册的一条语句。

一条语句看不出它等的那条连接是被调用方自己占着，还是被另一个调用方短暂占着，Go 也不给出协程的身份。数据库模块为替调用方发出语句的模块提供 `Connection`，在一个界内取连接，等锁照引擎自己的设置；模块自己的语句经它取连接，不各自设界（[ADR-db-waits-2026-09-29](adr-db-waits-2026-09-29.md)）。

名册表不在——施加迁移的命令没有收集本模块的迁移集，或表此后被删——是一种要改迁移命令的失败，`ErrRosterMissing` 为它而设。一条读写名册表的语句失败时，驱动报出的原因各不相同：表不在、等锁超时、连接断开、没有权限，各驱动措辞各异，本功能目录不 import 驱动。

## 考虑过的选项

### 取连接的等待交给调用方的上下文

名册的语句取连接一直等到调用方的上下文结束。

**否决**：进程内总线的订阅者、一个在事务里逐个租户做事的任务，上下文往往没有期限，在只开一条连接的库上会一直等下去，并把进程里唯一的连接一起占住。调用方给了期限，得到的也只是期限到了，那段等待本来就等不到结果。

### 名册自己限时取连接

名册自己从交付连接池取连接，给取连接设一个界，取到之后照调用方的上下文执行。

**否决**：它与数据库模块的 `Connection` 做的是同一件事，取连接、钉住会话、交还连接的代码在本功能目录里再写一份，失败的形状与交还时的处置随之与审计、设置各写的一份各自漂移，正是数据库模块否决的由各模块自己设界（[ADR-db-waits-2026-09-29](adr-db-waits-2026-09-29.md)）。

### 取不到连接时，进入按快照作答

快照要拒绝而读不到表时，退回快照的答案，以 `ErrInvalidTenant` 或 `ErrTenantDisabled` 拒绝。

**否决**：拒绝是不经请求面的路径据以丢弃工作的答案，而快照可能落后于表，别的副本刚登记或重新启用的租户会被答成不存在或停用，那件工作就此丢掉——否决"进入只读快照"的理由在这里原样成立（[ADR-tenant-scoping-2026-09-28](adr-tenant-scoping-2026-09-28.md)）。写入也没有快照可退。

### 名册的语句加入调用方的事务

名册的语句跑在调用方的事务里，不另取连接。

**否决**：调用方的事务不在上下文里，要拿到它就得改名册功能的签名，或让数据库模块把事务放进上下文，两者都改变别的模块的契约。名册的写又要各自原子：一次写并进调用方的事务，调用方回滚时它一起回滚，而写之后的那次重读已经把它发布进了快照。

### 给名册的整次调用设界

从取连接到语句结束，一起设一个期限。

**否决**：要约束的是等别人占着的东西，不是数据库做事要多久。语句开始之后被期限打断，一次正在提交的写落没落地由引擎决定，调用方得到失败而写可能已经生效；调用方自己给了更长的期限时，这个界还替它把期限收短。SQLite 上期限也结束不了等锁那一段。

### 识别只开一条连接的库，另行处置

池只有一条连接时，名册不去等它，或改用别的读法。

**否决**：池的大小说不出那条连接被谁占着：另一个调用方的一条短语句占着它时，等一会儿就取得到；PostgreSQL 也可以配成只开一条连接，那时别的副本照样在写名册表。连接池被占满的形状也不因池的大小而消失。

### 取不到连接时以数据库模块的错误作答，不另立哨兵

`Connection` 取不到连接时返回的错误包着 `context.DeadlineExceeded`，原样交出。

**否决**：调用方看自己的上下文是否已经结束，能把它与自己的期限到了分开，可那要每个调用点都写出这一判别；本功能目录判定出的每一类确定失败都以哨兵交给调用方，按 `errors.Is` 判别，而这一类的处置——把调用挪出事务，或者给连接池扩容——与既有哨兵的都不同。

### 名册表的每一次读写失败都以 `ErrRosterMissing` 作答

表不在时的失败各驱动报法不同，与别的原因失败的分不开，索性一律带上它。

**否决**：等锁超时、连接断开、没有权限也带上"名册表不存在"，哨兵给出的修复——改施加迁移的命令——把操作者引到一个没有问题的地方。

### 按驱动的错误认出表不在

SQLite 的"no such table"、PostgreSQL 的 `42P01`，认出其一才带上 `ErrRosterMissing`。

**否决**：要么 import 驱动，要么比对错误文本；本功能目录经数据库功能拿句柄，不认识驱动，换一个引擎就要再认一遍。

### 失败之后列出库里的表

经 GORM 的迁移器列出库里的表，列出的表里没有名册表时带上 `ErrRosterMissing`。

**否决**：PostgreSQL 上迁移器读信息模式，而信息模式只列出当前角色有某种权限的表。一个对名册表没有任何权限的角色，读写失败之后列表里没有它，一次权限不足就被答成表不在，哨兵给的修复是错的。

### 失败之后问数据库有没有这张表，PostgreSQL 上按名字解析

**采纳**，见决策。

## 决策

采纳：名册自己的每一次读写——整张名册的读、进入方法按标识的那一读、写入与写入里的核对读——经数据库模块的 `Connection` 取交付连接池里的一条连接，取连接的界为五秒。五秒之内取不到连接，以 `ErrNoConnection` 作答，什么也没做，它不是两个拒绝哨兵中的任何一个，也不是 `ErrRosterMissing`。语句照调用方的上下文执行，等锁照引擎自己的设置；引擎放弃等锁时，那条语句以引擎自己的错误失败。

一条读写名册表的语句失败之后，在同一条连接上、任何事务之外，问数据库有没有名册表：SQLite 上看 GORM 迁移器列出的主库的表，PostgreSQL 上按搜索路径解析这个名字，与那条语句找表的路径相同，解析不看对表的权限。没有名册表时以 `ErrRosterMissing` 作答，那条语句的错误留在错误链里；有、或这一问本身失败时，那条语句的失败原样交出，不带哨兵。

- **五秒与审计模块自己写的行取同一个界**（[ADR-audit-failure-2026-09-21](adr-audit-failure-2026-09-21.md)）。负载之下被占着的连接在一条语句的工夫里就会放开，远在界内。
- **调用方的上下文先于这个界结束时，取连接的等待以上下文的错误作答**，不带 `ErrNoConnection`，也不带 `ErrRosterMissing`。取到连接之后，语句照调用方的上下文执行：PostgreSQL 上上下文结束打断它的等锁，SQLite 上等锁那一段不随上下文结束，等满连接的忙等时限。
- **一次写取到的那条连接承载它的整个事务、失败之后的核对读与问表的那一次**，在写之后的那次整表重读之前放回，重读另取一条。问表放在事务之外，因为 PostgreSQL 上一条语句失败的事务不再接受任何语句。
- **本功能目录自己的答案不问表**：别名冲突、标识已登记、没有这个租户，都是读了表才给出的答案。

## 后果

在调用方的事务里、只开一条连接的库上，快照要拒绝的进入与名册的写入五秒之后以 `ErrNoConnection` 失败，而不是一直等下去；快照放行的进入不读表，照常当即作答。取连接的等待在数据库模块交付的每一种库上都有界。一条语句失败时带上 `ErrRosterMissing` 的只有表确实不在的那一种，它给出的修复对这一种总是对的；快照尚未发布时被读或被进入的名册同样以它作答，那是调用早于本模块的 `Init`，不是这一问的答案。

**接受的代价：**

- **在调用方持有的事务里、只开一条连接的库上，快照要拒绝的进入得不到答案。** 这是数据库模块接受的"界是失败而不是答案"落在名册上的形状（[ADR-db-waits-2026-09-29](adr-db-waits-2026-09-29.md)）：订阅者拿到的失败既不是拒绝也不是放行，发布方的事务为此多占五秒。避开它的办法是事务提交之后再发布事件、再调用名册。
- **繁忙但正常的库上，五秒之内取不到连接的调用同样失败**，即便调用方给的期限更长。连接池被别的调用方长时间占满时，名册的读表与写入失败，而不是排队等过去。
- **等锁不在界内。** SQLite 上一次调用的每一条语句各至多等一个忙等时限，失败之后为说明原因补发的核对读与问表各自再等一个，整个库被别的连接占着时，一次写入等到忙等时限的几倍才失败；同一个文件库上调用方的事务写过之后，名册的写入当即以 `SQLITE_BUSY` 失败，SQLite 不为把读升级成写而等。PostgreSQL 上调用方的事务写过名册表的某一行、又在这个事务里写同一行时，名册的写一直等到调用方的上下文、会话的 `lock_timeout` 或 `statement_timeout` 结束它，都没有就永远等下去。
- **引擎放弃等锁的失败没有哨兵。** 它是引擎自己的错误，与 SQLite 为避开死锁立即报的 `SQLITE_BUSY` 从错误上分不开。
- **名册功能的方法多一种失败。** 五秒之内取不到连接的调用以失败返回，而不是等到上下文结束或一直不返回；接口面多一个哨兵，调用方按 `errors.Is` 判别它。
- **一次失败的读写多问一次。** SQLite 上名册表建在主库之外——附加的库、临时库——时，名册表明明读得到，别的原因失败的语句也会被答成 `ErrRosterMissing`；本模块的迁移不把表建在那里。

## 失效条件

若数据库模块提供一种把调用方的事务交给别的模块的途径，或名册功能改为收下调用方的会话，名册的读在调用方的事务里就不必另取连接，这个界要与"读调用方的会话"重新比较。

若正常负载下取连接的时间普遍接近五秒，这个界要改成一个输入项。

若数据库模块开始把"语句所指的表不存在"归为一个哨兵，问表的那一次可以换成判别它。
