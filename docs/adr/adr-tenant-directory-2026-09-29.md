# 名册自己的语句限时取交付连接，取不到即以一个单独的哨兵作答

## 状态

已接受

## 背景

名册的语句跑在交付句柄上：整张名册的读、进入方法在快照要拒绝时按标识的那一读、登记与改状态的写，每一条都从交付连接池里取一条连接（[ADR-tenant-directory-2026-09-21](adr-tenant-directory-2026-09-21.md)）。名册功能的方法只收调用方的上下文，调用方的事务不在上下文里；名册的写各自开一个事务，合不进调用方的事务。

数据库模块把只属于一条连接的库——SQLite 的内存库——交付成只有一条连接的池（见 [db](../design/modules/design-db.md)）。调用方在交付句柄上开着一个事务时，那条连接由它占着，要到它自己的调用返回之后才放开。名册的一条语句这时去取连接，等的是调用方自己：上下文没有期限就一直等下去，调用方的事务与进程里唯一的那条连接一起被占着，别的语句也跟着停住。

这个形状是常态而不是误用。进程内的事件总线在发布方的协程上、以发布方的上下文同步调用订阅者，发布可以就在发布方的事务里（见 [event](../design/modules/design-event.md) 的并发与事务边界）；订阅者按事件的租户标识经 `Enter` 进入那个租户，而快照要拒绝时——一个停用的租户，一个快照里没有的标识——进入要读表（[ADR-tenant-scoping-2026-09-28](adr-tenant-scoping-2026-09-28.md)）。停用期间仍属于一个租户的清除与导出在事务里做、并发布事件，订阅者进入的正是那个停用的租户（[ADR-tenant-scoping-2026-09-29](adr-tenant-scoping-2026-09-29.md)）。连接池被占满时形状相同：占着连接的调用方各自在等名册的一条语句。

一条语句看不出它等的那条连接是被调用方自己占着，还是被另一个调用方短暂占着，Go 也不给出协程的身份。审计模块为它另占连接写出的行面对的是同一件事，它给取连接的等待设了界（[ADR-audit-failure-2026-09-21](adr-audit-failure-2026-09-21.md)）。

## 考虑过的选项

### 取连接的等待交给调用方的上下文

名册的语句取连接一直等到调用方的上下文结束。

**否决**：进程内总线的订阅者、一个在事务里逐个租户做事的任务，上下文往往没有期限，在只开一条连接的库上会一直等下去，并把进程里唯一的连接一起占住。调用方给了期限，得到的也只是期限到了，那段等待本来就等不到结果。

### 取不到连接时，进入按快照作答

快照要拒绝而读不到表时，退回快照的答案，以 `ErrInvalidTenant` 或 `ErrTenantDisabled` 拒绝。

**否决**：拒绝是不经请求面的路径据以丢弃工作的答案，而快照可能落后于表，别的副本刚登记或重新启用的租户会被答成不存在或停用，那件工作就此丢掉——否决"进入只读快照"的理由在这里原样成立（[ADR-tenant-scoping-2026-09-28](adr-tenant-scoping-2026-09-28.md)）。写入也没有快照可退。

### 名册的语句加入调用方的事务

名册的语句跑在调用方的事务里，不另取连接。

**否决**：调用方的事务不在上下文里，要拿到它就得改名册功能的签名，或让数据库模块把事务放进上下文，两者都改变别的模块的契约。名册的写又要各自原子：一次写并进调用方的事务，调用方回滚时它一起回滚，而写之后的那次重读已经把它发布进了快照。

### 给名册的整次调用设界

从取连接到语句结束，一起设一个期限。

**否决**：要约束的是等别人占着的东西，不是数据库做事要多久。语句开始之后被期限打断，一次正在提交的写落没落地由引擎决定，调用方得到失败而写可能已经生效；调用方自己给了更长的期限时，这个界还替它把期限收短。

### 识别只开一条连接的库，另行处置

池只有一条连接时，名册不去等它，或改用别的读法。

**否决**：池的大小说不出那条连接被谁占着：另一个调用方的一条短语句占着它时，等一会儿就取得到；PostgreSQL 也可以配成只开一条连接，那时别的副本照样在写名册表。连接池被占满的形状也不因池的大小而消失。

### 取不到连接时以数据库的错误作答，不另立哨兵

限时取连接，过界时把等待的超时原样交出，不另立哨兵。

**否决**：错误链里那个超时与调用方自己的期限到了是同一个值，调用方分不出是自己的期限到了，还是名册等不到连接；而两者的处置不同，后者要把调用挪出事务，或者给连接池扩容。本功能目录自己判定出的一类确定失败，要么并入既有哨兵，要么补一条，而既有哨兵里没有一条说的是这件事。

### 每一条语句限时取连接，过界以单独的哨兵作答

**采纳**，见决策。

## 决策

采纳：名册自己的每一条语句——整张名册的读、进入方法按标识的那一读、写入与写入里的核对读——在交付连接池里取一条连接，至多等五秒；过界以 `ErrNoConnection` 作答，什么也没做，它不是两个拒绝哨兵中的任何一个，也不是 `ErrRosterMissing`。取到连接之后，语句照调用方的上下文执行，不再另设界。

- **五秒与 SQLite 驱动默认的忙等时限同长**，与审计模块自己写的行取同一个界（[ADR-audit-failure-2026-09-21](adr-audit-failure-2026-09-21.md)）：文件库上，同一条语句等调用方占着的锁，定位符里不另设时也是等这么久；只开一条连接的库上那条连接就是锁，同一个引擎的两种库因而以同一个方式失败。负载之下被占着的连接在一条语句的工夫里就会放开，远在界内。
- **调用方的上下文先于这个界结束时，以上下文的错误作答**，不带 `ErrNoConnection`；上下文结束同样打断取到连接之后的那条语句。
- **一次写取到的那条连接承载它的整个事务与失败之后的核对读**，在写之后的那次整表重读之前放回，重读另取一条。

## 后果

名册的每一次调用都在有限的时间里返回。在调用方的事务里、只开一条连接的库上，快照要拒绝的进入与名册的写入五秒之后以 `ErrNoConnection` 失败，而不是一直等下去；快照放行的进入不读表，照常当即作答。整表读一次只有一个在进行，占着那个槽位的读至多等五秒取连接，等槽位的一方因而也有界。

**接受的代价：**

- **在调用方持有的事务里、只开一条连接的库上，快照要拒绝的进入得不到答案。** 订阅者拿到的失败既不是拒绝也不是放行，那件工作照样做不成，发布方的事务为此多占五秒。避开它的办法是事务提交之后再发布事件、再调用名册（见 [tenant](../design/modules/design-tenant.md) 的非保证）。
- **繁忙但正常的库上，五秒之内取不到连接的调用同样失败**，即便调用方给的期限更长。连接池被别的调用方长时间占满时，名册的读表与写入失败，而不是排队等过去。
- **这个界只约束取连接。** 取到连接之后的等锁仍由数据库自己的时限与调用方的上下文约束：SQLite 文件库上等调用方占着的写锁，到连接的忙等时限为止；PostgreSQL 上名册的读不等行锁，名册的写只等别的写在同一行上的锁，而本模块自己的写各在自己的事务里、写完即提交——只有本模块之外写名册表或给它整表加锁的语句，能让它一直等到上下文结束。
- **名册功能的方法多一种失败。** 五秒之内取不到连接的调用以失败返回，而不是等到上下文结束或一直不返回；接口面多一个哨兵，调用方按 `errors.Is` 判别它。

## 失效条件

若数据库模块提供一种把调用方的事务交给别的模块的途径，或名册功能改为收下调用方的会话，名册的读在调用方的事务里就不必另取连接，这个界要与"读调用方的会话"重新比较。

若正常负载下取连接的时间普遍接近五秒，这个界要改成一个输入项。
