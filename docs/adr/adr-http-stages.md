# 中间件的定位由固定的一组阶段给出，阶段内以约束与整数 Order 取舍

## 背景

中间件由彼此独立的模块贡献，各自在链上占一层；层与层的先后影响正确性。入口模块不认识任何具体功能，新增一种横切机制不修改入口模块；登记面不带登记方身份，一层代表哪个功能只能由那一层自己说。

跨类别的先后必须由框架给出，因为下面这些定位诉求落不到一条「我相对某个具体功能在哪」的边或一个全局数值上：

- **对开放集合的全称约束。** “观测层在所有会拒绝请求的层之外”要求点名每一个会拒绝的层，可宿主的层和以后新增的模块事先点不了名。
- **框架内建层没有落点。** 兜底、请求体上限、访问日志要落在“观测之内、拒绝之外”，也就是模块层之间的位置。用边表达，要么入口模块点名具体能力（与“不认识任何功能”相悖），要么每个会拒绝的模块都记得写一条指向兜底的约束，漏写就静默落到错误的位置。
- **丢边破坏传递性。** A 在 B 之内、B 在 C 之内，而 B 不在场时，A 与 C 之间就没有约束，可能反过来。各层因此只能把所有锚点写全。
- **锚点按类型身份认，造成 import 耦合。** 写一条指向某能力的约束就得 import 那个包；反过来，要让观测层声明位于所有人之外，底层的观测模块就得 import 上层的全部模块。

一套全局数值承担不了第一类诉求：它由各模块互相看着对方定值，等于用另一种形式回到全局协调，而“我属于哪一类”被隐含在取值里。固定的一组阶段给出跨类别的先后，对框架没见过的类别照样成立。

类别之内还需要一层更细的定位。`After` 与 `Before` 是硬约束，只表达“我读你写入的东西”这类关系；一个层若只想排在本阶段没有约束的各层之外、不点名任何人，约束表达不了。用一个只在阶段内比较的整数 `Order` 承担这件事：每个层自由挑值，不必点名别人，也不必跨阶段协调——阶段边界已经由框架给出，`Order` 只在同一阶段内比较，跨阶段的数值不可比。

其他产品对中间件定位的做法：

| 产品 | 机制 | 数字与阶段的关系 |
|---|---|---|
| Spring Security | 框架给内建过滤器分配序号；自定义过滤器只写相对某个锚点的 `addFilterBefore`、`addFilterAfter`、`addFilterAt` | 数字由框架分配，使用者不写数字，只写锚点 |
| Micronaut | 命名的阶段（`ServerFilterPhase`），每个阶段带前后两个序号 | 阶段是槽位；数字只是阶段的编码，因为 Java 的 `Ordered` 只认一个整数 |
| Spring Boot | 整数加公开常量划分区段 | 数字就是全部依据，再由公开常量补上区段的含义 |
| Kong | 插件分阶段运行，插件自带静态优先级 | 阶段在先，优先级在阶段内比较；相对约束是后来补上的，且只作用于一个阶段 |

speed 的 `Order` 与 Kong 同形：阶段在先，`Order` 只在阶段内比较，跨阶段的数值不参与先后。数字不承担类别，类别由 `Stage` 给出，数值因而只在同一阶段之内需要协调——同阶段里两个模块的数字撞上，也不会跨类别错位。

## 考虑过的选项

### 保留全局整数 Order，不引入阶段

维持约束图加一个全局整数偏好。

**否决**：上面那些诉求一类都表达不了。最外层那一档尤其关系到正确性——宿主写一个更小的数就把观测层挤到会拒绝的层之内，而挤错时不产生任何信号。全局数值还要求跨模块协调，因为一个模块无从知道别人取了什么值。

### 只用名称或数值优先级排序，不引入阶段

去掉约束图，链按一列优先级整数（或一列名字）排列。

**否决**：与“只用数值优先级”和“只用功能标识声明的约束”两项同因。数值的含义来自全局协调，模块无从知道别人取了什么值；名字排序对“与任何具体功能都无关的位置诉求”没有可写的东西。跨类别的先后由谁决定仍然悬空。

### 阶段集合开放，模块可新增阶段

阶段作为可扩展的枚举，模块可以声明新的一类。

**否决**：开放的类别又回到“对开放集合的全称约束”那一类问题——框架无法为它没见过的类别规定先后。管线的通用类别多年不变，新增一类属于修改入口模块并另写记录，代价小。

### 固定阶段，阶段内以约束与三值 Position 取舍

框架定义一组命名的阶段并规定其先后；阶段之内 `After` 与 `Before` 是硬约束，`Position` 在该阶段内取舍，取 `PositionDefault`、`PositionFirst`、`PositionLast`。

**否决**：三值 `Position` 只在同 `PositionDefault` 层比较时有语义，落在同一边缘的层之间没有可比较的量，只能退回登记先后；而登记先后由 `Init` 的依赖序线性化给出，与“该在外还是内”无关，又随本次装配有哪些模块而变。于是“同一边缘按登记先后决定”不是一条规则，是没有规则。阶段之内其余诉求——放开到“不点名任何人的相对位置”——也比三值格能表达的更细。

### 固定阶段，阶段内以约束与整数 Order 取舍

框架定义一组命名的阶段并规定其先后；阶段之内 `After` 与 `Before` 是硬约束，整数 `Order` 在约束留下的自由度内取舍，越小越靠外。

**采纳** —— 见决策。

## 决策

采纳：链的跨类别先后由一组固定的阶段给出，阶段之内用一个整数 `Order` 承担精细排序，三值 `Position` 删除。

阶段是 HTTP 管线的通用类别，不是某个具体能力：观测、防护、鉴别、限流、记录、授权，按此顺序由外到内运行。它们固定在入口模块里，模块只声明自己属于哪一个，不能新增。`Stage` 是必填项，零值与未定义值在登记时 panic，不给默认值——漏填而落到某个默认阶段，等于让一层在没人选择的类别里运行。

`Order` 是一个整数，越小越靠外，只在同一阶段之内比较；跨阶段的数值不可比，谁在外由阶段顺序决定，与数值无关。各模块自由挑值，不必填、不校验取值。零值表示无偏好，落在本阶段已表态的各层之间；`OrderOutermost` 与 `OrderInnermost` 是两个公开哨兵，取 `math.MinInt` 与 `math.MaxInt`，用于“不被任何普通值超越”的诉求。**相等的 `Order` 不承载次序语义**：两层由登记先后分开，不报诊断、也不构成失败。

`Order` 只在就绪集合里取舍，让位于阶段内的约束，因而与约束不会互相矛盾；结果确定：`(Order, 登记先后)` 是阶段内的全序，而登记先后由 `Init` 的依赖序线性化给出。这条全序建立在登记先后这个量上，而它不是本模块对外的契约（见后果）。

阶段之间的先后由框架决定，因此一条跨阶段的 `After` 或 `Before` 是冗余的：与阶段顺序同向时它已被满足、不建边，记 Debug；反向时启动失败，返回 `ErrStageConflict`，点名两层的层名、阶段与这条约束。`After` 与 `Before` 只在同一阶段内建边，阶段内的图照旧做拓扑排序，成环返回 `ErrMiddlewareCycle`。

内建层不经登记面，也不出现在任何约束里：它们在组装时挂在各阶段之间，访问日志在观测阶段之外，兜底在观测之内、防护之外，请求体上限在防护之内、其下各阶段之外。这属于入口模块的实现，见 [ADR-http-recovery](adr-http-recovery.md)、[ADR-http-body-limit](adr-http-body-limit.md) 与 [ADR-http-access-log](adr-http-access-log.md)。

## 后果

跨类别的定位不再需要 import 对方的包：一条跨阶段的边一律可以删除，方向反了则启动失败，老代码迁移时不会静默错位。阶段内的约束只剩下真正“我读你写入的东西”的那几条。

与具体功能无关的位置诉求由 `Order` 承担，声明它的层不必点名任何人。

组装结果是确定的、可读的：启动时逐端写出一条 `chain=` 行，标出阶段与各层声明的功能。

**接受的代价：**

- **阶段集合封闭。** 新增一类（例如请求解压或响应压缩）需要修改入口模块并另写一条记录。代价是这类需求被挡在门外，换来的是类别之间的先后始终由框架给出。
- **`Order` 是偏好，不是保证。** 取 `OrderOutermost`/`OrderInnermost` 只表示“不被任何普通值超越”；多个层同取一个哨兵时它们之间仍无序，最外与最内因而都不是保证，也不产生任何信号。要独占某个位置，只有一条 `After`/`Before` 约束做得到。
- **并列不再有诊断。** 两层取同一个 `Order` 时，先后由登记先后决定，可能不是任何一方的本意；这一并列不报诊断、也不失败。共享一个 `Order` 的两层之间，落败的一方不再有任何途径得知它的声明与别人共享，旧的那条并列诊断因此消失。
- **跨阶段的数值不可比，写错方向不报错。** 一个层取了一个在别的阶段看来“很小”的数，只在本阶段内有效；把本阶段的数值当作跨阶段的先后，写错方向不会失败，只能靠文档与评审察觉。
- **与阶段顺序相反的一条跨阶段约束会让启动失败。** 迁移时旧的跨阶段边若方向与阶段相反，不会静默降级，而是报错要求改；这比静默错位好，但要求迁移方逐条核对锚点。
- **宿主不能按端覆盖顺序。** 链的先后只由阶段、阶段内约束与 `Order` 决定；真需要按端调整时，要另立机制。
- **兜底层在观测阶段之内，观测阶段自身的 panic 不由它应答。** 观测阶段的层抛出的 panic 越过兜底层抵达 `net/http`：`net/http` 关闭该连接，并经该监听配置的日志器写一条记录；调用方拿到的是连接中断，而不是一次 500。兜底层覆盖的是它之内各层与 handler 的 panic。
- **复现性依赖登记先后。** `(Order, 登记先后)` 的全序建立在登记先后这个量上，它来自 `Init` 的依赖序，不是入口模块对外承诺的契约；同一个模块在两个宿主里因而可能落在不同的层数上，一层的最终位置取决于本次装配里有哪些别的层。

## 失效条件

本记录的前提是 HTTP 管线的通用类别很少变化，且阶段之内的精细排序足以用一列整数表达。若实际装配里反复出现放不进现有阶段、又需要与现有阶段交叉排序的层，则阶段的划分过粗，需要重划或另立机制；若阶段之内的定位反复需要点名某个具体层、或反复需要跨阶段比较数值，则整数 `Order` 不足以承载细粒度，需要另立机制；若新的类别长期只增不改、阶段内也无需跨阶段比较，这两项取舍成立。
