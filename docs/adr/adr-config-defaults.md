# 默认值层可以取第二份来源：宿主编译进二进制的文档

## 背景

配置来源分层，主配置源唯一（[ADR-config-source](adr-config-source.md)）。默认值层的来源是各模块承载结构体中字段的当前取值，粒度是一个叶子一个值。

一个产品骨架携带的平台拓扑——监听、端点、各模块的接线——是一大张表，与具体部署无关；部署之间不同的只是其中少数取值。这张表只能写进配置文档，因为映射与结构体列表这类容器没有环境变量或命令行能给出的扁平表达。于是每一份产品配置都要从一张完整的拓扑表写起，拷贝方改的往往只是其中几项，而拓扑本身的改动要在每一份配置里重做一遍。

装配由配置驱动，代码中不预置组合结构。为骨架提供一份随二进制分发的拓扑，只能落在配置的某一层。

## 考虑过的选项

### 增加第二个主配置源

允许一次运行读入两份主配置源，按顺序合并。

**否决**：设计固定主配置源唯一。两份文件合并会让未知键的判定失去单一的归属——一个键在前一份里被拒绝、在后一份里被接受时，结论取决于合并顺序；一个值的来源也变成两份文件之间的推断，排障无法定位到唯一一层。

### 代码中的预置结构

在代码里写一个预置的结构体或映射，承载平台拓扑，运行时直接采用。

**否决**：装配由配置驱动，代码中不预置组合结构。预置结构会把拓扑从配置面移进代码，拷贝方改用配置修改它时，代码与配置两份来源同时存在，而哪一份生效取决于实现细节。

### 生成器：从声明产出配置文档

提供一个命令，读各模块的输入项声明，生成一份完整的配置文档，供拷贝方保存与修改。

**否决**：它解决的是拓扑表的可见性，不是重复维护。生成物仍是一张与声明重复的表，声明一变就要重新生成，拷贝方在生成物上的修改会在下一次生成时被覆盖。

### 在单个文档内提供 include 或合并

让一份配置文档引入另一份，或按节合并两份。

**否决**：这在文档语法内部再引入一层叠加，而层叠语义由来源层定义，必填判定依赖每个叶子记住它来自哪一层。文档内部的合并来源不受这套机制管辖，值的来源因此又多出一处无从归属的地方。

## 决策

采纳：默认值层可以取第二份来源——一份宿主随二进制编译进来的配置文档，由宿主注册的一个模块以 `Defaults` 资源声明。一次运行至多一份。主配置源仍唯一，该文档不是主配置源。

- 文档只替换默认值层中它给出的叶子，其余叶子保留原型中的值。
- 文档的格式由 `Defaults.Format` 给出，按主配置源同一规则选定：名字折为小写后精确匹配，不做内容嗅探。
- 文档的键按与主配置源相同的判据校验：清单中没有的键，或清单中有而该输入项不接受主配置源的键，都是启动失败。
- 文档满足 `Required`：宿主在文档里点名一个取值，与在配置文件里写出它是同一个动作；原型中的字段取值不满足 `Required`。文档把某个键写成空值等同于没有给出，那样的键不满足必填。

## 后果

一份产品配置只需写出相对拓扑的差异，拓扑随二进制分发，拷贝方不必从一张完整的表写起。

**接受的代价：**

- **默认值层的两段在必填判定上性质不同。** 原型是模块自己的占位：承载结构体的字段总有取值，把它算作给出，必填与取到零值就无从区分。文档是宿主的明确声明，与配置文件里的条目同质，因此满足 `Required`。
- **只由原型给出的必填项仍然失败。** 一个必填项在原型中有取值、文档没有点名、其余来源也没有给时，`Decode` 仍返回 `ErrMissingRequired`。模块不能靠自己的占位值把必填项变成可选。
- **拷贝方可能看不出一个必填值来自二进制。** 必填项的值可以不写进任何配置文件而由文档供给；拷贝方读配置时看不到这一项，改文档、或换用不含该键的文档时才会发现它在启动时缺失。必填项因此要区分「由文档供给」与「由部署供给」：前者只适合每个部署都相同的值。
- **容器仍整体替换。** 文档给出的容器替换原型中的整个容器，主配置源给出的容器替换文档中的整个容器，层内不逐键合并。要在文档的拓扑上改一个容器的某一项，仍需在主配置源里重写整个容器。
- **凭据不能写进文档。** 文档随二进制分发，会出现在制品、镜像与调试输出里；凭据仍由环境变量、主配置源或命令行给出。
- **拷贝方仍可覆盖任何键。** 文档只补充默认值，环境变量、命令行与主配置源的优先级不变；一份拷贝因此可以只替换它要改的那几项。
- **删掉模块要一并改文档。** 文档的键按完整清单校验，拷贝方从一个二进制里删去某个模块而文档仍写着它的键时，启动失败。这是有意为之：留着无人读取的键，正是这份文档最容易积累的失效。
- **默认值的来源多了一处。** 默认值不总等于承载结构体的字段取值：一个值不在原型里时，还要看文档是否给出了它。

## 失效条件

若多数拷贝方仍要覆盖文档中的大部分取值、或需要文档之上再有一份分层的文档，说明一份随二进制分发的拓扑不足以承担这份职责，应重新评估默认值层的来源形态。
