# 一个登记单元承载各条捕获通路

## 背景

各条捕获通路分别挂在不同的扩展点上：数据库插件、事件订阅、入口中间件、模块间调用。它们可以各自登记为一个模块，由宿主按需取用。

## 考虑过的选项

### 每条通路各登记一个模块

**否决**：各条通路共用一套记录结构与一张表。拆开之后，表与写入接口要么由其中一个模块排他交付，其余几个在构造期依赖它——把一条内部关系变成一份公共契约；要么每个模块各写一次库，表的结构随之有了多个所有者。

### 一条通路一个模块，另设一个只提供表与写入接口的模块

**否决**：那个模块除本模块自己的通路外没有第二个使用方，为它造一份交付声明与一条构造期依赖，换来的是三个模块每次启动都要各自表态，而它们从不同时缺席。

### 各条通路同属一个登记单元

**采纳**，见决策。

## 决策

采纳：**各条捕获通路属于同一个登记单元。**

接口包 `pkg/audit` 承载接口与数据类型，不登记模块；实现子包 `pkg/audit/journal` 登记模块 `audit.journal`，排他交付审计功能。

## 后果

宿主取用审计是一件事；哪几条通路在起作用由配置决定，不由取用了哪几个模块决定。

**接受的代价：**

- **取用是整取的。** 语句级与接口级随装配生效，没有开关——与租户隔离插件相同，装配即生效。一个只想在请求路径上留痕的宿主仍然得到全部写语句的捕获。
- **接口与实现分处两个包，两者的一致性没有编译期约束。** 接口类型定义在接口包，实现在子包，一个实现了接口却没有被声明交付的类型只有测试能发现。
- **模块名带一个子包后缀。** 取用与配置都写作 `audit.journal`。

## 失效条件

若出现一种宿主明确要求「只要请求级留痕，不要语句级捕获」，则通路要拆成可由宿主选择的单位，本决策随之失效。
