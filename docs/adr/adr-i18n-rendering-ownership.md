# 渲染责任随载荷形态划分，复合消息由后端渲染、类型化的值交给客户端

## 背景

一次响应在服务端与客户端之间传递的东西有两类形态：一个是后端拼好的复合字符串，即一段把文本、计数、复数、数字与日期时间合在一起的句子；一个是类型化的值，即时间戳、数量、货币。渲染一段文本所需的上下文（复数规则、要填入的计数）在谁手里，谁才渲染得出它。

决定错误响应结构的接口，即入口模块的 `ErrorResponder`（[ADR-http-errors](adr-http-errors.md)），同时是承载语言的地方时，一个只决定响应结构的模块被迫连语言一起变化。这与“结构归结构、语言归语言”的分工相悖。

服务端生成的用户可见文本的范围边界，以及机器码不随语言变化的契约，见 [ADR-i18n-scope](adr-i18n-scope.md)。这段文本由哪一侧渲染，本记录给出判据。

## 考虑过的选项

### 在边缘集中格式化

由入口模块读语言、查目录、渲染全部用户可见文本。

**否决**：一段复合文本的插值上下文（计数、复数）只有产生它的模块才有，把文案与上下文都搬到边缘，等于把每个模块的消息知识集中到一处，而边缘不认识任何具体功能。一处集中的渲染点撑不起各模块自己产生的复合文本，只撑得起它自己认识的那一类。

### 全部交给客户端渲染

后端只发类型化的值与机器码，客户端渲染全部文本。

**否决**：一个返回复合字符串的后端，客户端没有拼出它的上下文；把复合文本拆成值让客户端重组，等于让每一个调用这条 API 的客户端各自重建后端的措辞与复数规则，措辞的改动随即成为一次 breaking change，而这条改动本不必是对外契约的变更。

### 责任随载荷形态划分

返回复合字符串的一方渲染它的全部；返回类型化值的一方把渲染交给客户端。

**采纳**，见决策。

## 决策

采纳责任随载荷形态划分：

- 一个返回复合字符串的模块渲染它的全部：文本、计数、复数、数字与日期时间。
- 一个返回类型化值（时间戳、数量、货币）的模块把渲染交给客户端。
- 推论：倾向发一个类型化的值而非一句话，后端因而渲染得尽可能少。

一条消息由产生它的模块渲染：一个产出用户可见文本的模块承载自己的文案并按请求语言渲染它；错误消息由写它的模块渲染；一个只发机器字段（`Type`、`Status`）的模块不承载任何文本。

## 后果

复合文本的渲染落在产生它的模块，没有一个集中的文案渲染点；每条 API 的措辞由它的产出方掌握，改动不越出该模块。

一个决定响应结构的模块不再同时承载语言：结构接口接收的是成品文本，语言在产生文本的模块里已经定下（[ADR-i18n-error-rendering](adr-i18n-error-rendering.md)）。

一段复合文本里的计数、数字与日期时间按它的语言渲染，日期时间另按账户时区；一个把日期时间**作为独立字段**返回的模块才把渲染交给客户端，那时它走标准 ISO 格式（[REF-iso8601](../references.md)）（[ADR-i18n-message-rendering](adr-i18n-message-rendering.md)）。**归属由返回形态决定，不按字段种类决定**。

**接受的代价：**

- 文本随请求语言变化的部分，渲染依赖后端在场；不像全类型化那样由客户端独立决定语言，一次复合文本的响应要后端按请求语言渲染。
- “优先类型化”是判据不是强制：一个模块仍可发一句话，代价是那句话的措辞被钉死在后端，改措辞是一次对外变更。这条判据没有全局强制，落在每个产出的模块自己的判断上。
- 判断一条载荷是复合字符串还是类型化值，也落在产出它的模块，判错时后端多发或漏发一段文本，没有一处拦截。
- 各模块各自承载自己的文案来源与渲染路径，文案没有单一出处；跨模块统计“一种语言覆盖了哪些文本”要逐个模块收集。

## 失效条件

若出现某类载荷既要求后端渲染复合文本、又要求客户端能独立重述同一段文本的情形（两处都要同一份措辞与同一套插值），则这条划分不成立，共用的那一部分要么整体落在一侧，要么另立一份共享的文案源。

若渲染一段复合文本所需的上下文不在产生它的模块（例如计数由另一个模块在更晚的时刻给出），则“产生它的模块渲染”这一条不够，要重新定位渲染点。
