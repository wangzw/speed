# 租户标识由请求侧解析得到，取法由配置选定，不从认证身份派生

## 背景

租户标识由依赖图上层的模块产生，随 context 传递（[ADR-db-plugin-scope](adr-db-plugin-scope.md)、[ADR-log-context](adr-log-context.md)、[ADR-tenant-ordering](adr-tenant-ordering.md)）。可选的来源为账户的成员关系、请求头、子域名、路径前缀与配置映射，本记录在其中选定取值途径。

认证这一侧关闭了其中一条。身份以账户为中心，只读方法给出的事实例如账户、实际操作者与责任键，字段不导出，注入口只在认证树内可达、请求链上的身份只由网关写入，没有角色，也没有租户（[ADR-authn-identity](adr-authn-identity.md)）。身份是 `pkg/authn` 明列的跨模块契约，在它上面加一个租户字段等于要求每一个校验后端回答租户问题。豁免路由与无凭据的可选认证路由上没有身份，从身份派生租户覆盖不到它们（[ADR-authn-exemption](adr-authn-exemption.md)）。

账户全局，可属多个租户：同一个人在两个租户下是同一个账户，一个租户下有多个账户；成员关系是认证模块的一张表（[ADR-authn-accounts](adr-authn-accounts.md)）。从账户派生租户得到的是一个租户集合，不是一个租户；在集合里选定一个，所需的输入只能来自请求侧，成员关系回答的是账户属不属于请求侧指名的租户，是核对，不是选取。

请求侧的取法是同一批宿主并存的部署形态：子域名与路径前缀各自成片，写死一种等于替宿主决定对外 URL 的形态，而那是 API 的形态，不是装配的自由度（[ADR-authn-scope](adr-authn-scope.md) 为「免认证的路由分到另一个端点」记下的同一条理由）。

## 考虑过的选项

### 从认证身份派生

租户是账户的一个属性，从 `Identity` 上读出租户，或者在 `Identity` 上加一个租户字段。

**否决**：`Identity` 的字段不导出、注入口只在认证树内可达，链上任何一层都写不进去，加字段要改一个已发布的接口包；豁免路由与无凭据的可选认证路由上没有身份，从身份派生覆盖不到它们；账户与租户是一对多，从账户派生得到的是候选集，选定其中一个仍要请求侧指名，成员关系只能核对指名的租户，代替不了指名——绕开请求侧不多得到任何东西，只多出一条依赖。

### 取法写死为一种

本模块内建一种取法，宿主按它组织对外 URL。

**否决**：子域名与路径前缀是并存的两片部署形态，写死一种等于替宿主决定 API 的对外形态。它还会把取法的字符集约束变成库的约束（见 [ADR-tenant-identifier](adr-tenant-identifier.md)）：换一种取法就换一套合法字符，而已经入库的标识不跟着变。

### 只做扩展点，本模块不内建任何取法

本模块只定义取法的接口，每一种取法由宿主自己写。

**否决**：每个宿主各写一遍同一段解析，而写错的形态是静默地把另一个租户的名字读出来。取法交回的名字还要对得上名册上的别名，那是本模块的事实，推出去就没人对得上了。

### 由宿主在 handler 里自己解析并写进上下文

本模块不占链上的位置，把解析摊给每一条需要租户的路由。

**否决**：把一处集中判定摊成每条路由各自的动作，漏掉一条就是无租户或错租户，而漏掉本身不产生任何信号。认证为「缩小职责只交付校验能力」记下的否决理由同源（[ADR-authn-guarantees](adr-authn-guarantees.md)）。

### 取法由设置给出

取法作为运行期可变的参数，存放于数据库。

**否决**：自举失败。读设置的租户层要先知道租户（[ADR-config-scope](adr-config-scope.md) 的推论正是这条）；取法在运行中改变还会让同一个请求头在两个瞬间解析出不同的租户。

### 内建一组取法由配置选定，另留取法的扩展点

**采纳**，见决策。

## 决策

采纳：租户标识由请求侧解析得到；取法由本模块的内建实现提供、由配置选定，另留一个取法的扩展点。**不从认证身份派生，本模块不改动 `Identity`。**

判据是取值途径与判定所需的输入：认定一个请求属于哪个租户只需要请求侧，不需要凭据，也不需要账户。身份属不属于解析出的租户，是另一个判定，由租户准入层读身份与租户上下文作出（[ADR-tenant-admission](adr-tenant-admission.md)）。

取法的扩展点与登记接口的确切形态写在设计文档的外部接口契约里。**登记接口拿不到登记方的身份**，因而重名冲突点得到那个名字与两处登记的实现类型，点不到模块名——与认证的路由登记一致（[ADR-authn-exemption](adr-authn-exemption.md)）。

**取到的名字是别名，不是最终标识**：解析层按别名查，换回不可变标识，写进请求上下文的是标识；标识不在请求侧参与解析（[ADR-tenant-identifier](adr-tenant-identifier.md)）。

**平台管理面的租户寻址路由不在本层守护之内，但在各自的端点边界上按同一规则换名。** 那些路由判定在平台域，路径段同样只接受别名：租户管理模块注册的一层中间件在 handler 之前按名册把别名换成标识，停用与墓碑都能命中，未知别名答 404。换名之后各模块的内部读写仍用标识与既有实现一致。

**一次请求只由一种取法解析。** 允许多种并存时，任何优先级都意味着一条请求可以用两种方式声称自己是某个租户，而两条途径得出的结论可能不同。迁移期需要同时支持两种 URL 形态的，形态是把它们放进两个进程——取法配在模块自己的命名空间下，作用于它登记中间件的全部端点，一个二进制里并存两种取法表达不出来（[ADR-tenant-packaging](adr-tenant-packaging.md)）。

**注入口不导出，`FromContext` 不回退**，与认证的身份一致（[ADR-authn-identity](adr-authn-identity.md)）：回退等于把一条没有租户的请求读成某个租户，导出注入口等于让链上任何一层改写租户。

**解析层守护哪些端点由配置列举**，清单必填、无缺省；认证网关则缺省守入口模块的全部端。未被列举的端点上不登记这一层，那条链上的请求没有租户，受约束模型的语句一律拒绝。

**哪些端必须列举，由判定域决定。** 一条路由只有既按租户寻址（租户是路径段，不是查询值）、又由该租户治理（判定在该租户的策略域）时，才交给解析层与准入层（[ADR-http-api-path-scopes](adr-http-api-path-scopes.md)）。认证的租户管理作用域路由满足两条，其挂载端必须在清单里；平台管理作用域的单行名册路由、授权与冒充记录判定在平台域，审计在整张表上读，设置的租户层由查询串点名，它们的端都不在清单里。

## 后果

解析层不把身份与租户绑在一起：一个已认证的调用方可以在请求侧指名另一个租户，解析层与认证网关都不参与成员判定。成员判定由租户准入层承担，它排在解析层之后，读身份与租户上下文；没有装入准入层的装配里，这仍是一条开放路径（[ADR-tenant-admission](adr-tenant-admission.md)）。这一条与 [ADR-tenant-scoping](adr-tenant-scoping.md) 的零值防线是同一条设计的两面——租户的作用域由请求侧、装配与配置划定，不由身份划定；身份只是准入层核对的输入。

**接受的代价：**

- **取法是启动期配置，改它要重启。** 按租户取值的参数一律归设置侧（[ADR-config-scope](adr-config-scope.md)），而取法在数据库可用之前就被需要，两个条件把它钉在配置一侧。
- **请求侧在反向代理之后可被伪造。** `Host` 与 `X-Forwarded-*` 由前置代理写入，本模块信任它读到的东西；把入站头当作可信输入转发，或让一个不受信的客户端直接够到本进程，都能让调用方选定自己要读哪个租户的数据。前置代理的净化是宿主的事，这一条写进非保证。
- **一个进程里只能有一种取法生效**，它作用于解析层守护的全部端点；迁移期同时支持两种 URL 形态要靠两个进程，分成两个端点做不到。
- **下游必须处理「取不到租户」这一档。** 未被本模块守护的端点，以及本模块不在参与集里或未启用的进程，上下文里都没有租户；宿主为解析模块预置的实例不是该模块的产物时，解析层不登记，经请求侧到达的请求同样没有租户（[ADR-supplied-instance](adr-supplied-instance.md)）。**豁免路由与无凭据的可选认证路由不在此列**：解析层排在认证之内，在解析层守护的端上，认证层放行的这两类请求照常经过它（[ADR-tenant-ordering](adr-tenant-ordering.md)）。认证的常规接口与平台管理面挂载端不在解析层守护之内：登录、会话与令牌的请求不带租户名；平台管理的端点面向全局账户或平台资产，其中租户寻址的路由按别名在各自的边界上换名，不写进本层上下文，那些端上的请求因此没有上下文租户。租户管理作用域的挂载端相反，必须在清单里：那些路由既按租户寻址、又在该租户的策略域判定，没有解析出的租户就没有可判定的域。
- **一个不需要租户的路由不能与需要它的路由共处一个被守护的端点。** 探活、诊断这类路由要放到另一个端点：解析层在 handler 之前就以 404 收口，注入口又不导出，宿主没有位置替这样一条请求给出一个租户。解析层按端点守护，没有按路由的例外，这一条是守护粒度换来的。

## 失效条件

若身份承载一项租户属性，且该属性对每一个校验后端都是必答项，则「账户与租户一对多」不再是拒绝从身份派生的理由，本记录的取值途径要与它重新比较。

若账户改为租户私有、一个账户只属于一个租户，则从账户派生得到的是一个租户而不是候选集，同样要重新比较。

若出现一种入口不经中间件链——本仓已有的形态只有 HTTP——则「解析占链上一层」这一形态不再覆盖它，本模块的交付范围需要重新裁定。
