# 接口的时刻以带 Z 的 UTC ISO 8601 时间串交出，显示时区与格式由前端渲染

## 背景

一个时刻在接口上有多种表示。接口是生成的契约（[ADR-http-openapi-generation](adr-http-openapi-generation.md)）：模块在 Go 里声明字段，生成器把类型反射成 JSON Schema。前端是读这份契约的界面，查看者的显示时区是账户偏好（[ADR-i18n-preferences-storage](adr-i18n-preferences-storage.md)），不是服务端在本进程里能据以渲染一个固定字符串的事实。

渲染责任随载荷形态划分（[ADR-i18n-rendering-ownership](adr-i18n-rendering-ownership.md)）：复合文本由产生它的模块渲染。经接口送到网页的那一部分应当怎样交出时刻，这条划分没有说；一段按账户时区渲染好的时间进入网页文本后，显示时区就被钉死在产生文本的那个进程里。

时刻字段无值时用零值时间或空串占位，是另一处偏差：占位值在语法上是一个合法时刻，读方无从区分“没有值”与“那个具体的时刻”，契约也无法把该字段声明为可空。

## 考虑过的选项

### 服务端按账户时区格式化

服务端在每次应答里把一个时刻按查看者账户的时区与格式渲染成字符串。

**否决**：账户可能没有存过时区，服务端据以取值的时区不是查看设备的事实；同一份应答因此随查看者而变，无法缓存，第二个读者也无法原样重放。把显示格式放进接口，等于把界面的外观钉死在服务端，改格式是一次契约变更。它与“经接口到网页的文字不嵌时间”这条判据相悖。

### 整数时间戳

时刻以 Unix 秒或毫秒的整数交出。

**否决**：整数丢掉可读性，日志与调试里无法直接读出一个时刻；接口的其余字段是 JSON 文本，时刻单独用数字是另一套约定；前端仍要换算，换算没有消除，只换了表示。

### 无值用零值时间或空串占位

没有值的时刻写成 `0001-01-01T00:00:00Z` 或空串。

**否决**：两个写法都是合法的取值，读方要把一个哨兵值当作“没有值”，每个读方各自记住这条约定，契约无法把字段声明为可空。`null` 是 JSON 表达“没有值”的既有写法，契约可以声明它可空。

### ISO 时间串由前端渲染

服务端交出带 `Z` 的 UTC ISO 8601 时间串，显示时区与格式由前端按查看者渲染；无值写 `null`。

**采纳**，见决策。

## 决策

采纳：

- 接口里的时刻是带 `Z` 的 UTC ISO 8601（[REF-iso8601](../references.md)）时间串，即 RFC 3339（[REF-rfc3339](../references.md)）的写法；契约声明为 `type: string, format: date-time`。
- 没有值的时刻交出 `null`，契约声明该字段可空，或按字段既有约定省略；不用零值时间或空串占位。
- 经接口送到网页的文字不嵌入格式化好的时间：时间作为参数或独立字段交给前端，由前端经统一入口按查看者的显示时区渲染。邮件、短信不经前端，仍由服务端渲染并标明时区（[ADR-i18n-message-rendering](adr-i18n-message-rendering.md)）。
- 时长不是时刻，保持整数秒（`expires_in`、`resend_after`、`ttl_seconds` 这类）。

## 后果

- 前端成为网页上时间显示的唯一渲染点，服务端不再为网页文本选时间格式；同一份应答可以被不同时区的查看者各按自己的显示时区读取。
- 契约里的时刻是一个字符串，生成的客户端可以直接读；前端解析后经统一入口渲染，时间格式的改动落在前端，不是一次契约变更。
- 无值写 `null` 使“没有值”成为契约的一部分。生成器默认去掉类型联合里的 `null`，可空字段因而要显式标记，未标记的字段仍按不可空发布（[ADR-http-openapi-generation](adr-http-openapi-generation.md)）。
- 时间作为独立字段或参数交给前端，使一段带时间的网页文案要拆成文本与值两部分呈现，文案不再是一整句。

**接受的代价：**

- 字段改名是破坏性变更：读这些字段的前端、生成的客户端与契约在同一批改动里更新，不保留旧字段名的兼容层（[ADR-no-stability-promise](adr-no-stability-promise.md)）。
- 一个不解析 ISO 时间串的调用方要自己解析；服务端不再提供一个已经格式化好的网页可读时间。
- 邮件、短信与网页的同一段文案有两套渲染路径：邮件、短信由服务端引擎按账户时区渲染，网页由前端按查看者显示时区渲染。两者的一致性没有一处统一核对。
- 契约没有自动检查器逐个核对时间字段的格式与可空声明；它靠生成器的类型映射、可空标记与各模块的生成片段测试守住。

## 失效条件

若出现一个不经前端、又要求服务端把时间渲染成网页文本的渠道，或一个不能解析 ISO 时间串的调用方成为契约的主要读者，则这条表示对那个渠道不再成立，要按渠道重新划分。

若前端拿不到查看者的显示时区（例如账户偏好与设备时区都不可读），则“由前端按查看者渲染”落空，时间的显示要另找落点。
