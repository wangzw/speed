# 审计的检索面由一个独立的 audit.admin 模块承载

## 背景

审计交付捕获，不交付查询面：检索与导出要先回答「谁可以查谁」，那是授权判定，而审计没有这项能力所依赖的上层概念（[ADR-audit-scope](adr-audit-scope.md)）。那条记录把承载者留白——「承载它们的模块不由本记录裁定，本记录只定它不在这里」——并把一个需要检索审计记录的宿主指向本模块之外，自带授权面。

一个宿主因此要自己读审计表、自己挂路由、自己判定、自己定租户隔离。示例宿主曾手写过这一面：`GET /audit`、`GET /audit/:id` 与 `GET /audit-entries`，带 `since`、`until`、`limit`、`tenant`，经授权能力的 handler 内 API 判定，并把跨租户的读写成一行审计（见 design-audit）。审计表对读它的一方的承诺只覆盖租户列、行键与唯一写入方（[ADR-audit-table-contract](adr-audit-table-contract.md)），其余列的形状不在承诺里，所以一个自建这一面的宿主把查询的字段与审计模块的列耦合起来，而这段代码在每个需要检索的宿主里重复。

权限 `audit.read` 与 `audit.export` 由授权能力自己携带；审计的实现子包 `pkg/audit/journal` 持有审计表、它的模型与它的写入。

## 考虑过的选项

### 继续由宿主自建

采纳它意味着保留现状：每个要检索审计记录的宿主自己挂路由、自己判定、自己读表。

**否决**：同一面在每个宿主里重写，租户隔离与授权各自发明；示例宿主曾经手写过一次，是这段代码会重复的证据。

### 把查询面并进审计模块

采纳它意味着审计模块既捕获又查询，一种登记单元里同时挂路由与判定。

**否决**：查询要先回答「谁可以查谁」，那是授权判定，审计没有这项能力所依赖的上层概念——这一条正是 [ADR-audit-scope](adr-audit-scope.md) 的判据，把查询并进审计模块等于让它裁一次授权。捕获侧也不该为查询背上授权层与入口模块的依赖。

### 由一个独立的检索面模块承载

采纳它意味着新增一个挂在固定基路径下的叶子模块，它判定经授权能力的 handler 内 API、读经审计实现子包新增的读面，自己不持数据、不持规则、不写审计表。

**采纳**，见决策。

## 决策

采纳：**审计的检索面由独立模块 `audit.admin` 承载。** 它挂在固定基路径 `/api/v1/audit/admin` 下，把审计记录的检索暴露成路由（`GET /api/v1/audit/admin/records` 与 `GET /api/v1/audit/admin/records/:id`）；判定在 handler 内经 `authz.guard` 的 handler 内 API 就 `audit.read` 做出，跨租户的读落在平台域；读经审计实现子包（`pkg/audit/journal`）新增的读面完成，用的是租户模块认可的只读模型。

审计模块仍不提供查询面：`pkg/audit` 与 `pkg/audit/journal` 不挂路由、不做判定；查询面落在一个独立的叶子里，`audit.read` 的判定与它同处一层。审计表仍只由审计模块写入，读面只发读语句。

**本记录只裁定承载者。** [ADR-audit-scope](adr-audit-scope.md) 说审计交付捕获、不交付查询面，这一条仍成立；它明文把承载者留给本记录之外裁定，本记录裁定的正是那个留白处。

## 后果

`pkg/audit/journal` 多出一个供别的模块调用的读面——一个游标分页的读（形状照 design-audit 与账户列表的形态），按租户模块认可的只读模型读审计表，只发读语句。读面与捕获同属 `audit.journal` 这一个登记单元，与写入面共用同一张表与模型。`audit.admin` 是可撤掉的一个叶子，不改变审计的捕获与写入。

**接受的代价：**

- **读面的字段读取审计表的列，本模块改那些列要跟着改。** 审计表除租户列、行键与写入方之外的列不在对外接口面内（[ADR-audit-scope](adr-audit-scope.md)）；读面读这些列时依赖的是一个非承诺的形状，两侧同属一个模块因而改动没有校验点，靠评审对上。
- **跨租户的读是平台操作。** 判定落在平台域，一个在某租户获授权的调用方读不到别的租户的行；代价是它读不到自己的行——一个租户自查自己轨迹的面不在本模块，是另一条路由、另一个域。
- **本模块的读不写审计行。** 谁读过哪份轨迹在审计表里看不见，除非宿主把审计管理面所在的端与本模块的路由写进审计模块自己的请求级捕获；取证要在日志与审计表之间对照。
- **读面在实现子包里，不在接口包里。** `pkg/audit` 是只依赖标准库的接口包，读面要经审计模块自己的表与模型读，因此落在 `pkg/audit/journal`；取用它的管理面 import 实现子包，`authz.admin` 以同形 import `pkg/authz/guard` 取接缝。

## 失效条件

- 若出现一条要求，规定审计记录的检索必须在租户域内判定（一个租户读自己的轨迹不需平台授权），则本决策「跨租户读落平台域」的判据不再成立。
- 若出现一条合规要求，规定检索与捕获必须由同一个模块提供、且两者之间不得另有授权面，则把查询面与捕获分开的判据不再成立（[ADR-audit-scope](adr-audit-scope.md) 的失效条件）。
