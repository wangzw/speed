# 种入面：独立于 Manager 的 Seeder 与 Reconciler 能力

## 背景

内置角色对管理面必须固定：不可删除、不可改写、不可改其授权（REQ-platform-config-025）。这条冻结保护的是运营者的全部权限——删掉或掏空该角色会让管理员被锁在管理后台之外，且没有命令能把角色放回去。

宿主同时必须能重复种入自己的策略数据，新声明的权限在下次 `seed` 时由内置角色持有（REQ-deployment-010）。冻结与重跑在这条路径上相遇：经 `Manager` 的写全被 `ErrBuiltinRole` 拒绝，种入于是只有两个坏结局——命令失败退出，或管理员静默地少一条权限。

管理面（`authz.admin` 的 HTTP 路由）与宿主种入是两个信任面：管理面由一个持有 `authz.role.manage` 的请求驱动，宿主的种入是它自己的部署步骤。冻结约束的是管理面，不应该约束宿主的种入。要把两者分开，写入口的可见性就必须在类型上分开，而不是靠 handler 里「不要调用它」的约定。

平台现在把权限分成治理与非治理两类，业务租户与 `system` 租户的租户管理员取治理集，个人租户取「治理集与宿主业务资源集的交」再减去宿主的排除集（[ADR-authz-tenant-management](adr-authz-tenant-management.md)）。业务租户与 `system` 租户的内置 `tenant-admin` 角色要在每次声明变化时收敛到新的治理集：新增的治理权限要进去，本次版本废弃的权限要出来。`Seeder` 只增不删，收敛到一个变小的集合它做不到；留给管理面又会回到「管理面不能写内置角色」这条要被守住的约束。

## 考虑过的选项

### 在 `Manager` 上新增种入方法

采纳它意味着 `Manager` 增加 `SeedGrants` 一类的方法，种入命令与其它写共用同一个接口。

**否决**：`authz.admin` 取用的正是 `Manager`。管理面的模块声明里没有第二个 token，但同一个接口同时装着管理写与种入写，墙就只存在于 handler 的调用约定里——一个未来的路由或一次重构即可越过，审查也只看得到「它持有 Manager」。这与「管理面不能绕过」这条判据冲突。

### 收窄冻结语义：`PutGrant` 只拒绝删改，允许新增

采纳它意味着 `builtin` 从「整角色冻结」改为「冻结到一批已声明的授权」：角色行需要记录冻结集，`PutGrant` 对已冻结的授权拒绝删改、对新的授权放行。

**否决**：管理面的 `PUT /api/v1/system/tenants/:tenant/roles/:role/grants/:permission` 走的正是 `PutGrant`。放宽它等于让管理面可以直接给内置角色增补授权，与本决策要守住的第一条判据相反。此外冻结集要落进角色行，表结构与公开记录形状都要改，代价大于收益。

### 让种入绕过 `Manager`：直接写库，或经管理面 HTTP 路由

采纳它意味着 `seed` 自己开事务写 `authz_grants`，或把权限授予伪装成管理面调用。

**否决**：直接写库绕过薄 adapter 的租户核对与行形状，也绕过提交后的快照换指针与 `authz.policy.changed` 发布，本副本在下次重载前会继续按旧策略判定。走管理面则要求 `role.manage`，而管理面本身对内置角色返回 409，等于用被拒绝的路径做种入。

### 给 `Seeder` 增加删除方法

采纳它意味着 `Seeder` 从「只增」变成「增删合一」，收敛与种入共用同一个能力。

**否决**：`Seeder`「只增」是它的安全性质——一次种入不会删掉任何既有授予，重复执行只会补齐。加上删除之后，同一个能力既能补齐也能收回，宿主的一次误调用就可能清掉内置角色的权限；收敛需要的是把目标集与当前集比较后按明确规则改动，不是让 `Seeder` 多一个删除入口。

### 独立于 `Manager` 的 `Seeder` 与 `Reconciler` 能力

**采纳**，见决策。

## 决策

采纳：**种入与收敛是两个独立于 `Manager` 的能力。`authz.Seeder` 由 `authz.policy` 排他交付，只增不删；`authz.Reconciler` 同样由 `authz.policy` 排他交付，把一个业务或 `system` 租户的 builtin `tenant-admin` 的授予集收敛到目标治理集，从不作用于 `platform-admin`，也不作用于个人租户的 `tenant-admin`。两者都不交给 `authz.tenantadmin`。**

**`Seeder`。** 它只声明 `SeedGrants(ctx, tenant, role, grants)`：给一个已存在的角色添加它尚未持有的（资源，动作）对，返回本次实际写入的行数。它只增——不删除、不改写、不重写时间戳——且幂等：已持有的授予不写、不报错、不计数。

**`Reconciler`。** 它声明一次收敛：给定租户、目标集与废弃集，它把该域的 builtin `tenant-admin` 授权集收敛——先添加缺失的授予，再删除本次版本声明为废弃的授予，全过程在一个数据库事务里。目标集与废弃集重叠时目标集胜出：两者都列出的授予保留。事务失败整体回滚，重试重新收敛。它从不对 `platform-admin` 生效，也不作用于个人租户的 `tenant-admin`（该角色不是内置角色）。它可重试、幂等：目标集与当前集一致时不写行、不发事件。错误顺序固定：角色不是 `tenant-admin` 时在任何读取之前返回 `ErrReservedRole`；`tenant-admin` 不存在时返回 `ErrUnknownRole`；`tenant-admin` 存在但不是内置时返回 `ErrReservedRole`。调用方在调用前落一行强制档审计，审计写不进即不收敛。

**收敛的规则。** 删除只针对调用方明确列出的废弃集，不按「不在目标集里就删」推断：另一个副本可能仍在运行一个仍声明该权限的版本，按差集删除会让副本之间互相清掉对方仍在使用的授予。目标集是本次版本的治理集；废弃集是本次版本已经移除的权限。两者都由调用方给出，`Reconciler` 不自己从权限目录推断。

**提交之后。** 事务提交之后，本进程重装策略快照并原子替换指针，再发布 `authz.policy.changed`；发布失败不回滚写入，其余副本由事件或周期重载跟进（[ADR-authz-cache](adr-authz-cache.md)）。

**管理面的墙不变。** `authz.admin` 只取用 `Manager`，不取用 `Seeder` 或 `Reconciler`；`authz.tenantadmin`（尚未实现）同样都拿不到。因此 `/api/v1/system/*` 与 `/api/v1/tenants/{tenant}/*` 下的任何写路由在类型上都够不到种入与收敛路径。管理面对内置角色的写继续以 `ErrBuiltinRole` 拒绝，映射为 409。

机制在设计文档 [design-authz](../design/modules/design-authz.md) 的「种入面」一节。

## 后果

宿主的重跑与内置角色的冻结不再互斥：声明集未变时种入返回零、不写行、不发事件；进程新增一条权限时，下一次种入把它补进内置角色，管理员自动拿到，命令不再失败。管理面与内置角色之间的墙由模块持有的能力决定，而不是由 handler 的分支约定维持。内置角色随声明集收敛，新增与废弃两个方向都可处理。

**接受的代价：**

- **公开接口面增加两个接口与两个方法**（`Seeder.SeedGrants` 与 `Reconciler.ReconcileGrants`），二者共用输入类型 `Grant`：种入接收一组授予，收敛接收目标集与废弃集两组，都是 `[]Grant`。这是兼容性新增，不破坏既有实现；取用 `Manager` 的宿主不受影响。
- **做种入或收敛的宿主必须解析对应的能力。** 只取用 `Manager` 的命令写不了内置角色的授权；只取用 `Seeder` 的命令收不回废弃的授予。这是分离的代价，也是分离的意义。
- **`Seeder` 与 `Reconciler` 都不核对权限目录。** 它们接受调用方给的（资源，动作）对，种入面是宿主 Go 代码的信任边界；管理面则先经目录与翻译核对，两者不是同一类调用方。宿主的种入与收敛步骤只写入目录翻译出的对。
- **废弃集由版本维护。** 一次声明变化要同时给出目标集与被移除的权限；漏列废弃项会让旧授予留在内置角色上，多列一项会让一个仍被使用的权限被收回。这份清单没有类型系统强制。
- **收敛是一个时刻的一致，不是持续的一致。** 多副本各自运行自己的版本，只有在下一次收敛或部署时才对到同一份目标集；「只删本次废弃」减小了副本互相干扰的可能，但不让所有副本在同一时刻看到同一份授予。

## 失效条件

- 若管理面被要求让运营者给内置角色增补或收回授权，独立种入面与收敛面的墙与本决策同时失效，需要重新裁定写入口的用途约束。
- 若宿主种入或收敛需要在写入前核对权限目录或租户名册，`Seeder` 与 `Reconciler` 的「不核对目录」这一条与当前签名都要重新评估。
- 若权限的废弃可以由声明本身自动推出，且各副本能保证在同一版本上运行，`Reconciler` 的「只删调用方列出的废弃集」这一条要重新比较。
