# 消息按语言整体渲染，复数用自写语法，日期与时间不归后端渲染

## 状态

已接受

## 背景

一次响应在服务端与客户端之间传递的东西有两类形态：后端拼好的复合字符串，以及类型化的值；渲染责任随载荷形态划分，复合字符串由产生它的模块整体渲染，类型化的值交给客户端（[ADR-i18n-rendering-ownership-2026-10-13](adr-i18n-rendering-ownership-2026-10-13.md)）。这句「整体渲染」对一个只写 `{{name}}` 插值的引擎还不成立：一条消息里的计数与数字要按消息的语言正确渲染，才算把复合字符串渲染完整。

引擎的目录是「键到消息」的 JSON 对象，消息是模板，`Args` 承载插值用的值（[ADR-i18n-catalogs-2026-10-13](adr-i18n-catalogs-2026-10-13.md)）。语言匹配需要 `golang.org/x/text`，它已在这一能力目录的依赖闭包里，在本能力目录内被绑定在引擎一处（[ADR-i18n-locale-type-2026-10-13](adr-i18n-locale-type-2026-10-13.md)）。

一条消息要能表达计数，就要有一处写复数的语法；要按语言渲染数字，就要有一处把整数与数字格式化。同时要给定日期与时间由谁来渲染。

## 考虑过的选项

### 采用 golang.org/x/text 的 message 与 message/catalog

用上游的 `golang.org/x/text/message` 与 `golang.org/x/text/message/catalog` 承载复数与选择。

**否决**：那个库不从文件解析一条复数消息——一条复数消息在 Go 代码里构造，或由 gotext 之类的工具从代码生成，库本身不认识「消息文件里怎么写一条复数」。采纳它不回答「一条 JSON 消息里的复数怎么写」，反而要把刚建起的 JSON 目录格式与覆盖目录重做一遍。

### 后端只写字面文本，计数与数字交给客户端

引擎只插值 `{{name}}`，复数与数字的格式由客户端按语言定。

**否决**：与渲染责任随载荷形态划分相悖。一段复合文本的插值上下文——计数与复数——只有产生它的模块才有；把它拆成值交客户端重组，等于让每一个客户端各自重建措辞与复数规则，措辞的改动随即成为一次对外变更。

### 日期与时间也由后端渲染

消息里可以内嵌一个按语言与账户时区格式化的日期。

**否决**：一个时间戳是类型化的值，客户端据它能独立、可交互地渲染，相对时间与本地化格式都对客户端可得；由后端预先格式化会把时区与格式钉进后端，而一个时间戳同时是机器可读的值。本功能目录改为交出账户的 IANA 时区，时间戳作为类型化的值交给客户端。

### 消息按语言整体渲染，复数用自写的小语法，日期与时间不归后端

引擎渲染一条消息的文本、计数与数字；复数段写作 `{{name, plural, <category>=<text>, ...}}`；日期与时间不渲染，只交出账户的时区。

**采纳**，见决策。

## 决策

采纳：

- 引擎把一条消息按它的语言整体渲染：字面文本、一个 `{{name}}` 占位符，以及一段复数。`Args` 的取值带类型——字符串原样写入，整数与数字按消息的语言格式化，分组与分隔取该语言的 CLDR 数据而非 `fmt` 的默认格式。
- 一段复数写作 `{{name, plural, <category>=<text>, ...}}`：按计数的 CLDR 类别选分支，类别是六个 `zero`、`one`、`two`、`few`、`many`、`other`，`other` 必填，分支里的 `#` 是格式化后的计数；计数不属于的类别回落到 `other`；参数不是整数（缺失或类型不符）时该段原样保留。分支文本是一段字面文本与 `#`，不能再嵌一个占位符：嵌套的占位符在装配期以 `ErrInvalidMessage` 报出，而不是被当成一个缺 `other` 的段。
- 语法是本功能目录自己的小语法，不是 `golang.org/x/text` 的消息格式。`golang.org/x/text` 已被这一能力目录的闭包带上，位置不变：在本能力目录内它仍只绑定在引擎一处，根包与其余子包不拉它（[ADR-i18n-locale-type-2026-10-13](adr-i18n-locale-type-2026-10-13.md)）。
- 日期与时间不归后端渲染：本功能目录交出账户的 IANA 时区（`Resolver.TimeZoneOf`、`Resolver.TimeZoneFor`），一个时间戳作为类型化的值交给客户端渲染。
- 一条不能解析的消息在装配期终止启动，以 `ErrInvalidMessage` 点名该键与它来自的来源（[ADR-i18n-catalogs-2026-10-13](adr-i18n-catalogs-2026-10-13.md)）。

## 后果

一条复合消息由产生它的模块按请求语言整体渲染，计数与数字随语言变；时间戳与账户时区以类型化的形态跨越边界，客户端独立渲染。

**接受的代价：**

- `Args` 的取值类型由 `map[string]string` 变为 `map[string]Value`：每一个插值字符串的调用方都要改用 `i18n.String` 构造，这是对公开面的一次破坏性变更。
- 复数语法由本功能目录自己解析与校验：六个类别、`other` 必填、分支的边界与 `#` 的展开都归引擎，`golang.org/x/text` 只提供类别判定与数字格式化，不提供文件的语法。
- 复数段只按整数计数选分支：一条要按非整数量（货币、分数）选分支的消息表达不出。
- 日期与时间不在后端的渲染范围：一个要显示时间戳的客户端须自己渲染，后端只交出时区。
- 本仓库当前没有任何模块渲染计数或复数——本记录要求的能力先在引擎就位，预期第一个用它的地方是通知与邮件的正文。

## 失效条件

若一条后端拼出的复合消息必须内嵌一个按语言与时区格式化的日期，则「日期与时间不归后端渲染」不成立，时区要从一项交出的偏好变为渲染的输入，本记录要重新定位日期渲染的归属。

若复数要按整数之外的量选分支（货币、分数），或消息文件需要这套小语法表达不出的选择（按性别、嵌套复数），则自写的语法不够，要扩充语法或改回上游的消息格式。

若一条消息要选用的上下文不在产生它的模块（例如计数由另一个模块在更晚的时刻给出），则渲染责任随载荷形态划分这一条不够，要重新定位渲染点（[ADR-i18n-rendering-ownership-2026-10-13](adr-i18n-rendering-ownership-2026-10-13.md)）。
