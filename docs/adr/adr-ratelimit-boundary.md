# 限流不算架构的安全边界

## 背景

架构文档的安全边界一节点名了几样东西：敏感输入项脱敏、配置定位符、租户隔离、审计覆盖面。限流不在其列，而它是否属于这一类决定两件事：它被绕过要不要进安全评审，以及计数后端故障时它该放行还是拒绝。

限流被绕过时，调用方得到的是超额的服务，不是别人的数据。

## 考虑过的选项

### 算作安全边界

**否决**：本模块的判定不隔离任何数据，只约束请求的频次，被绕过的结果是拒绝服务面失守，与数据越权不是同一类。把它计入安全边界会让它的故障取舍与安全边界要求的处置冲突——安全边界要求宁可拒绝，而按拒绝处置会把一次后端故障放大成全端拒绝。

### 不算安全边界

**采纳**，见决策。

## 决策

采纳：**限流不计入架构的安全边界。** 它被绕过是拒绝服务面的事实，不是数据越权面的事实。

## 后果

**接受的代价：**

- 限流被绕过不触发安全层面的评审。一个把它当作唯一防线的部署要自己把这个缺口补上。
- 本模块的故障取舍按可用性优先裁定（见 [ADR-ratelimit-failure](adr-ratelimit-failure.md)），它因此不适合承担安全边界的角色。

## 失效条件

若某个部署把限流用作某个高价值接口的唯一防线，那一处应按安全边界的处置另做一层，本记录不为它改判。
