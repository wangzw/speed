# 请求侧只产一个时长直方图，属性只取方法与状态码

## 状态

已接受

## 背景

`http` 设计文档的「Serve 阶段的组装」一节写明，登记层按排序结果依次交给该端 gin 引擎的 `Use`，每一层作用于该端的全部路由，包括无匹配路由与方法不允许的响应。层在引擎之内、路由匹配之后运行。

已匹配的路由在链上可读：`c.FullPath()` 返回已匹配路由的完整路径写法，与登记方传给 `Endpoint.Route` 的 `path` 相同，没有匹配的路由时为空串。路由属性在这里取得到，要决定的是属性面是否纳入它。

属性是闭集还是开放集合，决定它日后改不改得动。含标识的维度一旦被宿主的看板与告警引用，改名与去留都要连带改那些引用；认证把这条代价写在自己的后果一节（[ADR-authn-verdict-2026-09-20](adr-authn-verdict-2026-09-20.md)：「未表态」作为可观测面上的一类计数，名字一旦被看板与告警引用就改不动）。属性表因此是一条决策，不是实现的细节。

租户是另一个候选维度。它的取值与租户一一对应，取值集合随租户数增长；而租户标识已经在另一条通路上有承载处——事件总线携带它，并把「可观测性要按租户与业务类型切分」写成自己存在的理由之一（[ADR-event-scope-2026-09-21](adr-event-scope-2026-09-21.md)）。

## 考虑过的选项

### 带上路由属性

采纳它意味着直方图按已匹配的路由切分，请求量、错误率与延迟落到一条具体的 API 上，指标侧不必依赖跨度侧。

**否决**：属性是闭集还是开放集合，决定它日后改不改得动（见背景）。路由属性的取值随宿主登记的路由集合而增长，不由本模块限定；它一旦被看板与告警引用，路由的改名与去留都要连带改那些引用。放宽属性面容易，收回不行，因而本记录取窄的属性面。

### 带上租户属性

采纳它意味着请求指标按租户切分，多租户宿主在指标侧直接得到每租户的延迟与错误率。

**否决**：基数与租户数同阶，且租户标识已经在事件派生的跨度上有承载处；把它再放进请求指标的属性里，等于把一个高基数维度放到最热的信号上。

### 另立一个请求计数器

采纳它意味着请求量由一个计数器承载，直方图只负责时长。

**否决**：直方图自身带计数，请求量从它的计数读出；另立一个计数器会让同一个事实有两个来源，两者在采样与重试上的口径还会不一致。

### 只产一个时长直方图，属性取方法与状态码

采纳它意味着请求侧只有一个计量，属性面收得最窄。

**采纳** — 见决策。

## 决策

采纳：**采集层对每个请求记一次时长直方图，携带的属性只有请求方法与响应状态码；方法取九种标准方法之一，其余一律折叠为一个固定值；不携带路由，不携带租户。**

## 后果

请求侧只产生这一种计量，宿主拿到一张「方法 × 状态码 × 时长」的表，不需要在多个计量之间对齐口径。

**接受的代价：**

- **按路由聚合不在请求指标里。** 本记录选择不纳入这条维度，要按 API 切分的指标看板在本模块的装配下没有依据。
- **按租户聚合在指标侧同样没有。** 多租户宿主做租户级延迟与错误率时，这个维度只在事件派生的跨度上，一个没有装配事件总线的宿主取不到它。
- **非标准方法分不开。** 自定义动词与扩展方法连同真正未知的方法全部落进同一个固定取值，按方法排查时它们在指标上无法彼此区分。

## 失效条件

若在已发布的宿主上，按 API 切分的请求指标是普遍的需要——看板与告警普遍要按路由读请求量、错误率与延迟——则属性面应当放宽到纳入路由属性。
