# 接口字段统一用下划线命名

## 背景

接口是生成的契约（[ADR-http-openapi-generation](adr-http-openapi-generation.md)）：模块在 Go 里声明字段，生成器把 `json`、`form` tag 反射成 JSON Schema 的属性名。字段名进入契约、生成的客户端与前端读取处，是接口的一部分，读方按它取值。

字段名只应有一套拼写。两套拼写并存时，同一份应答里的字段要按名字逐个记住用哪一种，而名字里有没有下划线不携带含义。本仓库的 Go 结构体、事件载荷与审计明细已经用下划线命名，接口上的时刻字段也已经是下划线；这是契约其余字段要跟随的写法。

本仓库在 1.0 之前不考虑兼容（[ADR-no-stability-promise](adr-no-stability-promise.md)）：改名不保留旧字段名，读方与契约在同一批改动里更新。

## 考虑过的选项

### 沿用驼峰命名，把已有的下划线字段改成驼峰

**否决**：这是与反向改名同样规模的破坏性变更，却要把 Go 结构体、事件载荷与审计明细的既有写法一并反过来；下划线在那些地方已经是一致的约定。

### 两套拼写并存

时间字段用下划线，其余字段用驼峰。

**否决**：读方要按字段逐个记住拼写，生成的客户端因此暴露两种约定；混用增加记错的成本，而它换不到任何区分。

### 全部字段用下划线命名

**采纳**，见决策。

## 决策

采纳：接口字段与路径参数统一用小写加下划线的命名；请求体与应答体的属性名、路径参数名同属这条规则。

## 后果

- 字段改名是破坏性变更：读这些字段的前端、生成的客户端与契约在同一批改动里更新，不保留旧字段名的兼容层（[ADR-no-stability-promise](adr-no-stability-promise.md)）。
- 没有自动检查器逐个核对字段名的拼写；命名靠 operation 声明与各模块的片段测试守住。
- Go 的导出字段名不是接口：它可以继续用 Go 的驼峰命名，`json`、`form` tag 写出下划线，两者不必同名。

## 失效条件

若出现一个不能使用下划线命名的调用方或载荷形态，例如某个协议把字段名集合固定在它自己的写法里，则那条载荷不受这条规则约束，要按协议另定。
