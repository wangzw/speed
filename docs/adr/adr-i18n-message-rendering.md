# 消息按语言整体渲染，复数与时间段用自写语法，内嵌的日期时间按语言与时区渲染

## 背景

一次响应在服务端与客户端之间传递的东西有两类形态：后端拼好的复合字符串，以及类型化的值；渲染责任随载荷形态划分：一个返回复合字符串的后端渲染它的全部，一个返回类型化值的后端把渲染交给客户端（[ADR-i18n-rendering-ownership](adr-i18n-rendering-ownership.md)）。这句“渲染它的全部”对一个只写 `{{name}}` 插值的引擎还不成立：一条消息里的计数、数字与日期时间都要按消息的语言与账户时区正确渲染，才算把复合字符串渲染完整。

引擎的目录是“键到消息”的 JSON 对象，消息是模板，`Args` 承载插值用的值（[ADR-i18n-catalogs](adr-i18n-catalogs.md)）。语言匹配需要 `golang.org/x/text`（[REF-golang-x-text](../references.md)），它已在这一能力目录的依赖闭包里，在本能力目录内被绑定在引擎一处（[ADR-i18n-locale-type](adr-i18n-locale-type.md)）。

一条消息要能表达计数，就要有一处写复数的语法；要按语言渲染数字，就要有一处把整数与数字格式化；要渲染内嵌的日期与时间，就要有一处写下它的格式与据以换算的时区。

## 考虑过的选项

### 采用 golang.org/x/text 的 message 与 message/catalog

用上游的 `golang.org/x/text/message` 与 `golang.org/x/text/message/catalog` 承载复数与选择。

**否决**：那个库不从文件解析一条复数消息：一条复数消息在 Go 代码里构造，或由 gotext 之类的工具从代码生成，库本身不认识“消息文件里怎么写一条复数”。采纳它不回答“一条 JSON 消息里的复数怎么写”，反而要把刚建起的 JSON 目录格式与覆盖目录重做一遍。

### 后端只写字面文本，计数、数字与日期时间交给客户端

引擎只插值 `{{name}}`，复数、数字与日期时间的格式由客户端按语言定。

**否决**：与渲染责任随载荷形态划分相悖。一段复合文本的插值上下文（计数、复数，以及一条内嵌日期所用到的语言与时区）只有产生它的模块才有；把它拆成值交客户端重组，等于让每一个客户端各自重建措辞与复数规则，措辞的改动随即成为一次对外变更。

### 不渲染日期与时间，一律交给客户端

引擎渲染文本、计数与数字，日期与时间不渲染：本功能目录只交出账户的 IANA 时区（[REF-iana-tz](../references.md)），一个时间戳作为类型化的值交给客户端。

**否决**：与渲染责任随载荷形态划分相悖。一条后端拼出的复合消息若内嵌一个日期，把它拆成一个类型化的值交给客户端，就是把这条消息劈成两半：后端给出其余部分与一个空位，客户端用一个值去补。归属由返回形态决定：一个日期一旦落在后端拼出的复合字符串里，它就是那串复合字符串的一部分，与它周围的文本、计数、复数一样由后端渲染；只有作为独立字段返回的日期或时间才是类型化的值，走标准 ISO 格式（[REF-iso8601](../references.md)）交给客户端。让一条复合消息缺掉它内嵌的日期，是把“渲染完整”这条判据做残。

### 消息按语言整体渲染，复数与时间段用自写的小语法

引擎渲染一条消息的文本、计数、数字，以及内嵌的日期与时间；复数段写作 `{{name, plural, <category>=<text>, ...}}`，时间段写作 `{{name, time, <layout>}}`，时间按段里写下的 Go 布局与渲染上下文的时区渲染。

**采纳**，见决策。

## 决策

采纳：

- 引擎把一条消息按它的语言整体渲染：字面文本、一个 `{{name}}` 占位符、一段复数，以及一段时间。`Args` 的取值带类型：字符串原样写入，整数与数字按消息的语言格式化，时间按渲染上下文的时区格式化；分组与分隔取该语言的 CLDR（[REF-unicode-cldr](../references.md)）数据而非 `fmt` 的默认格式。
- 一段复数写作 `{{name, plural, <category>=<text>, ...}}`：按计数的 CLDR 类别选分支，类别是六个 `zero`、`one`、`two`、`few`、`many`、`other`，`other` 必填，分支里的 `#` 是格式化后的计数；计数所属的类别在消息里没有对应分支时回退到 `other`；参数不是整数（缺失或类型不符）时该段原样保留。分支文本是一段字面文本与 `#`，不能再嵌一个占位符：嵌套的占位符在装配期以 `ErrInvalidMessage` 报出，而不是被当成一个缺 `other` 的段。
- 一段时间写作 `{{name, time, <layout>}}`：参数是一个时间（`i18n.Time`），布局是段里第二个逗号之后的内容：去掉分隔用的首尾空白后的一个 Go 布局，可以自带逗号、空格与冒号；取出该时间，按布局与渲染上下文的时区渲染成文本。上下文未指时区，或指了一个本进程加载不出的时区名时，都视为 UTC。参数缺失或不是时间时该段原样保留；布局为空时在装配期以 `ErrInvalidMessage` 报出。
- 语法是本功能目录自己的小语法，不是 `golang.org/x/text` 的消息格式。`golang.org/x/text` 已被这一能力目录的闭包带上，位置不变：在本能力目录内它仍只绑定在引擎一处，根包与其余子包不拉它（[ADR-i18n-locale-type](adr-i18n-locale-type.md)）。
- 一个把日期或时间**作为独立字段**返回的模块把渲染交给客户端：那时它走标准 ISO 格式。归属由返回形态决定，不按字段种类决定（[ADR-i18n-rendering-ownership](adr-i18n-rendering-ownership.md)）。
- 一条不能解析的消息在装配期终止启动，以 `ErrInvalidMessage` 点名该键与它的来源（[ADR-i18n-catalogs](adr-i18n-catalogs.md)）。

## 后果

一条复合消息由产生它的模块按请求语言整体渲染，计数、数字与内嵌的日期时间随语言与时区变；一个作为独立字段返回的时间戳以类型化的形态跨越边界，走标准 ISO 格式交给客户端独立渲染。

**接受的代价：**

- `Args` 的取值类型由 `map[string]string` 变为 `map[string]Value`：每一个插值字符串的调用方都要改用 `i18n.String` 构造，这是对公开接口的一次破坏性变更。
- 复数语法由本功能目录自己解析与校验：六个类别、`other` 必填、分支的边界与 `#` 的展开都归引擎，`golang.org/x/text` 只提供类别判定与数字格式化，不提供文件的语法。
- 复数段只按整数计数选分支：一条要按非整数量（货币、分数）选分支的消息表达不出。
- **布局是一个 Go 布局，由消息文件自带。** 月份与星期的名字随布局取自 Go 的固定英文，`time.Time.Format` 不按语言产出它们；一种语言要用自己的名字，就在自己的消息文本里写出它们。按语言的月份名与星期名因此不由此能力目录提供。
- **一个时间段把一次文件系统读取带进读路径。** `time.LoadLocation` 每次调用都重读 zoneinfo 文件，标准库不跨调用缓存，引擎为此持一份按名缓存的 `*time.Location`，置于一把互斥锁之后。独占写锁只在渲染一条带时间段的消息且该时区名第一次出现（缓存未命中）时取一次，此后每渲染一次该名仍取一次读锁；缓存是懒建的，只渲染文本、计数与数字的运行从不取锁、也不读文件系统。渲染文本、计数、复数与数字的路径因此仍是无锁、零 IO 的内存读，而带时间段的消息在时区名首次出现时读一次文件系统。
- **一个加载不出的时区名视为 UTC 而非失败。** 拼错的时区名，或本进程的 zoneinfo 里没有的名字，静默地按 UTC 渲染，没有一处拦截、也没有一行诊断；写侧以 `ValidTimeZone` 在写入时校验格式，本能力目录不对上下文里既有的名字回头复检。
- 本仓库当前没有任何模块渲染计数、复数或时间段；本记录要求的能力先在引擎就位，预期第一个用它的地方是通知与邮件的正文。

## 失效条件

若复数要按整数之外的量选分支（货币、分数），或消息文件需要这套小语法表达不出的选择（按性别、嵌套复数），则自写的语法不够，要扩充语法或改回上游的消息格式。

若一条消息要按语言产出月份名或星期名（而不只是按自带的 Go 布局拼出一串数字与分隔），则 Go 布局不够，时间段要新增一处按语言取名称的机制，或改回一个能按语言格式化的日期库。

若一条消息要选用的上下文不在产生它的模块（例如计数由另一个模块在更晚的时刻给出），则渲染责任随载荷形态划分这一条不够，要重新定位渲染点（[ADR-i18n-rendering-ownership](adr-i18n-rendering-ownership.md)）。
