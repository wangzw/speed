# 策略存储：自写薄适配器加真实租户列，取代 Casbin 的默认存储

## 背景

引擎桥接 Casbin（[REF-casbin](../references.md)） v3（[ADR-authz-engine](adr-authz-engine.md)），策略持久化经 Casbin 的存储接口 `persist.Adapter` 完成。

本仓的数据经数据库模块交付的句柄发出，隔离落在共享表加一列租户标识上：过滤经一条 GORM（[REF-gorm](../references.md)）插件作用于每一条针对受约束模型的语句，模型按约定声明自己受约束；上下文无租户时受约束模型的语句拒绝执行，跨租户必须在调用点字面写出（[ADR-tenant-isolation](adr-tenant-isolation.md)、[ADR-tenant-scoping](adr-tenant-scoping.md)）。隔离落脚的是一列真实的、可被插件与受约束模型认出的租户列。

旧实现成文否决了 Casbin（[ADR-authz-reversal](adr-authz-reversal.md)）。其针对存储的那条理由：官方 `casbin_rule` 表没有 `tenant_id` 列，租户藏在策略串的域值里，这张全产品在安全上最敏感的表因而退出租户隔离的全部三层——GORM 插件注入不到过滤条件、受约束模型用不了、Postgres 行级安全以 `tenant_id` 列为准而无从下手——隔离退化成「调用方传对了域字符串」。本记录正面回答该理由。

Casbin 的默认存储把全部策略落成一张 `casbin_rule` 表：一行是策略类型加若干文本列，没有一列承载租户。官方 `casbin/gorm-adapter`（[REF-casbin-gorm-adapter](../references.md)）能把这张表建在 GORM 之上，但它的默认构造自己开 `*gorm.DB`（`NewAdapter` 直接调 `gorm.Open`），与本仓经数据库模块交付的句柄、插件与租户过滤不是同一条路。

## 考虑过的选项

### 用 Casbin 的默认存储表 `casbin_rule`

策略落在 `casbin_rule` 上，租户藏在策略串的域值里。

**否决**：正是旧树针对存储的那条理由所指的形态——租户没有一列承载，这张表退出租户隔离，隔离退化成对域字符串的信任；本仓的隔离机制（过滤插件按租户列、受约束模型按约定）在它上面无处落脚。

### 官方 `casbin/gorm-adapter`

用官方的 GORM 适配器把默认存储建在 GORM 之上。

**否决**：它的默认构造自己开 `*gorm.DB`，与本仓经数据库模块交付的句柄不是同一条路，正是本仓数据规则禁止的裸访问形态；即便经它接受既有句柄的构造传入本仓句柄，它建的表仍是 `casbin_rule`，没有租户列，与用 Casbin 的默认存储表落到同一形态。

### 放键值或文件

策略放键值存储或文件，不经数据库表。

**否决**：键值与文件没有「列」的概念，隔离只能靠键前缀或路径约定，退出本仓按租户列的过滤与受约束模型；多副本下一次写入如何到达其余副本要不靠文件共享、要不靠键值的一致性，判定的装载点因而没有一个由本仓隔离机制守着的权威来源。键值模块交付的是原语、不承载语义（[ADR-kv-scope](adr-kv-scope.md)）。

### 自写薄适配器，落带真实租户列的表

**采纳**，见决策。

## 决策

采纳：策略持久化经数据库模块自写一个薄适配器，实现 Casbin 的 `persist.Adapter`；策略落在以 `tenant_id` 领衔键的表上，取代 Casbin 的默认存储。

- **被否的是默认存储，不是引擎。** 引擎被采纳（[ADR-authz-engine](adr-authz-engine.md)）；本记录替换的只是策略的存放形态，把租户从策略串里提到一列真实的列上。
- **每张表各承载一类行。** 角色落 `authz_roles`，授权（判定里的 `p` 行）落 `authz_grants`，绑定（判定里的 `g` 行）落 `authz_bindings`；这些表各以 `tenant_id` 领衔主键，租户列非空。
- **薄适配器实现 `persist.Adapter`。** 适配器把表里的行与 Casbin 的策略行互相转换，写时核对租户列与调用方给的租户一致，不一致即拒绝。
- **装载跨租户。** 判定进程持有全部租户的策略，装载读整张策略表。
- **不实现清表重写。** 策略只经本模块的管理接口逐条增删，`SavePolicy` 的清表重写不实现。

## 后果

承载策略的表带真实的 `tenant_id` 列，本仓的租户隔离机制在它们上面落脚——这正是旧树针对存储的那条理由的消解方式：租户不再是藏在策略串里的一个值，而是表上领衔键的一个非空列；过滤插件与受约束模型认得出这一列，隔离不再退化成对域字符串的信任。

**接受的代价：**

- **每个副本持有全部租户的策略。** 判定进程在内存里装载的是全部租户的策略（[ADR-authz-cache](adr-authz-cache.md)）：内存占用与启动装载量随租户总数增长，一个租户的策略改动会让每个副本重装整份策略。策略因此是共享的权威数据，副本之间靠事件失效与周期重载收敛。
- **装载必须跨租户读整张策略表。** `LoadPolicy` 是安全敏感表上一处跨租户读：读语句要在跨租户标记下发出，漏写这个标记的读会被租户过滤挡下或读空。这是「判定进程持有全部租户策略」的必然后果，不是可选的读法。
- **薄适配器要自己实现策略的读写与租户列的核对。** Casbin 的 `persist.Adapter` 方法不携带租户或上下文，租户列的填充与核对、跨租户标记的施加由本模块的适配逻辑承担；使用官方适配器所省掉的这份实现与维护，落到本模块头上。
- **这些表的键与租户列是声明方要守的义务。** 租户列领衔键、非空，是隔离与写入正确性的前提（[ADR-tenant-isolation](adr-tenant-isolation.md)），由本模块写迁移文件时守住，本模块之外没有一处会替它校验。

## 失效条件

- 若租户总数增长到「每个副本装载全部租户策略」在内存或启动装载时间上不可行，存储与装载的形态要重新裁定（[ADR-authz-cache](adr-authz-cache.md) 记有同一条件的失效面）。
- 若官方 `casbin/gorm-adapter` 改为能接入本仓的句柄、插件与租户过滤同一条路，且仍带真实租户列，「自写薄适配器」的必要性需要重新比较（[ADR-authz-reversal](adr-authz-reversal.md) 记有同一条件的失效面）。
- 若 Casbin 的存储接口改为携带上下文，「适配器自己拿租户与跨租户标记」这一条要重新评估。
