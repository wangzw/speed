# 受支持语言集由目录派生，默认语言是配置而非常量

## 背景

服务端生成的用户可见文本要按请求语言渲染。渲染需要两个量：本次运行能渲染哪些语言，以及一个什么都没指名的请求落到哪一种。前者是受支持语言集，后者是默认语言。

认证模块此前把两者都写进代码：`pkg/authn` 根包导出 `LocaleEN`、`LocaleZH` 两个常量，短信模板按 `zh-CN`、`en-US` 这个封闭集声明，`LocaleOf` 把空值读作其中之一。i18n 能力引入时的初版沿用同一形态：根包导出 `LocaleEN`、`LocaleZH` 与 `Default`，`Default` 是 `LocaleEN`。

这个形态假定服务端只讲两种语言，且默认是编译期事实。两个假定都不必成立：一个模块的文案可以只有一种语言，也可以有第三种；哪一个语言是默认是部署的产品选择，与代码的结构无关。默认语言另有一条记录约束它与认证共享（[ADR-i18n-default-locale](adr-i18n-default-locale.md)）。

## 考虑过的选项

### 代码里写死一个两语言集

受支持语言集是 `{zh-CN, en-US}` 两个常量，默认写死其中之一。

**否决**：加一种语言要改代码、重编译；服务端的目录与短信载体的模板各写一份同一张表，两处会分叉；而一个只讲一种语言的模块或载体被这条约束强加另一种。

### 受支持语言集在代码里枚举，默认是编译期常量

语言集是可扩展的常量列表，默认是其中的一个常量。

**否决**：默认仍是编译期事实，一个部署换目标语言要改代码；而语言集在代码里还有一个副本，与各模块实际携带的目录之间没有强制关系，一份未被声明的语言照样能被「支持」。

### 默认按模块各设一份

每个需要默认的模块各自声明自己的默认语言。

**否决**：同一个请求在错误响应与短信两处得到不同语言；默认的边界不显现，改动其一让两处悄悄分叉（[ADR-i18n-default-locale](adr-i18n-default-locale.md)）。

### 受支持语言集由已声明的目录与配置的覆盖目录派生，默认是配置项

语言集是各模块声明的目录与配置指定的覆盖目录所承载语言的并集，装配期派生；默认语言是配置项 `i18n.default-locale`。

**采纳**，见决策。

## 决策

采纳：**通信能力不枚举语言表**。一个进程的受支持语言集是各模块声明的目录与配置指定的覆盖目录所承载语言的并集，由引擎在装配期派生；短信模块没有一份整载体的语言集，一条消息能用哪些语言由它所用模板的声明给出，同样从声明派生。代码里没有任何一处写出「本运行支持哪些语言」。

默认语言是配置项 `i18n.default-locale`，取值是一个 BCP 47 标签，未设置时为 `en-US`。默认必须是被受支持语言集覆盖的语言：引擎在启动期核验这一点，声明集非空而没有任何一份默认语言的条目时以 `ErrNoCatalog` 终止启动并点名那个语言。i18n 引擎与认证的短信模块读同一个项（[ADR-i18n-default-locale](adr-i18n-default-locale.md)）。

一个不受支持的请求语言不是一次错误：i18n 一侧回落到配置的默认语言，短信一侧解析到该消息所用模板声明的语言、落不到时用默认语言。语言是一份偏好，受支持语言集才是消息实际能发出的语言。

目录的声明机制、合并与校验见 [ADR-i18n-catalogs](adr-i18n-catalogs.md)。

## 后果

新增一种语言是新增一份目录、或在载体的模板声明里加一个语言，不改代码；一个只讲一种语言的模块或载体不被强加别的语言。默认语言由配置给出，一个部署换目标语言只改配置。

**接受的代价：**

- 受支持语言集在编译期不可知，只有装配期才知道；一段判断「这个语言受不受支持」的代码拿不到编译期的答案，只能经引擎在运行期问。
- 默认语言的覆盖成为启动硬约束：声明集里没有任何一份默认语言的条目，整个进程起不来，换来的是运行期不会静默落到一个没有目录的语言。
- 一个不受支持的语言不再被当场拒绝，而是落到默认语言；调用方若需要「拒绝未知语言」的行为，要自己先比对受支持语言集。
- 默认语言是启动期输入，取值不是 BCP 47 标签时启动失败。

## 失效条件

若出现必须由运行期数据决定语言集的场景（例如按租户启用语言），则「语言集在装配期由声明派生」不再成立，本记录要改为区分静态声明与运行期来源。

若某个消费方在编译期就需要知道受支持语言集（例如生成前端的语言切换清单），则「编译期不可知」这条代价变得不可接受，需要另立一条把语言集在构建期发布出去的机制。
