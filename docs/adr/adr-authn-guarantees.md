# 装配层面的性质写成非保证，不为它们改动别的模块

## 背景

认证的否决力是 HTTP 中间件链上的一层，由认证网关在 `Init` 登记。这条链的登记接口对 `Init` 期的任何模块开放，且拿不到登记方的身份：`Endpoint` 不带它，`core` 不提供「当前正在 `Init` 的模块」这样的查询，登记又允许发生在模块自己起的协程里。入口模块因此不校验一层声称代表的功能与它所属模块交付的功能是否一致，一层可以声称代表认证而它所属模块并不交付认证。

层与层的先后由各层声明的阶段给出，阶段之内由指向功能标识的 `After`、`Before` 与 `Order` 决定。「位于最外层」这个诉求与任何具体功能都无关，只能用最外的阶段与该阶段内的 `Order` 表达，而两个都要求位于最外层的层之间互相不知道对方取了什么位置（[ADR-http-stages](adr-http-stages.md)）。「链上没有任何一层在认证之外」因此不是链上任何一方能单独声明出来的性质。认证之后的层同样如此：租户准入层、授权层与宿主自写的层，各自声明自己的阶段与阶段内的 `After`、`Before`，认证只知道自己的阶段与锚点（[ADR-tenant-admission](adr-tenant-admission.md)）。

认证网关是否在场由宿主的命令树与预置决定，模块不声明、也无从知道自己出现在哪条命令下（[ADR-command-tree](adr-command-tree.md)、[ADR-supplied-instance](adr-supplied-instance.md)）。未被本次命令纳入、也没有预置实例的模块不在参与集里，连 `Prepare` 都不执行。启动诊断的义务写的是：启动成功时，未进入启用集的模块必须在诊断中列出，并给出它被消解禁用的原因。架构文档把未被纳入的模块明确排除在这条义务之外，理由是它起于宿主写在命令树上的决定、不是意外；义务要求的那个原因它也一个都写不出——`Prepare` 都没执行，没有参与消解。按名查询启用结果对这种模块给出禁用，原因写明它不在这条命令的参与集里；注册表另有一个查询单独回答它在不在本次参与集内。这些查询都要宿主主动去问，不会自己出现在任何输出里。

认证的覆盖面随范围扩大而变宽。网关校验的凭据除 `Authorization` 头之外还有校验后端认领的 cookie；登录会话令牌、JWT（[REF-rfc7519](../references.md)）访问令牌、刷新令牌都是凭据，各自经头、cookie 或请求体到达（[ADR-authn-credential-dispatch](adr-authn-credential-dispatch.md)）。网关默认守入口模块声明的全部端，显式清单只作收窄，枚举靠入口模块的端名读口（[ADR-http-enumeration](adr-http-enumeration.md)）。冒充身份只被放进租户准入层所守的端与登记为可冒充的路由，准入层是 tenant 目录的模块，由它交付 `authn.ScopeGuard`（[ADR-authn-impersonation](adr-authn-impersonation.md)）。

想要而拿不到的是这样一类性质：成立与否取决于本次装配里还有哪些层、它们各自怎么写，而认证既不认识它们，也没有任何声明位能约束它们。链上没有任何一层能绕过认证层、凭据不向认证层以内泄漏、认证层以内的缓存或合并层不把一个主体的应答交给另一个主体、准入层所守的端上的路由都带着租户上下文，都属于这一类。要把其中任何一条变成入口模块强制的性质，落点都在 `pkg/http` 的接口上——那是认证不拥有的模块，它的接口被每一个贡献路由的模块使用，新增的代价落在每一个宿主头上，与这个宿主是否纳入认证无关。

架构的错误模型在这里既给了义务也给了边界：每一层为自己产生的失败提供哨兵，不允许留下它自己造出却说不出名字的失败；而这条约束不延伸到经由这一层返回的一切失败（[ADR-authn-failure](adr-authn-failure.md)）。哪些失败必须配哨兵、哪些才谈得上写成非保证，判据由此而来。

## 考虑过的选项

### 在入口模块上增开接口，把性质变成强制

为认证判定在 `pkg/http` 上开一个专属位置：每端唯一的守卫席位、可读回的已登记模式清单、向路由引擎问「这条请求会分发到哪条路由」的接口，以及一个「本端只在守卫之后服务」的配置键。链的组装把这个席位当作一层普通登记层排入，而登记层的先后由阶段与阶段内的约束排出：认证在鉴别阶段，观测阶段的各层在它之外，它做不到「排在全部登记层之外」。席位的唯一性在组装时校验。

**否决**：每一个接口把可被绕过的点挪到别处，不消掉它。把判定从登记层挪到最里侧插槽这一形态修掉了「认证之后有层重写路径」，换来的是网关与插槽之间的任何一层只要自己应答就完全绕过认证——同一套装配上的对照：无凭据的 `GET /admin/secret` 在这个形态下得 200 且短路的缓存层应答一次，判定位于全部登记层之外时得 401 且该层与受保护 handler 各零次。暴露范围比它修掉的那一条更大。守卫席位这一形态同样不闭合：席位的名字由占座者自报，一个注册名为别的东西的模块把名字填成认证的名字，冲突文本按同一个名字两次处理，单独占座时启动行印出的守卫名也是它；认证不在装配里时，占座者靠占住席位就满足了「本端只在守卫之后服务」这条数据声明而什么都不做。这些残余项都落在「装配里已经有一个坏模块」这一类，接口换掉的只是哪个坏模块得手。而想要的性质里有一个接口根本够不着：席位之内的流量是已认证的，按路由核对分发的接口对身份不作断言——装一个按 URL 合并并发请求的层，两个调用方各带自己的正确凭据并发请求同一条路由，两人都得 200 且两份应答带的是同一个主体，handler 只跑一次，核对点没有报出任何不符，计数桶里也没有异常。

### 缩小认证的职责，只交付校验能力

认证不在链上占位，只交付校验后端；由宿主或各 API 模块在自己的 handler 里调用校验。「链上没有任何一层能绕过认证」不再是这个功能目录的主张。

**否决**：它把一处集中判定摊成每条路由各自的动作，漏掉一条就是无认证放行，而漏掉本身不产生任何信号——同一个失效形态从装配层搬到了路由层，并且变密。想要的性质一条也没有因此成立：凭据仍然穿过整条链到达 handler，缓存层仍然按方法加路径做键。它还与入口模块的分工相悖：入口模块把「哪些路由免于认证」划在自己的非职责里，并指明路由的认证策略归实现认证的那个模块、以中间件的形式接入；认证范围扩到登录与会话之后，登录路由与被保护路由同址，由网关统一收口才有「豁免与路由成对登记」这条边界（[ADR-authn-exemption](adr-authn-exemption.md)）。

### 由网关与准入层互相核对宿主在各端上的配置

网关核对准入层所守的端上有没有路由被租户解析豁免，准入层核对网关所守的端上有没有被开出的口子，不符即启动失败，使「准入层所守的端上没有无租户上下文的路由」「链上位于认证之外的层」也成为强制的性质。

**否决**：核对的对象是别的模块的登记内容。租户解析的豁免表归解析层，要读它就得在 tenant 上新增读口，落点又回到「为认证改动别的模块」；链上的层则没有任何可读的声明说明某一层是否自答请求，能读到的只有它的阶段与锚点。核对即使做成，也只覆盖已登记的层与已登记的豁免，宿主自写层在 handler 内部自答、豁免登记之外的路径依旧不在范围里，启动期的一次通过会被视为保证。`ScopeGuard.Covers` 因此只交付准入层守哪些端这一个事实，不兼作核对口。

### 为预置的网关实例补登记脱敏规则

宿主为网关预置的实例不经过网关模块的 `New` 与 `Init`，脱敏规则因此一条也不登记；补上，使规则全集不依赖实例的来历。做法是让核心对预置的实例也调用 `New`，或把登记挪到不依赖网关产物的位置，由每个持有秘密的 authn 模块各自幂等地登记同一份。

**否决**：让核心调用 `New` 改的是核心对预置实例的装配语义：预置实例代替所属模块的 `Prepare` 与 `New`（[ADR-supplied-instance](adr-supplied-instance.md)），落点是认证不拥有的模块。各模块各自登记则把规则全集的归属从网关分散到每个持有秘密的模块，而值格式规则依赖各后端认领的 scheme，只有网关在 `Init` 才知道，别的模块登记不了。预置了网关实例的宿主本就自己承担认证层是否在链上、挂载端是否受守这些网关的职责，脱敏规则按同一判据归入这一侧；单为它另开一条路径，使「预置实例的宿主自己负责」只对一部分成立。

### 写成非保证，不为它们改动别的模块

认证的收口止于它自己产生的失败；装配层面的性质作为非保证载入文档，每条附可观察的失效形态与宿主自己该做的核对；认证自己的信息写进启动诊断，使这些情形可被人察觉。

**采纳**，见决策。

## 决策

采纳：装配层面的性质写成非保证，不为它们在 `pkg/http`、`pkg/tenant`、`pkg/log` 或任何别的模块上增开接口。

落在哪一侧由判据决定，判据覆盖认证的每一种失败：

- 认证在启动期自己判得出来的确定失败，配哨兵与修复动作，不得写成非保证。
- 成立与否取决于本次装配里还有哪些层、它们各自怎么写的性质，写成非保证，每条写清可观察到什么、哪一层不报错。

非保证的成员按判据归入，本记录指名的例举如下，不是封闭集：

- 链上位于认证之外的层仍可绕过认证：声明在鉴别阶段之外各阶段的层、阶段内被排到网关之外的层、入口模块内建的请求上下文、访问日志与兜底层、声称代表认证功能而所属模块并不交付认证的层。
- 凭据向认证层以内泄漏：覆盖登录会话令牌、JWT 访问令牌、刷新令牌，也覆盖 `Authorization` 头。凭据进日志的覆盖面同属此类，其中包括宿主为网关预置的实例不是网关模块的产物时的情形：键名规则在网关的 `New` 里登记、值格式规则在 `Init` 里登记，预置的实例两者都没有经过，日志模块与持有秘密的其他模块照常运行，规则全集缺席。
- 属性键的保留前缀 `idp.` 与 `authn.` 不由网关在盖章处判：宿主自写的校验后端能交出任意此类键，授权读到的 `idp.*` 是否出自 IdP 映射，取决于装配里的校验后端；键空间的保证落在写属性的一方（[ADR-authn-verdict](adr-authn-verdict.md)）。
- 认证层以内的缓存或合并层把一个主体的应答交给另一个主体；此类层的键必须含账户与会话。
- 准入层所守的端上、被租户解析豁免的路由没有租户上下文，冒充身份对它们的拒绝完全落在准入层对「无租户上下文」的判定上；网关与 `ScopeGuard` 都不核对宿主有没有开这类豁免。
- 链上各层的次序由算法从声明推得，装配后的真实次序由装配测试读链清单核对，核对方式见失效条件的假设。

符合判据的新情形归入非保证，不为此修订一份列举。

认证为此所立的防线不需要改动别的模块，只用认证自己的信息：

- 默认守全部端。`endpoints` 缺省守入口模块声明的全部端，写端名即收窄；漏写一个端只会多拒。
- 网关的实例是网关模块的产物时，启动的成功路径上无条件写出展开后的受守端、冻结后的豁免表、可选认证与可冒充的登记、冒充身份可到达的端、本次实际接上的校验后端名单与放宽项。
- 宿主为网关预置的实例不是网关模块的产物时，网关的回调不对它做任何事，诊断不写出，脱敏规则也不登记；该实例要自己承担 `mount.endpoints` 各端受守以及各作用域与租户两层覆盖关系的核对，由预置它的宿主负责。

## 后果

收口口径与架构的错误模型一致：认证为自己产生的失败提供哨兵，不为发生在它之外、或经由它返回的失败发明名字。

`pkg/http` 的接口不因认证的装配性质而变：`Endpoint` 的方法集不扩，配置不新增键，端点的构造不为认证改写。端名读口是 [ADR-http-enumeration](adr-http-enumeration.md) 出于覆盖全部端的需要作的决定，它不提供守卫席位，不回读已登记的模式，也不回答一次请求分发到哪条路由。不纳入认证的宿主不为认证付任何代价。

认证层在链上与别的横切层相同：它的位置用阶段表达（网关属鉴别阶段），它对外的锚点是它在链上声明的功能标识，要排在认证之内的层在同一阶段内用指向该标识的硬约束表达。各层所属的阶段由各自的模块文档承载，本记录与认证文档只写认证自己的层与锚点。

非保证是文档承诺的一部分，不是省略。每一条非保证的失效形态、可观察的信号与宿主该做的动作只写在设计文档里：性质的逐项表述见 authn 的「非保证」，宿主动作见同一文档的「对宿主的要求」，威胁与残余风险见 authn-threats。下列各条只记代价，不复述那些内容。

**接受的代价：**

- **链上没有任何一层能绕过认证层不成立。** 登记接口不知道登记方是谁，位于认证之外的层、另一层认证与冒名的层都拦不住；这类绕过没有信号，净效果落在放行一侧。
- **凭据不向认证层以内泄漏不成立。** 豁免路由上网关不校验也不改写凭据，脱敏规则的登记时机弱于日志模块给出的那一条（[ADR-log-redaction](adr-log-redaction.md)）；失效形态不止一种，覆盖面是装配的结果，不是日志模块的承诺。
- **认证层以内的缓存或合并层不把一个主体的应答交给另一个主体不成立。** 认证层放行之后，同一条路由上的请求在它看来等价，串身份时没有任何计数异常。
- **准入层所守的端上，被租户解析豁免的路由没有租户上下文，租户范围在这些路由上没有可比对的对象。** 冒充身份是否被拒只取决于准入层的判定，网关与 `ScopeGuard.Covers` 都不核对宿主开了哪些解析豁免（[ADR-authn-impersonation](adr-authn-impersonation.md)、[ADR-tenant-admission](adr-tenant-admission.md)）。
- **一条没有纳入认证网关的命令，在宿主也没有为网关预置实例时不主动告知。** 缺席的净效果落在放行一侧，不落在拒绝一侧；未被纳入的模块不落在启动诊断的义务覆盖面里，按名查询答得出缺席，但要宿主自己去问（[ADR-module-enablement](adr-module-enablement.md)、[ADR-command-tree](adr-command-tree.md)）。宿主命令树的写法见 [ADR-authn-wiring](adr-authn-wiring.md) 与 authn 的「对宿主的要求」。
- **宿主为网关预置的实例不是网关模块的产物时，链上同样没有认证层，而注册表答网关在场。** 净效果与没有纳入网关相同，察觉途径更弱：按名查询答不出缺席（[ADR-supplied-instance](adr-supplied-instance.md)）。它按判据落在「取决于装配」一侧：网关认得出实例不是自己的产物，认不出顶替者为什么顶替、链上由谁承担认证。同一原因使日志脱敏规则也一条不登记，日志模块在场也一样：网关的 `New` 与 `Init` 都没有经过，规则全集不在。
- **属性键的保留前缀只由写属性的一方保证。** 网关在盖章处不判前缀，宿主自写的校验后端交出任意 `idp.*` 与 `authn.*` 键时没有任何信号；授权把 `idp.*` 当强授权依据，就是在信任装配里的每一个校验后端。
- **默认守全部端使宿主没有列举的端也要求凭据。** 探活与运维端须由宿主显式处理，写法是 `Gate.Exempt` 登记或显式收窄 `endpoints`；对既有宿主，这是升级时必须处理的变化，细节见 authn-gate 的「对宿主的要求」。
- **显式收窄的 `endpoints` 把未列出的端留在认证之外。** 宿主写下的清单本身是一个决定：未列出的端上全部路由无认证放行；启动诊断只说守了谁，说不出哪些端本应被守。
- **驱动深度浅于 `StageServe` 时，运行期的收口语义整段不适用。** `StagePrepare` 是 `Stage` 的零值，一条忘了写深度的命令会跑完表态就退出、退出码为零，而认证层从未存在过。
- **别的层用指向认证功能标识的硬约束把自己排在认证之内，本端链上没有认证层时这条边不存在、约束自动满足。** 启动诊断只在本端有层点名过认证功能时留下一行「该功能在本端无人代表」，且分不出成因；没有任何层点名过认证功能时一行都不打印。
- **要把这些性质变成硬保证，落点在入口模块的接口上，是一次宿主可见的破坏性变更。**

## 失效条件

入口模块若出于本决策之外的理由获得一个每端唯一、位于全部登记层之外、且能安放认证判定的位置——本决策考虑过的选项以守卫席位、可读回的已登记模式清单、向路由引擎问「这条请求会分发到哪条路由」的接口描述过这类位置——「链上没有任何一层能绕过认证层」不再需要为认证单独增开接口，这一条应当从非保证转为保证。

本决策所依据的几处入口模块能力均不满足这个前件，这一条非保证不随之转为保证：

- [ADR-http-recovery](adr-http-recovery.md) 采纳的请求路径兜底层每端唯一、落在观测阶段之内，但不提供其中任何一项：它不经登记接口，不校验席位的唯一性，不读回已登记的模式，也不回答一次请求会分发到哪条路由。
- [ADR-http-enumeration](adr-http-enumeration.md) 采纳的端名读口只列出已声明的端名，不提供席位、读回与分发查询中的任何一项，不改变任何登记层的位置。
- `authn.ScopeGuard` 是认证根包里的只读接口，说的是准入层守哪些端，不在入口模块上占位。

两项启动诊断的能力决定「没有纳入网关」一条代价的去留：

- 按名查询启用结果的取值：`core` 对「在可用集里但不在参与集里」给得出取值，按名查询启用结果给出禁用并写明原因，另有一个查询单独回答是否在参与集内。这一项成立，「完全静默」因而只对不主动查询的宿主成立，自检的判据是有的。
- 启动诊断义务覆盖未被纳入的模块：该义务若明确覆盖到它们，连不主动查询也能察觉，没有纳入网关一条代价随之作废。

下列行为是假设，依赖它们的断言只在这些假设成立时成立；守住每一条的测试是失效的检测手段：

- 链上各层的次序由 `orderLayers` 的算法从声明推得，没有跑装配读过链清单。守住它的测试跑一次真实装配，读 `chain=` 一行，断言准入层在审计与限流之内、在授权之外，网关在租户解析之外。次序与推导不符时，上文关于准入层与网关相对位置的叙述随之失效。
- 网关对 `ScopeGuard` 的可选取用与准入层在链上的位置不构成构造环（阶段与阶段内的 `After` 只定链序，不定构造序）。守住它的测试是同时装入网关与准入层的装配测试，构造成功且两者的锚点各自在场。构造环出现时，网关取得 `ScopeGuard` 的时机要重新安排，「冒充身份可到达的端」的诊断随之改写。
- 入口模块端名读口的最终形态可能随它自己的决定变化。读口若不再返回已声明的全部端、或保留端名 `*` 的写法改变，「`endpoints` 缺省守全部端、漏写只会多拒」这一条随之失效；守住它的测试是对一个声明了多个端的装配断言，缺省配置下每个端上都登记了认证层。
