# 设置项的取值域由声明方给出，写入时判定

## 背景

设置的写入接口按声明判两件事：键在不在册，值能不能按声明类型往返（[ADR-settings-declaration](adr-settings-declaration.md)）。一个值解得成声明类型，不等于声明方用得了它。限流的额度声明为整数，零与负数都是合法的整数；而额度为零时限流会拒掉每一条带身份的请求，它只能把这个值当作读不出可用值，放行并往标准错误写一行（[ADR-ratelimit-failure](adr-ratelimit-failure.md)）。写入接口收下这样一个值并返回成功，那个租户的限流从此失效，写入的人得不到任何拒绝。

取值域是声明方的知识，写入接口拿不到它。宿主的管理面要拒绝这类写入，只能照抄声明方的判据，抄错、抄漏都不报错，[ADR-settings-key-listing](adr-settings-key-listing.md) 否决“由宿主复述声明”用的是同一个理由。

库里已经存着的行不一定落在取值域内：取值域可能在那一行写下之后才声明，行也可能绕过本模块写进表里。读取怎样处置这些行，是这项决策的另一半。

## 考虑过的选项

### 维持现状，取值域只由使用方在读取时判

**否决**：写入的人收到成功，失效到读取时才出现，出现的形态是使用方的降级（限流放行），而不是对写入者的拒绝。修复动作离写下这个值的人最远。

### 宿主在调用 Set 之前自行校验

**否决**：取值域要么由宿主照抄，要么由声明方另外导出一个校验函数、再由每个宿主记得调用。前者是复述声明；后者让拒绝取决于每个写入口有没有接上它，漏接一个入口不报错。写入接口是所有写入的必经之处，判定放在那里才不依赖调用方。

### 声明式的约束词汇（最小值、最大值、枚举、模式）

`Item` 上加若干约束字段，由本模块解释。

**否决**：约束的种类是一个要随声明方的需要不断扩充的闭集。限流窗口的上界是“两倍窗口仍能由时长类型表示”这条性质，写成一个字面的最大值只是它的推论；自带文本形式的类型没有序，最小值与最大值无从定义。这套词汇还得自成一套类型规则，收集期要逐条判它与声明类型是否相容。

### 由声明类型自己实现一个校验方法

声明类型实现形如 `Validate() error` 的方法。

**否决**：内建的标量类型带不了方法，要约束一个整数项就得把它改声明成自定义类型；读取的目标必须恰为声明类型，每一处 `Get[int]` 都要跟着改，从配置迁来的参数也保不住原来的承载结构。

### 声明方给一个返回错误的校验函数

`Item` 上加 `Check func(value any) error`，拒绝的原因由它写出。

**否决**：拒绝的文本出自声明方，校验函数完全可能把收到的值写进错误里，敏感项的值就这样进了错误文本与日志，而本模块的判据是敏感项的值不进入任何错误文本。`any` 形参让谓词与声明类型的错配要到某一次写入才暴露。规则也不是一段能单独取出的文本，列出设置项的管理面没法在写入之前把它告诉运维。

### 读取也按取值域判，越域的行按解码失败处置

**否决**：取值域常在新版本里才声明或收窄。装载时拒绝越域的行，一次收窄取值域的发布会让每个副本上那些键的读取同时失败，使用方为这种行设计的处置（限流放行并报信号）也被绕了过去。已经存着的行照原样读出，由使用方判它读到的值，波及面最小。

### 声明方给一个类型化的谓词与一段规则文本，写入时判定

**采纳**，见决策。

## 决策

采纳：`Item` 增加 `Domain`，由 `DomainOf[T](rule, admits func(T) bool)` 构造。`T` 是设置项的声明类型，`admits` 判一个值在不在域内，`rule` 以一个名词短语说出这个集合。零值的 `Domain` 接受声明类型的每一个值。

`Set` 先按声明类型归一化写入的值，再交给取值域判定；落在域外即以 `ErrInvalidValue` 拒绝，错误点名键与规则。这一步在落库之前，库里的行、快照与事件都不变。判定的对象是归一化之后的值，同一个数以数值、文本或 JSON 解出的浮点写入，得到同一个裁决。敏感项的拒绝不带值。

键表建立时判声明本身：`T` 与声明类型不同、规则为空、谓词为空、声明的默认值不在自己的域内，都是 `ErrInvalidDeclaration`。默认值一条的依据是 `Declared` 承诺它列出的默认值 `Set` 收得回去。

读取的行为不变：越域的行照原样交出，取值域只在写入时判。`Declared` 的每一项经 `Item.Domain.Rule()` 报出规则。

## 后果

写入接口挡得住类型正确而声明方用不了的值，拒绝发生在写入的那一刻；宿主的管理面把 `ErrInvalidValue` 返回给写入的人即可，不必知道任何一个模块的取值域。

**接受的代价：**

- **取值域是代码，不是数据**。谓词不能序列化，管理面拿得到的只有规则文本，没法在客户端预先校验；一个值在不在域内，只有写一次才知道。
- **使用方仍要判它读到的值**。取值域声明之前写下的行、绕过本模块写进表的行照原样读出，按读取结果行事的使用方要保留自己的读时判定；两处判据由它自己保持一致，最直接的做法是两处共用一个谓词。
- **给一个设置项声明或收窄取值域是一次契约收紧**。以前写得进去的值，升级之后被拒绝；滚动发布期间，新旧两版的副本对同一个值可能给出不同的裁决。
- **谓词是声明方的代码，跑在写入方的协程上**。它只该依赖自己的参数；它 panic 时 `Set` 随之 panic，收集期对默认值的那一次调用可能先把它暴露出来。

## 失效条件

若管理面需要在客户端或别的进程里预先判定取值（例如按声明生成表单校验），谓词的形态就不够用，取值域需要一种能序列化的表达，本记录要与声明式约束词汇那一项重新比较。
