# 每请求一条访问记录由入口模块内建，位于全部模块层之外

## 背景

链上需要一条请求级记录：每个到达该端的请求，无论成功还是被拒，都在日志模块的目的地上留下方法、路由、路径、状态码与响应体大小。缺了它，401、404、413、429 这些拒绝在不装观测模块的进程里不留任何请求级痕迹。

gin（[REF-gin](../references.md)）自带 `Logger` 中间件，但它把文本写进 `io.Writer`，绕过日志模块及其目的地与脱敏——这与入口模块把 gin 放进 release 模式是同一个理由（[ADR-http-surface](adr-http-surface.md)）。

记录的位置决定它看得见什么。排在会拒绝的层之外，才能把一次拒绝也记下来；排在绑定 trace_id、主体与租户的层之外，才能在读响应结果时拿到这些字段。

## 考虑过的选项

### 用 gin 自带的 Logger 中间件

**否决**：文本写进 `io.Writer`，绕过日志模块的目的地与脱敏；与用 release 模式否定调试输出同因。

### 由观测模块内建

**否决**：这条记录要进日志模块的目的地，属于日志，不属于跨度与计量。观测模块可选，没有它时记录就消失，而被拒绝的请求正需要它留下痕迹；观测模块的产物是 OTLP（[REF-otlp](../references.md)）信号，不是一个请求一行。

### 由各模块自报请求结果

**否决**：每个会拒绝的层都要记得写一行，漏一条就失效。

### 入口模块内建一层，位于模块层之外

**采纳** —— 见决策。

## 决策

采纳：每请求一条访问记录由入口模块内建，不经登记面，不加 `Endpoint` 的方法，每端唯一。它登记在 `holdAllow` 之后、观测阶段之外，因而排在每一个登记层之外。

记录经 `log.FromContext` 写出，走入口模块注入请求上下文的那个 logger；一行带端名、方法、`c.FullPath` 给出的路由、路径、状态码与响应体大小。观测层绑进上下文的 trace_id 与 span_id 随该 logger 的属性一并写出，本层不点名它们。

本层在 `c.Next` 返回之后重新读 `c.Request`，不沿用进入时捕获的那份指针。绑定 trace_id 的层会把 `c.Request` 整份换成一个带派生上下文的请求，进入时捕获的指针上仍是建链时的上下文，读它只会得到空字段；重读 `c.Request` 才拿到内层留下的上下文。**这与审计请求层正好相反**：审计层落在绑定层之内，持有的正是它收到的那份请求（`pkg/audit/journal/request.go`）。两处都容易写反，各配一条测试。

状态码取写出者持有的值，1xx（101 除外）折算为 200：信息性状态之后还有最终状态，命名它会把一次 200 的应答记成 103。审计模块的日记另存一份同样的规则。

## 后果

每个到达引擎的请求都留下一条记录，被拒绝的与匹配不到路由的也在内。记录不带请求体内容，是一行摘要。

**接受的代价：**

- **重读 `c.Request` 的时机是承重的，写反了不报错。** 沿用旧指针会得到空的关联字段；审计层则必须沿用旧指针。两处的正确写法相反，各由一条测试钉住。
- **引擎之前由 `net/http` 直接答掉的请求不留记录。** 畸形请求行或超限头部在进入任何 handler 之前由协议层写出 400，本层够不着；这是链外的已知盲区。
- **没有日志模块交付 logger 时，记录走进程默认 logger。** 入口模块注入不了 logger 时 `log.FromContext` 回退到进程默认输出，记录仍在，目的地不是配置的那一个。
- **一行一请求的写入量不随请求价值取舍。** 高流量宿主得到每条请求一行，是否采样不在本层。
- **记录的字段集是固定的，扩展靠修改本层。**

## 失效条件

若日志模块的目的地不再适合每请求一行的写入量，或宿主需要按值采样访问记录，则“无条件每请求一行”这一形态失效，需要把采样或开关交给配置，本决定随之不再成立。
