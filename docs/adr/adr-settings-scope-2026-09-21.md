# 设置以一个模块交付读写面，租户标识以字符串表达

## 状态

已接受

## 背景

配置与设置的划界已定：设置承载运行期可变的参数，存放于数据库，可按租户取不同值，由独立模块承载（[ADR-config-scope-2026-09-13](adr-config-scope-2026-09-13.md)）。承接它的功能目录叫什么、由几个模块组成、交付什么形状的接口，全仓没有出处。

判据点名的消费方是限流阈值、功能开关与通知模板（[ADR-config-scope-2026-09-13](adr-config-scope-2026-09-13.md)）。它们的读取频率差别很大：限流阈值的读取在请求路径上，通知模板的读取在发通知时；把读取做成每次查库，限流阈值这一类消费方承受不起。

租户标识在接口上以什么类型出现，有一条现成的先例：事件总线的 `Event.TenantID` 是字符串，理由是取用租户的标识类型会让发布方的包 import 租户的包，把总线接到租户这个具体功能的接口面上（[ADR-event-scope-2026-09-21](adr-event-scope-2026-09-21.md)）。设置同样只需要一个标识，不需要租户模块的任何类型。

写设置的路径有两条：消费方各自的代码路径，与宿主的运维面（登记一个新阈值、停用一个开关）。两者是否该由不同的交付承载，此前没有裁定。

## 考虑过的选项

### 交付无类型的键值存取

接口面收敛为按字符串键存取字符串值，不要求任何声明。

**否决**：与键值模块的能力重复——不透明字节的存取已由 `kv` 交付，而它带过期与原子操作。同样的面再做一遍，不增加能力；而设置特有的东西——键在册、类型、默认值——一样都没有。

### 租户标识取 `tenant.ID`

接口签名用 `pkg/tenant` 的标识类型表达租户，写错类型由编译器拦下。

**否决**：它把本模块的接口面接到租户这个具体功能上，判据与事件总线记下的同一条——构建与依赖清单由包内 import 的传递闭包给出：取用租户的标识类型，本模块的接口包就要 import 租户的接口包，这条边因而进入每一个使用本模块的宿主的 import 闭包；租户接口包自身只引标准库，代价不是一份第三方依赖，而是设置对租户接口面的依赖。设置的读取还把租户标识当输入而非输出：标识从哪来（`tenant.FromContext`）是调用方的事，本模块不产生它。

### 读面与写面各成一个交付

消费方取一个只读功能，运维面取一个可写功能，两个功能各由自己的模块交付或同一个模块排他交付两个标识。

**否决**：两者没有独立的演进节奏，也没有一个消费者会脱离另一个单独取用——消费方与运维面读写的都是同一张表、同一份快照。与租户名册的读写一体面同型（`pkg/tenant` 的 `Catalog`），那里没有拆，这里拆开只会多出一个标识与一次消解。

### 单模块交付读写一体面，租户标识以字符串表达

**采纳**，见决策。

## 决策

采纳：`pkg/settings` 以一个模块交付设置的读写面，功能标识为 `(*Store)(nil)`，排他交付；租户标识在接口上以字符串表达，本模块的接口包不 import `pkg/tenant`，这条边因而不进任何使用本模块的宿主的 import 闭包（测试包 import 租户根包，测试包的 import 不进产品闭包）；写面不判权限。

单模块的成形理由是设置的各组成部分——表、快照、变更事件——服务于同一个读写面，没有独立演进的第二块；存储只有数据库一种，不拆实现子包。

**写入不判权限。** 谁能改一个设置项是权限模型的事（[ADR-tenant-scope-2026-09-21](adr-tenant-scope-2026-09-21.md) 把按租户的授权判定判给权限模型），本模块只回答值是什么、往哪里写。写面的调用点是宿主自己的代码或它写出的管理命令。

**字符串租户的边界由调用方补齐**：从请求上下文取出标识、以及"没有租户"这一档的处置（读全局层，或拒绝），都在调用方。

## 后果

消费方声明对设置的构造期依赖，取用写作 `core.Resolve[settings.Store](reg)`——这是一次普通的模块依赖（[ADR-config-scope-2026-09-13](adr-config-scope-2026-09-13.md)）。

设置的依赖图位置随之确定：位于数据库、事件总线与日志之上；既有模块没有一个 import 它，按租户取值的上层模块（限流、通知）将来依赖它。

**接受的代价：**

- **消费方要自己处理"没有租户"的一档。** 从上下文取标识、取不到时读全局层还是拒绝，都由调用方决定；本模块拿到的只是一个字符串。这一条与租户模块为下游记的代价是同一条。
- **写面没有访问控制。** 一个暴露到网络的写入口，其鉴权由宿主自己负责；本模块不认识调用方。
- **租户标识是裸字符串。** 写错一个标识不会在编译期被拦下，落库后是一条没有人读的行；写入面按声明的键校验（见 [ADR-settings-declaration-2026-09-21](adr-settings-declaration-2026-09-21.md)），但校验不了租户是否在册——本模块不认识名册。

## 失效条件

若租户模块的标识类型获得独立于该功能目录的价值——例如它被拆成一个零依赖的类型包——这条接口面依赖随之消失，本记录对租户标识类型的选择需要重新比较。

若出现一种消费方，它只需要读一个全局设置、不持有任何租户概念，而空租户表达迫使它在每个调用点写下一个可能被误读为空值的东西，则读面里"全局层"的表达方式需要重新裁定。
