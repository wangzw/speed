# 本地化错误由 respond 子包交付 ErrorResponder，Problem 增 Key 与 Args

## 状态

已接受

## 背景

入口模块以 RFC 9457 的字段定义错误响应的内容（`Problem`），默认以 `application/problem+json` 写出，并允许一个模块交付 `ErrorResponder` 整体替换这一形状（[ADR-http-errors-2026-10-10](adr-http-errors-2026-10-10.md)）。`Problem.Type` 是客户端据以分支的机器码，不随语言变化（[ADR-i18n-scope-2026-10-13](adr-i18n-scope-2026-10-13.md)）。

要让错误文本随请求语言变化，需要一处渲染点，及一种把「哪条消息、带哪些参数」表达给它的方式。参数化消息是常见需求：一段文案里有剩余重试秒数、字段名、账户标识等需要填入的值。

方向约束固定：入口模块不 import 本能力目录，本能力目录的根包只依赖标准库（[ADR-i18n-locale-type-2026-10-13](adr-i18n-locale-type-2026-10-13.md)）。因此本地化不能内建进入口模块，只能经它已经提供的接缝接入。

## 考虑过的选项

### 把本地化内建进入口模块

入口模块自己读语言、查目录、渲染 `Title`。

**否决**：入口模块不认识语言资源，也不该认识；它若 import 本能力目录，就与「入口模块不 import 本能力目录」的方向约束相悖，并让每一个取用入口模块的宿主都被迫承受本能力目录。

### 只做类级文案，不支持参数

每类错误一句固定文案，不带任何插值。

**否决**：参数化消息——剩余秒数、字段名、涉及的标识——是常见需求，类级固定文案表达不了；要表达它就只剩「把参数拼进 `Detail`」，那会把展示文本重新耦合回产生它的代码，机器码与文本的分工被破坏。

### 让 `Problem` 携带已渲染好的 `Title`/`Detail`，消费方各自渲染

写出错误的地方先拿到本地化器，渲染好文本，再交给入口模块写出。

**否决**：每个写出错误的地方都要先取得本地化器并调它，写出面被拉宽到每一处产生错误的位置；渲染点不再集中，语言随写出方是否记得渲染而变化。

### 由 respond 子包交付 `ErrorResponder`，`Problem` 增 `Key` 与 `Args`

**采纳**，见决策。

## 决策

采纳：本能力目录的 `respond` 子包交付 `http.ErrorResponder`。它读请求语言，按 `Problem.Key` 在目录中取消息（`Key` 为空时由 `Problem.Type` 推导），用 `Problem.Args` 插值，渲染出 `Title`，保留 `Type`、`Status` 与 `Detail` 原样，并在响应上写 `Content-Language`。

入口模块的 `Problem` 增加两个字段：`Key string`（消息键）与 `Args map[string]string`（插值参数）。这是对 `pkg/http` 公开接口面的加性变更，需同步 `pkg/http/surface_test.go` 的接口金榜。默认形状不变：两个新字段不写进默认响应体，只供定制的 `ErrorResponder` 读取。

不内建进入口模块：本地化经入口模块已有的可选接缝接入，入口模块的方向约束不变。

## 后果

交付了 `respond` 的装配里，错误响应体的 `Title` 随请求语言变化，`Type`、`Status`、`Detail` 与默认形状不变；客户端按 `Type` 分支、按文本展示。

`Content-Language` 让客户端知道响应用的哪种语言。

**接受的代价：**

- `pkg/http` 的公开接口面发生加性变更，`surface_test.go` 的金榜要随之更新；任何以 `Problem` 为值类型或比较它的下游测试需复核新字段。
- 本地化只在交付了该 `respond` 实现的装配里生效。没有它时，文本仍是默认形状里的原样内容，这一缺席不产生失败信号，与「可选依赖的缺失是合法配置」一致。
- 写出错误的地方要用上本地化，须填 `Key`（或依赖由 `Type` 推导的约定）与 `Args`；不填则退回到默认文本。这依赖写出方的自觉，编译器不强制。
- 由 `Type` 推导 `Key` 是一种隐式约定：`Type` 的取值与键名要有可推导的关系，否则推导落空、回退到默认文本。这条关系不在编译器检查之内。

## 失效条件

若入口模块的接缝改为「渲染已完成的响应体」而非「接收 `Problem` 自行决定形状」，则 `Key`/`Args` 无处可放，本记录要改为在写出前渲染并把文本交给入口模块。

若 `Problem` 被要求承载的本地化信息超出「一个键加一组字符串参数」（例如结构化复数规则），则这套字段不够，需要重新考虑承载。
