# 权限模型：角色到权限，权限按（资源，动作），租户即策略域

## 背景

授权需要一个判定输入与一套规则：给定主体、域、资源、动作，回答是否允许。模型要能表达本项目的授权语义，又要能被判定引擎求值（[ADR-authz-engine](adr-authz-engine.md)）。

身份系统交付的身份要携带事实，但不携带角色与租户（[ADR-authn-identity](adr-authn-identity.md)）；成员关系的只读面键是（账户，租户），值只表示成员与否，不含角色。角色按（账户，租户）绑定的落点在授权，不在认证。

租户是数据隔离的边界（[ADR-tenant-isolation](adr-tenant-isolation.md)），同一账户在不同租户里的权限不同；平台运营需要一个跨租户的保留域，与旧实现一致取 `"system"`。

旧实现的判定链是 `subject → bindings → role → permissions`，权限命名 `resource:action`，精确匹配，没有角色继承，没有通配符。

## 考虑过的选项

### 角色等级（相对比较）

角色按等级排列，权限要求是一个等级门槛，主体角色的等级达到门槛即放行，判定退化为等级大小的比较。

**否决**：等级表要建在 Go 代码里，新增一个动作要改代码而不是写数据，权限不再是宿主可写的数据；相对比较在 Casbin 里要落成 ABAC 谓词，与「模型文本固定且简单」的取舍冲突（[ADR-authz-engine](adr-authz-engine.md)）。

### 角色继承（`g2`）

引入角色到角色的继承：一个角色吸收另一个角色的全部权限，判定沿继承链求值。

**否决**：一个角色的权限来源变成两层——直接授予的与经继承得到的。审计与撤销都要沿继承链展开，撤掉一条授予后要判断它是否仍经某条继承路径生效；这层关系在本项目的判定链里没有需求，旧实现的判定链也没有角色继承。

### 通配符权限

权限里用通配符匹配一批资源或动作，例如一个资源上的全部动作、一类资源。

**否决**：通配符语法是一个需要独立决策的安全面——一条通配规则覆盖了哪些动作在读策略时看不出来，授予一个通配符等于一次性授予一批边界不明的动作；旧实现明确把通配符列为「不是实现时随手猜一个」的决策，本设计沿用不做。

### 角色到权限、权限按（资源，动作）、租户即策略域

**采纳**，见决策。

## 决策

采纳：判定由主体的角色到权限的绑定给出；权限按（资源，动作）二元组声明；租户标识即策略域。模型不表达角色继承、不表达通配符、不表达 deny 行。

- **判定输入。** 一次判定是一个四元组：主体（账户标识）、域（租户标识或平台保留值）、资源、动作；判定即求「是否存在一条绑定，使主体在该域持有一个角色，该角色在该域持有一条（资源，动作）授权」。
- **权限是（资源，动作）二元组。** 一条授权指名一个资源与一个动作；两个判定在同域、同资源、同动作下才可能命中同一条授权。
- **租户即策略域。** 域取请求上下文里的租户标识；平台范围取保留域 `"system"`，与旧实现一致（[ADR-authz-decision-seam](adr-authz-decision-seam.md)）。
- **拒绝由无匹配表达。** 模型没有 deny 行；判定拒绝等价于「没有任何一条匹配的授权」。
- **无继承。** 角色的权限只来自直接授予它的授权行，不经任何角色到角色的关系传导。

## 后果

角色的权限可被读出：一条授权行即是它的全部含义，授予哪个角色对哪个资源做哪个动作，不经传导展开；授予与撤销都是数据操作，引擎无需改代码。

新增一个动作不改代码：动作是权限行里的数据，宿主写一行授权即引入它（相对等级模型要求改 Go 的等级表）。

**接受的代价：**

- **没有角色继承，权限的组合要用数据重复表达。** 想表达「高级角色吸收低级角色的全部权限」，要逐条把低级角色的授权授予高级角色；模型不提供聚合，新增一个动作要把它同时授给每个需要的角色。
- **没有通配符，成批授予要逐条列出。** 想表达「某资源上的全部动作」，要把每个动作各写一行；动作集合增长，权限行随之增长，且没有一处能表达「全部」。
- **域不承载层级。** 一个域不包含另一个域：租户之下更细的范围（部门、项目）在本模型里没有表达，权限只在租户（或平台）这一个粒度上区分；这类更细的范围要么落成不同的资源标识，要么需要模型之外的设计。
- **一次判定一个域。** 判定是（主体，某域，资源，动作）的精确匹配，没有「一个主体在多个域的权限合并」的形状；跨域的能力（例如平台角色进入租户）由平台域与判定接缝的回退分支表达（[ADR-authz-decision-seam](adr-authz-decision-seam.md)），不落进模型。
- **无 deny 行，策略只能靠给出的集合表达。** 模型表达不了「除某项之外都允许」或显式拒绝；这类语义只能改写成对应的允许集合，改写不出时模型给不出。

## 失效条件

- 若出现必须是属性相关的授权规则——授权取决于主体属性、资源属性或环境，而非（主体，域，资源，动作）的精确匹配——模型要重新裁定。
- 若出现产品必须表达的「角色等级」或「角色继承」语义，或必须由通配符表达的成批授予，本记录随之失效。
- 若出现必须按租户之下更细范围（一个域包含另一个域）判定的需求，域的形状要重新裁定。
