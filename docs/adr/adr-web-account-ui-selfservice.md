# 账户自助写归前端的一组组件

## 背景

authn 后端的自助写路由已经存在：档案（`authn.profile`）挂 `PATCH B/me`，自写显示名、通用属性集、语言与时区；登录自助功能（`authn.login`）挂 `PUT B/password`、`POST B/phone`、`POST B/phone/verify`、`DELETE B/identifiers/:id`、`DELETE B/links/:id`。自助里改口令、添加用户名、选作或取消登录方式、设置默认联系地址、删除标识与解绑外部身份要求新鲜认证（REQ-security-013），未提权时答 401 `authn.insufficient_user_authentication`；登记并验证一条联系方式（邮箱或手机）、档案与偏好（显示名、语言与时区）的写本身不要求新鲜认证，但验证的后果改变账户据以证明或找回自己的事实时（一条将成为默认联系地址或唯一邮箱地址的邮箱、一个将取代已启用短信因素目标的新手机号），服务端答提权 401。

前端 `@speed/account-ui` 交付的节覆盖偏好（语言与时区）、会话、社交绑定与两步验证，不含档案字段与口令、手机、登录标识的写。

这留下一部分自助功能在包外。这些写与包内各节同处一个账户页、共享同一条访问令牌与同一组 `@speed/api-sdk` 生成调用，且要求新鲜认证的写都经同一条提权流程（一条 `purpose: 'step-up'` 的流程）；登记并验证联系方式（邮箱或手机）本身不经这条门控。档案的另一半字段（语言与时区）已在包内的偏好节，档案的显示名却在宿主；一个端点的写在包内外各占一半。

## 考虑过的选项

### 保持现状：自助写留在宿主内容

**否决**：包内已交付偏好节（同一 `PATCH B/me` 的一半字段）与社交绑定的解绑，档案字段与口令却留给宿主，一个端点的写在包内外各占一半；账户页要凑齐安全类自助写，每个宿主重复实现同一提权门控与同一批错误文案。

### 把自助写并入偏好节

**否决**：偏好节是语言与时区两个下拉的自写，口令、手机与登录标识各自是独立的多字段表单与两步流，并入使一个节承载互不相干的四种写。

### 新增四个自助写节并接入 ui-kit 的表单家族

**否决**：四节是受控字段而非登录表单——每节带一次异步读（`AsyncSection`）、一条整次尝试失败横幅（`InlineError`）与会话级成功 live region，四节里唯一的客户端校验是口令节提交期的两条便利检查（新口令非空、两次一致），其权威在服务端。把只有两条提交期检查的受控字段接上 `useForm` 与 schema 驱动的 resolver 只增机械；表单家族（`FormField`、`zodFormResolver`）归同层 `@speed/auth-ui` 的登录表单。本包既有的偏好节同为受控字段。

### 在 account-ui 内新增四个自助写节

**采纳**，见决策。

## 决策

采纳：账户的自助写归 `@speed/account-ui`，新增四节——`ProfileSection`（显示名，`PATCH B/me`）、`PasswordSection`（`PUT B/password`）、`PhoneSection`（`POST B/phone` 与 `POST B/phone/verify` 两步）、`IdentifiersSection`（读 `GET B/me` 的 `identifiers` 字段、删 `DELETE B/identifiers/:id`）。四节中，`PasswordSection`、`PhoneSection` 与 `IdentifiersSection` 取 `AuthSession` 为属性；提权门控由 `PasswordSection`（改口令）、`IdentifiersSection`（添加用户名、登录方式的选择、默认联系地址的改选、删除标识）与受保护后果的验证驱动一条 `purpose: 'step-up'` 流程。发送（登记与更换目标地址）本身不要求新鲜认证，门控不为它打开；`PhoneSection` 与验证节的验证在后果受保护时经同一门控，拒绝后重放同一验证码恰好一次。`ProfileSection` 的显示名写同样不要求新鲜认证，不经门控。

判据是「自助功能同处一页、同一访问令牌、要求新鲜认证的写同一提权门控」——这是这些写归包内的依据，不是每个写都满足它：登记与验证联系方式同在这一页、同用一条令牌，发送（登记与更换目标地址）本身不要求新鲜认证、不经门控，被拒时按普通失败呈现且不重放；验证的后果要求新鲜认证时经同一门控，拒绝后重放同一验证码恰好一次。这些写与包内既有的偏好、会话、绑定节共享同一个账户页与同一条访问令牌，都是一次性写而非可分页列表，与包内各节处在同一组件层。通用属性集（自由键值对）的编辑留在宿主：它是任意键值，不属于账户页的固定字段。

四节建为受控字段：MUI（[REF-mui](../references.md)）的 `TextField` 直接受控，不接入 ui-kit 的表单家族（`FormField`、`zodFormResolver`）——判据是被否决的表单家族方案。「本包不属表单家族」是这一决策的一部分：表单家族只服务于登录表单（`@speed/auth-ui`）。

## 后果

账户页的自助写整体由包交付，宿主只组合节并供给会话。`@speed/account-ui` 的公开接口新增四个节与四个 props 类型，是对公开接口的附加式扩展。

**接受的代价：**

- 包多担四条自助路由，测试范围随之扩大；提权门控由 `@speed/auth-core` 的 `useStepUpGate` 提供（[ADR-web-auth-seams](adr-web-auth-seams.md)）。
- 通用属性集的编辑仍不在包内，账户页的档案写是不完整的一半：显示名在包内，自由属性在宿主。
- 改口令、添加用户名、选作或取消登录方式、设置默认联系地址、删除标识与解绑外部身份要求新鲜认证，节必须处理提权 401；登记联系方式（发送）本身不要求新鲜认证；验证的后果改变账户据以证明或找回自己的事实时服务端答提权 401，节开同一门控并重放同一验证码恰好一次；档案与偏好的写不要求新鲜认证，不经同一门控。
- 四节不接表单家族：口令节的两条提交期检查以内联辅助文本渲染在各自字段上，不走 `FormField`；一个校验增长到需要 schema 驱动的新节要重新评估接入成本。

## 失效条件

- 出现一种自助写，其授权依据不是「发起者就是这个账户」，或是一种安全类写却不经同一提权门控：四节的共同判据不再覆盖它，归属要重新裁定。
- 账户页不再由 account-ui 组合（宿主自建账户页）：自助写归包内的理由（同处一页）随之消失。
