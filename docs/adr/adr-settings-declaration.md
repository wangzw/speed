# 设置项由模块声明，读取与写入按声明校验

## 背景

设置的值在库里是文本，在消费方手里是某个具体类型——一个阈值是数值、一个开关是布尔、一个模板是字符串。值的类型信息从哪里来，决定了接口的形状与失效的方式。

配置侧有一个成熟的先例：模块用 `config.Schema` 资源声明输入项，挂载结构体的字段当前取值即默认值，键的路径由字段名派生，两个模块声明同一个键是收集期的冲突（`config` 的设计文档）。[ADR-config-scope](adr-config-scope.md) 把"配置结构体体量膨胀"当作参数应当迁往设置的信号，两套声明形态同构时那次迁移的键名与形状可以不变。

设置的写入者是运维，而不是编译器。一个写错的键名在有校验的模型下当场被拒，在没有校验的模型下落库后无人再读——写入成功、读取照常取默认值，没有任何一处会报出来。

## 考虑过的选项

### 无类型的键值面

任意键，值为不透明文本，消费方自行解码并自行处理缺失。

**否决**：拼写错误的键静默失效——写入者以为设置生效了，而读取方从未见过这个键。缺失处理也失去统一落点：每个消费方各写一遍"没读到就用某个默认值"，默认值散落在各调用点而非声明处。

### 声明为主，未声明的键也可存读

声明过的键有类型与默认值并受校验；未声明的键按无类型方式放行。

**否决**："哪些键在册"不再是一份可枚举的集合，未知键校验失去依据——写入一个拼错的键不再可判，因为任何键都可能是一个合法的未声明键。两种语义并存的写入面等于放弃校验。

### 声明式类型化

模块通过资源声明自己的设置项，读取与写入都按声明解码与校验。

**采纳**，见决策。

## 决策

采纳：设置项由模块声明，声明是资源，读取与写入都按声明校验；未声明的键在被声明之前不可读写。

**声明的形状与配置同构**：命名空间、挂载原型（结构体的字段当前取值即默认值）、逐项的元信息（是否敏感、说明文本）。键的路径派生采用与 `pkg/config` 同一套字段名规则，因而从配置迁往设置的一个参数，其键名不变。

**类型集合是封闭的**：字符串、布尔、整数、浮点、时长，以及既能从文本解码、也能编码回文本的类型（`encoding.TextUnmarshaler` 与 `encoding.TextMarshaler`）。容器（映射、列表）不在这个集合里——需要容器的消费方把一个 JSON 文本存进字符串项，自行解码。封闭集合给出的是声明的可校验性：任何一个声明的类型都在文本往返下良定义，只能解码不能编码的类型与写不成文本、读不回来的默认值因而在收集期就被拒绝。

**声明的收集取自可用集**：全部已注册模块的声明都在来源里；判据是键的有效性跟着二进制走，比任何一次命令长寿，因而未运行、消解落选与只被静态级纳入的模块，其声明一律在键表里。**取可用集的消费点不做减法**（架构不变量 15）：一份参数声明不是由哪一次运行产生的，减法会让同一个键在一条命令下合法、在另一条下非法，而声明本身没变。两个模块声明同一个键时，收集期判冲突并终止启动，点名冲突双方。

**读取与 `Set` 对未声明的键一律拒绝**，同一哨兵。`Set` 在落库之前拒绝一个没有声明过的键，读取在查表之前拒绝同一个键——两处都判，因为一处只挡住写入方自己的错误，挡不住声明被删而库里尚有旧值的那一档。**`Delete` 是这条规则的例外**：它不过键表，是声明被删之后留在库中的旧行的清理路径——少了它，那些行在接口内没有清掉的途径。

**按声明解码发生在快照装载时**，读取从预解码的快照取值。声明的类型信息在装配期已知、快照在装配期装载，两者之间存在一个可利用的时机：每个已写入的行在装载时解成声明类型，标量种类的读取路径上不再有文本转换。自带文本形式的类型是例外：它的拷贝之间可能共享存储而反射看不透，读取由文本重新解码，交出的值才与快照互不牵连。

## 后果

消费方拿到的是类型化的值：泛型读取套件 `Get[T]` 把类型失配挡在调用点，不需要每个消费方各写一遍文本转换。默认值在声明处给出，"没有设置"与"设置成零值"由此分得开——读取总能得到一个值。

**迁移路径存在**：一个参数按 [ADR-config-scope](adr-config-scope.md) 的判据从配置迁到设置时，声明形状与键名都不变，改动集中在读取的时机与来源。

**接受的代价：**

- **可设项的集合在装配期定死。** 运维不能新增一个没有声明过的键；增删设置项、改一个键的类型，都要一次发布。需要运行期自由增键的调用方得不到支持，它应当另找一个承载：键值模块是一种，由它自己按自己的形状存一份也是一种。
- **声明类型与库中旧值的错配在读取时暴露。** 声明从字符串改成整数而库里还是非数字文本时，读取报错而不是静默回落默认值；修复动作是把那行值改对或删掉，本模块不代改。
- **键在声明处与调用点各出现一次。** 读取的键拼错在运行期报错而非编译期；它报得出来，因为键不在册是确定的失败，不会静默取默认值。
- **容器不进设置。** 列表与映射类参数要么留在配置里，要么以 JSON 文本承载，字段的校验退回到消费方自己。

## 失效条件

若出现一种消费方，其设置项集合本身是运行期数据——例如每接入一个第三方渠道就多一组开关，而渠道名在发布之后才确定——声明式表达不了它，本记录与该消费方的形状需要重新比较。

若设置值的类型往返在实际使用中频繁需要超出文本往返的表达（例如二进制载荷、大对象），封闭类型集合与文本存储的组合需要重新检验。
