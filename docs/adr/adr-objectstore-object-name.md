# 对象存储记下调用方给的名字，入口规整一次后回显

## 背景

声明一个对象的请求体带 `name`，契约把它列为必填；根包的 `Declaration.Name` 注释称它是调用方自己的标签、在对象存储里不透明；对象行与 `Object` 都没有这个值。字段被要求必填，却在落行之前丢掉。结果是列表与详情只能显示对象标识，下载文件名由标识与扩展名拼成，上传方给出的人类可读标识没有地方存放。

名字是上传方可控的字符串。一旦存下，它会流向对字面量敏感的消费面：列表与详情的展示，以及下载文件名。路径分隔符、控制字符、方向控制与零宽字符、过长的值，在这些面上各有各的后果。

## 考虑过的选项

### 从契约里去掉 `name`，继续不存

**否决**：对象的其余字段（标识、状态、大小、类型、时间）没有一个是人类可读的，去掉 `name` 后控制台的对象页只剩一列标识，操作者无法凭它分辨两份对象；上传方唯一自然的标签随之丢失。去掉字段只是让契约与现有实现一致，没有解决字段原本要解决的问题。

### 原样存下，由各读取方自行规整

**否决**：名字会被列表、详情与下载文件名各读一遍，每个读取方各做一遍规整，漏掉一处就是一处缺陷；上传方可控的值应当在入口处一次规整，之后的读取方拿到的都是同一个安全的值。

### 原样存下，含不可接受字符的名字以 400 拒绝

**否决**：名字只是标签，不参与任何判定。浏览器与操作系统给出的文件名可以带反斜杠或首尾空白，拒绝它会让一次合法的上传失败，而这份拒绝保护的只是一个展示值。

### 在入口规整一次后存入并回显

**采纳**，见决策。

## 决策

采纳：**对象存储记下调用方声明的名字，在 `Create` 入口规整一次后存入 `objects.name`，对象视图回显存入的值；名字可省、可为空，从不使 `Create` 失败，也不参与任何查找或判定。**

- 存入的值满足：合法 UTF-8；不含 Unicode 类别（[REF-unicode-uax44](../references.md)）为 Cc、Cf、Zl、Zp 的字符，这些字符被丢弃；不含 `/` 与 `\`，它们被替换为 `_`；首尾无空白；至多 255 字节且不在字符中间截断；不是只由 `.` 组成，那样的名字存为空串。
- 没有名字（省略、空串、规整后为空）时，存入的 `name` 是空串。
- `Declaration.Name` 可省，`Object.Name` 总在场。
- 读址的应答在有名字时以该名字作 `Content-Disposition` 的文件名，名字为空时不带这一项。
- 规整的细节由对象存储的设计文档给出，本记录不重述。

## 后果

上传方可控的字符串在入口一次变成安全的标签：列表、详情与下载文件名拿到的是同一个值，不再靠各读取方各自记得规整。契约里「必填却被忽略」的字段消失，对象页有了人类可读的标识。

**接受的代价：**

- **存入的名字可能与声明的不同。** 分隔符被替换、控制字符被丢弃、超长被截断；视图回显存入的值，上传方能看到改写的结果，但原始声明值不保留。
- **截断可能带走扩展名。** 超过上界的名字在字符边界截断，不特意保留末尾的扩展名。
- **需要一次加法迁移。** `objects` 表新增 `name` 列，既有行的值为空串，不回填。
- **名字在库里是明文。** 文件名可能带个人信息，库转储即泄露。
- **名字不唯一，也不能用来查找对象。** 同名对象并存，标识才是对象的唯一指称。
- **规整只保证值本身，不保证它在任何载体里都安全。** 规整不去掉引号与分号；日后应答若设 `Content-Disposition`，须按 RFC 6266（[REF-rfc6266](../references.md)）以 `filename*` 编码名字，不得裸拼进头字段。
