# 语言选项按基础语言命名，同基础语言多变体时保留地区名

## 背景

账户设置的语言下拉为每个受支持语言给出「当前界面语言里的名字」，取值经 `Intl.DisplayNames` 由 BCP 47（[REF-bcp47](../references.md)）标签算出。

完整标签带地区变体：`en-US` 在英文界面读作 American English，在中文界面读作「美式英语」。部署支持的是语言，不区分同一语言的地区变体，这个地区名对使用者是多余信息，也把「支持的语言集合」说得比实际更细。

受支持集由目录派生，可以只有一种语言的多个标签，也可以同时有两种语言的各一个标签。

## 考虑过的选项

### 固定映射表

在语言包里为每个受支持标签写死名称。

**否决**：新增语言要同时改表与语言资源，受支持集来自 i18n 实例，两张清单会漂移。

### 始终用完整标签命名

**否决**：这正是要消除的结果。

### 始终用基础语言子标签命名

**否决**：部署同时支持同一语言的两个地区变体时，两项显示同名，使用者无法区分要选哪一个。

## 决策

采纳：语言名按基础语言子标签命名；当受支持集里同一基础语言出现多个标签时，这些标签改用完整标签命名。

命名链是「目标标签的 `Intl.DisplayNames` → 完整标签的 `Intl.DisplayNames` → 原标签」，任何一步构造或查询失败都落到下一级。

## 后果

- 名称依赖引擎的 `Intl.Locale` 与 `Intl.DisplayNames`；引擎不支持时回退到完整标签，仍不空、不抛。
- 具体措辞随引擎的 ICU（[REF-icu](../references.md)）数据变化，测试按同一次 `Intl` 调用算期望值，不钉死某个版本的写法。
- 命名规则需要知道受支持集才能判断是否保留地区名；不知道时按「没有变体」处理，即只给基础语言名。

## 失效条件

- 部署不再按地区变体区分同一语言：这条规则退化为「始终用基础语言名」。
- 不同地区变体在界面上另有区分手段（例如并排显示标签原文）：地区名的取舍要重新裁定。
