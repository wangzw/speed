# 监听按端点在配置里认领的前缀为请求选端，已登记的路由只用于核对归属

## 背景

一条监听可以挂多个端点，由一个分派 handler 为每个请求选出一个端点，再由该端点自己的引擎匹配路由、跑它的链（[ADR-http-listener-endpoint-split](adr-http-listener-endpoint-split.md)）。端点挂在哪条监听上、哪类流量归哪个端点，由配置决定。

被选中端点的链上可以有认证网关。受网关守卫的端点上，不命中 `Exempt` 登记、也不是不带凭据而命中 `Optional` 登记的未认证请求，不论匹配到受守的路由、不匹配任何路由，还是方法不允许，网关写出的应答都相同（[ADR-authn-unmatched-request](adr-authn-unmatched-request.md)）。分派引擎与端点引擎都不做尾斜杠与路径纠正的重定向。

同一个二进制以不同的装配运行：命令纳入哪些模块，模块之内哪些路由组随可选依赖挂载，都因部署而异。示范 import 了只为契约而 import 的 sms.admin，基线不运行它；从示范复制出去的产品可以删掉某项能力的 import。

选端若取决于已挂载的路由，未认证者就能按应答推断装配。分派按各端点登记的路由推出它占有的前缀时：

- 合一拓扑（API 端点与挂前端静态托管的端点同在一条监听上）下，未运行模块的路径没有端点占有，交给兜底的静态托管，`GET` 得到 200 入口文档；运行中模块的受守路由得到网关的 401。
- 分离拓扑下，同一条路径在模块未运行时得到分派自答的 404，运行时得到 401。
- 一个端点上的路由全部撤掉，它与别的端点同处一条监听即启动失败；端点上只剩一条较深的路由时，它占有的前缀随之变深，较浅路径上的请求转由兜底端点作答。
- 一条较深的 `*` 通配让整个端点被当作兜底端点。

要满足的约束：

- 不对端点上每个请求起作用、在各端点上没有[匿名路由](../glossary.md)的路由模块是否在运行，模块内随装配挂载、不含匿名路由的路由组是否挂上，未认证者都不能借 HTTP 应答的差异推断；合一拓扑与分离拓扑都要成立。匿名路由本就对未认证请求作答，不在这一约束之内。
- 入口模块不认识任何具体模块，也不认识认证；登记接口不列举路由，网关不读路由表。
- 资源是静态声明（[ADR-module-resources](adr-module-resources.md)）；`http.Spec` 不参与路由（[ADR-http-routing](adr-http-routing.md)）。
- `http.Spec` 片段里的端名是惯例名，不是配置点名的端；认证的挂载基路径可配置（`authn.gate.mount.bases.default`，缺省 `/api/v1/auth`），片段里写的是 `/api/v1/auth`。
- gin（[REF-gin](../references.md)）的路由匹配中静态段优先于参数段：同一端点上，一条非匿名的静态路由能遮住另一模块匿名参数路由的一部分取值，一条匿名静态路由也能遮住非匿名参数路由的一部分取值。
- 前端的页面路径在客户端路由表里，入口模块与静态托管都不认识它。

## 考虑过的选项

### 维持从各端点登记的路由推出前缀

多段全字面路由贡献父路径，单段路由贡献自身，首段动态的路由不贡献；含 `*` 通配或登记根路由的端点是兜底端点。

**否决**：选端随装配变化，背景所列的推断途径都由此而来。

### 在推出前缀之外加一项可选的声明

宿主可以为端点声明前缀；不声明时仍从路由推出。

**否决**：缺省配置仍然泄露，保证要靠宿主记得打开。

### 由可用集的 `http.Spec` 片段推出前缀

**否决**：

- 片段里的端名是惯例名，不是配置点名的端。
- 认证的挂载基路径可配置，片段里写死 `/api/v1/auth`。
- `Spec` 不参与路由（[ADR-http-routing](adr-http-routing.md)）。

### 资源类型 `http.Prefixes`

每个路由模块声明一项资源，带一个读自身配置、算出前缀的函数；入口模块取可用集。

**否决**：

- 每个路由模块都要改，authn 的挂载路径要特判。
- 资源带函数，与「资源是静态声明」（[ADR-module-resources](adr-module-resources.md)）相抵。
- 入口模块要在 `Prepare` 里为不运行的模块读配置。
- 覆盖不了删掉 import 的情形：被删的模块不在可用集里。

### 全部 API 路由收进一个固定命名空间

**否决**：要改每个模块的路径契约、前端 SDK 与文档。

### 分派之前对未认证请求统一作答

**否决**：入口模块不认识认证。合一拓扑下，前端深链接要入口文档、API 要 401，统一应答必然与其中一方冲突；按导航类请求头区分，取值又由攻击者控制。

### 只靠拓扑：API 所在的监听只挂一个端点

**否决**：限制部署形态，逼前端与 API 跨源；合一拓扑正是前端与 API 同源所需的形态（[ADR-http-listener-endpoint-split](adr-http-listener-endpoint-split.md)）。

### 由端点在配置里认领前缀

每个端点在配置里列出它认领的路径前缀，分派只读这些认领；已登记的路由只用来核对它落在登记它的端点的认领之内。

**采纳**，见决策。这一选项内部的取舍如下。

#### 认领写在哪里

写在端点条目的 `prefixes` 上。

否决「在监听条目上写一张前缀到端名的表」：端点挂在哪条监听上要在两处各写一次，两处不一致又是一类新的配置错误；只挂一个端点的监听，缺省也写不自然。

#### 省略 `prefixes` 时

省略即 `["/"]`。

- 否决「必填」：只挂一个端点的监听没有选端问题，必填只让它多写一行，行为不变。
- 否决「省略时退回从路由推出前缀」：缺省配置仍随装配泄露。
- 保留显式的 `/`：配置可读，兜底端点也能借此从外层认领里收回一段嵌套子树。

#### 兜底端点怎样判定

由认领 `/` 判定。

否决「按路由结构判定（含 `*` 通配或根路由）」：兜底与否随装配变化，静态托管不运行时它所在的端点零路由，启动失败；较深的通配也会被误判为兜底。

#### 无人认领的路径怎样作答

交给兜底端点的链；没有兜底端点时由分派答 404。两种应答都只由配置决定。

- 否决「统一答 401」：入口模块会因此认识认证。
- 否决「统一答 404」：合一拓扑下前端深链接拿不到入口文档。

#### 前缀的写法

只接受字面段。

否决「段通配（如 `/*/admin`）」：要多一套模式语言，还会与 `/api/v1/system/auth` 这类字面认领产生跨端点的优先级问题。

#### 路由落在认领之外

`Serve` 期失败，哨兵 `http.ErrUnclaimedRoute`。

- 否决「静默交给兜底端点」：路由挂上了却永远到不了。
- 否决「并入 `http.ErrRouteConflict`」：`http.ErrRouteConflict` 承载 gin 拒绝装载（同一端点内的路由冲突、层数超限），修复动作是改路由或减层；越界路由的修复动作是改配置或换端点，调用方要能分开判别。
- 否决「在 `Route` 调用时当场 panic」：越界是配置与装配不一致，属于数据错误，登记接口不为数据错误 panic；放在 `Serve`，与路由冲突同一时机。

#### 认领冲突的时机与分类

在 `Prepare` 读配置时判定：这些错误只与配置有关。跨端点的冲突设哨兵 `http.ErrClaimConflict`，调用方可以用 `errors.Is` 判别，与跨条目的引用错误 `http.ErrUnknownListener` 同一口径。单条前缀的写法错误与未知键、缺地址、保留端名同属读配置时判出的取值错误，与它们归入同一个哨兵 `http.ErrInvalidConfig`，错误点名完整键路径与原值。

否决「写法错误与跨端点冲突并入一个新哨兵」：前缀写法与地址写法同是取值错误，分开归类会让它们的判别口径不一致；跨端点冲突的修复动作是改另一个端点的认领，与改正单条取值不同。

#### 一致性核对的规则

一条统一规则：路由的字面前导路径按请求期的选端规则必须选中登记它的端点，允许部分遮挡。

- 否决「兜底端点与带前缀的端点各用一套规则」：两套规则要各自维护，而统一规则已覆盖全部情形。
- 否决「禁止一切部分遮挡」：会推翻嵌套认领取最长的语义，而遮挡与未认证应答是否随装配变化无关。

#### 认领覆盖的启动期诊断

否决「`Serve` 时读可用集 `Spec` 片段的路径，字面前导路径不落在任何非根认领之下的写一条警告」：

- 片段路径是静态的，挂载路径可配置；改了认证基路径的合法配置会得到一条永远消不掉的警告，警告不可处理。
- 片段的端名是惯例名，判不出命名空间该在哪条监听、哪个端点，单端点监听上的模块会被误报。
- 覆盖不了删掉 import 的情形：被删的模块不在可用集里。

#### 保证的单位

单位是路由模块与模块内随装配挂载的路由组，不含应答塑形模块，也不含带匿名路由的模块与路由组（术语见后果）。

- 否决「把匿名路由所属模块的在场也纳入保证」：这些路由就是用来对未认证者作答的，所属模块的在场视为登录前公开的事实；纳入保证要改这些模块的作答。
- 否决「藏住应答塑形模块的在场」：它们整端生效、不按路由区分，只暴露自己，带不出路由模块的在场；RFC 9110（[REF-rfc9110](../references.md)）要求 401 带一个适用的挑战；藏住它们需要另一套设计。

#### 豁免请求的界定

只豁免「至少在一次运行中命中匿名路由，且在每一次运行中要么命中匿名路由、要么不匹配任何路由」的请求，另以「同一端点上匿名路由与非匿名路由的匹配域不相交」为前提。

- 否决「在任一次运行中命中匿名路由即排除」：合一拓扑下被兜底通配吸走的选端漂移会被当作命中静态托管的匿名路由而排除，性质区分不出它要防的缺陷；一条受守静态路由遮住别的模块的匿名参数路由时，差异暴露的是受守模块，也会被排除。
- 否决「按 gin 静态段优先的规则逐次精确判定命中，不设前提」：要知道请求在每次运行中命中哪条路由，就要有受守路由的全表，而登记接口不列举路由，判不全。

#### 前端页面路径与认领的相交

由宿主负责。

否决「由入口模块或静态托管在运行期检查」：它们不认识客户端路由表；登记接口不列举路由，静态托管拿不到别的端点的认领。

#### 认领的粒度

按能力命名空间认领：示范把 `/api` 归业务端点，把 `/api/v1/auth`、`/api/v1/features`、`/api/v1/orgs` 归账户端点，把 `/api/v1/system/audit`、`/api/v1/system/auth`、`/api/v1/system/permissions`、`/api/v1/system/settings`、`/api/v1/system/sms`、`/api/v1/system/tenants` 归管理端点；`/api/v1/tenants` 落在业务端点的 `/api` 认领之下；只有要把一段子树划给另一个端点时才写更深的前缀。

否决「按 `/<能力>/admin` 这类子命名空间认领」：占用的命名空间更少，但认领要覆盖平台前端会寻址的全集，按子命名空间写最容易漏；能力增加子命名空间时还要改认领。顶层名字前端产物里本来就有，暴露它们带不出装配。

## 决策

采纳：**监听只按端点在配置里认领的前缀为请求选端；已登记的路由不参与选端，只用来核对它落在登记它的端点的认领之内。** 与网关对未认证请求的应答不随路由变化（[ADR-authn-unmatched-request](adr-authn-unmatched-request.md)）合起来，在后果所述的前提与界定下，未认证请求的应答不随路由模块的装配变化。

- 端点条目带键 `prefixes`（字符串列表），列出它认领的路径前缀，省略即 `["/"]`。认领 `/` 的端点是该监听的兜底端点：本监听上没有别的端点认领的路径交给它；`/` 不参与最长匹配。一个端点可以同时认领 `/` 与别的前缀。
- 前缀只由字面段组成：以 `/` 开头，除 `/` 本身外不以 `/` 结尾，不含空段、`.` 与 `..` 段、以 `:` 或 `*` 开头的段，不含 `%`、`?`、`#`、空白与控制字符。同一端点的列表非空、无重复，两条非根前缀互不为祖先。违反这些是读配置时判出的取值错误，与未知键、缺地址同归哨兵 `http.ErrInvalidConfig`，错误点名完整键路径与原值。
- 同一条监听上，两个端点认领同一前缀，或不止一个端点认领 `/`（包括多个端点都省略 `prefixes`），`Prepare` 以 `http.ErrClaimConflict` 失败，点名监听、两个端点与前缀。不同端点的前缀可以嵌套。
- 请求期，分派在本监听各端点的非 `/` 认领中，按段边界、区分大小写、对解码后的路径取最长的一条，把请求交给认领它的端点；没有一条匹配时交给兜底端点；没有兜底端点时由分派答 404。选中之后，由该端点的引擎匹配路由并跑它的整条链，以它自己的 200、404 或 405 作答。
- `Serve` 期，每条路由的字面前导路径（第一个 `:` 或 `*` 段之前的字面部分；根路由与首段动态的路由取空串）按请求期的选端规则必须选中登记它的端点，否则以 `http.ErrUnclaimedRoute` 失败。错误点名监听、路由、登记它的端点及其认领、实际会选中的端点与前缀，同一端点上落空的路由一次全部列出。被别的端点更长的认领截走一部分取值不算越界。
- `http.ErrRouteConflict` 只承载 gin 拒绝装载的情形：同一端点内的路由冲突、层数超限。
- 链上契约：观测阶段与防护阶段的层，以及鉴别阶段里排在网关之前的层，要不要作答、怎样作答，不取决于请求是否匹配路由、匹配了哪一条；`FullPath()` 与路由参数只可读取，用来写日志、打点。入口模块不在运行期强制这一条。

## 后果

**在下述前提与界定下，未认证请求的应答不随路由模块的装配变化。** 本记录内的术语：

- **应答塑形模块**：对一个端点上的每个请求起作用、不按路由区分的模块，按交付的能力判定，不按名字：交付 `authn.Verifier`、`authn.Gate`、`http.ErrorResponder`、`i18n.Localizer`、`i18n.Resolver`、`i18n.Negotiator` 任一功能的模块，以及在网关之前登记层的模块。一个这样的模块同时登记路由时（authn.token 登记 `/api/v1/auth/jwks.json`），仍按应答塑形模块看待。
- **未认证请求**：不带凭据的请求，以及网关没能从所带凭据得出一个通过出口检查的主体的请求；主体成立、只因冒充范围被拒的请求不在其列（[ADR-authn-unmatched-request](adr-authn-unmatched-request.md)）。
- **匿名路由**与命中匿名路由：按[术语表](../glossary.md)的界定。
- **豁免请求**：至少在一次运行中命中匿名路由，且在每一次运行中要么命中匿名路由、要么不匹配任何路由的请求。

取同一个二进制的两次运行，满足下列前提，两者之间允许不同的只有：哪些不属于应答塑形模块的路由模块在运行；模块内随装配挂了哪些路由组。那么任一条监听收到的任一个未认证请求：

- 两次由同一个端点作答，或两次都由分派自答；
- 不是豁免请求时，两次应答的状态码相同，除 `Date` 外的全部响应头逐字节相同（头名不分大小写，同名多值按出现次序比较），响应体逐字节相同，且都不是重定向。

请求的其余请求头取任何值都成立，包括 `Origin`、`Access-Control-Request-Method`、`Accept-Language`、`X-Tenant` 与 cookie；不论监听挂一个端点还是多个、有没有兜底端点都成立。由此，不属于应答塑形模块、在各端点上的路由都不是匿名路由的路由模块，以及路由都不是匿名路由、随装配挂载的路由组，未认证者不能借 HTTP 应答的差异判断它们是否在运行。

前提，任一条不成立时本记录不承诺这一性质：

- 网关由网关模块构造，不是宿主预置的外来实例；入口模块的 `Router` 由入口模块构造。
- 两次运行是同一个二进制，应答塑形模块集合相同，配置相同；配置包括端点的划分、认领、哪些端点受网关守卫、CORS（[REF-whatwg-fetch](../references.md)）允许源、请求体上限、会话 cookie 的取名项。
- 运行期状态相同：后端可用性、限流桶、网关并发预算。
- 网关守住它对未认证请求的作答承诺（[ADR-authn-unmatched-request](adr-authn-unmatched-request.md)）。
- 链上契约被遵守。
- 同一端点上，匿名路由与非匿名路由的匹配域不相交：可能同时出现在该端点上的一条匿名路由与一条非匿名路由，没有某个（方法，路径）能同时被两者的模式匹配。

**不在保证内的差异**，举例列出，不是封闭集；性质的范围由它的陈述与前提划定：

- 匿名路由本身的应答，以及经它们探出的所属模块的在场。例如登录方法与流程、令牌端点与 JWKS（[REF-rfc7517](../references.md)）、不带凭据时的会话读取接口、邀请落点、SSO 发现与 SAML（[REF-saml2](../references.md)）元数据，以及前端静态托管、ops 这类不受守端点上的全部路由。这些路由本来就对未认证者作答，所属模块的在场视为登录前公开的事实。
- 应答塑形模块的在场与配置，例如 `WWW-Authenticate` 的 scheme 清单、无效 cookie 引出的清除 `Set-Cookie`、CORS 预检的 204 与 403、来源地址限流的 429 与 `Retry-After`、语言协商带来的 `Content-Language`。它们整端生效、不按路由区分，只暴露自己。
- 配置本身：端名（即 realm）、认领集合、拓扑、哪些端点受守、CORS 允许源。认领集合可从「401 还是认领之外的应答」读出，是对匿名者公开的配置。
- 二进制层面的事实：前端产物（页面表与它调用的 API 按平台全集打包）、ops 在服的合并 OpenAPI（[REF-openapi](../references.md)）文档（取可用集）、契约文件。它们回答「这个二进制能提供什么」，不回答「这次在跑什么」。
- 不同二进制之间的比较。选端保持不变靠宿主的认领不随 import 增删；其余由可用集派生的取值（例如受支持的语言集）不在保证内。
- 计时与资源侧信道：命中与否的查找耗时不同，各端点的链长也不同。性质约束的是应答内容。
- 已认证调用者：在认领之内仍能分出 404、403、200。
- 跨请求状态：匿名路由上的请求影响限流桶，进而影响以后 429 的时机；带出的只是匿名路由上已经公开的事实。
- 起不来的装配：没有应答，不构成反例。

**零路由端点照常启动。** 认领来自配置，与路由无关。带非 `/` 认领的零路由端点，认领之下的每个请求都走它引擎的无匹配分支、跑整条链：受守端点上，不豁免的未认证请求得到网关的 401，与装了模块时逐字节相同，已认证请求得到该端点的 404；不受守端点一律得到该端点的 404。零路由的兜底端点答它自己的 404。较深的 `*` 通配（如认领 `/files` 的端点登记 `/files/*p`）只占它所在端点认领之下的路径，不让该端点成为兜底端点。

**前端页面路径不落在 `/` 以外的任何认领前缀之下。** 与前端同处一条监听时，落在某条非 `/` 认领之下的页面路径，整页导航拿到的是那个端点的应答（未认证得 401，已认证得 404），拿不到入口文档。入口模块不认识前端的页面表，这一条由宿主负责；相交只随配置变化，可以静态测试。

**对宿主的要求**，与前端页面路径的约束合起来，是本决策加给宿主的全部要求：

- 认领是产品固定的命名空间表，不随 import 增删，也不随运行集增删。它至少覆盖可用集里每个 operation 的命名空间，以及产品交付的前端会寻址的命名空间；平台前端包按运行期特性门控，寻址的是平台全集。
- 去掉一项能力时，它的命名空间留在认领里，不论是撤出运行集，还是删掉 import。
- 认领按能力命名空间写，只有要把一段子树划给另一个端点时才写更深的前缀。
- 模块的挂载路径可配置时，认领跟着改，例如 `authn.gate.mount.bases.default`。
- 同一端点上，匿名路由与非匿名路由的匹配域不相交。这也是写匿名路由的模块作者的义务。

漏写的认领一部分在启动时暴露：一个运行中的模块的路由落在认领之外时，`Serve` 报 `http.ErrUnclaimedRoute`。

入口模块不认识任何模块：`prefixes` 是宿主写的字符串，核对比较的是已登记的路由路径与这些字符串，与谁登记无关；网关不读路由表，登记接口不列举路由。

**接受的代价：**

- **配置是破坏性变更。** 端点条目多出键 `http.endpoints.<名>.prefixes`。同一条监听挂多个端点时，除至多一个端点外都必须写，否则 `Prepare` 以 `http.ErrClaimConflict` 失败，错误点名监听与端点，并给出 `prefixes` 的写法。只挂一个端点的监听不受影响。没有向后兼容垫片。
- **选端语义变化。** 兜底端点由认领 `/` 决定；一部分路径换了作答者。示范里，`/api/v2/x`、`/sms/...`、`/settings/x`、`/api/v1/features` 由入口文档转为认领它的端点作答，未认证得 401。
- **错误分类变化。** 两个端点登记同一（方法，路径），或兜底端点的字面路由被更长的认领遮住，都报 `http.ErrUnclaimedRoute`；同一前缀被两个端点认领，或不止一个端点认领 `/`，在 `Prepare` 报 `http.ErrClaimConflict`；「端点没有可选的前缀」这一类失败不复存在。用 `errors.Is(err, http.ErrRouteConflict)` 判别这些情形的调用方要改。Go 接口上只多出 `http.ErrUnclaimedRoute`、`http.ErrClaimConflict` 与 `http.ErrInvalidConfig`，`Router`、`Endpoint`、`Spec` 的签名不变。
- **示范前端的回调页离开 `/api/v1/auth`，落在 `/sign-in/callback`。** 它与认证的回调路由同在 `/api/v1/auth` 之下；用嵌套认领把它划给前端，又会截走后端的回调路由。
- **认领集合对匿名者公开，宿主要把它维护成固定的命名空间表。** 一个不运行的模块或一项已删掉 import 的能力，其命名空间漏写时入口模块判不出，匿名者能从「401 还是认领之外的应答」读出它缺席。认领写成了没有任何路由的命名空间（拼错），对应模块不运行时同样察觉不到。
- **匹配域不相交这一前提，入口模块与网关都判不出。** 入口模块不认识匿名登记，网关不读路由表；它由路由作者与宿主负责。
- **前端页面路径与认领的相交由宿主负责。** 认领占用的名字不能再用作页面路径。
- **链上契约不在运行期强制。** 一个在网关之前、按路由决定作答的层会让性质失效，启动期没有信号。
- 应答塑形模块与带匿名路由的模块，其在场对未认证者可见，见上文不在保证内的差异。

## 失效条件

- 网关对不命中匿名登记的未认证请求按路由区分作答。
- 分派引擎或端点引擎开启与路由相关的重定向。
- 入口模块能不经配置、从可用集可靠得知各模块在本配置下的命名空间与所在端点；届时可以重新评估是否从模块推出前缀，或加认领覆盖的诊断。
- 出现挂载路径只能在运行期决定的模块。
- 登记接口开始列举路由，使匹配域不相交这一前提可以在启动期核对。
