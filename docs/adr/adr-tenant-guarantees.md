# 装配层面的性质写成非保证，租户隔离不由框架承诺

## 背景

数据库模块已接受的代价里写着：按租户过滤在框架层没有机制保证，承担它的模块不被装配，或宿主预置的数据库实例落在数据库模块拒收管不到的情形里时，遗漏过滤不会被任何一层拦下（[ADR-db-plugin-scope](adr-db-plugin-scope.md)、[ADR-db-supplied-instance-refusal](adr-db-supplied-instance-refusal.md)）。本记录裁定本模块落在这一侧的失败怎么处置。

认证为同一类性质立过两分判据（[ADR-authn-guarantees](adr-authn-guarantees.md)）：启动期自己判得出来的确定失败配哨兵与修复动作，不得写成非保证；成立与否取决于本次装配里还有哪些模块、它们各自怎么写的性质，写成非保证，每条写清可观察到什么、哪一层不报错。那份记录还裁定不为这类性质在别的模块上增开接缝。

本模块有几处性质落在判据的第二支上，而它们各自的可观察形态不同。

中间件的先后由指向功能标识的硬约束决定，而约束指向的功能在链上无人代表时约束消失，声明它的那一层照常运行，且这一档不作启动失败（[ADR-http-stages](adr-http-stages.md)）。

插件的安装取启用集。一个只声明插件、自己不访问库的模块被禁用时，它提供的那项横切能力静默消失（[ADR-db-plugin-scope](adr-db-plugin-scope.md)）——**而名册子包正是这个形状的模块**。

已登记而未被本次命令纳入、也没有预置实例的模块不进启动诊断，理由是纳入哪些模块起于宿主写在命令树上的决定、不是意外（见架构文档的可观测性）。静态级纳入把模块放进声明集而不让它运行，`migrate` 这类命令因此收到表而不装插件。

## 考虑过的选项

### 在数据库模块上增开接缝

让数据库功能拒绝没有租户的语句，或者只交付带租户条件的句柄。

**否决**：数据库模块明写不认识租户，代价会落在每一个访问库的宿主头上，与它是不是多租户无关；"单租户应用不必承受这套概念"正是它拒绝内建租户过滤的理由之一。接缝也闭不合：自建连接与原生 SQL 都在它的接口面之外。

### 在入口模块上开一个每端唯一的租户席位

链的组装保证租户层每端只有一个，且位于全部登记层之内。

**否决**：与认证拒绝同一形态时给出的理由同源（[ADR-authn-guarantees](adr-authn-guarantees.md)）——席位的名字由占座者自报，入口模块拿不到登记方身份，接缝换掉的只是哪个坏模块得手。排他交付已经在功能目录这一层给出了"交付租户功能的模块唯一"，它管不到中间件登记面，而再开一层席位不闭合这个差。

### 让 `core` 认识租户

注册表按租户分实例，或者提供租户上下文。

**否决**：`core` 不解释任何资源，也不认识任何功能（架构不变量 2）。它也因此不代任何消费点过滤资源（架构不变量 15）。

### 写成非保证，不为它们改动别的模块

**采纳**，见决策。

## 决策

采纳：本模块的装配级性质写成非保证，不为它们在 `pkg/db`、`pkg/http` 或 `pkg/core` 上增开接缝。判据沿用认证立下的两分法：

- 本模块在启动期自己判得出来的确定失败，配哨兵与修复动作，不得写成非保证。
- 成立与否取决于本次装配里还有哪些模块、它们各自怎么写的性质，写成非保证，每条写清可观察到什么、哪一层不报错。

按判据直接指名的性质：

- **链上不保证每个受守护的端点都有解析层**，也不保证没有能绕过解析层的层。
- **解析层与名册子包不保证同时在场。**
- **不保证每条针对受约束模型的语句都经过插件。**
- **不保证本该受约束的模型都内嵌了约定。**
- **不保证租户标识不向内泄漏**，也不保证按请求做键的缓存或合并层把租户纳入键。
- **不保证停用即时生效。**
- **不保证请求面取到的租户不是伪造的。**
- **不保证别名回收之后旧书签不指向新租户。**

判据管到的不止这些指名的性质，符合判据的新情形归入非保证，不为此修订一份列举。

## 后果

收口口径与架构的错误模型一致：本模块为自己产生的失败提供哨兵，不为发生在它之外、或经由它返回的失败发明名字（见架构文档的错误模型）。

本模块的两处防线不需要改动别的模块：名册模块与解析模块的实例都是各自的产物时，启动成功路径上无条件写出名册的快照规模与状态分布，以及本次实际登记的取法与受守护的端点清单。它们只用本模块自己的信息。宿主为其中一个模块预置的实例不是该模块的产物时，那个模块的回调不对它做任何事，它负责写出的那一份也不写出，注册表却仍答那个模块在场（[ADR-supplied-instance](adr-supplied-instance.md)）。

**接受的代价：**

- **隔离不是框架的承诺。** 数据库模块已经记下这一条，本记录把它承接为本功能目录的对外口径：一个不装配本模块的宿主，其语句在无过滤状态下执行，这不是缺陷。
- **这些性质将来若要变成硬保证，代价不再落在本模块内部**：落点在数据库模块或入口模块的接口面上，届时是一次宿主可见的破坏性变更。认证为它的那几条记过同一条代价。
- **非保证是文档承诺的一部分，不是省略。** 每一条都要写出可观察的失效形态与宿主据此该做什么，逐条列在设计文档的错误与失败语义一节。
- **两处防线只让情形可被人察觉，不让它被拦住。** 一个从不主动查询的宿主仍然什么都看不到。

## 失效条件

若数据库模块获得一条"句柄只在带租户的上下文里可用"的途径，且那条途径不落在每一个访问库的宿主头上——例如在事务开启处而非句柄交付处——则"隔离不是框架的承诺"要重新比较。

若启动诊断的义务扩展到未被纳入与只被静态级纳入的模块，则本记录指名的性质里有几条的察觉途径从"要宿主自己去问"变成"自己出现在输出里"，判据的两分法要按新的可观测量重新检验。
