# 不订阅事件总线，领域事件不转成跨度

## 背景

横切能力取得领域事实的通路是事件总线：发布方按类型名发布，订阅方按类型名订阅，发布方与订阅方之间没有静态类型的共享，横切能力因而不必耦合每一个产生事实的业务模块（[ADR-event-scope](adr-event-scope.md)）。

总线的投递承诺是各实现都能满足的下界：`Publish` 返回成功只表示事件已被总线接受，不表示任何订阅者收到；总线不承诺投递次数与顺序，“某条事件丢了”不可判定（[ADR-event-delivery](adr-event-delivery.md)）。

`pkg/event` 的 `Event` 字段是 `ID`、`Type`、`TenantID`、`TraceContext` 与 `Payload`，没有时间戳。`ID` 由发布方设好，或在发布方留空时由 `Publish` 赋予；`TraceContext` 同样是发布方留空时由 `Publish` 写入、非空时原样携带（[ADR-event-tracing](adr-event-tracing.md)）；同一个事件的每个订阅者（每个副本上、每种实现下）收到同一个值，重投的条目也带着它（[ADR-event-identity](adr-event-identity.md)）。`Bus.Subscribe` 按类型名精确匹配（精确字符串比较，无通配与前缀），并带上订阅者名，它用作那个订阅者跨度的名称（[ADR-event-tracing](adr-event-tracing.md)）。

总线把一个事件交给它的每一个订阅者，各订阅回调彼此独立：一个订阅回调被调用，只说明它自己收到了这个事件，说明不了同一事件的别的订阅者收到了没有、处理用了多久、成功与否。

## 考虑过的选项

### 订阅点名的类型，回调把事件转成短跨度

配置点名的每一个事件类型，装配器在 `Init` 向总线订阅一次，回调把事件转成一个短跨度：名称为事件类型，属性含事件标识、租户标识与载荷的字段。

**否决**：这样的跨度只能证明本模块自己的订阅回调签收了事件，证明不了任何业务订阅者收到或处理了它。它的时长只测得记属性的几微秒，不承载信息；它的起点是消费时刻，不是事实发生的时刻；总线不承诺投递次数，跨度数不等于事实数，且可能缺样。它附带的业务字段、租户与追踪关联都是从发布方借来的，在发布侧或总线的分发层记录更可靠。

### 订阅全部事件，不做点名

本模块向总线订阅每一类事件，覆盖面不必写进配置。

**否决**：它产出的跨度与“订阅点名的类型，回调把事件转成短跨度”相同，同样只证明本模块自己的回调签收了事件；事件类型名与发布方之间又没有编译期联系，总线也不提供类型名的注册接口，全量订阅还会把不受控的类型基数直接带进信号。

### 在总线的分发层为每个订阅者记跨度

总线把事件交给每个订阅者时各起一个跨度，时长是该订阅者的处理时间，处理失败标为错误。

**不在本模块**：只有这种形态回答得了“订阅者收到并处理了吗”，而分发层是事件模块的实现，本模块够不着每一个订阅者的调用。它属于事件模块，不属于本模块。

### 把事件转成计数

订阅回调把每个事件累加进一个计数器。

**否决**：计数的目录与命名归产生该信号的模块。本模块替业务模块决定指标的形态与名字，而那些名字的语义只有产生它的模块知道：事件只是字段名与不透明载荷，本模块读不出一个名字该是什么。

### 不订阅总线

本模块只交付 provider、请求路径的采集与出站注入，不取总线的功能，装配器不声明点名事件类型的输入项。

**采纳**，见决策。

## 决策

采纳：**装配器不订阅事件总线，不把领域事件转成跨度，也不转成计数。**

## 后果

本模块不依赖事件总线，装配器的配置里没有事件类型的清单；一个只跑后台任务、没有总线的进程与有总线的进程纳入本模块的方式相同。

**接受的代价：**

- **领域事件的投递与处理在本模块产出的信号里没有踪迹。** “订阅者收到并处理了吗”要由事件模块在分发层记录，或由业务模块在自己的订阅回调里起跨度；两者都没有时，这个问题从追踪里答不出来。撞上它的是要从追踪里看事件处理的宿主。
- **本模块产出的信号不带租户维度。** 请求直方图与服务端跨度都不带租户维度（[ADR-observability-instruments](adr-observability-instruments.md)），本模块也没有别的信号承载它。撞上它的是要按租户切分延迟与错误率的多租户宿主。
