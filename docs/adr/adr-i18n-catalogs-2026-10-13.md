# 各模块以自己的资源声明消息目录，引擎收集为可用集并在启动期校验

## 状态

已接受

## 背景

每个产出用户可见文本的模块都要携带自己的文案，按语言分文件组织。模块以资源声明的机制对外暴露只读元数据，注册表按类型提供查询，引擎是这一种资源的消费点（[ADR-module-resources-2026-09-13](adr-module-resources-2026-09-13.md)）。

文案是编译期的静态事实：它与所在模块的代码一起编译进二进制，随发布一起变化。取材域按消费点是「让声明生效」还是「只校验声明」裁定，只校验的取可用集（[ADR-module-resources-2026-09-21](adr-module-resources-2026-09-21.md)）。目录这一种资源只被读取、被合并进一个索引，属于让声明生效的一类。

启动期必须检出的错误：某份文件不是合法 JSON；两个模块声明了同一个消息键；配置的默认语言在声明集里没有任何一份条目。

## 考虑过的选项

### 单一集中目录，全部文案放一处

所有模块的文案集中在一个目录，按语言分文件。

**否决**：模块的文案与模块分离，新增一个模块要改这个中心目录，删一个模块要记得回中心目录删它的条目；模块自治被打破，而模块化正是本仓库的组织原则。

### 用 TOML 或引入一个专门的文案库

消息文件用 TOML，或引入一个提供复数、性别等能力的文案库。

**否决**：为一个只需要「键到字符串、支持插值」的需求引入依赖；JSON 是标准库可解析、与 `embed` 天然配合的格式，`html/template` 与 `text/template` 已能承担插值，不需要新库。

### 从磁盘运行期加载文案

启动时从磁盘目录读消息文件，不从二进制内嵌。

**否决**：把一份编译期静态事实变成运行期可能缺失的文件，多一处启动失败面，且同一份二进制在不同部署下文本不同；热改也由此被拒（[ADR-i18n-scope-2026-10-13](adr-i18n-scope-2026-10-13.md)）。

### 每模块经资源声明自己的 `locales/{tag}.json`，引擎收集

**采纳**，见决策。

## 决策

采纳：每个模块经 `core.Resources[i18n.Catalog]` 声明自己的消息目录，格式是「一个语言一个文件」的 JSON，文件名为 `locales/{tag}.json`，放在模块自己的 `embed.FS` 上。

引擎收集全部声明，取可用集（遍历全部已登记模块的声明，不按启用结果过滤），把各文件合并成一个按语言、按键索引的表。一个键归声明它的那个模块，键以模块名起首命名，使两个模块不会撞在一个键上。

启动期校验：每份文件是合法 JSON；跨模块没有同名键冲突；配置的默认语言在合并后的索引里至少有一份条目；任一不满足即启动失败并点名。文案是编译期静态事实，没有运行期热加载。受支持语言集是各目录所承载语言的并集，代码不枚举它（[ADR-i18n-language-set-2026-10-13](adr-i18n-language-set-2026-10-13.md)）。

## 后果

模块的文案与模块在一起，增删模块不动中心目录；引擎是唯一的合并点，各消费方看到同一个索引。

一个键只在声明它的模块里定义，读一个键的来源可以从键名读出模块。

**接受的代价：**

- 配置的默认语言的覆盖是启动硬约束。声明集若没有任何一份默认语言的条目，整个进程起不来；换来的是运行期不会静默回退到另一语言。
- 改一处文案要重新编译并发布；这是运行期热改被拒的直接结果（[ADR-i18n-scope-2026-10-13](adr-i18n-scope-2026-10-13.md)）。
- 键冲突与缺配置的默认语言的校验在启动期做，不在编译期做；两个都声明了同一键的二进制能编译成功，要到启动才失败。
- 每份 JSON 的合法性与键形状由引擎在启动时检查，模块自身在编译期得不到这个保证；一个模块的目录写错，发现点在装配它的宿主的启动，而不是它自己的构建。

## 失效条件

若出现必须由运行期数据决定文案的场景——例如按租户自定义的消息——则「文案是编译期静态事实」不再成立，本记录要改为区分静态目录与运行期来源，并另立那份运行期数据的取材与校验。
