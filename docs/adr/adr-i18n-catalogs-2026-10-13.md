# 各模块以内嵌资源声明消息目录，装配期再并入一个可配置的覆盖目录

## 状态

已接受

## 背景

每个产出用户可见文本的模块都要携带自己的文案，按语言分文件组织。模块以资源声明的机制对外暴露只读元数据，注册表按类型提供查询，引擎是这一种资源的消费点（[ADR-module-resources-2026-09-13](adr-module-resources-2026-09-13.md)）。

模块内嵌的目录是编译期的静态事实：它与所在模块的代码一起编译进二进制，随发布一起变化。取材域按消费点是「让声明生效」还是「只校验声明」裁定，只校验的取可用集（[ADR-module-resources-2026-09-21](adr-module-resources-2026-09-21.md)）。目录这一种资源只被读取、被合并进一个索引，属于让声明生效的一类。

模块内嵌的目录之外，一个部署还需要一处不改二进制即可补文案的入口：覆盖个别消息的措辞，或补上一个声明目录没有承载的语言。这个入口的读取必须发生在装配期，此后运行路径不承担文件读取。

启动期必须检出的错误：某份内嵌文件不是合法 JSON；两个模块声明了同一个消息键；配置的默认语言在合并后的索引里没有任何一份条目；配置的覆盖目录里某份文件不是一个合法目录。

## 考虑过的选项

### 单一集中目录，全部文案放一处

所有模块的文案集中在一个目录，按语言分文件。

**否决**：模块的文案与模块分离，新增一个模块要改这个中心目录，删一个模块要记得回中心目录删它的条目；模块自治被打破，而模块化正是本仓库的组织原则。

### 用 TOML 或引入一个专门的文案库

消息文件用 TOML，或引入一个提供复数、性别等能力的文案库。

**否决**：本需求不止「键到字符串、支持插值」——一条消息还要按语言选择复数分支、按语言格式化数字，这些能力与它们的写法由 [ADR-i18n-message-rendering-2026-10-13](adr-i18n-message-rendering-2026-10-13.md) 定；但它们由已在本能力目录闭包内的 `golang.org/x/text` 提供，目录格式仍是标准库可解析、与 `embed` 天然配合的 JSON，`html/template` 与 `text/template` 能承担插值，不必为一个专门的文案库引入新依赖。

### 从磁盘运行期加载文案

启动时从磁盘目录读消息文件，不从二进制内嵌。

**否决**：模块的文案就此与模块分离，同一份二进制在任一部署下都可能缺文案；运行期加载还引出文件监视、缓存失效与多副本一致性面。热改也由此被拒（[ADR-i18n-scope-2026-10-13](adr-i18n-scope-2026-10-13.md)）。

### 内嵌声明是主体来源，另并入一个可配置的覆盖目录

模块仍以内嵌声明为文案的主体来源，另有一个配置项指定的目录，装配期读取并入其后。

**采纳**，见决策。

## 决策

采纳：每个模块经 `core.Resources[i18n.Catalog]` 声明自己的消息目录，格式是「一个语言一个文件」的 JSON，文件名为 `locales/{tag}.json`，放在模块自己的 `embed.FS` 上。这是模块文案的主体来源。

引擎收集全部声明，取可用集（遍历全部已登记模块的声明，不按启用结果过滤），把各文件合并成一个按语言、按键索引的表。一个键归声明它的那个模块，键以模块名起首命名，使两个模块不会撞在一个键上。

配置项 `i18n.catalogs-dir` 另行指定一个目录，与声明同形：一个语言一个 `{tag}.json`，文件名是语言，正文是键到消息的 JSON 对象。它由运维设定，未设定时为空。设定后，引擎在装配期读取它，读出的条目并入同一索引，排在全部已声明目录之后：同一个键上覆盖目录胜过声明，一个声明没有承载的语言因此进入受支持语言集与协商匹配器。

启动期校验：每份内嵌文件是合法 JSON；跨模块没有同名键冲突；配置的默认语言在合并后的索引里至少有一份条目——这一项在并入覆盖目录之后判，因而覆盖目录可以补上默认语言；覆盖目录里某份文件不是一个合法目录时，启动失败并点名该目录与该文件。任一不满足即终止启动。受支持语言集是合并后索引所承载语言的并集，代码不枚举它（[ADR-i18n-language-set-2026-10-13](adr-i18n-language-set-2026-10-13.md)）。运行期没有热加载接口：两个来源都在装配期读取，此后索引只读。

**采纳的形态与「从磁盘运行期加载文案」的区别在范围与时机**：内嵌声明仍是每个模块文案的主体来源，磁盘只补一层覆盖，不替换它；覆盖目录在装配期读取，不被重新读取、不被监视，运行期没有热加载；一份读不出来的覆盖文件终止启动并点名，而不是被跳过。

## 后果

模块的文案与模块在一起，增删模块不动覆盖目录；引擎是唯一的合并点，各消费方看到同一个索引。覆盖目录让一个部署在不改二进制的前提下调整文案，读取即定型，运行路径对文本、计数、复数与数字仍是无锁、零 IO 的内存读；时间段是唯一一处读文件系统的渲染——渲染一条带时间段的消息、且该时区名第一次出现时，引擎经一把互斥锁读一次 zoneinfo（[ADR-i18n-message-rendering-2026-10-13](adr-i18n-message-rendering-2026-10-13.md)）。

一个键只在声明它的模块里定义，读一个键的来源可以从键名读出模块。

**接受的代价：**

- 配置的默认语言的覆盖是启动硬约束。合并后的索引若没有任何一份默认语言的条目，整个进程起不来；换来的是运行期不会静默回退到另一语言。
- 覆盖目录里一条错拼的路径读作「没有额外文案」，不产生任何失败信号：宿主以为覆盖已生效，实际按声明的文案渲染，两处都不报错。
- 改一处覆盖文件要重启进程才生效；这是不做热加载的直接结果（[ADR-i18n-scope-2026-10-13](adr-i18n-scope-2026-10-13.md)）。改一处内嵌文案仍要重新编译并发布。
- 键冲突与缺配置的默认语言的校验在启动期做，不在编译期做；两个都声明了同一键的二进制能编译成功，要到启动才失败。
- 每份 JSON 的合法性与键形状由引擎在启动时检查，模块自身在编译期得不到这个保证；一个模块的目录写错，发现点在装配它的宿主的启动，而不是它自己的构建。

## 失效条件

若必须由运行期数据决定文案，且不重启即生效——例如按租户自定义消息——则「文案在装配期读取后只读」不再成立，本记录要改为区分装配期来源与运行期来源，并另立那份运行期数据的取材与校验。运行期热改本身仍被拒（[ADR-i18n-scope-2026-10-13](adr-i18n-scope-2026-10-13.md)）。
