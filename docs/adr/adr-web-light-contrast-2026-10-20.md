# 浅色模式的 warning、info 与 success 取 700 调，使 main 同时满足文字与填充两种读法

## 状态

已接受

## 背景

语义角色的 `main` 在界面上有两种读法：填充控件与状态标签把它当底色，文字取 `contrastText`；提示与状态文案（MUI Alert 等）则直接把 `main` 当文字色。WCAG 2.1 AA 对两种读法都要求普通文本 4.5:1。

原来的浅色取值只照顾了第一种：warning `#D97706`、info `#0284C7`、success `#16A34A` 上的白色文字分别为 3.19:1、4.10:1、3.30:1。把 `contrastText` 改为 `neutral[950]` 修好了填充标签，但同一个 `main` 作为文字落在浅色表面上仍只有同样的比值，提示与状态文案因此不达标。

深色模式的 `contrastText` 由主题工厂从中性色阶 900 派生、`main` 取角色的 `light` 调，两种读法都已满足要求；问题只在浅色模式。

## 考虑过的选项

### 保留原 `main`，只把 `contrastText` 改为深色

**否决**：只修好了填充标签。`main` 作为文字落在 `background.default`、`background.paper` 与 header 表面上仍低于 4.5:1，而提示与状态文案正是这样使用它。

### 保留原 `main`，把相关文字改用角色的 `dark` 调

**否决**：提示与状态文案的取值由 MUI 组件读 `main` 决定，逐组件改色会把同一个语义角色拆成两处取值，两处随后漂移；角色的 `dark` 调也不是为文字准备的。

### 把文字放大大字号阈值

**否决**：提示与状态标签是普通字号，不能以「大字号阈值更低」为前提；放大会改变控件密度。

### 三个角色取 700 调，`contrastText` 统一为白色

**采纳**，见决策。

## 决策

采纳：**浅色模式下 warning、info、success 的 `main` 取各自的 700 调（`#B45309`、`#0369A1`、`#15803D`），`contrastText` 为白色，`dark` 调依次为 `#92400E`、`#075985`、`#166534`；深色模式不变。**

- 白色在这三个 `main` 上分别为 5.02:1、5.90:1、5.02:1；同一 `main` 作为文字落在浅色表面上也是同一比值，两种读法同时满足 4.5:1。
- 六个语义角色在浅色模式下统一使用白色 `contrastText`，填充控件的文字颜色不再按角色而不同。
- 冒充横幅使用 `warning.main` 作底、`warning.contrastText` 作文字，两者由同一角色保证对比度。
- 对比度测试逐个预设、逐个角色、逐种模式地测两种读法：正文与角色文字对表面，填充标签对底色。

## 后果

- warning、info、success 的填充色比原来深一档，白色文字的视觉重量随之改变；三者作为文字时比原取值更清晰。
- 项目若覆写这三个角色的 `main`，必须同时核对两种读法：白色 `contrastText` 与 `main` 作文字对浅色表面的对比度。
- 深色模式不受影响，仍由 `roleOptions` 从角色的 `light` 调与中性色阶派生。

## 失效条件

- 品牌要求这三个角色回到更浅的调：需要把「文字读法」从 `main` 上拆出来（例如独立的文字 token），重新裁定。
- MUI 改变提示组件读取的角色槽：本决策对两种读法同时成立的前提消失，重新评估。
