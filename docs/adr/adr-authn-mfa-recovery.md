# 没有恢复码时的找回途径与接受的代价

## 背景

多因素的因素种类、登记簿与保障等级的合成由 `authn.mfa` 承载（[ADR-authn-mfa](adr-authn-mfa.md)）。账户一旦登记了因素，登录就必须通过该账户的第二因素，没有“记住这台设备”。因素丢失之后，账户主人需要一条回到可登录状态的路径，而这条路径本身是对强因素的一次绕过机会，决定了多因素的实际强度。

以下约束同时成立。

**不含恢复码。** 恢复码不在 authn 的范围内。

**邮件通道只承载证明，不承载登录。** 邮箱标识经 IdP 或管理员断言成为标识，或由本人经已认证的自助界面发码到地址，兑现后写入；匿名口令重置也用同一类验证码投递。不存在邮件链接登录（[ADR-authn-accounts](adr-authn-accounts.md)、[ADR-authn-selfservice-identifier](adr-authn-selfservice-identifier.md)）。

**两种情形会把真用户挡在门外。** 账户只有与第一因素同种类的因素时，登录无法完成；首次登记因素是信任首次使用，被抢先登记时真用户无法通过不属于自己的因素。两种情形的判据与后果由 [ADR-authn-mfa](adr-authn-mfa.md) 承载，出路都是把因素清掉的路径。

**重置他人因素是最高权限的动作之一。** 它一旦能绕过第一因素，就成为账户接管的原语；一旦不留审计，就无从事后追责。授权的判定不在 authn 内，由宿主经 `Decider` 提供（[ADR-authn-decision-seam](adr-authn-decision-seam.md)）；冒充是另一种有期限、受结构性限制的机制（[ADR-authn-impersonation](adr-authn-impersonation.md)）。

**忘记口令与丢失因素是两件事。** 口令的重置路径与因素的重置路径需要分别说明，且二者都不得给出免于第一因素的登录。

## 考虑过的选项

### 恢复码

登记因素时发放一组一次性恢复码，因素丢失时凭码登录或重置。

**否决**：恢复码不属于 authn 的范围。采纳意味着引入一种与因素并列的凭据：它有自己的生成、哈希存放、一次性消耗与重新生成的流程和表，持码者在不持有任何因素的情况下即可通过第二因素的要求，其强度取决于用户对一张纸或一个文件的保管。这笔复杂度与新增的攻击面超出 authn 的范围，缺口改由下文的找回途径与接受的代价承担。

### 用短信或邮箱找回 TOTP 与 WebAuthn

因素丢失时向账户已验证的手机或邮箱发送一次性码，凭码清除因素。

**否决**：对强因素的降级。攻击者只要拿下短信（SIM 劫持、号码携转）或邮箱，就绕开 TOTP（[REF-rfc6238](../references.md)）与 WebAuthn（[REF-webauthn](../references.md)），多因素的实际强度降为所用找回通道的强度。本条否决的是**清除因素**；它不否决用已验证的联系方式重置口令，后者不解除任何因素（见决策）。

### 管理员重置之后直接登录

管理员重置因素时一并放行，使账户主人免过第一因素直接得到会话。

**否决**：重置成为登录绕过。持有管理员发起权限的一方，或骗过管理员的社会工程者，一步就得到账户的会话。保持“重置之后仍要先过第一因素，再登记新因素”，使重置只解除第二因素的阻塞，不产生任何凭据。

### 借冒充接口完成重置

管理员冒充账户主人，以其身份登记新因素。

**否决**：冒充期间登记因素本来就属于被冒充账户的自助界面，因此“冒充之后登记一个因素”不是重置的实现：它留下的是一次账户自助类的因素写入，没有重置动作自己的平台域判定与审计行，事后答不出“谁重置了这个账户的第二因素”。重置功能走自己的判定动作与自己的审计；冒充登记的审计记发起者并带被冒充账户，两者不能互相替代。

### 重置只要求 `Decider` 放行

管理员重置因素只经 `Decider` 判定，不对发起者另设认证强度要求。

**否决**：`Decider` 的实现由宿主写，质量不可控；发起者的会话若被盗，一次放行就能清掉他人的因素。对发起者的认证强度要求写进 authn 的结构性检查（要求的内容见 [ADR-authn-mfa](adr-authn-mfa.md)），`Decider` 只能在其上进一步收紧。

### 不提供管理员路径，丢失因素即联系运维改库

authn 只提供冗余因素，其余一律由运维处理。

**否决**：每一次因素丢失与每一次抢先登记都要有人手工改库，改库不留 authn 层面的审计与事件，也不撤销会话。管理员路径把这类事件收进有判定、有审计、有事件的接口；改库只留作最后手段。

### 匿名口令重置

忘记口令的人凭账户已证明的邮箱或手机收到一次性码，提交正确的码后设定新口令，不经过任何已认证会话。

**采纳**，边界见决策。它不是因素找回：账户已登记的因素一个也不清除，重置之后的下一次登录仍要先过第一因素，再按账户原来的要求过第二因素。它的重置依据是账户本人曾经兑现过的那一条联系方式，而不是管理员的判断。

### 把重置做成登录流程的一个目的

在既有 `POST /auth/flows` 的流程目的闭集里增加 `reset`，复用流程记录、`/flows/answer` 与登录流程的绑定 cookie。

**否决**：登录流程目的闭集是登录方法、账户解析、终态动作与第三方方法共同依赖的契约；重置既不建立会话，也不走第一因素证明，塞进同一台状态机要求解析与终态为它开分支，还让重置绑定与登录绑定共用一枚 cookie：同一浏览器里开始一次登录会覆盖进行中的重置。重置是一条独立动作，配独立的路由、独立的绑定与独立的记录（见 [design-authn-login](../design/modules/authn/design-authn-login.md)）。

## 决策

**找回途径是封闭集：多因素冗余、匿名口令重置、管理员重置因素、管理员重置口令、运维接口。** 各条依赖的外部判断不同；排列顺序即使用顺序，靠前的不可用时才退到靠后的。

- **多因素冗余。** 账户登记了不止一种因素时，丢失一种之后用另一种做加强认证，撤销丢失的因素并重新登记。不依赖任何外部判断，是唯一不经第三方的路径。
- **匿名口令重置。** 依赖账户本人对一条已证明联系方式的控制。账户必须处于启用状态、是用户账户、持有口令凭据；提交的邮箱或手机必须是该账户的标识，且该标识的证明渠道是本人兑现过的验证码（邮箱为 `email-code`，手机为 `sms-code`）。IdP 断言的邮箱、邀请带来的证明、管理员断言、未证明预留与本人断言都不作为重置依据。渠道由用户选择：同一个账户同时有已证明邮箱与已证明手机时，两条都可走；只有其中一条时，只有那条可走。
- **管理员重置因素**（`MFA.Reset`）。依赖宿主经 `Decider` 给出的判定、发起者的强认证与强制档审计。用于因素丢失而没有冗余可用的账户，以及被抢先登记的账户。
- **管理员重置口令。** 依赖的外部判断与管理员重置因素相同。用于组织内的口令找回，也是只有口令登录名、由管理员创建的账户的唯一重置路径。这条解决的是口令而不是因素丢失。
- **运维接口。** 宿主的命令直接调用 `MFA.Reset` 与 `Passwords.Set`，不经 `Decider`，是最后手段，用于没有可用管理员的情形。强度完全取决于宿主对命令的访问控制。

**匿名口令重置的判据如下，全部成立才允许：**

- **只认本人兑现过的验证码。** 邮箱必须由 `email-code` 证明，手机必须由 `sms-code` 证明；其他来源一律不算，未证明的地址与号码无法被提交命中。
- **不产生会话、不建立登录。** 完成只写新口令并结束该账户既有的全部 browser 与 token 会话，不签发任何凭据；重置之后的下一次登录从头开始，先过第一因素，再按账户原来的要求过第二因素。
- **不触碰因素。** 因素行、`mfa_required` 与因素的启用时长都不改变；重置不解除、不降级、不重新登记任何因素。
- **只替换已存在的凭据。** 没有口令凭据的账户不能借此设置首个口令；这类账户经其现有的登录方式进入账户设置后设置口令。
- **应答一致。** 合格目标与不合格目标（不存在、未证明、停用、删除、无口令）得到同一个状态码、同一个响应体与同一组响应头；真实差异只有申请者自己的收件箱或手机是否收到消息。验证码错误、过期、被抑制与不存在同样答以一个拒绝。
- **发送有门槛。** 每次发送先过部署的人机验证门槛，再受预算与每码尝试上限约束。
- **写入前必须留痕。** 每次成功的匿名口令重置在写口令之前写一条强制档审计；审计写不成就不写口令。
- **默认关闭。** 部署以设置显式打开该能力。

**下列判据是封闭集，对上述每一条路径都成立：** 不以短信或邮箱清除或降级因素；不产生免于第一因素的登录；重置他人凭据的动作必须有成功的审计；重置功能不借道冒充（冒充期间登记因素属于被冒充账户的自助界面，审计记发起者并带被冒充账户，不算一次重置）。

**账户只有一个因素又没有可用管理员时，丢失该因素即不可自助找回。** 这一后果写成接受的代价，不为它增设别的自助通道。

## 后果

- 因素丢失的恢复强度由最弱的一条可用路径决定，而不是由最强的因素决定。冗余路径不引入新的凭据；管理员路径的强度由发起者的强认证要求、`Decider` 与审计共同给出；运维接口不经 `Decider`，强度取决于宿主。
- 管理员重置不绕过第一因素，重置之后只能登记新因素，因此被盗的管理员会话换不到账户主人的会话。
- 重置因素与重置口令都撤销该账户的全部会话，账户主人在重置后的下一次登录从头开始。匿名口令重置还在写口令的同一事务里推进账户的 `valid_after`，使其他副本上的旧会话在会话状态缓存过期后也失效。目标的 bearer（[REF-rfc6750](../references.md)）冒充令牌按 `valid_after` 失效，发起者的 cookie 冒充会话继续有效：同一次重置对两种冒充方式结果不同。
- 找回途径不依赖邮件链接登录；邮件只投递验证码。
- 匿名口令重置把“控制一条已证明的邮箱或手机”变成“可以改这个账户的口令”。对登记了第二因素的账户，攻击者仍拿不到会话；对没有第二因素的账户，这等于账户接管。这是选择可自助找回而不是把用户挡在门外所付的价。
- 只有用户名、没有任何已证明邮箱或手机的账户没有自助找回路径；由管理员重置口令或运维接口兜底。
- 邮箱仅由 IdP 断言而未由本人兑现验证码的账户不能匿名口令重置；账户主人需先在账户设置里证明该地址，或由管理员重置。
- 审计不可用时匿名口令重置不可用：强制档审计写成功之前不写口令，且发现端点不发布该能力。

**接受的代价：**

- 只有一个因素又没有可用管理员的账户，丢失该因素即无法自助找回，只能由运维直接改库，改库不留 authn 层面的审计与事件。
- 管理员重置是找回链上最弱的一环：确认来求助者身份的核验在 authn 之外，社会工程可以骗过它。authn 只提供判定接口、发起者的强认证要求、审计与事件，不替宿主核验。
- 被抢先登记或只有同种类因素的账户，真用户只能靠管理员重置；运维靠日志与事件发现这类账户。
- 匿名口令重置之外没有别的兜底：不愿或无法依赖管理员的账户，登记两种以上的因素是唯一的自我保障。
- 对单因素账户的提示只是建议，不阻止用户停留在单因素。
- 匿名口令重置只解决口令，不解决因素丢失；同时丢失口令与唯一强因素的账户仍走管理员或运维。
- 重置渠道的强度就是这次改口令的强度：邮箱被攻陷、号码被回收或 SIM 被劫持时，持有该渠道的人可以改口令。第二因素保护的是登录，不是改凭据这一动作。
- `verified_via` 是写入方自报的标签；持有 `AccountAdmin` 的宿主命令与管理面可以写 `email-code` 或 `sms-code`。它们本就能直接重置口令，因此不构成新的提权；匿名口令重置的资格承诺只对没有管理权限的调用方成立。
- 关闭该能力的部署没有匿名口令重置；打开是一次显式的放宽，经设置变更可见。

## 失效条件

- 范围改为含恢复码：本记录对恢复码的否决失效，找回途径要加一条自助路径，并重新评估其对强因素的降级程度。
- 部署中出现因素丢失而无管理员可用的账户成为常态：说明“接受的代价”超出了可承受的范围，需要在管理员之外增设有判定、有审计的受托途径。
- 匿名口令重置的滥用超出预算与人机验证的约束，或被用来定向锁死他人：收紧到“重置时另过一个与重置标识不同的已启用因素”，或关闭该能力。
- 对高权限账户，仅凭邮箱或短信改口令被认为不可接受：按账户类别收窄资格，或对这类账户要求因素步。
- 假设：发起者的强认证要求与 `MFA.Seasoned` 能使抢先登记者得不到发起重置的资格。守住它的测试要求：登录期间登记的因素不能满足发起要求，启用未满 `sensitive-min-age` 的因素不能满足 `MFA.Seasoned`，静态口令表主体与冒充中的会话被拒绝。
- 假设：审计写失败时重置不执行。守住它的测试要求：注入审计写失败，断言账户的因素与会话保持原状。
- 假设：重置因素之后的下一次登录仍要先过第一因素。守住它的测试要求：重置完成后不存在由重置本身产生的会话，缺少第一因素的登录尝试在重置之后仍然失败。
- 假设：重置口令之后的下一次登录仍要过该账户的第二因素。守住它的测试要求：对有已启用因素的账户完成一次匿名口令重置，断言登录仍停在第二因素。
