# 一个 Go module 承载全部功能，功能按包划分

## 背景

speed 以库的形式交付：宿主通过 `go get` 引入所需的包，编译进自己的二进制。

宿主的依赖面由它 import 的包决定。Go 的模块图裁剪按 import 路径可达性计算，在包粒度生效，且与提供它的包位于哪一个 Go module 无关。一个包没有进入宿主的 import 闭包，它绑定的第三方库就不进入宿主的 `go.mod`；被 import 包的测试闭包所及的实现子包，其绑定的库则会进入宿主的 `go.sum` 并在 `go mod tidy` 期间被拉取——被 import 包的测试文件 import 了实现子包或测试夹具，`go mod tidy` 把这一层计入。读整图的操作则会看到全部实现所绑的库。

同一种功能通常有多种实现，各自绑定不同的第三方库。键值功能的内存实现无外部依赖，Redis 实现需要 Redis 客户端库。只使用内存实现的宿主不必在 `go.mod` 里背负 Redis 客户端。

Go module 是版本与发布的粒度：一个 Go module 一条版本序列，序列里任一处的改动都抬升它对全部使用者的版本下限。

## 考虑过的选项

### 每种功能一个独立 Go module，实现为其子包

`pkg/<功能>` 是一个 Go module，根包承载该功能的接口，绑定具体后端与驱动的实现位于其子包。

**否决**：依赖清单那一面的隔离已经由包粒度达成——宿主 import 一个包时，未被 import 的兄弟实现所绑的库不进它的 `go.mod`；`go.sum` 与实际下载仍会经被 import 包的测试闭包带上这些库，拆成独立 Go module 也不改变这一面，因而在此之上不增加隔离效果。它带来的是每个 Go module 各持一份 `go.mod` 与 `go.sum`，跨 Go module 的引用要经 `replace` 或版本协调；版本序列的数量随功能数增长，而这一点只在某个功能确实需要独立发版时才是收益。

### 每种实现各自独立 Go module

功能与实现都是 Go module，`pkg/kv` 与 `pkg/kv-redis` 平级。

**否决**：与上一条同源。隔离由包粒度达成之后，独立 Go module 在 `go.mod`、`go.sum` 与实际下载上不带来额外隔离，却为每一个实现再付一份 `go.mod`、跨 Go module 引用与版本协调的成本，版本序列的数量随实现数量增长。

### 一个 Go module 承载全部功能，功能按包划分

`pkg` 是一个 Go module；其下每个目录是一个包。功能目录的根包承载该功能的接口与公共逻辑，绑定具体后端与驱动的实现位于其子包，导入路径形如 `github.com/vislake/speed/pkg/<目录>/...`。

**采纳**，见决策。

## 决策

采纳：`pkg` 是一个 Go module，全部功能在其中按包划分。功能目录的根包承载该功能的接口与公共逻辑，实现位于子包并各自绑定自己的第三方库；仓库内的包相互引用是同一个 Go module 内的引用，不经版本协调。

## 后果

宿主的 `go.mod` 由它 import 的包精确决定：未被 import 的实现子包所绑定的第三方库不进入它，新增一种实现也不因此改变既有消费者的 `go.mod`。宿主的 `go.sum` 与实际下载则会经被 import 包的测试闭包带上同一 module 内其他实现子包所绑的库——被 import 包的测试文件 import 了实现子包或测试夹具，`go mod tidy` 把这一层计入。读整图的操作会看到全部实现所绑的库（见下条代价）。

仓库只有一份 `go.mod` 与一份 `go.sum`，包之间的引用不经版本联动，Go 的模块图不随功能数增长。

**接受的代价：**

- **Go 的完整模块图被放大。** 读取整图的操作——`go list -m all`、`go mod download all`，以及按整图取数的依赖扫描——会看到全部实现的第三方依赖，即便其中没有一个被 import。按 import 闭包取数的操作不受影响。
- **依赖预算只能在包上判。** 这个 Go module 的 require 声明是全部实现的并集，无法再用它表达某一个包的预算；约束一个包不引入某类依赖的检查，判据落在那个包的 import 面上。
- **版本粒度是仓库一个。** 任一处的改动都抬升整条版本序列对全部使用者的下限，消费者不能只取某个功能的补丁而不取其余改动。
- 子包边界没有编译器强制：把某个实现的驱动误写进功能目录的根包，编译不会报错，只能由评审与依赖面检查发现。

## 失效条件

若某个功能的消费者要求脱离其余功能单独引入，或该功能的发布节奏必须独立，则把它拆为独立 Go module：目录边界已经就位，拆分是为它加一份 `go.mod` 与一条版本序列。本记录对那个功能不再适用。
