# 审计的存在与覆盖面是装配的结果，不是框架的承诺

## 背景

语句级、事件级与请求级都依赖装配里别的模块在场：分别依赖数据库模块、事件总线、入口模块与两个排在它之外的层。数据库模块已经裁定，插件这一消费点的取材域是启用集，一个只声明插件、自己不访问库的模块被禁用时，它提供的那项横切能力静默消失（[ADR-db-plugin-scope](adr-db-plugin-scope.md)）。租户模块把同形的结论写成了非保证（[ADR-tenant-guarantees](adr-tenant-guarantees.md)）。

## 考虑过的选项

### 把「发生过的事都留下了痕」写成保证

**否决**：保证要能被判据检验，而「所有该记录的事」的集合不在本模块手里——它取决于配置点了哪些类型与哪些请求、哪些模块被装配、发布方是否真的发布了。写一条验不了的保证比不写更坏。

### 缺少任一条依赖即启动失败

**否决**：这让审计成为入口模块与事件总线的强制依赖，与「功能缺席是合法配置」冲突，也让只想在请求路径上留痕的宿主被迫装配一条事件后端。

### 写成非保证，随装配与配置变化，并给出察觉途径

**采纳**，见决策。

## 决策

采纳：**审计的存在与覆盖面是装配与配置的结果，不是框架的承诺。**

- 本模块未被纳入、也没有预置实例，或被禁用时，各条通路都不存在；没有任何一层会拦下，也没有诊断行说明「本可以审计而没审」。宿主预置的数据库实例出自一次收取了捕获插件的 `New` 时是例外：语句级捕获在它的句柄上照样生效（[ADR-db-supplied-instance-refusal](adr-db-supplied-instance-refusal.md)）。
- 本模块的两条构造期依赖缺席是另一回事：那是依赖解析失败，进程不启动，不是静默缺一条通路。
- 本模块的实例是本模块的产物时，配置点名的类型名与请求决定事件级与请求级的覆盖面；语句级与接缝级随装配生效，没有开关。语句级的捕获装在数据库模块的 `New` 构造的句柄上，宿主预置的数据库实例若不是这样构造的，在数据库模块的 `Migrate` 被拒收（[ADR-db-supplied-instance-refusal](adr-db-supplied-instance-refusal.md)）；预置的实例落在拒收管不到的情形里时——在拒收之前就被取用，或出自一次没有装捕获插件的 `New`——语句级捕获在它的句柄上缺席，同样没有任何一层拦下。
- 请求级与事件级记录缺失的察觉途径是本模块另报的信号，不是审计面本身；语句级那条的缺失就是那条语句的失败，调用方看得见。

## 后果

一个宿主可以只装配审计的一部分通路，并按自己的配置决定覆盖面。

**接受的代价：**

- **缺失不可见。** 装配里少了审计，与审计在场而什么都没记，从审计面看不出区别，两者都不进启动诊断。
- **语句级与接缝级有关不掉的一档。** 两者随装配生效，一个只想在请求路径上留痕的宿主仍然得到全部写语句的捕获。
- **覆盖面的正确性要宿主自己验。** 配置写错一个类型名，与发布方改了类型名，表现相同。
- **宿主为本模块预置外来的实例时，请求级与事件级通路不存在，注册表却答本模块在场。** 本模块的回调对不是本模块产物的实例不做任何事：不登记请求级捕获层，不订阅配置点名的类型，本模块那份配置不被读取，配置点名不起作用，本模块另报的信号也不存在；启用结果与参与结果却都答本模块在场，宿主去问也问不出请求级与事件级通路的缺席。语句级捕获照常，插件由数据库模块按启用集安装，与本模块的实例从哪来无关；接缝级的记录交给那个外来实例，由它自己处置（[ADR-supplied-instance](adr-supplied-instance.md)）。

## 失效条件

若出现一条要求「审计必须存在且覆盖全部写操作」的合规规定，则它要由宿主在自己的装配与配置上保证，本模块给不出这条保证。
