# 模块机制只交付一个库，额外的连接由调用方经接口自建

## 背景

模块之间只按功能取用彼此，不按名称取用（架构不变量 9）。取用一个功能时，`Resolve` 要求恰好一个提供者，多于一个即失败。

数据库功能有多种实现，每种绑定一个方言的驱动。同一个进程 import 了多个实现时，它们都进入可用集。

迁移集由各模块声明，在 `Migrate` 阶段统一应用（[ADR-db-migration](adr-db-migration.md)）。一条迁移要施加到某个库上。

访问第二个库是真实需求：读写分离的只读副本、另一个系统的库、一次性的数据迁移来源。这些库与本进程的模块装配无关——没有模块声明它们的迁移，也没有模块需要把它们当作自己的依赖来取用。

## 考虑过的选项

### 多个库都经模块机制交付

多个实现同时启用，取用方用 `ResolveAll` 整体取出后按名路由，名字由功能接口自己提供。

**否决**：按名路由正是架构不变量 9 排除的取用方式，而多库没有别的区分手段——依赖声明落在功能上，表达不了「依赖其中某一个」。迁移随之要回答每一条施加到哪个库，迁移资源因此要带目标库标识，而标识的取值同样只能是名字。整个装配接口从「取用一种功能」退化为「取用一个具名实例」。

### 一个进程只连一个库，不提供别的途径

数据库功能排他交付，此外没有建立连接的手段。

**否决**：访问第二个库的需求不会因此消失，只会转移——调用方自己 import 驱动去连，而那样得到的连接不带本模块安装的任何插件，也不带加密序列化器，且脱离任何生命周期管理。把一个真实需求堵在模块之外，换来的是一条没人看得见的旁路。

### 自建连接的定位符原样交给驱动，空白值由驱动解释

`Open` 收到的定位符为空白时，本模块不加规则，照驱动的行为落地，以便调用方能用空串故意开一个临时库。

**否决**：空白串在两个驱动那里都不是「没有库」。PostgreSQL 的驱动用进程环境里的 `PG*` 变量、本机套接字与进程用户补全它，连上的是环境指向的那个库，一个留空的副本定位符就这样连到了别处；`glebarez/sqlite`（[REF-glebarez-sqlite](../references.md)）为池里的每条连接各开一个临时库，一条连接上建的表在另一条上不存在，「故意开一个临时库」这个用法在连接池下并不成立。两种结果都是拿着可用句柄、连着一个没人点名的库，全程不报错。

### 自建连接的空白定位符判为失败

`Open` 收到的定位符为空白时判 `ErrConnectFailed`，与交付侧「没有连接信息即启动失败」的口径一致。

**采纳**，见决策。要一个临时库的调用方写出它，例如 SQLite 的 `:memory:`。

### 模块机制只交付一个库，额外的连接经接口自建

数据库功能仍然排他交付，经模块机制交付的库只有一个；需要另一个库的调用方从交付的实例上自建连接。

**采纳**，见决策。

## 决策

采纳：数据库功能排他交付，经模块机制交付的库只有一个——配置给出的那个，或宿主为数据库实现预置的那个实例；额外的连接由调用方从该实例自建。

命令树点名多于一个实现而它们都表态启用时，消解阶段判为 `ErrExclusiveViolated`，启动终止。只被 import、既不被点名也没有预置实例的实现不进参与集，不构造、不表态（[ADR-supplied-instance](adr-supplied-instance.md)）。

从数据库模块自己构造的实例自建的连接，与交付的那个装配一致：同样装好已声明的插件与加密序列化器，取用方因而不会因为换了个库就失去这些。宿主预置的实例若不是数据库模块构造的，在 `Migrate` 被拒收（[ADR-db-supplied-instance-refusal](adr-db-supplied-instance-refusal.md)）；拒收之前，从这样的实例自建的连接怎样装配，取决于预置的一方（[ADR-supplied-instance](adr-supplied-instance.md)）。自建的连接不施加任何迁移，也不由本模块持有——调用方自己关闭它。

自建连接的定位符与交付侧的 `dsn` 服从同一条规则：一个连接必须说得出它连的是哪个库。交付侧的 `dsn` 缺失或空白即启动失败，错误点名该输入项；宿主预置了实例时，数据库模块的 `Prepare` 不执行，不做这项检查，也不用 `dsn` 建立连接；`Open` 收到空白定位符判 `ErrConnectFailed`。

## 后果

取用数据库功能的模块拿到唯一的实例，不需要区分取到的是哪一个。

迁移集有唯一归宿：一条迁移施加到经模块机制交付的那个库上——配置给出的，或宿主预置的——迁移资源不需要携带目标库标识。

读写分离、访问另一个系统的库、一次性的数据来源，都有一条在模块之内的途径，不必绕过本模块自己 import 驱动。

冲突暴露在消解阶段，不留到取用时。

**接受的代价：**

- 自建连接的生命周期由调用方负责。漏关就是连接泄漏，本模块不持有它们，也就无从代为释放。
- 自建连接的库，其 schema 由调用方保证。迁移机制只覆盖经模块机制交付的那个库，第二个库上缺表的表现是运行期的查询失败。
- 自建连接的方言与被启用的实现相同。连接另一种引擎的库，要求那个引擎的实现也被启用，而排他不允许。
- 自建的连接不出现在任何声明里。谁连了哪些库，从描述符看不出来，只能从代码里看。
- 依赖驱动对空白定位符自有解释的用法——用 `PG*` 环境变量指定库、用空串开 SQLite 临时库——不再可用，调用方要把定位符写出来。

## 失效条件

若出现一种部署形态，其第二个库同样需要迁移、需要参与依赖定序、或需要被别的模块按功能取用，则「额外连接在模块机制之外」不再成立，多库需要重新进入装配范围。
