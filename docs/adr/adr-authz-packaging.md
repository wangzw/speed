# 打包：根包只放接口与常量，策略、强制点、管理面各为一个叶子模块

## 背景

宿主的依赖面由它 import 的包决定，登记随 import 发生——import 一个包即执行它的 `init`，该包登记的模块随之进入可用集（[ADR-module-layout](adr-module-layout.md)、[ADR-module-registration](adr-module-registration.md)）。一个包所绑的第三方库只有 import 它的宿主才背负；被每个使用方 import 的根包，其 import 随之进入全部使用方的依赖闭包。

授权的各项交付依赖闭包不同：策略引擎经数据库模块读写自己的表，绑定 Casbin（[REF-casbin](../references.md)）引擎；请求路径上的强制点落在入口模块的授权阶段，读租户上下文；管理面 HTTP 路由落在入口模块，取用策略模块的 `Manager` 与 `Catalog`。判定接口、权限常量与模型文本要被这几处与读取权限的代码共用。

`authn` 功能目录的先例是根包只放接口、一个功能一个叶子包一个模块，判据是依赖闭包（[ADR-authn-packaging](adr-authn-packaging.md)）。把一个交付拆成独立 Go module 的判据是「该功能自身需要独立发布节奏」（[ADR-module-layout](adr-module-layout.md)）。

## 考虑过的选项

### 一个包一个模块，承载全部交付

采纳它意味着 `pkg/authz` 单包登记一个模块，接口、引擎、中间件与管理面都在这一个包内。

**否决**：各项交付的依赖闭包不同。只装管理面的命令、或只要强制点而不写策略的命令，都会被拉进策略引擎所绑的 Casbin 与数据库模块；一个模块只有一份 `Requires`、一个配置命名空间与一次表态，任一项交付的必填配置缺失即整个模块启动失败。

### 根包即实现并登记

采纳它意味着 `pkg/authz` 根包既定义接口与常量，又登记模块并实现引擎。

**否决**：根包被每个使用方 import——强制点、管理面与将来读取权限常量的业务代码都 import 它。根包登记模块，这些 import 就都把一个策略引擎（连同数据库模块与 Casbin）带进可用集，「本二进制有没有策略引擎」不再由宿主的 import 决定；根包还要随之占用一个模块名与一个配置命名空间。判据与 [ADR-authn-packaging](adr-authn-packaging.md) 针对 `authn` 根包的同一条相同。

### 把 Decider 实现与中间件拆成两个模块

采纳它意味着强制点拆成「中间件」与「`Decider` 实现」两个模块，各自登记。

**否决**：两者共用同一份路由声明表与同一次租户读取，是同一个判定产品的两个接口面。拆开要把声明表经一个新接口暴露给另一个模块，多一处需要同步的中间契约，且两个模块必须同进同出——单独装一个都不构成可用的强制点。

### 每个叶子功能一个独立 Go module

采纳它意味着 `policy`、`guard`、`admin` 各持一份 `go.mod`。

**否决**：依赖清单那一面的隔离已由包粒度达成，拆成独立 Go module 不在其上再增加隔离，只多出各自的 `go.mod`、跨 Go module 引用的协调与版本序列（[ADR-module-layout](adr-module-layout.md)）；授权的各项交付没有一项要求独立发布节奏。

### 根包只放接口与常量，策略、强制点、管理面各为一个叶子模块

**采纳**，见决策。

## 决策

采纳：`pkg/authz` 根包是接口包，策略、强制点与管理面各为一个叶子子包、各登记一个模块。

- **根包。** 根包定义判定接口、类型、权限常量、模型文本与哨兵，不登记模块，也不导出模块名常量。它被强制点、管理面与读取权限的代码 import，其 import 面因此受限：不 import 第三方库（尤其不 import Casbin），也不 import 实现子包。封闭的非测试 import 集由依赖面测试守住。
- **叶子模块。** 策略（表与迁移、薄适配器、引擎、权限目录、管理接口、账户生命周期）、强制点（中间件、路由声明面、处理函数内 API、实现 `authn.Decider`）、管理面（管理面 HTTP 路由）各为一个模块，模块名取包名。
- **不登记的内部单元。** 内部库包与测试夹具不登记为模块。
- **Decider 的交付方。** `authn.Decider` 由强制点的产品实现，编译期断言它的实现。这一条使「判定接缝的实现在哪里」唯一：装强制点即接入接缝（[ADR-authz-decision-seam](adr-authz-decision-seam.md)）。
- **模块名、配置与设置命名空间、迁移与权限点的落点在设计文档 design-authz 里。**

## 后果

宿主的依赖面按功能裁剪：只要强制点的宿主不背负策略引擎所绑的库；只要策略引擎的宿主不背负入口模块；接口与权限常量经根包共享，不给任何使用方带进第三方库。登记随 import 发生，「本二进制有没有强制点」「有没有策略引擎」由宿主的 import 决定。

**接受的代价：**

- **模块多，宿主在命令树上逐点点名。** 缺哪个模块的后果各异（缺强制点则无请求路径判定、缺策略引擎则判定不可用），每种缺法在运行期的表现不同，宿主必须理解它们的差别。
- **权限常量与判定接口住根包，是各项交付共用的面。** 新增权限常量要与 authn 的动作常量同步（[ADR-authz-decision-seam](adr-authz-decision-seam.md)），改根包的接口是各叶子模块同时受影响的改动。
- **`Decider` 由强制点交付，二者不可分。** 只用策略引擎或只用管理面而不装强制点的装配，接缝缺席即全拒；要交付 `Decider` 就必须装强制点。
- **根包不绑第三方库是一条纸面规则。** 违反它不会编译报错，只会把库带进每个使用方，靠依赖面测试发现。

## 失效条件

- 若授权的某一类交付出现独立发布节奏的需求，把它拆为独立 Go module：目录边界已就位，拆分是为它加一份 `go.mod` 与一条版本序列（[ADR-module-layout](adr-module-layout.md)），本记录对那一类不再适用。
- 若强制点与管理面的依赖闭包在实现中实际合流（二者都落在授权阶段、都取入口模块），拆分的收益要重新评估。
