# 冒充期间由应用壳在应用栏之下显示可隐藏的横幅、外壳常驻 chrome 区里的身份指示并提供结束入口，身份变更按会话边界处理依赖身份的状态

## 背景

冒充开始后，会话的主体是被冒充账户。网关对冒充身份只放行两类请求：准入层所守的端（示范里是租户 `api` 端，限记录租户），与登记为可冒充的路由。authn 自己登记的可冒充路由是封闭集合，含账户自助接口与判定域为该租户的管理面（见 ADR-authn-impersonation 与冒充模块的设计文档 `design-authn-impersonation`）。租户功能目录的本人租户读取也登记为可冒充，应答在 handler 里收窄到冒充授予的那一个租户：它是宿主在整页重载后命名当前租户的名称来源，授予租户之外的成员关系仍不交给冒充者（[tenant](../design/modules/tenant/design-tenant.md) 的“调用方本人的租户读取”）。平台域的管理面两条都不是，被网关拒绝。

在这个前提下：

- **结束入口只在管理后台的冒充页。** 冒充期间管理后台不可达：被冒充的账户不持平台域权限，管理后台入口不出现，访问任何 `/admin/*` 路径都按非员工静默重定向回首页。
- **冒充期间没有全局提示。** 唯一的可见变化是头像缩写。用户菜单没有结束入口，唯一的界面出口是退出登录，会话整个丢掉。
- **管理后台对平台权限集为空者的重定向静默、不带说明。** 管理后台页面集合对非员工不可见（REQ-platform-admin-036）。

另有三件事使问题不止是缺一个按钮：

- 冒充开始与结束都改变此后每个读所属的身份，查询缓存里的每一行都是在另一个身份下取的。
- 宿主附上的权限集来自一条调用方自身的读；这条读的主体是生效账户 `Identity.Account()`，冒充期间它是被冒充账户，所以这条读答的是被冒充账户的集合：平台域对它为空，租户域是它在该租户里的集合。而会话恢复保留已附上的集合，不会自己改正它。
- 会话快照不携带“当前在冒充”，会话核心自己不得知开始与结束这两个事件。

## 考虑过的选项

### 保持现状，只在冒充页内放结束入口

**否决**：冒充身份到不了管理后台，冒充页在冒充期间不可再进入，入口随页面一起消失。

### 只在用户菜单里加一条“结束冒充”

**否决**：菜单条目没有持续的可见提示，冒充中的人仍不知道自己处于冒充，要结束得先想到去菜单里找。它给出出口，不回答“现在以谁的身份在操作”。菜单项作为第二个结束入口与持续的可见提示并用，不在此项否决之内。

### 管理后台把被重定向到首页的请求标注原因

**否决**：重定向处的说明只在访问者恰好访问管理后台路径时出现一次，页面加载后就消失；冒充者在租户框架内的每个页面都需要知道自己处于冒充、怎么结束，这由横幅与外壳常驻 chrome 区里的身份指示承担。管理后台对非员工的同一个重定向一旦对冒充身份带说明，就在管理后台区引入第二种落点，而这两处已经覆盖冒充者的需要；这个重定向必须保持静默，否则非员工能据此得知管理后台存在。

### 让冒充期间的管理后台继续可用

**否决**：管理后台的入口与页面由生效账户的权限集决定，被冒充的账户从不持有平台域权限，冒充者进得去也只是无处可去。管理后台页面会落到失败占位或陈旧提示，重试永远失败，冒充者读不出原因。

### 由管理后台的页面库自带横幅

**否决**：管理后台页面库只在管理后台区渲染，冒充期间管理后台区不可达；横幅要在租户框架内的每个页面可见，只能属于应用壳。

### 横幅放在应用栏之上，不可隐藏

**否决**：满宽横幅把说明逐句堆叠，在 1280 与 800 宽的视口下实测约 112px 高，占去每个租户页顶部相当一块视口，且冒充者无从收回这块空间。降低高度减轻占用，不可隐藏则占位始终存在。

### 横幅可隐藏，隐藏后不留任何提示

**否决**：隐藏之后冒充者没有任何可见的标记说明自己仍以他人身份操作，也没有结束入口；它把横幅唯一的出口一并藏起，回到“冒充期间没有全局提示”。

### 横幅在应用栏之下并可隐藏，外壳常驻 chrome 区里的身份指示，账户菜单提供结束项

**采纳**，见决策。

## 决策

采纳：**冒充期间，租户框架在应用栏之下显示冒充横幅，说明正在以谁的身份操作，并提供不依赖任何页面的“结束冒充”；横幅可隐藏，隐藏后外壳的常驻 chrome 区里仍有一个常驻的身份指示，它同时是横幅的显示开关，账户菜单里另有“结束冒充”；管理后台的入口与页面由生效账户的权限集决定，被冒充的账户不持平台域权限，管理后台区在冒充期间因此一律静默重定向到租户区首页；开始与结束冒充都是一次身份变更，宿主统一处理依赖身份的状态。**

- 横幅属于应用壳：槽在布局包，展示组件在登录组件族，由宿主挂在租户框架里；管理后台页面库不自带横幅。
- 常驻身份指示位于外壳的 chrome 区：`topbar` 形态在顶栏里，`sidebar` 形态在侧栏纸的顶部行或底部行里；侧栏收起为窄栏时指示仍须可见。
- 横幅的隐藏状态是租户框架里的内存状态，不落任何存储：新一次冒充开始、冒充结束、任一次身份变更与结束尝试失败时复位为显示，整页重载也复位。
- 横幅与账户菜单里的“结束冒充”是同一次结束尝试的两个入口，在途与结果在两处一致。
- 会话快照携带“当前在冒充”，由宿主读会话时得到。
- 身份变更的统一处理覆盖查询缓存、会话快照、宿主附上的权限集、当前租户与实时订阅；管理后台页面库经宿主回调接入同一处理。
- 横幅给出到期时刻时，到期那一刻宿主同样走这一处理，并在服务端尚未回到发起者自己的身份时有界重试。
- 冒充页内的记录区域收起保留，作为页面库自己的行为，不依赖宿主装配。
- 各条款的细节由各包与示范宿主的设计文档给出，本记录不重述。

## 后果

冒充者在租户框架内的任何页面都看得到自己正处于冒充（横幅与外壳常驻 chrome 区里的身份指示至少有一处始终可见），随时能结束，不必靠停留在某个页面、也不必退出整个会话；冒充期间的缓存、权限集、当前租户与实时订阅不会把一个身份下的状态当成另一个身份的。管理后台对非员工保持不可见，重定向仍静默；被冒充的账户不持平台域权限，冒充期间管理后台因此不可达，这是权限判据的结果。权限集必须在身份变更后重读，是因为不重读时冒充期间附上的租户域集合会留到冒充结束之后：那是被冒充账户在冒充记录那个租户里的集合，运营者回到自己的身份后当前租户另行落定，却仍带着冒充记录那个租户的集合（平台域在冒充期间答的是被冒充账户的集合，对它为空）。

**接受的代价：**

- **改动范围跨越多个包。** 布局包、装配壳、会话核心、登录组件族、管理后台页面库与示范宿主各有一处新增。会话快照新增必选字段 `impersonating`：宿主构造的快照字面量与会话替身必须补上它，按不兼容变更登记；其余新增是纯附加，未使用冒充的宿主不受影响。
- **冒充期间管理后台不可达。** 被冒充的账户从不持有平台域权限，管理后台的入口与页面因此都不出现，冒充者要看管理后台得先结束冒充。判据是权限而不是冒充本身；本决定做的是在这一判据下让冒充者仍看得见横幅、随时能结束。
- **横幅的租户只能显示标识。** 租户名册属平台管理面，冒充期间读不到，横幅的租户一项是标识本身，不是可读名。
- **横幅只覆盖租户框架内的页面。** 公开落点页（邀请受理页）渲染在租户框架之外，不挂横幅。
- **横幅隐藏之后，持续的提示降为外壳 chrome 区里的一个身份指示。** 操作者可以收起文字说明，此后只靠一个小标记提醒自己仍以他人身份操作；复位条件与指示的常驻只是缓解，不排除操作者忽视它。
- **结束入口有两处。** 横幅与账户菜单都能结束冒充，在途与失败的状态必须在两处一致；失败文本只落在横幅内，横幅被隐藏时要先复位它，结束尝试因此多一条与隐藏状态相交的路径。
- **`banner` 槽的位置由应用栏之上改为之下。** 槽名不变、位置语义翻转，使用该槽的宿主随之改变版面，按不兼容变更登记。
- **到期之后最长晚一个校验缓存期才回到发起者自己的身份。** 冒充记录的有效性判定按 `check-ttl` 缓存，到期没有可发的事件，宿主的到期处理因此不能假定一次重读就读到已结束。
- **冒充页的记录区域收起在示范宿主里很少被看到。** 宿主在开始冒充后重读会话并把页面带离管理后台，收起只在宿主不做这些的装配或重读尚未落定的短暂窗口里出现；保留它是为了页面库不依赖宿主装配。
- **结束冒充成功的文案留在顶部区域里。** 横幅卸载后文案仍在那个挂载着的区域内，结果不自动消失，直到下一次尝试或页面重载替换它。
- **身份变更时整体逐出缓存会让当前页的读全部重取。** 与会话结束的缺省策略同一代价，换来不把旧身份的行带进新身份。
- **冒充期间的当前租户名称取自被冒充账户本人的成员关系读取。** 该路由登记为可冒充，应答收窄到冒充授予的那一个租户；宿主以它命名当前租户，整页重载或新开标签页因此仍宣告名称。名册仍不可达，横幅的租户一项仍是标识本身。多出来的暴露是这条账户级读取对冒充身份可达，而它的应答不含授予之外的任何成员关系。
