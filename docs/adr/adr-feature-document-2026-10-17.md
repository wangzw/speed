# 特性文档发布本进程服务的特性名，名字由服务该面的模块声明，只对已认证调用者可读

## 状态

已接受

## 背景

前端产物带着各功能目录的页面、区块与入口控件的代码；一次部署实际服务其中哪些后端面，由装配决定：既取决于命令纳入了哪些模块，也取决于一个模块之内哪些路由组或路由内分支随可选依赖成立。例如 authn.login 有 `SMSCodes` 时才挂手机号自助路由，其邮箱添加分支在没有 `EmailCodeSender` 时答 503；authn.admin 的会话、因素、密钥、SSO、冒充记录各管理组随相应功能挂载；notification.delivery 的邮件与短信渠道随相应接缝兑现。

前端对未启用的面的行为是 404：导航里不出现，直接访问其链接得到与不存在的路径相同的 404。未登录者读不到这份装配信息；登录前就需要判断的事实可以匿名读取，现由 authn 的 `GET /api/v1/auth/methods` 提供。

约束：

- `core` 不解释任何资源、不认识任何功能，也不按名称识别模块（架构不变量 2、13）；宿主向装配提供的声明一律经由模块机制（不变量 5）。
- 每一处按类型收集资源的消费点自行裁定取材域；减法只属于所述之物由这次运行产生的消费点；宿主经带 `AllResources` 的静态级纳入，可以令所列模块的声明当作在册处理，越过消费点自己的取材域（不变量 15，[ADR-module-resources-2026-09-21](adr-module-resources-2026-09-21.md)）。
- 对一份声明可以问「这个二进制提供什么」，也可以问「此刻这个进程在服务什么」。ops 合并 `http.Spec` 回答的是「这个二进制提供什么」，取可用集、不做减法（[ADR-ops-spec-reader-2026-10-15](adr-ops-spec-reader-2026-10-15.md)）。前端门控需要的是「此刻这个进程在服务什么」。
- 权限目录是词汇，取可用集；`authz.policy` 无条件声明 authn、audit、settings 的权限码。持有某个权限码，不意味着服务它的模块在本进程运行。
- 登录方法以描述符自报渲染形状：方法集合是开放的，前端要按描述符通用地渲染没见过的方法。登录发现记录为此否决了「复刻 legacy 的公开配置端点」与「名字数组加前端硬编码的名字到界面映射」（[ADR-authn-login-method-discovery-2026-10-16](adr-authn-login-method-discovery-2026-10-16.md)、[ADR-web-auth-channel-discovery-2026-10-16](adr-web-auth-channel-discovery-2026-10-16.md)）。
- 认证网关的登记面 `authn.Gate` 只有 `Exempt`、`Optional`、`Impersonable`；一条登记落在网关不守的端上，启动即失败。
- 租户解析层在请求读不出租户时答 404；选定租户之前，前端读不到解析租户的端上的任何路由。
- `pkg/http` 功能目录位于全部登记路由的模块之下，不 import 其中任何一个。
- 同一个源背后可以有多个 `serve` 副本，请求在副本间轮转。

## 考虑过的选项

### 发布单位取模块名

发布启用集中声明了 `http.Spec` 的模块名，前端按模块名门控。

**否决**：模块名表达不了模块之内随装配挂载的子面——手机号自助、邮箱分支、通知渠道、authn.admin 的各管理组；这些子面的存在性只能另找出处，前端要从多处读取、处理多种等待态。前端声明直接引用后端模块名，模块一拆分或改名就成了前端的破坏性变更。

### 发布单位取在服的 `operationId`

取路由登记与契约的交，发布本进程在服的操作名；发布者放在一个独立的顶层功能目录。

**否决**：要给 `http.Router` 加列举路由的方法、给 `authn.Gate` 加读面，都是 Go 接口的破坏性变更。OpenAPI 的 `{name}` 与 `gin` 的 `:name` 要互译，`authn.gate.mount.base-path` 一改值，整片都对不上。一个页面要列多个操作名。该做法附带一份匿名可读的操作清单，与「未登录者读不到装配信息」相抵。

### 从路由表或分派前缀反推

**否决**：暴露整张路由表；路由内的分支（邮箱添加分支）不对应任何一条路由，反推不出来。

### 在合并后的 OpenAPI 上按片段归属做减法

以 `x-fragments` 标出的片段归属，从 ops 合并的文档里减去本进程未运行模块的片段。

**否决**：片段取可用集，回答「这个二进制提供什么」；在它上面做减法，等于让同一份文档同时回答 ADR-ops-spec-reader-2026-10-15 刻意分开的「这个二进制提供什么」与「此刻这个进程在服务什么」。

### 宿主在 `main` 里手写特性清单

**否决**：这是命令树之外的第二份事实，绕开模块机制（不变量 5）；清单与实际挂载的路由各自维护，必然漂移。

### 复刻 legacy 的公开配置端点

配置里写特性开关，经一个公开端点发布。

**否决**：与登录发现记录否决同名选项的理由相同：配置开关与模块自报是同一事实的不同数据源，必然漂移；配置面承载的是部署参数，而这里要发布的是「本进程服务哪些面」。它还对匿名者公开，与「未登录者读不到装配信息」相抵。

### 权限目录改取参与集，以权限码代表存在性

**否决**：权限目录是词汇，取可用集；`authz.policy` 无条件声明 authn、audit、settings 的权限码，持有权限码不等于服务它的模块在本进程运行。改动目录的取材域，还会让「先于装配变更授予权限」不再可行。

### 模块自报渲染描述

模块发布页面路径、标签、图标等渲染描述，前端按描述生成页面与导航。

**否决**：页面与控件的代码只存在于前端产物里。后端能断言的只有「该面在不在」，断言不了「怎么画」；前端也只能门控自己已经带着代码的面，一个前端不认识的特性名不可能被渲染成任何东西。登录方法不同：方法集合开放，前端要通用地渲染没见过的方法，所以登录发现记录让方法自报描述符。

### 发布者落在 ops

**否决**：ops 不设防；在示范装配里它在独立的监听上，与前端不同源；它只回答二进制级的事实（ADR-ops-spec-reader-2026-10-15）。

### 发布者落在 `pkg/http` 之下

**否决**：发布者自己登记路由，还要取用认证网关的登记面；`pkg/http` 位于全部登记路由的模块之下、不 import 其中任何一个，把发布者放进去违背这条方向。

### 扩展 `GET /api/v1/auth/methods`

**否决**：它是匿名面，又归 authn；非 authn 模块往里放内容会反转依赖方向，也把需认证的事实放进匿名可读的应答。

### 随前端产物发布

由静态托管模块 webui 或 `runtime-config.json` 携带特性集合。

**否决**：webui 与 `runtime-config.json` 都是静态产物，不知道本次运行的启用集，也不设防；`runtime-config.json` 是随前端产物部署、承载 API origin 的文件（[ADR-web-runtime-config-2026-10-15](adr-web-runtime-config-2026-10-15.md)），由部署方写出，与装配无关。

### 挂在解析租户的端上

**否决**：租户解析层在读不出租户时答 404，选定租户之前读不到。

### 特性文档匿名可读

**否决**：未登录者读不到装配信息。登录前就要用的事实另有归属：拥有该事实的模块自己的匿名发现面。

### 进程里没有认证网关时照常挂出读面

**否决**：读面的保密全部来自网关；网关不在时照常挂出，等于把装配信息公开。失败方向取启动失败。

### 按调用者权限过滤特性文档

**否决**：特性在场与授权是两件事。已认证成员本来就能对契约里的路径逐条请求，按 404 与非 404 区分挂载情况，按权限过滤减不了成员能得到的信息；按租户收窄时，还要在存在性之外再处理一个维度。

### 每个应答带集合摘要，前端发现不一致即重取

**否决**：请求在副本间轮转时，页面会反复出现又消失。

### 模块以资源声明特性名、发布名字集合，发布者是挂在受网关守卫且不解析租户的端上的独立模块

服务某个用户面的模块以资源声明特性名；成立与否取决于装配的面声明为条件特性，由声明模块在本次运行中报告成立（报告的时机与位置见 [ADR-feature-ownership-2026-10-17](adr-feature-ownership-2026-10-17.md)）；发布者按本进程实际服务的集合作答，只发布名字。发布者是一个独立模块，读面挂在受网关守卫、不解析租户的端上：同时满足「只有已认证者可读」「选定租户之前可读」「与前端同源」的落点只有这一处。

这在形状上就是登录发现记录否决的「名字数组加前端映射」。那条否决的理由是前后端各自维护同一套视图会漂移、名字不是给前端渲染用的接口面；它针对的是开放的方法集合，渲染形状必须由方法自报。特性对应的是前端已经带着代码的页面与控件，渲染知识本就归前端，名字只承担「在不在」；前后端之间的漂移由 `contracts/features.json`、编译期类型与前后端新鲜度测试挡住（[ADR-feature-vocabulary-2026-10-17](adr-feature-vocabulary-2026-10-17.md)）。

**采纳**，见决策。

## 决策

采纳：**服务用户面的模块以资源声明特性名，条件特性由声明模块在本次运行中报告成立；模块 `feature.board` 按本进程的启用集作答，只对已认证调用者可读；匿名可读的内容不增加。**

- 声明的资源类型是 `feature.Spec`，声明面在只依赖标准库的根包 `pkg/feature`；一个特性名在可用集内只由一个模块声明。
- 静态特性在声明模块进入启用集时计入。条件特性还须由声明模块在本次运行中报告成立，才计入；报告的时机与位置由 ADR-feature-ownership-2026-10-17 裁定。
- `feature.board` 在 Prepare 按可用集校验全部声明：没被本次命令纳入的模块，名字写错同样让启动失败。它在 Start 按启用集冻结本进程的特性集合；消解落选的模块不计入；宿主经带 `AllResources` 的静态级纳入点名的模块，其静态特性计入（不变量 15）。
- 读面是 `GET /api/v1/features`，挂在部署方指定的、受认证网关守卫且不解析租户的端上，并登记为可冒充；进程里没有认证网关提供者时，`feature.board` 启动失败。应答不按调用者权限过滤，带 `Cache-Control: no-store`。
- 登录前要用的事实只经拥有该事实的模块自己的、形状封闭的匿名发现面发布，现有的唯一一处是 `GET /api/v1/auth/methods`；特性文档不承载匿名可读的内容。
- 同一个源背后的全部 `serve` 副本跑同一条命令、同一份配置，这是部署前提；日志功能在场时，每个进程在 Start 写一行带集合摘要的日志，供逐副本比对。

## 后果

前端以一份由后端给出的集合门控页面、导航与控件。知道一个面成立与否的仍是挂载它的模块，`core` 不变。

**接受的代价：**

- 多一种资源类型、一个模块；每个服务用户面的模块各多一条声明。
- 已认证调用者可以一次列举本进程服务的特性。在解析租户的端上，没有任何成员身份的账户本会先被租户准入层拒绝、探测不到那里的挂载情况，特性文档把这份信息告诉了它。前端产物本来就写着它会调用的每一个面，这份信息的敏感度低。
- 宿主经带 `AllResources` 的静态级纳入点名一个声明了特性、本身不在本进程运行的模块时，它的静态特性计入。这种装配的含义是宿主显式声明「该面由同一源背后的另一进程服务」，该面在部署里是开启的。宿主借此声明的面若实际没有任何进程服务，前端会显示一个请求必然失败的页面；这是宿主显式声明的后果，由宿主负责。条件特性不受这一覆盖影响：模块不运行，就不会报告。
- 「匿名请求得到 401」依赖网关模块构造的网关：宿主给网关预置一个不出自网关模块的实例时，认证层与登记核对都不在，这一条不成立。
- 在 [ADR-http-dispatch-2026-10-17](adr-http-dispatch-2026-10-17.md) 所列前提下，不对端上每个请求起作用、在各端上都没有[匿名面路由](../glossary.md)的路由模块，以及不含匿名面路由、随装配挂载的路由组，未认证者不能借 HTTP 应答的差异推断它们是否在本进程运行：入口模块按配置认领的前缀选端，选端不随装配变化；受网关守卫的端上，认领之内未挂载的路径与已挂载的受守路由，对未认证请求同答网关的 401（[ADR-http-dispatch-2026-10-17](adr-http-dispatch-2026-10-17.md)、[ADR-authn-exemption-2026-10-17](adr-authn-exemption-2026-10-17.md)）。不在这一保证之内的是：带匿名面路由的模块——以 `Exempt` 或 `Optional` 登记了路由的模块，以及前端静态托管、ops 这类挂在不受网关守卫的端上的模块——其在场可经这些路由本身探出；凭据后端、跨源策略、语言协商、来源地址限流这类对端上每个请求都起作用的模块，其在场体现在每个应答上。
- 没有日志功能的进程不写集合摘要，它与别的副本无从逐份比对。
- 特性集合在 Start 冻结，滚动发布期间各副本可能不一致；前端在一个会话内不重取，不一致在下次登录或整页刷新时收敛。请求打到缺少该特性的副本时，页面落到既有的可重试错误；各副本在服务端各自授权，没有安全后果。
- 分派按配置的认领为 `/api/v1/features` 选出的端须是读面所在的端，否则启动失败；与前端同源部署时，前端页面路径不得落在 `/` 以外的任何认领前缀之下。

## 失效条件

- 前端需要渲染一个它没有带着代码的面（由后端描述驱动的界面），则「名字只承担在不在」的前提不成立，发布单位要重审。
- 同一个源背后出现有意不一致的副本装配（例如按副本分流到不同装配），「部署前提加 Start 摘要」不再足够。
- 带 `AllResources` 的覆盖在实践中常被用来点名并无进程服务的模块，则计入静态特性的代价不再只落在个别宿主身上，这一覆盖对本消费点是否生效要重审。
