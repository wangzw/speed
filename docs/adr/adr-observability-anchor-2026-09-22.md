# 采集层的锚点用本模块交付的功能，本层自带记录后重抛

## 状态

已接受

## 背景

中间件的排序按功能标识建图：一层用 `Provides` 声明它在链上代表什么，别的层用 `After` 或 `Before` 指向那个标识（[ADR-http-middleware-2026-09-14](adr-http-middleware-2026-09-14.md)）。`pkg/http` 的登记面把一层的名字与它声称代表的功能分开。`http.Middleware` 的 `Name` 字段只用于诊断，写在 panic 文本与启动时列出的链里；指向功能的是同一结构上的 `Provides`，其元素是 `core.Token`（`pkg/core/module.go`）。登记面拿不到登记方的身份——`http.Endpoint` 不带它——因此 `pkg/http` 不校验 `Provides` 与登记方描述符里交付面的一致性，一层可以声称代表一个它所属模块并不交付的功能（见 `http` 设计文档的中间件一节）。

入口模块的 panic 兜底由它内建，位于全部登记层之外（见 `http` 设计文档的兜底层一节、[ADR-http-recovery-2026-09-22](adr-http-recovery-2026-09-22.md)）。内层抛出的 panic 因此先穿过登记层，才到兜底层。

采集层由上游 gin 采集库的中间件与本模块的守护层组成（[ADR-observability-request-layer-2026-10-11](adr-observability-request-layer-2026-10-11.md)）。上游采集库不接住 panic，穿过它的 panic 不进计量，接住它的一层因而必须位于它之内。

## 考虑过的选项

### 另立一个只在这一层出现的标识

采纳它意味着采集层的 `Provides` 取一个本模块不交付、只为这一层新造的值。

**否决**：链上会因此多出一个没有任何模块交付的功能，而约束与描述符的一致性本来就没有一层能判。用交付标识时，链上出现的名字与模块真交付的东西同源，少一处可以对不上的地方。

### 不声明本层代表的功能

采纳它意味着 `Provides` 留空。

**否决**：声明为空会让任何别的层的 `After` 或 `Before` 都指不到本层，那些约束随之被丢掉。丢掉一条约束不失败，只在启动诊断里记一行 Info（`pkg/http/assemble.go` 的 `reportUnlanded`），与本模块缺席、或没有在这个端上登记采集层时合法装配记下的那一行同形——声明方以为自己有位置保证，而这一点在启动期看不出区别。

### 依赖入口模块的兜底层接住 panic，本层不捕获

采纳它意味着采集层不写自己的记录动作，跨度的错误标记交给入口模块的兜底层。

**否决**：兜底层在采集层之外，panic 先穿过采集层，穿过上游采集库的请求不进计量，跨度也没有错误状态。而且采集层是否必须捕获不能取决于另一个模块的落地状态，那会让同一份代码在两种装配下行为不同。

### 守护层也以交付的功能标识声明

采纳它意味着守护层的 `Provides` 与外层相同，外层与守护层都代表追踪与指标的功能标识。

**否决**：别的层的 `After` 或 `Before` 指向追踪或指标的功能时，会落在外层与守护层上，位置不再唯一；守护层只靠自己的 `After` 放在外层之内，不代表任何功能。

### 采集层的锚点取本模块交付的功能，采集层自带记录后重抛

**采纳** — 见决策。

## 决策

采纳：**采集层在链上的标识取本模块实际交付的两个功能**——`(*observability.TracerProvider)(nil)` 与 `(*observability.MeterProvider)(nil)`，两者都是装配器排他交付的功能，不另立一个只在这一层出现的标识。

**采集层自带一次捕获与记录动作，记录后原样重抛。** 外层承载 `(*observability.TracerProvider)(nil)` 与 `(*observability.MeterProvider)(nil)`；守护层不声明任何功能，以 `After` 指向追踪 provider 的功能标识，放在外层之内。守护层接住内层抛出的 panic，给跨度记下错误、异常事件与状态，把值交给外层，外层在上游采集库记录完成后把同一个值抛出；写出响应不是采集层的职责。

## 后果

**接受的代价：**

- **上游重命名或换版会静默打散链上约束。** 本模块的功能标识是上游 SDK 类型的别名，上游把它们改名或换版时，指向本层功能的 `After` 或 `Before` 落不到任何一层，表现只是启动诊断里的一行 Info，与本模块缺席时合法装配记下的那一行同形；框架无法核对某一层声称代表的功能是否真由某个模块交付，这一处对不上没有别的拦截点。撞上它的是写出这类约束的第三方模块：位置保证在一次依赖升级后消失，而启动不失败。
- **守护层按 `After` 放置，不按相邻放置。** 别的层可以被放在外层与守护层之间，那样的层里抛出的 panic 不被守护层接住（[ADR-observability-request-layer-2026-10-11](adr-observability-request-layer-2026-10-11.md)）。
