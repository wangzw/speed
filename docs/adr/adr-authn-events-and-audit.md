# 事件、审计、日志与指标的契约：事件是提示，审计分强制与尽力，日志与指标不带高基数值

## 背景

认证模块产生的事实（账户、会话、令牌、因素、冒充、IdP 登记的变化）经事件、审计、日志与指标被观察。每条通路有各自的承载能力与不能越过的限制，契约要在它们之上同时成立。

**事件总线。** 订阅表在模块 `Init` 之后冻结，没有退订，冻结后的 `Subscribe` 被拒绝；经传输投递的实现每个事件类型占一条流与一条读取连接。总线不承诺投递次数，后端可能重投，同一个事件按 `Event.ID` 去重（[ADR-event-identity](adr-event-identity.md)、design-event）。事件类型因此必须在 `Init` 前静态已知，数量随功能增长、不随租户与 IdP 增长。可观测性不订阅总线，载荷的顶层字段不进跨度属性——跨度由事件模块在分发层记，属性是 `messaging.*` 那一组；审计把载荷写进明细，而审计的脱敏键名是闭集，逐字比较，嵌套值里的键不比对（[ADR-observability-events](adr-observability-events.md)、[ADR-event-tracing](adr-event-tracing.md)、[ADR-audit-redaction](adr-audit-redaction.md)）。载荷里的任何一个顶层字段因此会出现在审计明细里，挡在载荷之外是发布方的义务。

**事件与写入的先后。** 账户状态、账户删除、成员关系的变化被授权与别的模块订阅，用来清除角色绑定、会话与缓存；丢失一条意味着残留一条指向已失效账户的绑定。总线的发布独立于事务，发布失败不回滚写入；发件箱在写入的事务里暂存、提交之后由中继发布，承诺至少一次，要求宿主装配中继与总线（[ADR-outbox-scope](adr-outbox-scope.md)）。

**审计。** 请求级采集在没有身份的豁免路由上取不到行动者；登录与 SSO 回调恰在这类路由上发生。接缝级的 `Audit.Record` 由调用方主动交出一行，在 `Start` 之前返回 `ErrNotAccepting`，在 `Start` 之后可能因写表失败返回 `ErrWriteFailed`。接缝写入另占一条连接，在调用方的事务里调用它会在单写者引擎上等锁而失败（design-audit）。审计表的列是对读它的宿主的承诺，只有明细里的键可以自由增减（[ADR-audit-table-contract](adr-audit-table-contract.md)）。身份分实际操作者与生效账户，冒充期间两者不同（[ADR-authn-identity](adr-authn-identity.md)、[ADR-authn-impersonation](adr-authn-impersonation.md)）。

**日志与指标。** 日志里的身份值是账户标识，而 `subject` 在账户体系里指外部身份绑定的主体（外部标识的第二段），同名字段会让读日志的人把两类标识读混；冒充时实际操作者与生效账户并存，一个字段也无法同时表达两者。配置的 `Sensitive` 只约束配置模块自己的输出面（错误文本、帮助默认值、必须带说明），不向日志模块登记脱敏规则，所以标为 `Sensitive` 的值不会因此被日志遮蔽。指标经 `observability.MeterProvider` 报出，属性的基数由上报方负责；路由与租户已因基数不可控被入口指标否决（[ADR-observability-instruments](adr-observability-instruments.md)）。网关的收口计数器 `authn.gate.conclusions` 的名字与取值已被看板引用。

完整的事件类型表、审计动作表、日志字段表、仪器表与各自的取值集在 design-authn-events；本记录只裁定这些表遵守的契约。

## 考虑过的选项

### 每个 IdP、每种登录方式一个事件类型

事件类型随租户的 IdP 与登录方式展开，订阅方按类型名过滤。

**否决**：类型集合不再在 `Init` 前静态已知，冻结后的订阅表不能为后来登记的 IdP 补订阅；Redis 与 NATS 上每个类型占一条流与一条读取连接，类型数随租户增长而无上界。变化用载荷字段表达，类型按功能划分即可。

### 登录失败发事件

失败的登录发 `login.failed`，让订阅方做告警与封禁。

**否决**：被攻击时每次失败发一个事件，把对认证的攻击放大成对总线的写压力。载荷里的登录标识或其摘要还会使事件流成为账户存在性的旁路，而载荷只放标识、枚举与时刻的规则无法同时容纳它。失败已经由审计（尽力档）、日志与计数器覆盖；订阅方真正需要的是「退避开始」这一个状态变化，它用 `authn.throttle.engaged` 表达，仅在退避开始时发一次。

### 账户状态、删除与成员关系的变化只走总线，不用发件箱

所有事件一律提交之后 `Bus.Publish`。

**否决**：发布失败或进程在提交与发布之间终止时，授权清不掉角色绑定，残留的绑定指向已停用或已删除的账户或已不是成员的账户，而这类残留不产生任何信号。

### 发件箱设为硬依赖

账户状态、删除与成员关系的事件必须经发件箱，缺发件箱时认证模块不能启动。

**否决**：发件箱要求宿主同时装配中继与总线。把它设为硬依赖，使只要账户而不要事件订阅方的宿主也被迫装配两者；没有事件订阅方的宿主不应为此付出装配代价。

### 把登录成败交给请求级审计采集

登录行为由请求级采集记录，认证模块不自写审计。

**否决**：登录与 SSO 回调在没有身份的豁免路由上，请求级采集的 `actor` 为空；请求级只覆盖配置点名的（方法，路由）对，点名之外的登录不留痕。登录类动作由认证模块经接缝自记，行动者才是登录成功的账户。

### 所有审计写失败都拦住业务

每个动作都先写审计，写失败则动作不执行。

**否决**：登录因审计表变慢而整体不可用，认证成为审计表的可用性的函数。拦截只适用于没有记录就无法问责的动作，其余动作的审计失败只能降级为错误日志与计数。

### 审计表加可空列 `on_behalf_of`

被冒充者进审计表的一列，带索引，使「某账户被谁冒充过」可直接查询。

**否决**：审计表的列是对读它的宿主的承诺，加列要由审计模块自己裁定并附迁移，不由认证模块的需要驱动（[ADR-audit-table-contract](adr-audit-table-contract.md)）。明细里的键增减不动表。按被冒充者查询的需求已有来源：冒充记录表按目标保留每次冒充的开始与结束。

### 扩充审计敏感键闭集，认证模块依赖它遮蔽令牌与验证码

把 `code`、`otp`、`refresh_token`、`id_token`、`assertion`、`state` 这类键名加入 `audit.journal` 的敏感闭集，认证模块的明细可以放这些键，由闭集遮蔽值。

**否决**：闭集是审计模块的契约，扩充它是另一个模块的决定；认证模块把「秘密不落库」押在别的模块的集合上，集合的任何收窄都使秘密静默落库。遮蔽也只对键名生效，值形状与嵌套值不在判定面内。认证模块的明细只放标识、枚举与计数这一类不带秘密的值，键名取自固定的一组，不依赖闭集；扩充闭集作为对审计模块的建议另行提出，不构成本契约的前提。

### 指标属性带租户、账户或 IdP 标识

按租户与 IdP 切分登录与断言的计数，便于定位谁在失败。

**否决**：基数随租户、账户与 IdP 数量增长而无上界，入口指标已因同一理由否决路由与租户（[ADR-observability-instruments](adr-observability-instruments.md)）。哪个 IdP 在失败由日志回答，指标只回答协议、方式与结果。

### 经事件而不是审计接缝记录安全动作

订阅自己发出的事件，由审计的事件级通路落表。

**否决**：事件是提示，总线不承诺投递次数也不回放，事件丢失时审计里没有任何信号；审计要的是写不进就失败的语义，事件级通路没有可以告知失败的调用方。

### 事件为提示，审计分强制与尽力，日志与指标不带高基数值

事件类型静态、载荷只放标识；账户状态、删除与成员关系在发件箱在场时经它发出；强制与尽力两档审计经接缝自记；日志与指标的字段与属性取固定集合。

**采纳**，见决策。

## 决策

采纳：事件、审计、日志与指标按下列契约发出；各自的表与取值集由 design-authn-events 承载。

**事件是提示，不是权威。** 账户状态、成员关系、会话与撤销的权威在 db；订阅方只能用事件清本地缓存与触发清理，不得把它当唯一依据，也不依赖次序与次数，按 `Event.ID` 去重。

- 事件类型在 `Init` 前静态已知，按功能划分，不按 IdP、登录方式或租户拆分；变化用载荷字段表达。
- 载荷的顶层字段只放标识、枚举与时刻；不放秘密、自由文本（理由、显示名）、邮箱、手机号与登录标识。判据：载荷的每个顶层字段都会被审计写进明细，所以放进去的值必须在审计明细里出现时无害。
- `authn.account.status-changed`、`authn.account.deleted`、`authn.membership.changed` 在 `outbox.Outbox` 在场时经它在写入的同一事务里暂存，缺席时提交之后 `Bus.Publish`，发件箱与总线都没有时不发，并在启动诊断写一行 Warn。这是「在场则用」，不构成硬依赖。其余事件一律 `Bus.Publish`，发布失败只记 Warn，不使业务操作失败。
- 不设登录失败事件。退避开始时才发 `authn.throttle.engaged`。

**审计分强制档与尽力档，判据是这个动作若没有记录、事后能不能问责。** 认证模块的审计经 `Audit.Record` 的接缝级通路自记。

- 强制档：先写审计，写成功才执行动作，审计写失败（含 `ErrNotAccepting` 与 `ErrWriteFailed`）则动作不执行并应答 503。审计写在动作的事务之外。归属以判据为准；例举，不是封闭集：冒充开始、管理面写操作、因素与口令的管理员重置、账户的创建、停用与删除、IdP 与域的变更。完整的动作表在设计文档。
- 尽力档：审计写失败只记 Error 日志并计数，不影响业务。归属以判据为准；例举，不是封闭集：登录与登出、自助的账户变更、令牌重用检测、放宽设置的审计 `authn.settings.relaxed`（来源是订阅 `settings.changed`，只含键名与方向，不含值）。
- 强制档只对 HTTP 管理面与冒充成立：`authn.admin` 与 `authn.impersonation` 把 `audit.Audit` 当必需依赖；经 Go 接口的直接调用不受此限，没有审计的装配里只写 Warn。
- 审计同时记实际操作者与生效账户：`actor` 列恒取实际操作者，冒充的生效账户进明细，不增表列，审计表的结构不变。冒充的明细键（`on_behalf_of`、`impersonation_scope`、`session`）只由审计模块在冒充行上写入，非冒充行上调用方的同名键被剥掉，判据与代价见 [ADR-audit-impersonation](adr-audit-impersonation.md)。明细的键名与各动作的取值见设计文档。
- 明细的键名取自设计文档登记的封闭集合，值只放标识、枚举、计数与密钥摘要的前缀；秘密、令牌、验证码、断言与 `state` 从不进明细。

**日志的身份字段取名 `account`，值是生效账户。** 冒充时实际操作者另用独立字段表达，一个字段不同时承载两者。日志不使用 `subject` 字段，因为 `subject` 在账户体系里指外部身份绑定的主体，同名字段会使读日志的人把两类标识读混。具体字段与绑定见设计文档。

- 永不记录：凡持有它即可冒用或重放认证过程的值，以及用户提交的原文，包括请求体与表单字段、验证码、口令、令牌、cookie 值、断言原文、授权码、`state`、PKCE 校验串、流程令牌、带 `secret` 的微信 URL；这是判据加例举，不是封闭集，完整的清单在设计文档。记录的是类别、标识与结果。
- `Sensitive` 的配置项不向日志模块登记规则，所以「`Sensitive` 值不进日志」是认证模块自己的纪律，由测试守住：对每个模块的错误路径断言输出里不含配置里的哨兵值。
- 退避、重放、克隆告警这类安全事件各写一行；退避的那一行带 `reason_class`，取值取自设计文档登记的封闭集合，不另写自由文本；账户标识可带，用户输入的标识字符串不带。
- 级别按「谁有事要做」：调用方的事记 Info，要运维去查的记 Warn，缺陷记 Error；强制档审计写失败是缺陷。

**指标属性只取取值有限的维度。** 判据是属性的取值个数不随租户、账户与 IdP 增长；例举，不是封闭集：方式、协议、结果、因素、算法。属性不含租户、账户、IdP 标识与路由。属性集合与仪器名以设计文档的仪器表为准。登录方式的属性值对 SSO 只到协议（`oidc`、`saml`），不含提供方标识。

- 仪器名与属性名属于对外接口面：改名或删除是破坏性变更；每个属性的取值集是闭集，新增取值是兼容的，改名、删除或改变既有取值的含义是破坏性变更。`authn.gate.conclusions` 的 `outcome` 含 `anonymous`，表示可选路由上无凭据而放行。
- `MeterProvider` 缺席合法，缺提供者时静默跳过上报，其他错误终止启动。
- 除网关的可观察计数器外，仪器是同步计数器与直方图，事件稀疏，不为上报在请求路径上多付代价。
- 业务指标归产生信号的模块自己上报，不进 observability 的文档。

## 后果

订阅方拿到的事件类型稳定、载荷不含个人可识别的自由文本与秘密；授权据账户状态、删除与成员关系的事件清除绑定时，在发件箱在场的装配里不因进程在提交与发布之间终止而丢失。冒充期间的每一行审计都同时指出谁在操作与替谁操作，审计表的列不因认证的需要变化，读这张表的宿主不受影响。看板对 `account` 字段与指标属性的引用不被租户、IdP 与账户的增长撑出基数。

**接受的代价：**

- **事件在没有发件箱的装配里是尽力而为。** 授权在这类装配里要靠账户读口对账，事件不能当唯一依据。
- **强制档的审计与动作不在同一事务里。** 动作失败时审计里已有一行表示已准许而没有生效，随后补写一行失败记录，两行用动作标识关联；审计与动作之间没有原子性，换来的是审计写入不在调用方事务里等锁。
- **尽力档审计在审计模块拥塞时会丢**，只留 Error 日志与计数。
- **审计库故障时，冒充与高危管理动作不可用。** 这是偏向留痕的有意选择。
- **强制档只约束 HTTP 管理面与冒充。** 宿主经 Go 接口直接调用账户管理的方法时，没有审计的强制。
- **按被冒充者聚合审计要扫 `Detail` 里的 JSON。** 需要按它高频聚合时，在审计表上加列是审计模块自己的一次变更。
- **指标看不到哪个 IdP 或租户在失败。** `authn.login.completions` 只按方式聚合，定位到 IdP 要读日志。
- **事件载荷里的 `account_id` 是个人信息。** 审计只对配置里点名的类型订阅，被点名的类型的顶层字段进入审计明细；要求更严的宿主不点名这些类型，或在导出端过滤。每个事件类型在 Redis 与 NATS 总线上占一条流，被订阅的类型另占一条读取连接。
- **语句级审计会为认证的每次模型路径写留一行。** 这些行只记表、动作与受影响行数，没有业务语义，业务语义由接缝级的行给出；量由登录以外的写决定。登录路径上的 `Touch`、`Throttle` 与计数推进走原生 SQL，不留行。
- **按 `subject` 检索日志的看板与告警查不到身份。** 日志的身份字段是 `account`，按 `subject` 检索不报错，只是没有命中。对 `authn.gate.conclusions` 的 `outcome` 全部取值求和的口径包含 `anonymous` 一类。
- **「`Sensitive` 值不进日志」没有机制保证。** 只靠逐模块的错误路径测试；漏测一处即漏一处。宿主自己的 handler 若记录请求体，认证模块管不到。

## 失效条件

下列假设依赖尚未核实的行为，各由一条测试守住；测试不成立时，本记录中依赖它的条目失效：

- 假设语句级审计行不带列值，只带表、动作与受影响行数。含加密列的模型经模型路径写入，必须有「审计行里不得出现秘密字节」的测试；不成立时，认证模块哪些表可以经模型路径写要重新裁定。
- 假设审计把事件载荷的顶层字段原样写进明细，且脱敏键名只比对扁平键。载荷规则（只放标识、枚举与时刻）建立在这个假设上；审计的判定面不同时，规则的严格程度要重新核定。
- 假设接缝级 `Record` 在调用方事务里调用会在单写者引擎上等锁而失败。审计与动作不在同一事务里这一代价建立在它上面；审计模块提供与调用方事务一致的写入通路时，强制档可以改为与动作同事务，本决定不再成立。

下列情形出现时，本记录要重新裁定：

- 审计模块在表上增设按被冒充者查询的列。「明细里的键」这一选择随之作废，明细里的冒充生效账户迁入该列。
- 事件总线支持退订，或各类型不再各占一条流。事件类型数量的约束随之放宽。
- 看板需要按 IdP 或租户切分登录失败的指标，并给出可接受的基数上界。指标属性的闭集要重新划定。
