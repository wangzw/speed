# 纳入分为运行级与静态级，人机界面跟运行级走

## 状态

已接受

## 背景

命令树上的一次纳入同时决定三件事：这个模块会不会被构造与驱动、它的输入项会不会出现在这条命令的参数面上、它声明的资源会不会生效（[ADR-command-tree-2026-09-20](adr-command-tree-2026-09-20.md)）。三件事由同一个动作表达，前提是一条命令对它们的需求一致。

施加迁移的那条命令推翻了这个前提：它只运行数据库引擎，却要收齐那些不运行的带表模块的迁移集（REQ-deployment-016）。

三者收不到一处。依赖闭包只沿 `Requires` 向提供者方向展开：带表的模块依赖数据库，数据库不依赖它们，闭包因此够不到它们。把它们逐个纳入，它们的全部输入项连同必填项一并进入这条命令——`migrate` 会因为缺一个 HTTP 监听地址而启动不起来。不纳入，它们落在参与集之外，启用结果查询对它们报禁用，按启用结果过滤声明的机制随之丢弃它们的迁移集：这条命令建立迁移记录表、取得互斥、施加零条迁移、释放互斥，退出码为零。

参与集在各处的定义都不含"决定资源声明是否生效"这一项。术语表说它是"本次运行有资格表态的模块集合"；架构不变量 5 把参与集据以展开的运行级纳入归为"这一次运行要做什么"的驱动参数；[ADR-command-tree-2026-09-20](adr-command-tree-2026-09-20.md) 的后果一节只列帮助输出、可用参数与必填项，并写明"全是人机界面"；`config` 的设计文档说它决定哪些模块有资格在 `Prepare` 中表态。把过滤声明加给它的只有 `core` 的设计文档一处，而那里给出的理由是"否则依据启用结果过滤声明的机制会把不运行的模块算进去"——用被过滤方的需要去定义过滤依据。

已登记而未被本次命令纳入、也没有预置实例的模块不进启动诊断，理由是纳入哪些模块起于宿主写在命令树上的决定，那一种不是意外（见架构文档的可观测性）。依赖这一种的功能缺失因而补不上告警。

## 考虑过的选项

### 施加迁移的命令纳入全部可用模块

`migrate` 写成 `IncludeAll()`，深度止于 `Migrate`。参与集与提供服务那条命令一致，区别只在驱动多远。

**否决**：命令树决定的参与集决定必填项的判定范围。一个带必填项的认证后端会要求 `migrate` 给出它的密钥，一个 HTTP 入口会要求给出监听地址，而这条命令既不认证也不监听。帮助输出同时列出全部模块的参数，读者无从分辨哪些与施加迁移有关。认证模块的设计文档已经把这组后果逐条记下过。

### 迁移集的收集不看参与集

数据库模块收齐迁移集时只排除消解落选的模块，未被纳入的照常施加。宿主不必为此写任何东西。

**否决**：宿主失去表达范围的手段。"这个二进制里全部已登记模块的表"是唯一可选的答案，写不出"只要这几个模块的表"。它还产生一个反向的陷阱：一个带表模块不被纳入时表照常建立；被运行级纳入时它必须启动，配置不齐即这条命令启动失败，而这条命令并不运行它。纳入这个动作在迁移这件事上因此没有收益，只有代价。

### 由 `core` 提供按启用结果过滤后的资源查询

注册表另给一个只返回启用集中声明的查询，消费方按需选用。

**否决**：`core` 不解释资源（架构不变量 2），无从知道某一种该按哪个集合裁断。它要么替所有资源类型选定同一个集合，那正是上面两个选项各自的失败；要么认识每一种资源，与不变量 2 直接相悖。

### 命令声明它需要哪些声明，由框架反向展开

命令列举它要哪几类资源，框架沿声明关系反向找出提供这些资源的模块。

**否决**：与 [ADR-command-tree-2026-09-20](adr-command-tree-2026-09-20.md) 否决"命令声明所需能力"时的理由同源——得到的集合与显式列举相比并不更小，却让"这条命令收了谁的声明"不再能从宿主代码上直接读出。反向展开还要求 `core` 认识资源类型之间的关系。

### 纳入分为运行级与静态级

宿主在命令树上分别列举运行级纳入与静态级纳入的模块。静态级纳入的模块只让声明生效，不构造、不表态、不贡献参数、不判必填。

**采纳**，见决策。

## 决策

采纳：**命令树上的纳入分为两级**。

**运行级纳入**的模块被构造与驱动，在 `Prepare` 中表态并参与排他消解，其依赖闭包照常展开（排他交付的功能除外：闭包不为它自动纳入提供者，只取命令树上已点名的实现，见 [ADR-dependency-resolution-2026-09-13](adr-dependency-resolution-2026-09-13.md)），其输入项出现在这条命令的参数面上并按命令树决定的参与集判定必填。这是既有的 `Include` 与 `IncludeAll`，语义不变。

**静态级纳入**的模块只让它声明的资源进入本次运行的收集范围。它不被构造，不执行任何阶段回调，不表态，不参与消解，其依赖闭包不展开——它不构造，没有构造期依赖可言。它的输入项默认不出现在这条命令的参数面上，且**任何情况下都不判必填**。

三个集合因此扩成四个，架构不变量 8 随之改写：

```
可用集   ⊇   声明集   ⊇   参与集   ⊇   启用集
```

参与集是运行级纳入的模块经依赖闭包展开得出（不写命令树的调用方走 `Run` 入口时是注册表里已登记的每一个模块，见 [ADR-drive-entry-2026-09-21](adr-drive-entry-2026-09-21.md)），再加上预置了实例的模块，它们不看命令树是否纳入（[ADR-supplied-instance-2026-10-08](adr-supplied-instance-2026-10-08.md)）；声明集是参与集与静态级纳入的模块之并——**因而含闭包拉进来的与预置了实例的那些**。把声明集定义成宿主写下的两级名字之并会让包含链断掉：一个经闭包拉进参与集、或因预置了实例而进入参与集的模块会真的运行，却将落在声明集之外，于是它的插件照装而它的表不建。一个模块同时被两级纳入时按运行级处置；预置了实例的模块被静态级纳入时，注册表同样如此，命令树不知道预置，它的参数面与必填照静态级处置。

**宿主可以逐个打开静态级纳入模块的参数可见性**，打开之后它的输入项出现在帮助输出中并可在命令行上给出，必填仍然不判。**宿主可以令某个静态级纳入的模块全部声明生效**，覆盖消费点自己的裁定。

**声明进入收集范围不等于生效**。一份声明是否在某个消费点上生效，由该消费点按自己的取材域裁定（[ADR-module-resources-2026-09-21](adr-module-resources-2026-09-21.md)）。静态级纳入把模块放进声明集，取哪个集合是消费点的事。

**"全部静态纳入"是一项可写的选择，且是施加迁移这类命令的推荐写法。** [ADR-command-tree-2026-09-20](adr-command-tree-2026-09-20.md) 为"纳入全部可用模块"记下的代价是命令树决定的参与集重新成为 import 图的函数，而它决定帮助输出、可用参数与必填范围，全是人机界面。静态级不碰人机界面，那条代价对它不成立。

## 后果

一条命令要运行什么、要显示什么、要收谁的声明，成为三个可以分别写出的决定。

施加迁移的命令只运行数据库引擎，参数面只有引擎与根命令那一层的，而全部已登记模块的表照常建立。

静态级纳入给出了一个不构造模块即可取用其静态声明的位置。导出接口规格、打印有效配置这类命令由此有了可写的形状，它们此前只能在纳入全部模块与收不到声明之间二选一。

**接受的代价：**

- 宿主要写的样板又多一层。命令树上的每个节点现在可能有两份模块清单，而"哪些模块支撑哪个命令"这项知识本就已经从模块转移到了宿主。
- 静态级纳入漏写一个模块、也没有为它预置实例时，其声明不生效，而这一种不进启动诊断，失效静默。"全部静态纳入"这项选择存在正是为了让宿主不必维护那份清单，但它是宿主写下的一行选择，不是默认。
- 一个模块被运行级纳入而在消解中落选时，其声明按各消费点的减法退出；只被静态级纳入的模块不表态，声明不退出。同一个二进制下，两条命令收到的声明集合因此可以不同。
- 参数可见性打开之后，一个能在命令行上给出、却没有模块读取的参数就存在了——那个模块不构造，不会去 `Decode`，读到这个值的只有命令自己的动作，没有这样一个动作的命令上，给与不给都不改变任何结论。**它服务的那类命令今天一条也没有**：一个模块都不运行、只报告或校验配置的命令，是它唯一说得通的用途，而这样的命令由宿主决定写不写。为它保留这个开关，是把一个还没有使用者的公开面先立在那里；一份设计按无使用者来读它，会以为它是冗余的。
- 令全部声明生效这项覆盖会把一个不运行的模块的插件装到数据库句柄上，绕过"没启用就不生效"（[ADR-db-scope-2026-09-14](adr-db-scope-2026-09-14.md)）。它是宿主的显式选择，不是默认行为。
- 架构不变量 8 从三级链改为四级链，每一处按它推理的文档都要复查。

## 失效条件

若出现一种静态资源，其内容必须由本次配置决定，则"静态级不判必填、不构造"与"声明在收集之前就已确定"不再相容，静态级纳入要么获得一条读取配置的途径，要么那种资源不能走静态级。

若启动诊断的义务扩展到未被纳入与静态级纳入的模块，则"静态级漏写失效静默"这条代价消失，"全部静态纳入"作为推荐写法的理由随之减弱。

若某条命令需要一个模块既不运行、又要判它的必填项，则"静态级永不判必填"不再覆盖全部情形，必填的判定要从纳入级别中分离出来单独表达。
