# 示范宿主为没有成员关系的账户建一个个人租户：服务端幂等的 ensure，由租户框架触发，不进 pkg 公共面

## 状态

已接受

## 背景

自助注册开出的账户没有任何成员关系，访问租户资源得 404（[ADR-authn-signup-2026-10-18](adr-authn-signup-2026-10-18.md)）。产品要求注册成功后账户在租户区即可使用，而不是停在一个什么都读不到的页面。

决定要在下列既有约束内成立：

- **租户是请求的路由事实，客户端没有读取本人成员关系的接口。** 租户记录只有标识、别名与状态，没有展示名。
- **授权的角色与绑定是按租户存的数据。** 迁移不种任何角色；租户区的 API 端有授权守卫，账户要在租户里持有带对象存储等权限的角色才能使用租户区。
- **认证模块不依赖租户。** 开户事件 `authn.account.created` 在提交之后尽力发布，不经发件箱；开户前的钩子 `Provisioner` 在账户存在之前调用，只能改显示名与属性。
- **新租户在别的副本上要等名册快照刷新。**

## 考虑过的选项

### 订阅 `authn.account.created`，在事件里建租户

**否决**：该事件不经发件箱，是尽力而为的提示，丢失就留下一个没有租户的账户，「每个注册账户都有个人租户」不能成为不变量；事件在账户创建之后异步到达，用户的第一批租户请求可能先于租户建立。

### 在 `Provisioner` 里于开户前建租户

**否决**：账户此时还不存在，成员关系与绑定无从写入，而且钩子只能改显示名与属性。

### 由 `pkg/` 提供「个人租户」能力模块

**否决**：个人租户是一类产品的策略，不是租户、认证或授权的原语。这样的模块要同时依赖三者，而认证不依赖租户，它只能放在它们之上；目前只有示范一个宿主需要，等第二个宿主出现再提升。

### 客户端在注册完成后创建租户，服务端不设守卫

**否决**：客户端的注册模式不跨重定向类渠道，也不可信；一个任何已认证调用方都能调用、没有守卫的建租户接口没有上界。

### 只给引导页与文案

**否决**：产品要求自动创建，引导页留下的仍是一个无法使用租户区的账户。

### 示范宿主的服务端 ensure，由租户框架触发

**采纳**，见决策。

## 决策

采纳：**示范宿主提供一个服务端的、幂等的个人租户 ensure，由租户框架在已认证账户没有当前租户时触发；不新增 `pkg/` 公共面。**

- ensure 属于示范宿主的一个模块，与通知面的宿主侧授权同类；由宿主配置开关，缺省关闭，审查装配开启；开关关闭时路由不挂、特性不在场。
- 路由在 `account` 端，没有租户解析；调用方须已认证、不在冒充中。
- 资格在服务端判定：开关开启，且调用方的成员关系为空，或只有它自己的个人租户。已有其他成员关系的账户不建，也不加第二个租户。
- 租户标识与别名都由账户标识确定性派生，不取手机号、显示名或任何个人信息；别名是请求面标识，不翻译。
- ensure 的每一步都幂等，每次调用都核对并补齐：租户行、成员关系、租户内的非内置角色、该角色对租户域全部权限的授予、账户到该角色的绑定。
- 展示在前端：应答标明租户是个人租户，前端按语言渲染个人空间的文案，不把展示名存进租户记录。
- 触发在客户端：租户框架在账户已认证、没有当前租户且特性在场时调用；注册模式只决定落点与引导，不是资格判据。
- 各条款的细节由示范宿主的设计文档给出，本记录不重述。

## 后果

注册完成的账户在租户区立即可用，对象存储等租户面照常按授权工作。开户路径、验证渠道与授权模型都不改，创建租户的路径由一个只能为自己建一个租户的服务端函数承担，上界清楚。

**接受的代价：**

- **租户随账户增长。** 每个账户至多一个个人租户，增长的上界由已验证手机与短信预算给出。
- **账户删除不级联删除个人租户。** 租户与它的数据留在名册里，清理由运维决定。
- **多副本下有一个可见窗口。** 其它副本在名册快照刷新之前可能对新租户答 404，上界是名册的刷新周期。
- **角色的授权在建立与每次 ensure 时补齐，不即时。** 角色取当时租户域的全部权限，进程之后新声明的权限要到下一次 ensure 才进入该角色。
- **已有其他成员关系的账户得不到个人租户，也仍然没有读取自己租户的接口。** 这是旧缺口，本决定不填。
- **新增一个宿主侧的账户端路由、一个特性与一个配置开关。** 路由前缀在每份配置里认领，认领与装配无关，开关关闭时该前缀只会答 404。

## 失效条件

产品要求每个账户有多个个人租户、团队租户的自助创建，或第二个宿主需要同样的能力。
