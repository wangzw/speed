# 用顶层 starters/ 提供可运行的示范骨架

## 背景

[ADR-core-scope](adr-core-scope.md) 裁定 `core` 不编码应用形态，并在后果段写明：“组成什么样的应用”没有模板，新项目要自己搭出第一个 `main`，这部分由脚手架而不是由 `core` 承担；其失效条件段进一步写明，若宿主在 `main` 里写出的形态代码最终雷同，应把共同结构固化下来，但归宿是一个独立模块而仍不是 `core`。

`pkg/` 交付模块与接口，示例宿主是为评估模块而建的程序。两者都不是“拷走即可长出业务”的起点：`pkg/` 是库，不是程序；示例宿主 import 全部功能模块、带评估用的业务域与覆盖全模块的验收用例。框架缺一块：一个已装配好的产品骨架，供新项目拷贝、改名、在其上写业务。

## 考虑过的选项

### 把形态模板放进 `pkg` 或 `core`

提供一个装配入口，读配置、解析启用集、构造模块、驱动生命周期，宿主调用它即得到一个装配好的应用。

**否决**：这是 [ADR-core-scope](adr-core-scope.md) 已否决的方向。对形态的编码会以选项、开关或分支的形式回流到被所有模块 import 的包；脚手架是一个程序，不是一个接口，放进 `pkg` 会把它塞进模块依赖图。

### 由示例宿主兼任产品起点

把某个示例宿主当成新产品起点的模板。

**否决**：示例宿主为评估模块而建：它 import 全部功能模块、编写覆盖全模块的端到端用例、带一个评估用的业务域。拷走它会连评估的负担与那个业务域一起带上，而需要的骨架只是其中的一小部分。且示例宿主的 `go.mod` 以 `replace` 指向兄弟检出，一个拷贝出去的产品需要的是制品库依赖。

### 把骨架固化成一个独立模块

在 `pkg/` 下建一个模块（如 `pkg/starter`），把骨架做成模块交付。

**否决**：骨架是一整个可运行程序（入口点、命令树、部署栈、前端应用、构建与打包约定），不是模块。模块机制交付的是接口与实现；程序形态不是模块的产物，做成模块等于把一个程序塞进所有模块共处的依赖图。[ADR-core-scope](adr-core-scope.md) 失效条件段预言的“固化成模块”指的是形态里可复用的一块（如一种新的入口），而非整个程序。

### 在顶层 `starters/demo` 放一份可运行示范

在仓库顶层建立 `starters/`，与 `pkg/`、`tools/` 并列，其中放一份可运行、可拷走的示范程序。

**采纳**，见决策。

## 决策

采纳：在仓库顶层建立 `starters/`，放一份可运行的示范 `starters/demo`，供拷走后当一个新产品的起点。

- **它是产品起点，不是评估宿主。** 示例宿主为评估模块而建，`starters/` 为承载业务而建；示范的业务目录是空位，使用者拷走后按自己的业务域改名。
- **形态归脚手架，不归 `core`。** 这承接 [ADR-core-scope](adr-core-scope.md) 失效条件段所指的那部分责任。
- **依赖来自制品库，仓库内以 `replace` 过渡。** 示范的 `go.mod` 以 `require github.com/vislake/speed/pkg <版本>` 取 `pkg`，前端对 `@speed/*` 包按 registry 版本范围声明。`pkg` 尚无发布版本时它带一条 `replace` 指向兄弟检出，仓库自己的 `GOWORK=off` 构建环节（standalone 构建与 `tidy-check`）需要它，拷贝出去的树删掉这一条。**验收不得借助这条 `replace`**：否则会把“本机有这份仓库”当作前提，构建通过只证明本机检出可用，不证明消费者能取到发布版本。

## 后果

新增一个产品不必再自己搭出第一个 `main`：拷走 `starters/demo`、改名、按业务填模块。

`pkg/` 不受影响：示范在 `pkg` 之外，不进模块依赖图、不被模块 import。

**审查装配的控制路由是测试控制，不是产品 API。** 审查装配（`-tags review`）挂载两条控制路由：短信审核判定路由为一个厂商编号落一个审核结果，通知派发路由为调用方派发一次通知。两条都只在 `review` 构建标签下编译、只由审查装配登记，任何部署或基线二进制都不含它们。它们由认证网关识别调用方，认证之后不做权限判定；这条放行的依据是审查装配为只监听回环地址的测试进程，而不是它们对产品调用方安全。前端对应的控制仍由特性门控：特性不在场时不渲染控件、不发请求。

**接受的代价：**

- **示范会随 `pkg` 漂移。** 示范以 `require` 取 `pkg` 的版本，`pkg` 的装配契约（模块描述符、命令树、入口模块的契约）一旦不兼容变更，示范要跟着改；示范不是本仓库检查流水线的产物，它的过期不会在任何一道门里自动亮红。
- **固定一个骨架是押注。** 若使用者的产品在命令树、部署栈或打包拓扑上与示范差异很大，拷走后保留的比例就低，固定的价值随之下降。
- **合一拓扑把前端绑进 Go 的构建。** 二进制内嵌前端产物要求先前端后 Go 地构建，改一次前端就要重编一次 Go；这是合一换来的单产物部署的代价。

## 失效条件

- 示范拷走后被使用者保留的比例若很低，即命令树、部署栈、打包拓扑被大幅重写，说明“一个固定的产品骨架”这个前提不成立，应重新评估它的结构，或退回由各自模板承担。
- 若示范装不起来的原因是 `pkg` 缺一个通用接口，而不是示范自身写错，那么缺的是 `pkg` 的一个接口而非示范；那种接口应按 [ADR-core-scope](adr-core-scope.md) 预言的方向固化，仍不是 `core`。
