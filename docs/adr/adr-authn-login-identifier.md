# 口令账户必须保留一个登录名，最后一个登录名保护只约束邮箱

## 背景

口令登录的登录名是用户名，或账户持有并已选作登录方式的已验证邮箱（[ADR-authn-contact-and-login-ways](adr-authn-contact-and-login-ways.md)）。用户名一经写入，在账户存续期内不可删除、不可更换（[ADR-authn-username-permanent](adr-authn-username-permanent.md)）；删除标识能移走的登录名只剩已选作登录方式的已验证邮箱。

账户自助页与管理面都允许删除标识；若删除不受登录方式数量的约束，带口令凭据的账户删掉最后一个邮箱登录名之后，口令仍然存在，却不再能认证任何东西：账户只剩手机验证码、通行密钥或外部身份等入口，界面上的口令节仍显示口令已设置，用户也无法用口令登录。

已有的「解绑最后一种登录方式」规则只覆盖外部身份绑定，不覆盖标识删除。

约束：

- 登录名是用户名，或账户持有并已选作登录方式的已验证邮箱；手机不是口令登录名。
- 用户名不可删除，没有改名操作；删除用户名的请求在账户页与管理面都被拒绝（[ADR-authn-username-permanent](adr-authn-username-permanent.md)）。
- 口令凭据是否存在是一个独立事实，与账户有没有登录名无关。
- 删除标识在一个事务内完成，失败必须整体回滚。
- 管理面与自助一侧调用同一个 `AccountAdmin.RemoveIdentifier`，两面的拒绝形态应一致。
- 没有口令凭据的账户以短信、通行密钥或外部身份登录，不依赖登录名。
- 正常写入下每个用户账户都有用户名；库里没有用户名的行只能来自绕过写入接口。

## 考虑过的选项

### 允许删除，由界面提示或禁用唯一登录名的删除按钮

服务端不为最后登录名加判定，前端在只剩一个登录名时隐藏或禁用删除入口。

**否决**：界面约束不是不变量。直接调用 API、并发删除或更换客户端都能留下无法口令登录的账户；服务端是唯一能保证该性质的位置。

### 删除最后一个登录名时连带删除口令凭据

把账户自动降级为无口令账户，使状态与「没有登录名」自洽。

**否决**：删除标识不应隐式删除另一项凭据。持有人以为只是删掉一条标识，实际失去口令，需要重新设口令而账户上可能没有可作登录名的邮箱；这一步还会改变认证事实，超出删除标识的语义。

### 允许删除用户名，由最后一个登录名保护兜底

用户名可以像邮箱一样删除，只剩一个登录名时拒绝删除。

**否决**：用户名是账户的永久标识，删除用户名就是开放改名，与用户名不可更换冲突；删除与添加之间还会留下没有用户名的账户，最后登录名保护要重新覆盖用户名。

### 拒绝删除最后一个登录名，并允许先添加另一个

删除前要求账户还有另一个登录名——用户名，或已选作登录方式的已验证邮箱；正常写入下账户总有用户名，需要保护的只剩邮箱登录名；没有口令凭据的账户不受限，删除手机不触发规则。

**采纳**，见决策。

## 决策

采纳：**带口令凭据的账户删除标识后必须仍保留至少一个登录名；删除最后一个登录名时 `RemoveIdentifier` 在事务内返回 `authn.ErrIdentifierRequired`，删除回滚（REQ-account-044）。用户名一经写入不可删除、不可更换，删除用户名在账户页与管理面答 409 `username-immutable`（Go 哨兵 `authn.ErrUsernameImmutable`），删除不生效（REQ-account-070）；最后一个登录名保护因此只约束已选作登录方式的已验证邮箱。没有口令凭据的账户不受此限，删除手机永不触发该规则。**

- 判定在 `AccountAdmin.RemoveIdentifier` 的事务内完成，读口令凭据行的存在与剩余的标识，判定删除后是否仍有一个登录名；拒绝不留下部分状态，也不发布删除事件。
- 自助一侧与管理面把 `ErrIdentifierRequired` 映射为 409 `login-identifier-required`，把 `ErrUsernameImmutable` 映射为 409 `username-immutable`，两面形态一致。
- 删除最后一个 `Proves` 为真的邮箱仍把 `signup_state` 从 2 拉回 1，但这只在删除生效时发生。正常写入下账户总有用户名，删除邮箱不会命中 `ErrIdentifierRequired`；账户此后是否视为未验证取决于它是否还持有别的已证明邮箱（[ADR-authn-signup](adr-authn-signup.md)）。只有在绕过写入接口、库中没有用户名的行上，这条邮箱同时是唯一登录名时，删除先返回 `ErrIdentifierRequired`，删除不生效，状态不变。
- 账户没有改名操作，前端不提供更换用户名的入口；删除用户名的直接请求得到 409 `username-immutable`。
- 无口令凭据、库中没有用户名的行删除最后一个邮箱登录名之后，再设口令得到同一个 409：口令需要一个登录名。
- 各接口的契约细节由账户、登录与管理面的设计文档给出，本记录不重述。

## 后果

口令账户在任何时候都保留至少一个可以配合口令使用的登录名，删除标识不会静默地把账户变成只能用其他方式登录的状态；用户名不可删除，删除操作能移走的登录名只有邮箱；管理面与自助一侧对同一种拒绝给出同一个错误码。

**接受的代价：**

- **唯一登录名的删除请求会失败。** 删除最后一条已选作登录方式的已验证邮箱时，客户端必须渲染 409 `login-identifier-required` 并引导用户先添加登录名，而不是把它当作通用错误。
- **删除用户名一律被拒。** 持有人或管理员不能用删除用户名的办法改掉账户已有的名称，只能删除账户另建；客户端必须渲染 409 `username-immutable`，而不是把删除当作可用的操作。
- **管理面的运维脚本会遇到新的拒绝。** 删除最后一条邮箱登录名或删除用户名的管理员请求答 409，脚本需要先添加登录名或改为删除账户。
- **无口令账户的后续设口令仍可能被拒。** 库中没有用户名的行可以删除最后一个邮箱登录名，但随后设口令会得到同一个 409，用户需要先添加登录名。
- **状态可能经其他写入接口出现。** 本规则只约束 `RemoveIdentifier`；正常写入下每个账户都有用户名，库中没有用户名的行只能来自绕过写入接口。这类行上的口令账户没有登录名可删，删除其手机等操作仍按无登录名的状态处理。

## 失效条件

- 写入路径不再保证每个用户账户都有用户名，库中可以出现没有用户名的行；最后一个登录名保护重新成为账户一侧的常规规则，而不是只在绕过写入接口的行上可达的边界。
- 产品要求账户可以在没有登录名的情况下用口令认证，或要求删除最后一个登录名时自动迁移到另一个登录名，本决定的前提不再成立。
- 产品允许删除或更换用户名，用户名不可删除的前提不再成立。
