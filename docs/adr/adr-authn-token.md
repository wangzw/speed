# 令牌：JWT 访问令牌与不透明刷新令牌，签名密钥放文件，服务账户走 client_credentials

## 背景

浏览器用 cookie 会话（[ADR-authn-session](adr-authn-session.md)）；脚本、移动应用与服务没有 cookie 罐，需要另一种载体。这个载体要同时满足以下约束：

- 第三方资源服务器可以只凭公钥离线验签，不必回调 authn。
- 撤销要与会话的撤销面一致：会话被撤销、账户被停用、口令被改，已发出的令牌随之失效，不能各设一套撤销机制。
- 令牌默认不携带角色；角色由授权模块实时查询并自行缓存。
- 冒充要有对应的令牌形态，而且冒充的结束必须即时生效。
- 非交互的 API 客户端没有人在场，需要一个不依赖口令与多因素的凭据。

令牌的校验是一个校验后端（[ADR-authn-credential-dispatch](adr-authn-credential-dispatch.md)），在网关的 `recover` 之内运行，输入是未经认证的任意字节。失败的方向由 [ADR-authn-failure](adr-authn-failure.md) 约束：依赖不可用时拒绝，有界放宽逐项列出。

**JOSE 库的事实。**

- 现有 JWT 库都把验签与声明校验分成两步，`exp` 缺失时默认放行；`typ` 没有内建的校验选项。`exp` 必填、`iss` 与 `aud` 必校、`typ` 显式，都是使用库的策略，要由桥包自己补。
- `go-jose/v4` 在解析时强制传算法白名单，自带 `JSONWebKey` 与 `JSONWebKeySet`，没有远程抓取与缓存。
- `golang-jwt/jwt/v5` 的算法白名单是可选项：校验函数返回 PEM 字节形式的公钥、又没传 `WithValidMethods` 时，RS256 到 HS256 的混淆实测通过。它没有 JWK 类型。它因 `go-webauthn` 已在模块图里。
- `go-oidc/v3`（企业 SSO 与社交登录的校验桥，[ADR-authn-oauth-flow](adr-authn-oauth-flow.md)）依赖 `go-jose/v4`，其要求的 v4.1.4 受 GHSA-6mp9-8xrw-74r4（畸形输入触发 panic，修于 v4.1.5）影响。`go-jose` 另有 CVE-2026-34986（JWE 解密触发 panic）。

**状态的事实。**

- 刷新令牌的重用检测依赖「这个令牌已被用过」这一条记录；记录丢失，重用就无法识别，方向是放宽。这类状态按 [ADR-authn-state-placement](adr-authn-state-placement.md) 进 db。
- 多副本同时启动时，谁来生成签名密钥没有天然的仲裁者。

## 考虑过的选项

### `golang-jwt/jwt/v5` 作 JOSE 桥

已因 `go-webauthn` 在模块图里，引入它不新增模块。

**否决**：安全性取决于调用方每次都传 `WithValidMethods`、`WithExpirationRequired`、`WithIssuer`、`WithAudience`，并让 keyfunc 只返回带类型的公钥；漏掉任何一项，缺省行为都是放宽。`go-jose` 把白名单变成解析的必传参数，漏传不是能编译的写法。它没有 JWK 类型，发布 JWKS 要另行实现。`go-oidc` 仍然带入 `go-jose`，选它的结果是依赖图里同时有两套 JOSE 实现，而不是少一套。它已经在图里这一点不构成选它的理由，也不构成否决它的理由；选 `go-jose` 的依据只有：白名单解析时必传、自带 JWK 与 JWKS 类型、与 `go-oidc` 共用同一套 JOSE 类型。换库只波及 `authn/token` 一个包。

### `lestrrat-go/jwx` 作 JOSE 桥

密钥与算法成对给出，默认校验声明，`jku` 须显式开启；自带 JWKS 远程缓存。

**否决**：它的区别性能力是从远程抓取并缓存 JWKS，而令牌校验只用本地密钥集、从不抓取头里指向的任何地址，这项能力没有用处。当前主版本依赖一个预发布版本的 `option/v3`，上一主版本只接收常规修复，`SECURITY.md` 自述维护者人数有限，链接的模块数远多于 `go-jose`，并且与 `go-oidc` 并存仍是两套 JOSE。

### 刷新令牌也用 JWT，或访问令牌用不透明串加自省

**否决**：刷新令牌的轮换与重用检测要服务端状态，签名只增加攻击面，也不会让任何一方受益，因为刷新令牌没有被资源服务器离线验证的需要。不透明访问令牌加自省端点，等于要求每个资源服务器回调 authn；访问令牌本来就要核对会话与账户快照，自省没有额外收益，却失去第三方离线验签的可能。

### 签名私钥放 db（加密列），由模块自动生成与轮换

**否决**：多副本同时抢着生成要新增一套协调机制。加密列依赖 db 根密钥，缺根密钥时直到第一次使用才失败。私钥与根密钥同在 db 一侧，库转储加根密钥失守即全部签名钥泄露。配置里放文件路径符合「配置承载启动必须项」（[ADR-authn-settings-and-secrets](adr-authn-settings-and-secrets.md)），并且直接适配 Kubernetes 一类的密钥挂载。

### HS256 共享密钥

**否决**：每个验证方都要持有签名密钥，第三方资源服务器因此能铸造令牌；RFC 9068 建议非对称；共享密钥也是算法混淆攻击的前提。

### 按 `jti` 的撤销清单（kv 的 `SetIfAbsent`）

**否决**：清单放在 kv 里，丢键意味着「撤销失效」，方向是放宽；内存与 Memcached 实现还会无声丢键。令牌已经带 `sid`，以会话为粒度的撤销面在 db 里，已有「列出与踢下线」的权威，再加一份按令牌的清单只会产生两个互相可能不一致的撤销面。

### 令牌放进 cookie

**否决**：令牌发给 API 客户端，cookie 会话发给浏览器；把令牌放进 cookie 会把令牌与 cookie 的 CSRF 面混在一起，两个载体各自一套防线才能各自成立。

### OAuth 范围与按资源的 `aud`；发送方约束（DPoP、mTLS）；整套 OAuth 服务端框架

**否决**：当前的需求只有 JWT 认证，令牌的权能等于主体的权能，限制权能是授权模块与 `ClaimsContributor` 的事。authn 不是 OP，只需要 `client_credentials` 与 `refresh_token` 这些 grant（封闭集，见决策），整套框架（`fosite`、`go-oauth2`）带入授权码、范围、同意等当前不使用的面；这些 grant 只需要令牌端点与刷新令牌表，不需要框架的客户端注册、同意与授权码存储。发送方约束没有需求。

### 个人访问令牌

**否决**：长寿命、无持有人证明、难以审计与逐个撤销。需要长期凭据的场景用服务账户，它的密钥有账户、有到期时刻、有撤销、有审计。

### 刷新令牌清扫逐行经 `Sessions` 核对

清扫条件里前三个（会话不存在、已撤销、已过绝对期限）经 `Sessions` 接缝逐行核对，不经联表批量删除。

**否决**：逐行经 `Sessions` 核对的写法既不是一批、也没有上界，与有界批量删除不符。

### 访问令牌与刷新令牌的形态按职责分开，JOSE 桥取 `go-jose/v4`，密钥放文件

**采纳**，见决策。

## 决策

采纳：访问令牌是短寿命的 JWT，刷新令牌是不透明的随机串，二者以登录会话为撤销粒度；JOSE 的唯一桥是 `go-jose/v4`；签名密钥放配置给出的文件并按人工的分相流程轮换；非交互客户端用服务账户加 `client_credentials`。各项的判据如下；字段、校验的次序、声明取值表、界限数值、启动校验项、轮换步骤、刷新令牌的格式与表结构、撤销的逐类处理与令牌端点的应答形状由 design-authn-token 承载。

**载体与撤销面**

- 访问令牌与刷新令牌的撤销粒度是登录会话（`sid`），撤销与会话共用一个面。令牌侧不设按 `jti` 的清单；账户级 `valid_after` 使该时刻之前签发的令牌一律失效。
- 令牌的声明集不含授权相关的声明，角色、租户、权限与范围是其中的例子。宿主经 `ClaimsContributor` 追加声明时，追加的名字不得与本模块使用的保留名冲突，冲突以 `ErrReservedClaim` 拒绝；把角色放进令牌是宿主的选择，角色在令牌有效期内无法撤销是该选择的后果。
- authn 不是 OIDC 的 OP：不实现授权端点与授权码授权；支持的 grant 是封闭集：`client_credentials` 与 `refresh_token`。不提供个人访问令牌。交互式脚本与应用经登录流程的 `delivery=token` 取令牌对。
- `authn.token` 作为校验后端登记，只认领 `Authorization` 的 `bearer` 方案；登记的账户命名空间与能力声明见设计文档。

**JOSE 桥与使用策略**

- 桥是 `go-jose/v4` 的 `jose` 与 `jwt` 子包。`pkg/go.mod` 对它的下限是 v4.1.5。这是一条必须守住的约束，`go-oidc` 要求的 v4.1.4 受 GHSA-6mp9-8xrw-74r4 影响。
- 签名算法是非对称算法的封闭集，缺省 ES256，可配 RS256；不支持对称算法与 `none`。每把密钥只配一种算法，且启动校验要求每把密钥的算法都等于配置的 `authn.token.algorithm`，所以验证用的白名单是该算法本身、恒为单元素集合；运算前由桥自己核对头里的算法等于该密钥登记的算法。
- 访问令牌的头 `typ` 取 `at+jwt`，使访问令牌与 OIDC ID 令牌等其他令牌互斥。头里指向外部密钥材料的字段一律不采用、不抓取，不认识的关键扩展一律拒绝；公钥只从本地密钥集按 `kid` 取，取不到即拒绝。`kid` 取公钥的 RFC 7638 指纹，不取配置里的名字。
- 声明的必需项、`iss` 与 `aud` 的必校、有效期长度的上界，是桥自己补的策略，不依赖库的缺省，因为库的缺省对缺失声明放行。解析之前先限制令牌总长；非测试代码里禁止出现 `UnsafeClaimsWithoutVerification`，由依赖测试或静态检查守住。

**声明的取值**

- `sub` 是生效账户：冒充令牌里是被冒充者。服务账户令牌的 `sub` 是该账户标识而不是 `client_id`，避免客户端自选 `sub` 造成混淆（RFC 9068 §5）。
- `amr`、`acr`、`auth_time` 的取值与 [ADR-authn-mfa](adr-authn-mfa.md) 的闭集一致，只为让外部资源服务器不必再查会话。`check-session` 为真时，本进程校验不比较它们，也不因不一致而拒绝：认证后端建立身份时取自会话行。加强认证之前签发、仍在有效期内的令牌因此继续有效，它的 `acr` 偏低是保守的一侧。`check-session` 为假时不读会话行，普通令牌的方式集、等级与认证时刻取自令牌自己的这三个声明，冒充令牌同样取自令牌的 `amr`、`acr` 与 `auth_time`；这几个值由本模块自己签发，但等级随令牌而非会话行，属于该放宽开关的一部分。
- 冒充令牌带 `act`（RFC 8693 §4.1）、`imp` 与 `imp_tenant`。冒充令牌的 `amr`、`acr` 与 `auth_time` 取自发起的会话：身份的认证事实取自发起者，与生效账户无关。`imp_tenant` 只供外部校验方读到冒充的范围；本进程校验时范围取自冒充记录，不取这个声明。

**校验的判据**

- 令牌的签名与声明只证明它由本系统签发，不证明它仍有效：账户快照、会话与冒充记录都要读。`Principal` 在全部检查通过之后才构造。账户非 `Active`，或签发时刻早于账户的 `valid_after`，一律 `Denied`。
- 令牌带 `sid` 或 `imp`，而对应的会话或冒充能力缺席，一律 `Denied`。db 不可用时：缓存命中按缓存，未命中答 `Unavailable`（503），不放行。
- `check-session` 是设置项，缺省为真。设为假时关闭整个会话步骤：不读 `Sessions.Status`，也随之跳过 service 种令牌的 `sid` 指向 `service` 种行这一核对。成为「对普通令牌无状态」的模式，撤销最晚到令牌 `exp` 才生效，方式集、等级与认证时刻随令牌（见上），`Provider` 为空、`IDPAssured` 为假。它不关闭账户快照，也不关闭 `imp` 非空时对 `Impersonation.Active(imp)` 的读取：冒充的结束、管理员或目标被停用、成员关系被移除、记录被管理面撤销照常即时生效。这是显式的放宽开关，缺省不开；运行期设为假时写一行 `Warn` 并记 `authn.settings.relaxed`，启动时已是假时写同一行 `Warn`。
- 冒充令牌与会话端的规则对称（[ADR-authn-impersonation](adr-authn-impersonation.md)）：令牌里的操作者、目标与管理员会话的账户都必须与冒充记录相符，任一不符即 `Denied`；保障等级、认证时刻、方式集与 `IDPAssured` 取自发起者的会话，范围取自冒充记录。
- 外部资源服务器用 JWKS 离线校验时，必须校验 `iss`、`aud`、`typ`、`exp` 与签名，并接受它读不到撤销这一事实；冒充令牌的范围读 `imp_tenant`。

**签名密钥、轮换与 JWKS**

- 签名私钥与验证密钥都放配置给出的文件，是启动必须项，不落库，不进设置。没有配置签名私钥时，本模块只验证、不签发：`Tokens.Issue` 返回 `ErrNoSigningKey`，签发路径答 503。不自动生成，不自动轮换。启动校验不符即终止启动并点名文件。
- 轮换是人工的分相流程：先让全部副本的验证密钥认识新钥，使 JWKS 已发布它、各副本都认它签的令牌；等待超过 JWKS 的缓存时长之后，才把签名密钥切到新钥；旧钥在其签出的令牌全部过期、且任何 JWKS 缓存都不再持有它之后移除。顺序保证任一时刻没有副本签出另一副本不认识的令牌。刷新令牌是不透明的，不受轮换影响。
- 应急撤销一把泄露的密钥：从全部副本的配置里删去它并滚动重启，用它签的令牌随之被拒；会话仍有效，用户用刷新令牌换新令牌。
- JWKS 公开发布全部已配置密钥的公钥，不含任何私钥字段，带有限的公开缓存时长，轮换的等待时间依据它计算。

**刷新令牌**

- 刷新令牌是不透明的随机串，带可识别的前缀，库里只存摘要：库转储得不到可用的令牌，前缀使密钥扫描工具与日志脱敏的匹配器能识别它。「族」就是会话，刷新令牌的权威存放在 db。
- 每次使用即轮换。出示一个真实存在、已被用过的旧令牌，判定重用：撤销该会话（整族失效），发 `authn.token.reuse-detected` 事件，写审计，应答 `invalid_grant`。合法客户端与窃取者必有一方出示已作废的令牌，服务端分不清是谁，所以撤销当前有效的整族，代价是合法客户端要重新登录（RFC 9700 §4.14.2）。出示库里不存在的字符串只应答 `invalid_grant`，不触发撤销：任意字符串若能触发撤销，任何人都能把别人踢下线。
- 重用宽限缺省关闭，即严格；宽限若开，上限由设置的取值范围约束，窗口内重复出示视为客户端重试。
- 刷新时会话强制新读，不走缓存。消费是对「尚未被用过」这一条件的原子更新，以影响行数判胜负，不依赖 `RETURNING`。刷新不抬高保障等级：新访问令牌的 `acr` 与 `auth_time` 取自会话行。
- 绝对期限是会话的 `expires_at`，取值规则见 design-authn-session；空闲期限在刷新令牌行上，每次轮换重置。`token` 种会话不受浏览器会话的空闲期限约束。改口令、停用账户、会话被撤销，都使整族失效，因为每次刷新都核对会话行。
- 冒充会话与客户端凭据不签发刷新令牌。

**服务账户与令牌端点**

- 服务账户（`kind=service`）由管理面创建，动作是 `authn.client.manage`。密钥只在创建应答里出现一次，库里只存摘要。账户可同时持有多个有效密钥，使客户端无停机切换。账户与密钥的存放见 [ADR-authn-accounts](adr-authn-accounts.md)。
- `client_credentials` 的客户端标识是账户标识。校验失败的退避键是出示的 `client_id` 字符串，与该账户是否存在无关，应答统一为 `invalid_client`（[ADR-authn-throttling](adr-authn-throttling.md)）。服务账户不经 `Basic` 校验后端。
- 成功时取得或创建该密钥对应的 `service` 种会话，会话的有效性随密钥，只经撤销密钥终结（[ADR-authn-account-lifecycle](adr-authn-account-lifecycle.md)）；只签发访问令牌，没有刷新令牌。这类令牌的身份是方式 `client-secret`、单因素。
- `Tokens.Revoke` 遵循 RFC 7009，出示的令牌有效、无效或不存在都答 200，使出示者无从探测令牌的状态；依赖答不出来时答 503，不报一个没有发生的撤销。撤销只作用于出示的令牌对应的最小对象：刷新令牌撤其会话；冒充令牌结束它的冒充记录而不撤管理员的会话；`service` 种访问令牌上无操作，因为该行由同一密钥签出的全部令牌共享，按令牌撤销会连带终结其余令牌，要立即失效只能撤销密钥或前移账户的 `valid_after`。
- 令牌端点自带客户端认证。失败应答用 RFC 6749 §5.2 的 JSON 形状，不走入口模块 `Fail` 的缺省形状：OAuth 客户端库按 `error` 字段解析，读不懂 `problem+json`。这是对「拒绝经 `Fail` 写出」的有意例外。db 不可用答 503 `temporarily_unavailable`，不是 `invalid_grant`，客户端据此保留刷新令牌重试。

## 后果

访问令牌可被第三方资源服务器离线验签；本进程的校验则读会话与账户，撤销与登录会话共用一个面，没有第二套撤销状态需要保持一致。`go-jose` 的白名单必传使「忘了传白名单」不再是能编译的写法，算法混淆与 `alg:none` 在解析处被拒；缺 `exp`、缺 `typ` 的令牌由桥的策略拒绝，不依赖库的缺省。

签名密钥不进库，库转储得不到签名钥；密钥文件的存放与 Kubernetes 的密钥挂载一致；多副本没有生成密钥的竞争。刷新令牌的重用检测在 db 里，丢失键值存储不会让重用无法识别。冒充令牌在 `check-session` 关闭时仍然可以即时终结。

**接受的代价：**

- 访问令牌被盗后，在其有效期内可重放，没有持有人证明。服务账户的访问令牌无法逐枚撤销：要立即失效，只能撤销密钥（连带其会话）或前移账户 `valid_after`。
- `check-session` 为假时，普通令牌的方式集、等级与认证时刻随令牌而非会话行；加强认证或降级之后，仍在有效期内的令牌保持签发时的值。
- `check-session` 开启时，缓存未命中的每个带访问令牌的请求有一次 db 点查，抵消了「JWT 免查库」的一部分好处。这是可撤销性的代价，由 `check-ttl` 缓冲，且可由放宽开关关闭；关闭后撤销最晚到令牌 `exp` 才对普通令牌生效。
- 刷新宽限若开启，窃取者在宽限窗口内有一次不被识破的机会；缺省 0 时两个标签页并发刷新，后到的一方被当作重用，合法客户端要重新登录。
- 密钥轮换是人工的分相流程，要靠运维纪律，每相都要滚动重启；密钥文件的权限只能 `Warn`、不能强制；没有 KMS 或 HSM 的签名接缝。
- 令牌端点用 OAuth 的错误形状，与 authn 其他端点的 `problem+json` 不一致，调用方要为这一处单独解析。
- JWT 载荷只编码不加密：令牌里的账户标识、认证方式与会话标识对持有者可读。
- `go-jose` 披露过高危公告，版本要紧跟；下限只靠 `pkg/go.mod` 里的一条要求维持，删去它会使依赖图里 `go-oidc` 的要求把版本带回受影响的 v4.1.4。
- 依赖图里同时存在 `go-jose` 与 `golang-jwt`（后者经 `go-webauthn` 进入）：`authn/token` 不使用后者，但它仍在图里，其公告同样需要关注。
- 不提供个人访问令牌，也不是 OP：需要长期凭据的人工使用者没有现成的出口，只能经服务账户，或经 `delivery=token` 的登录取得会过期的令牌对。

## 失效条件

以下假设尚未核实，各自由一条守住它的测试承担；测试失败或假设不成立时，对应的判据需要重写，而不是在桥里打补丁。

- 假设 `go-jose` 不在运算时核对「每把密钥只配一种算法」，因此桥自己核对头里的算法。守住它的测试：头里的算法与密钥登记的算法不一致的令牌被拒，算法在白名单之外的令牌被拒。
- 假设取得已解析令牌 `typ` 头的接口，与签发时设置 `typ` 的 `WithType` 选项，在实际依赖的 `go-jose` 版本上与已核对的版本行为一致（已核对的版本早于下限 v4.1.5）。守住它的测试：`typ` 缺失、取值为 `JWT`、`at+jwt` 与 `application/at+jwt` 的大小写变体、OIDC ID 令牌，逐一给出期望的接受或拒绝；签发的令牌头里 `typ` 为 `at+jwt`。
- 假设限长加网关的 `recover` 足以收口 `go-jose` 披露过的畸形输入 panic。若出现限长之内、`recover` 接不住的崩溃（例如致命的栈耗尽），仅靠限长不足以守住校验后端，需要把解析放到受限的执行环境里。守住它的测试：已披露公告的畸形向量在校验入口得到 `Denied` 而不是进程崩溃。
- 假设不依赖 `RETURNING` 的条件更新能在两个 db 方言下仲裁并发刷新。守住它的测试：对同一刷新令牌的并发出示，恰有一个成功，其余按宽限或重用处理。
- 假设 `check-session=false` 不使冒充令牌失去可撤销性。守住它的测试：该开关下结束冒充后，同一冒充令牌被拒；冒充令牌打到不在准入层所守的端得 401，打到别的租户得 404。
- 假设外部资源服务器接受「离线验签读不到撤销」。若出现要求外部资源服务器即时感知撤销的场景，需要自省端点或更短的访问令牌有效期，本记录里「不设自省」的判据随之失效。
- 假设人工两相轮换与应急撤销的运维成本可接受。若合规要求自动轮换，或要求密钥不落在进程可读的文件里，需要 KMS 或 HSM 的签名接缝，「密钥放文件」的判据随之失效。
- 假设没有第三方应用需要经授权码授权取得本系统的令牌，也没有需要长寿命个人令牌的人工使用者。任何一项成立，「不是 OP、无个人访问令牌」的判据重议，选用整套 OAuth 服务端框架的评估重新开始。
