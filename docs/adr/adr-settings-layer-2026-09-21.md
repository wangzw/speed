# 设置的层由显式的层选指代，零值不是一个层

## 状态

已接受

## 背景

设置的读写四个方向都收一个字符串租户参数，空串指全局层（[ADR-settings-precedence-2026-09-21](adr-settings-precedence-2026-09-21.md) 记下了这一编码选择）。全局层因此与"没有租户"共用同一个值，接口上分不开。

调用点上的两种情形由此同形：本该作用于一个租户而漏填了标识，与有意指名全局层。漏填的后果是全站动作——一次本该影响一个租户的写入改掉了全体租户共享的那一格，而调用点的一切看起来都正常。

租户标识的取值域里没有空串：请求面取出的名字非空且不含空白，名册上换成的标识同样非空（[ADR-tenant-identifier-2026-09-21](adr-tenant-identifier-2026-09-21.md)）。空串从来不是"某个租户"，它在接口上只是全局层的一个别名。

消费方从请求上下文取出标识，取不到租户时读全局层还是拒绝由调用方决定（[ADR-settings-scope-2026-09-21](adr-settings-scope-2026-09-21.md)）：这两档在字符串参数上落在同一个格子里。

[ADR-settings-scope-2026-09-21](adr-settings-scope-2026-09-21.md) 记下的失效条件由此触发：一种只需要读一个全局设置、不持有任何租户概念的消费方，被空租户表达迫使在每个调用点写下一个可能被误读为空值的东西。本记录是对该失效条件的处置。该记录的决策——租户标识以字符串表达、本模块不 import `pkg/tenant`——仍然成立，本记录不取代它。

## 考虑过的选项

### 保留字符串参数，空串继续指全局层

**否决**：这正是本记录要消除的形态。"漏填"与"有意指全局"在接口上同形，静默的全站后果没有代价可换。

### 保留字符串参数，把空串判为非法

读写面拒收空串，全局层另择一个哨兵值。

**否决**：哨兵值与真实标识之间靠约定区分，而约定无人强制。一个恰好等于哨兵的租户标识会静默地写进全局层，与空串是同一类失效，只是换了一个值。

### 导出的层结构体，零值指全局层

层是导出的结构体，字段是租户标识，零值的结构体指全局层。

**否决**：零值不可用是这一项裁定的判据本身，而结构体的零值必然存在且可用——`Layer{}` 与 `Global()` 是同一件事的两个写法，问题原样保留。

### 每个方向给两个方法

读取、写入、删除、列举各给一对方法，一个作用于租户层，一个作用于全局层。

**否决**：四个方法翻倍成八个，而每个调用点仍要先判"这次是全局还是某个租户"——那正是回落与选层要收进本模块的判断。调用方多写的一层分支没有比字符串参数更安全，只是把同一个错误搬到了另一个位置。

### 封口的层选接口，配两个构造器

层是接口类型，带一个未导出方法，因而只有本模块能实现它；两个构造器分别交出全局层与租户层。

**采纳**，见决策。

## 决策

采纳：**设置的层由显式的层选指代，零值不是一个层。** 读写面收层选，不收字符串租户标识；指名一个层要经构造器，租户层的构造器只收租户标识取值域之内的标识（非空、不含空白与控制字符），域外的一律拒收。

**零值不可用是调用点的编程错误**，当场 panic，不返回错误。判据与"非法形态是调用点的编程错误"这一类同一条，与 `core` 收非法功能标识的处置同类：不涉及第二方，与数据无关，首次执行即确定暴露，调用点也无从处理它——修法是改代码。

本记录一并承载设置的取值三级回落：读取按「租户行 > 全局行 > 声明默认值」依次回落。

**全局行以空的租户列落在与租户行同一张表里。** 租户标识的取值域里没有空串——请求面取出的名字非空且不含空白，名册上换成的标识同样非空（[ADR-tenant-identifier-2026-09-21](adr-tenant-identifier-2026-09-21.md)）——空的租户列因而不与任何真实租户相撞，在存储上唯一地指全局行。接口侧不以空值指代全局层，指名层由层选承担。

**设置的表不自持租户插件**：它承载全局行，因而不内嵌租户模块的模型约定、不依赖名册与隔离插件；按租户的取数在查询自身携带的条件里完成。这同时是"设置不依赖 `pkg/tenant`"的一部分（[ADR-settings-scope-2026-09-21](adr-settings-scope-2026-09-21.md)）。

**读设置的租户层要先有租户**：这条推论在 [ADR-tenant-resolution-2026-09-21](adr-tenant-resolution-2026-09-21.md) 否决"取法由设置给出"的理由里已被用上，本记录与它一致——取法在数据库可用之前就被需要（[ADR-config-scope-2026-09-13](adr-config-scope-2026-09-13.md) 的判据），而读设置的任何一层都要先有数据库。

本记录取代 [ADR-settings-precedence-2026-09-21](adr-settings-precedence-2026-09-21.md) 整篇。

## 后果

接口上不再存在"空租户"这个值，层在每一个调用点都是显式指名的。漏填与有意指名全局层不再同形：漏填留下的是一个零值，它在调用点当场 panic。

消费方仍从请求上下文取出标识，经构造器打包成层选；取不到租户时读全局层还是拒绝仍由调用方决定。

**接受的代价：**

- **宿主与消费方对设置的每一处调用都要改。** 字符串与层选之间的转换只在调用点发生；接口的稳定性承诺随之把层选与两个构造器收进契约面。
- **零值检测是运行期的，不是编译期的。** 不构造层选的调用点仍然编译通过，跑到那里才 panic；编译器不参与这一项保护。
- **接口值比字符串重。** 层选是一个接口值，跨模块传递它比传一个字符串多一层间接；回落与快照查找的路径不因它改变。
- **"没有租户"这一档仍由调用方处置。** 租户层的构造器拒收空标识，判断"该读全局层还是拒绝"仍在调用方，与 [ADR-settings-scope-2026-09-21](adr-settings-scope-2026-09-21.md) 记的代价同一条。
- **存储侧的表达不变。** 全局行仍以空的租户列落在同一张表里；改变的是接口，不是表。

## 失效条件

若出现第三种层的需求——一个集团的取值要能覆盖在子租户之上——两个构造器表达不了它，层的表达方式需要与层级化的形状重新比较。

若层选在消费方侧造成大量适配代码——层需要被存进配置、跨进程传递或序列化——则封口接口是否仍是最合适的形状需要重新裁定。
