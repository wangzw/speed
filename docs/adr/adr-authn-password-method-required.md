# 口令登录方式不可被关闭

## 背景

`authn.login.disabled-methods` 是运行期设置，取值为登录方式名的数组，用于在事故中关闭某个方式，例如短信轰炸时关闭 `sms`（[ADR-authn-settings-and-secrets](adr-authn-settings-and-secrets.md)）。登录方式发现与登录流程按这个设置判定一个方式是否可用（REQ-signin-001）。

用户名加口令是不依赖持有人另行登记其他因素即可使用的登录方式。每个用户账户在任一写路径建号时都带一个合法用户名，没有用户名就不建户（REQ-signup-004、[ADR-authn-username-required](adr-authn-username-required.md)）；服务账户以服务密钥登录，不作这项要求。用户名一经写入，在账户存续期内不可删除、不可更换（[ADR-authn-username-permanent](adr-authn-username-permanent.md)）。如果部署能经 `authn.login.disabled-methods` 关闭口令方式，账户会保留一个不可删除、不可更换的用户名，同时不能用它认证；没有已验证邮箱选作登录方式、也没有绑定外部身份或登记通行密钥的账户，因此失去全部登录入口，且无法由持有人自行恢复。

账户级规则不覆盖部署层。口令账户保留至少一个登录名（[ADR-authn-login-identifier](adr-authn-login-identifier.md)）约束的是账户删除标识，不约束部署设置；部署可以在每个账户都保留用户名的情况下关闭口令方式，账户级保证在部署层不产生作用。

相邻开关都不关闭口令登录方式：

- `tenant.admission.require-sso` 是租户准入要求：成员访问租户时须经企业单点登录认证。它不改变账户能否以口令认证。
- `authn.account.password-signup` 是口令注册开关：决定能否经口令注册开新账户。它不改变已有账户以口令登录。
- `authn.login.password-reset` 是匿名口令重置开关：决定能否不经登录找回口令。它不改变口令登录本身。

需要成立的条件：

- 口令方式的在场只由口令模块是否装配决定，装配归宿主。
- 写入面不是唯一写入途径：直接写库或宿主自建的设置写入口可以留下含 `password` 的原生值，读取侧不得据此关闭口令方式。
- 相邻开关的语义各自成立，不被读作「关闭口令登录」。

## 考虑过的选项

### 允许部署经 `authn.login.disabled-methods` 关闭口令方式

`password` 是合法取值，写入生效，发现文档与登录应答移除口令方式。

**否决**：关闭后，账户仍持有一个不可删除、不可更换的用户名，却不能以它认证。没有已验证邮箱选作登录方式、也没有绑定外部身份或登记通行密钥的账户失去全部登录入口，且无法由持有人自行恢复。口令方式因此不是部署可关闭的方式。

### 只靠账户级「用户名永远是登录方式」的保护，不约束部署开关

账户层保证每个账户有用户名与登录名（[ADR-authn-login-identifier](adr-authn-login-identifier.md)），`authn.login.disabled-methods` 维持现状。

**否决**：账户级规则约束标识删除，不约束部署设置。部署可以在每个账户保留用户名的情况下关闭口令方式。账户级规则与部署级开关互相独立，账户级规则在部署层不产生作用。

### 允许关闭，但要求另一方式在场作兜底

写入 `password` 前要求至少一个其他登录方式已装配并启用，否则拒绝写入。

**否决**：方式在场是部署级能力，不是账户可用性。账户可能未绑定任何外部身份、未登记手机、未登记通行密钥；一个全局启用的社交或企业方式不使该账户可登录。兜底条件使保证取决于部署配置与账户登记的组合，仍允许移除每个账户唯一必然可用的方式。

### 只在写入侧拒绝，读取侧照常生效

取值域拒绝 `password`，读取侧信任库中原生值。

**否决**：写入面不是唯一写入途径。直接写库或宿主自建的设置写入口可以留下含 `password` 的原生值，读取侧照常关闭口令方式，且没有信号指出这次绕过。口令的可用性会依赖写入面的完整性。

### 取值域拒绝口令方式，读取侧过滤原生值

`authn.login.disabled-methods` 的取值域不含 `password`，含它的写入被拒绝；读取时过滤原生值里的 `password` 并记一条 Error；口令方式照常可用。口令方式是否在场只由口令模块是否装配决定。

**采纳**，见决策。

## 决策

采纳：**`authn.login.disabled-methods` 的取值域不包含 `password`；含 `password` 的写入被取值域拒绝、不生效。读取该设置时，库中原生值里的 `password` 被过滤掉，口令方式照常可用，并记一条 Error。口令方式是否在场只由口令模块是否装配决定，装配归宿主。**

- **取值域。** 设置的取值域拒绝 `password`；写入该值的请求不生效，设置保持原值（REQ-signin-039）。取值域拒绝适用于该设置接受的写入，不区分写入来源。
- **读取侧过滤。** 每一处读取 `authn.login.disabled-methods` 的路径先移去 `password` 再作判定；口令方式因此始终被视为未关闭。原生值含 `password` 时记一条 Error，指出该键的原生值含口令方式，供运维纠正。
- **口令方式的在场。** 装配了口令模块的部署中，匿名发现文档与登录入口始终列出口令方式；口令方式只随口令模块的装配出现或消失（REQ-signin-001、REQ-signin-039）。
- **相邻开关。** `tenant.admission.require-sso`、`authn.account.password-signup` 与 `authn.login.password-reset` 各自按本义生效，都不是关闭口令登录方式：`tenant.admission.require-sso` 是租户准入要求，`authn.account.password-signup` 是注册开关，`authn.login.password-reset` 是匿名重置开关。这些开关在打开或关闭的任一取值下，装配了口令模块的部署仍列出口令方式，账户仍可以口令登录（REQ-signin-039）。
- **写入面之外的写入。** 系统不把设置写入面的完整性当作前提；绕过写入面的原生值由读取侧过滤兜底，并留一条 Error。
- 拒绝的形状、日志字段与发现文档的字段由登录与配置的设计文档给出，本记录不重述。

## 后果

装配了口令模块的部署中，口令登录方式在任何运行期设置下都可用；每个用户账户持有的用户名因此总有一个可用的认证入口。账户级规则约束账户内的标识，部署级开关约束部署范围的方式可用性，两者互相独立。

**接受的代价：**

- **紧急关闭的取值域少了一个方式。** `authn.login.disabled-methods` 可以关闭短信等事故相关的方式，不能关闭口令方式。需要在运行期停用口令登录的部署没有这个杠杆，只能改变装配或调整租户准入。
- **原生值会被过滤并记 Error。** 绕过写入面留在库中的 `password` 不会被读取侧自动改写；读取照常提供口令方式，并记一条 Error 指出该键的原生值含口令方式。该记录按值去重，同一个值不重复记录，直到该行被纠正或读到一次干净的值。
- **取值域不再是「全部登录方式名」。** 运维工具、设置界面与文档要说明 `password` 不在可关闭集合内；把口令方式与其他方式并列展示的界面需要另作呈现。
- **相邻开关更易混淆。** 想停用口令登录的运维者会先碰到 `authn.account.password-signup`、`authn.login.password-reset` 与 `tenant.admission.require-sso`，这些开关都不产生这个效果。文档与界面必须分别说明它们的本义，否则操作者会以为已经关闭口令登录。
- **装配排除仍在宿主手里。** 宿主不装配口令模块时，口令方式不在场，本决定不使其可用。口令方式「不可关闭」的保证以装配为前提。
- **账户可能没有口令凭据。** 口令方式可用不等于每个账户都有口令。开户时未设口令的账户仍不能以口令登录，需要先设置口令。

## 失效条件

- 产品要求部署能在运行期停用口令登录，例如合规要求某一时段只允许企业单点登录；此时取值域拒绝不再成立，停用需要由另一个机制承载并写明其对账户的影响。
- 出现一种每个用户账户都必然持有、且不依赖部署装配与账户登记的登录方式，使口令不再是唯一必然可用的入口；口令方式可以被关闭的前提随之改变。
- 口令模块不再是可装配的模块，口令方式在所有构建中恒在场；「装配是否在场」这一条件失去含义，决定需要按新的在场规则重写。
