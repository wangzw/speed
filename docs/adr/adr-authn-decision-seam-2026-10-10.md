# 判定接缝 Decider：管理面与冒充缺席即全拒，自助范围不过接缝

## 状态

已接受

## 背景

`pkg/authn` 交付身份系统，授权另立，`pkg/authn` 不 import 授权模块（[ADR-authn-scope-2026-10-10](adr-authn-scope-2026-10-10.md)）。身份系统自己的管理面动作作用于他人的账户或租户级资源：建账户、停用与删除账户、重置他人的因素与口令、读写成员关系、配置企业 IdP 与域、创建与撤销服务账户的密钥、撤销他人的会话、发起冒充。「谁可以做这件事」需要认识资源、动作与一份策略，策略的模型形态由应用决定，授权不在 authn 内，由授权模块或宿主经判定位置提供。authn 需要一个自己定义、由别人交付的判定位置。

这些动作要经 HTTP 对外，处理函数由 authn 自己交付，请求到达时已过网关，调用方的身份已定。authn 的挂载端不在准入层所守的端之内（[ADR-tenant-admission-2026-10-10](adr-tenant-admission-2026-10-10.md)），所以管理路由上没有租户上下文，租户归属只能由 `authn.admin` 解析。自助动作不同：账户读写自己的会话、因素、口令与标识，授权依据是「就是这个账户」，不需要策略。

判定位置缺席时的失败方向是拒绝（[ADR-authn-failure-2026-10-10](adr-authn-failure-2026-10-10.md)）。模块之间的取用受 `core` 规则约束：排他功能写进 `Requires`，漏点名即在构造之前以 `core.ErrMissingProvider` 启动失败；取用方在 `Init` 里以 `Optional` 取用时，提供者缺席是合法配置（[ADR-authn-wiring-2026-10-10](adr-authn-wiring-2026-10-10.md)）。「默认拒绝」要求宿主什么都不做也是安全的。

判定要的输入里，租户并不总在请求路径上：会话、因素、服务密钥的路由只带对象标识；IdP 与域、冒充记录的归属租户存在 authn 自己的表里。宿主若按租户管理员的规则判定，看到的 `Tenant` 是什么，直接决定一个租户的管理员能不能动另一个租户的资源。

租户准入层位于 tenant 目录，默认拒绝非成员，拒绝以 404 回答（[ADR-tenant-admission-2026-10-10](adr-tenant-admission-2026-10-10.md)）。平台级角色，例如跨租户的客服与平台管理员，发出的正是非成员请求；这类请求在授权之前就被准入层拦下，授权模块没有位置可以承载这类角色。

状态码的位置由 [ADR-authn-scope-2026-10-10](adr-authn-scope-2026-10-10.md) 定下：网关从不写 403，authn 自己的处理函数只在转述认证之外的策略拒绝时写 403，集合封闭。判定拒绝落在哪个状态码，是本接缝的一部分。

第一个账户、第一份成员关系、第一个 IdP 在没有任何管理员时从哪里来，需要有答案，且这个答案不能是一份内置的放行名单。

## 考虑过的选项

### Decider 缺席时默认放行，或由 authn 内置放行名单

没有 `Decider` 的装配里管理动作照常执行；或 authn 自带一份「某些主体可以通过」的名单，例如口令表里的运营账号。

**否决**：

- 默认放行使「什么都不装配」成为最弱的状态：任何通过认证的主体都能建账户、停用账户、重置他人因素、冒充他人。宿主漏写一个接口实现，没有任何信号。
- 内置名单把授权的事实写进 authn：哪个主体拥有管理权是策略，策略的形态由应用决定，写进 authn 等于替每个宿主选定一种。口令表主体能否通过由接缝判定，接缝能看到 `Identity.Account().IsStatic()`。

### 管理面只提供 Go 接口，不挂路由

`AccountAdmin`、`Memberships`、`Sessions`、`SSOProviders` 只作为 Go 接口交付，宿主在自己的命令与 handler 里调用，HTTP 管理面由宿主自写。

**否决**：列出与踢下线、IdP 配置、冒充端点这些需求本身要经 HTTP 提供；每个宿主各自重写一遍，强制审计的先后顺序、新鲜多因素的要求、`Decision` 的填法与撤销后的同步清理都要逐个重复，漏掉任何一项都是越权或遗漏审计。Go 接口仍然保留，作为宿主自己的命令与最后手段，不取代路由。

### 缺接缝时照常挂出路由，但全部拒绝

`authn.admin` 无论 `Decider` 是否在场都挂出全部路由，缺席时每条都答拒绝。

**否决**：一个永远拒绝的路由没有任何功能，只增加攻击面：它暴露路径形状、处理链与应答差异，并且在没有 `Decider` 的装配里始终是可探测的入口。路由随对应能力在场才挂，缺席时路由引擎对它按未命中处理；整个管理面不纳入时一条路由也没有。

### 管理面不过接缝，只要求已认证

`authn.admin` 的路由全部 `Required`，通过认证即可执行。

**否决**：认证回答「是谁」，不回答「能不能」。任何通过认证的主体，包括普通租户成员与服务账户，都能建账户、停用账户、重置他人因素。

### 把 Decider 写进 Requires，或交付一个「默认拒绝」的模块

`authn.admin` 与 `authn.impersonation` 把 `Decider` 当必需依赖；或 authn 目录交付一个只会拒绝的 `Decider` 实现，由宿主点名。

**否决**：`Decider` 是排他功能，依赖闭包不替宿主挑选实现，宿主漏点名即启动失败。「默认拒绝」恰恰要求宿主什么都不做也安全；要宿主点名一个「默认拒绝」的模块，等于要求宿主为了得到默认状态做一件事，漏做的后果是进程起不来，而不是安全。取用方以 `Optional` 取用，缺提供者即全拒，默认状态由取用方的行为给出，不需要模块。

### 每个管理动作一个接口，或冒充与管理各一个接口

把「是否允许冒充」「是否允许停用账户」等各做成独立接口，宿主与授权模块分别实现。

**否决**：每增一种动作就增一个导出接口，宿主与授权模块要逐个满足；而授权的路由键本来就是动作。一个接口加动作常量，授权按动作字符串路由，「是否允许冒充」仍是其中一个动作。

### Decision 只带路径里的标识，由 Decider 自己解析归属

`Decision` 里只放路径上出现的标识，对象属于哪个租户、哪个账户，由 `Decider` 的实现自己去查。

**否决**：归属存在 authn 的表里，表由 authn 的实现独占；`Decider` 的每个实现都要读这些表，或者漏读。漏读的后果是越权：租户 T1 的管理员对 T2 的 IdP、T2 成员的会话发起操作时，路径里没有租户，宿主按 `Decision.Tenant` 判租户管理员，得到的是空值或 T1，放行。归属由 authn 解析并填入，宿主只做策略判断。

### 自助动作也过接缝

账户修改自己的口令、因素、会话与标识，同样要 `Decider` 放行。

**否决**：没有 `Decider` 的装配里，用户连自己的口令都改不了。自助动作的依据是「发起者就是这个账户」，这是 authn 自己可以核对的事实，不需要策略；新鲜度要求由多因素的结构性检查承担。

### 准入层对非成员不设放行接缝

非成员一律在准入层被拒，授权模块只能给成员授予租户内的权限。

**否决**：跨租户的客服、平台管理员这类独立的授权模型里常见的角色落不了地：请求在授权之前就被准入层拦下，授权模块要落地它们只能改准入层。非成员时由准入层询问 `Decider` 的 `authn.tenant.access` 动作，缺省拒绝，授权模块经同一个接缝落地平台级角色而不必改准入层与 authn。

### 管理拒绝一律答 404 或 401

见 [ADR-authn-scope-2026-10-10](adr-authn-scope-2026-10-10.md)：404 是隐瞒资源存在，管理员分不清「没有权限」与「没有这个资源」；401 的语义是凭据缺失或强度不够，策略拒绝时重新认证不改变结果。答 404 与答 401 均被否决，本记录沿用其结论。

### 单一 Decider 接缝，管理面独立成模块，自助范围不过接缝

**采纳**，见决策。

## 决策

采纳：根包交付判定接口 `Decider`，授权的位置只有这一个接缝；管理面是独立模块 `authn.admin`；自助范围不经接缝。

- **`Decider` 的性质。** 它是 authn 根包的接口，由授权模块或宿主实现，排他。取用方（`authn.admin`、`authn.impersonation`、`tenant.admission`）在 `Init` 里以 `Optional` 取用，缺提供者是合法配置，行为是全部拒绝，不写进 `Requires`。`Decide` 返回 error 一律按 503 收口，不当作拒绝，也不当作放行。`pkg/authn` 不内置任何放行名单，口令表主体能否通过由接缝判定。
- **经接缝的动作的判据。** 作用于他人账户或租户级资源的管理面动作、冒充的开始与读写、非成员进入租户，经接缝判定。动作集合随新增的管理面能力增长，归属以这条判据为准；动作常量的完整清单与各路由对应的动作只在设计文档 design-authn-admin 里给出。
- **租户级动作的 `Tenant` 由 authn 填入。** 对象属于某个租户的动作，其 `Decision.Tenant` 由 `authn.admin` 在调用 `Decider` 之前解析对象的归属后填入，`Decider` 永远不会收到租户为空的租户级动作；账户级动作的 `Tenant` 为空，表示平台范围。字段的逐项填法、路径与请求体租户不一致时的处理、`Params` 的限制，只在设计文档 design-authn-admin 的「`Decision` 的填法」里给出。
- **`authn.admin` 是独立模块。** 不纳入它就没有 `/api/v1/auth/admin/*` 路由，Go 接口照常可用，调用方的授权由宿主自己负责。纳入它而缺 `audit.Audit`，在构造之前启动失败。每组路由随对应能力在场才挂，能力缺席则该组路由不存在，启动诊断写出挂了哪几组。管理面处理器内各步的先后次序在 design-authn-admin 里给出。管理动作不在冒充中执行。
- **拒绝的状态码。** `Decide` 返回 `false` 回 403 `forbidden`；返回 error 回 503。403 只来自 authn 自己的处理函数，集合与判据见 [ADR-authn-scope-2026-10-10](adr-authn-scope-2026-10-10.md)。网关与 `tenant.admission` 不写 403。
- **自助范围不过接缝。** 账户对自己的会话、因素、口令、标识与外部关联的读写，只要求发起者是本人（`Actor`、`Account` 与路径上的账户一致）、未在冒充、满足多因素的新鲜度要求（[ADR-authn-mfa-2026-10-10](adr-authn-mfa-2026-10-10.md)）。
- **非成员进入租户。** `tenant.admission` 对非成员且 `Identity.Scope()` 为空的身份，询问 `Decide`，动作为 `authn.tenant.access`，`Decision` 带 `Actor` 与 `Tenant`。缺省拒绝：`Decider` 缺席或返回 `false` 即按准入层的 404 处理，返回 error 即 503。放行只表示「可以进入这个租户」，不赋予任何角色，租户内能做什么仍由授权判定（[ADR-tenant-admission-2026-10-10](adr-tenant-admission-2026-10-10.md)）。
- **引导。** 第一个账户、第一份成员关系、第一个 IdP，由宿主在自己的命令里经 `AccountAdmin` 与 `Memberships` 的 Go 接口创建，或由宿主实现一个简短的 `Decider` 先放行某个口令表主体。默认部署不能被远程管理，这是有意的。

接缝的形状、动作清单、路由表与各路由的额外要求在设计文档 design-authn-admin 里，状态码与哨兵在 design-authn-failure 里，审计与事件的契约在 [ADR-authn-events-and-audit-2026-10-10](adr-authn-events-and-audit-2026-10-10.md) 里。

## 后果

没有授权模块的装配也有安全的默认状态：什么都不接，管理动作与冒充一律被拒；装入 `tenant.admission` 的装配里，非成员一律进不了租户。接上授权的方式只有一个，实现 `Decider`，不改 authn，也不改准入层。

租户管理员对别租户资源的越权，在接缝的输入上被切断：宿主按 `Decision.Tenant` 判定时，看到的总是对象真实所属的租户。平台级角色经 `authn.tenant.access` 有了落点。

管理面路由只在对应能力在场时存在，没有永远拒绝的路由。

**接受的代价：**

- 没有 `Decider` 的装配里管理路由与冒充一律 403，宿主必须自写一个 `Decider`，一个函数即可，才能远程管理。默认部署开箱即不可被远程管理。
- `Decider` 的实现质量由宿主承担。authn 保证它收到的输入，不保证它的判定；一个对 `authn.tenant.access` 一律返回 `true` 的实现，使每个租户对所有已认证的非成员敞开。准入层缓存判定结果，策略撤销在缓存期内不生效，期限由设置承载，见设计文档 design-tenant-admission。
- 动作常量属于对授权的对外接口面。新增动作对已有的 `Decider` 实现表现为一个它不认识的动作字符串，按未知动作拒绝还是放行由实现决定；authn 不能替它收紧。
- `authn.admin` 要在调用 `Decider` 之前解析对象的归属，每个租户级路由多读一次归属。路由的 `Decision` 是否按此填法填入，是每条新增管理路由要自己守住的约束，守护的手段是测试，不是类型系统。
- `Decider` 的询问发生在 authn 的处理函数里，请求已经过网关，所以它的拒绝不进网关的收口计数，只进各自的日志与审计；准入层的成员关系检查在缓存未命中时多一次库内点查。
- 调用方读到的 403 可能来自 authn 的处理函数，也可能来自链上的授权层或宿主的 handler，仅凭状态码区分不了来源。
- 管理面的路由集随装配变化：同一份请求在不同装配里得到 403 或路由引擎的未命中应答。
- 运维人员直接经 Go 接口操作时不经 `Decider`，其强度完全取决于宿主命令自己的访问控制。

## 失效条件

- 授权模块的设计要求 `Decision` 携带当前字段表达不了的资源属性，例如属性集或层级关系：`Decision` 的形状需要重新裁定，`Params` 的少量参数不是承载它们的位置。
- 出现必须由平台范围的 `Decider` 判定的租户级动作，即租户为空而对象仍属于某个租户的动作：「`Decider` 永远不会收到租户为空的租户级动作」不再成立，该动作要有自己的动作常量与填法。
- 授权模块要求一个接口承载多种判定形状，例如批量判定或带返回义务的判定：单一接缝需要重新评估。
- 出现需要把 `authn.admin` 的部分路由在 `Decider` 缺席时仍然开放的部署要求：「缺席即全拒」的默认状态需要重新裁定。

以下行为是未经运行核实的假设，依赖它们的断言以对应的测试守住，测试失败即视为本决策的前提不成立：

- 假设链上的次序是：准入层在授权阶段、在授权层之外，该阶段在记录与限流之内；授权层对准入层写 `After`。次序由阶段顺序与阶段内的 `After`、`Before`、`Order` 经 `orderLayers` 推得，没有跑装配读过链清单。装配测试用真实注册表纳入网关、租户解析、审计、限流与准入层，读链清单中的次序并断言。
- 假设 `Decision` 的填法对每条租户级管理路由都成立。表驱动测试对每条路径里不带租户的租户级路由，让租户 T1 的管理员对租户 T2 的对象发起请求，断言收到的 `Decision.Tenant` 是 T2、`TargetAccount` 是对象所属账户。
- 假设没有任何 `Decider` 的装配对每条管理路由、冒充发起与非成员请求都落在拒绝一侧。装配测试在这样的装配里逐项断言管理路由回 403、冒充被拒、非成员请求回 404。
