# 判决不可字面构造，未表态读作拒绝而非故障

## 状态

已接受

## 背景

校验后端是独立的模块，认证网关不拥有它的代码。网关拿到的只有一个接口，以及后端交回的那一份判决；后端说得对不对，网关无从校验。网关能决定的只有这份数据长什么样，以及后端什么都没说时按什么读。

一次校验的结果穷尽为凭据有效、凭据无效、答不上来。有效与无效是关于这条凭据的正面知识，答不上来是关于后端自身的。对外，无效收口成 401，答不上来收口成 503。

401 与 503 的差别不止在数字上。以 401 为键的那些设施——失败计数与账号锁定、限速、应用防火墙的规则、安全事件平台的告警线都在其列——只认 401，503 不进它们的任何一条计数。一段时间里所有拒绝都以 503 出去，这些机制在那段时间里一次都不触发：后端不可用期间，针对同一账号的连续口令猜测全部得到 503，拒绝计数为零，锁定与限速都没有动作。

在 Go 里，失败的原因放进 error 返回值，查不到记录返回的是 `sql: no rows in result set` 这一类错误。后端把这个 error 原样填进判决的诊断字段、不再另外表态，是这门语言里常见的写法，不是疏忽才会出现的写法。判决的读法若把"没有表态"归到故障那一档，这种写法就把每一次拒绝都报成了后端故障。

漏写落在哪一格由零值决定：结构体字面量省略掉的字段、没有赋值的返回值、枚举的第一个常量，都落在零值上。

判决由后端构造。字段导出就意味着包外能拼出任意组合，包括"认证通过并且带着失败原因"和"只有原因没有结论"这种自相矛盾的组合。

## 考虑过的选项

### 判决用 `(Identity, error)`，结果靠哨兵错误区分

后端返回身份与一个 error：`nil` 表示认证通过，拒绝与故障各由一个哨兵错误表示。

**否决**：error 槽的零值是 `nil`，而 `nil` 在这个形状里就是成功。一个漏了表态的后端返回 `(Identity{}, nil)`，网关读成认证通过，放行一个主体为空串的身份。漏写落在放行那一格上：写错的方向是放行，不是拒绝。

### 判决是字段导出的结构体，未表态读作故障

后端用结构体字面量填判决，诊断原因放在导出的字段上，结论的零值读作故障。

**否决**：字面构造让"只填原因、不填结论"成为能编译、看着也完整的写法，而那恰好是把 error 原样搬过来的写法。这样的后端在口令错误与查无此人的情形下都收口成 503，正确口令仍旧通过：功能上看不出问题，而拒绝这一档在它身上整体消失，键在 401 上的设施随之全部失灵。同一形状还让故障计数失去意义——健康后端上的日常口令错误全部记进故障桶，基于它的告警只剩噪声。

### 判决不可字面构造，未表态与显式拒绝同属一格

结论枚举的零值就是"拒绝"，漏写与后端明确拒绝落在同一个结论上。

**否决**：收口方向对，但运行期没有任何信号指出某个后端根本没在表态。后端的缺陷与调用方的错口令混进同一个计数，只能靠人读代码发现。

### 判决不可字面构造，未表态收口为 500

零值读作网关自身出错。

**否决**：500 告诉调用方这次失败与它的凭据无关、原样重试也许能成，而事实是它没有认证上。它还把某个后端的缺陷说成网关的故障，归因指向错误的一方。

### 判决不可字面构造，未表态读作拒绝并单独计一类缺陷

**采纳**，见决策。

## 决策

采纳：判决的字段一律不导出，只能经构造器产生；结论枚举的零值是"未表态"，网关把它收口成拒绝，同时单独计一类缺陷并记一条错误日志。

- 构造器按结论分开，各自只收该结论用得上的东西：`Authenticated` 只收主体，`Denied` 与 `Unavailable` 各只收一个诊断原因。"既认证通过又带着失败原因"与"只有原因没有结论"在包外不是能写出来的程序。
- 诊断原因只进日志，不进响应。
- 未表态对调用方收口成拒绝：这个调用方确实没有认证上，401 与事实相符。
- 未表态同时是后端的缺陷信号，单独计数并单独记一条错误日志，不与正常拒绝混在一个桶里。
- 一次拒绝记在谁名下，判据是这个拒绝由谁作出，不是它发生在问后端之前还是之后：网关凭自己持有的事实作出的拒绝记在网关名下，不计进任何后端的缺陷计数。出口绑定不符要等后端交回判决才检得出，作出这个拒绝的仍是网关（[ADR-authn-ownership-2026-09-20](adr-authn-ownership-2026-09-20.md)），因而同样记在网关名下。

## 后果

把 error 原样搬进判决的写法不再是能编译的程序，这一类错误落在编译期。

故障这一档的来源穷尽为后端自报与网关自证：网关自证的判据是这件事由网关亲历，网关掐断一个超出预算的调用、网关接住后端的 panic 都在其中。后端漏答不再能伪装成故障，故障计数因此可以拿来告警：健康后端上的日常口令错误全部记进拒绝，故障计数保持为零。

凭据不成立的拒绝重新落在 401 上，以 401 为键的下游设施在后端健康时按预期触发。

**接受的代价：**

- 未表态收口成拒绝，代价落在调用方身上：一个有缺陷的后端会把自家用户的请求全部变成 401，而 401 正是上游锁定与防火墙规则计数的键，后端的一个缺陷因此升级成账号锁定事件。
- 后端把自己的宕机写成拒绝，运行期无法与真拒绝区分。网关没有后端的错误分类学，它看到的只是一个结论。这类误标只能由后端自己的测试挡住，挡不住不写测试的后端。
- 宕机分支漏了表态的后端，在真故障期间一个 503 都不产生：带正确口令的请求全部收口成 401，未表态计数上涨而故障计数为零。缺陷信号在计数与日志里，不在状态码里。
- 判决在包外不可字面构造，后端自己的测试也只能用构造器给出的组合。要造一份违反契约的判决去测网关的收口，只能在 `pkg/authn` 包内做。
- "未表态"是可观测面上的一类新计数，它的名字一旦被宿主的看板与告警引用就改不动。

## 失效条件

若 Go 提供一种使"结论未被赋值"无法表达的类型，未表态这一格随之消失，本记录中关于零值读法的部分不再有对象。
