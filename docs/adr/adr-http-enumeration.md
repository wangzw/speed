# 入口模块的登记接口列出已声明的端名，`*` 保留为端名

## 背景

入口模块的登记接口只有按名取端一个读方法，端的全集只存在于入口模块自己的配置里。多个具名端点是 [ADR-http-endpoints](adr-http-endpoints.md) 的决定，那条记录接受了端名是字符串、对应关系靠启动期校验建立的代价；登记接口要不要列出端名，那条记录没有讨论。

其余模块的端名清单是各自的输入项，清单里没有点名的端，那个模块的层就不会出现在那个端上，启动期不失败，也没有一行诊断指向它。对守护类的层，清单由宿主逐个点名；有的模块需要对每个已声明的端登记同一层，遥测的采集层需要这样：它的覆盖面应当是入口模块声明的全部端，而不是宿主逐个写下的那几个。

按清单收窄的模块仍然存在，也仍要按名取端：只守业务端的认证与限流，不在管理端上登记。

清单的元素是端名，端名是配置里的任意字符串。清单里要写出「全部已声明的端」，就需要一个不会同某个真实端名重合的写法。

## 考虑过的选项

### 另设一个可选接口

在 `Router` 之外定义一个可选接口，实现它的 `Router` 才能列出端名，调用方对取到的 `Router` 做类型断言。

**否决**：`Router` 不实现它时，「覆盖全部端」只能退化成别的行为，最自然的一种是一个端都不覆盖，而这个退化不报错、不进诊断，正是要消灭的失败形态。宿主为入口模块预置的 `Router` 就是这样一种实现，它写在宿主的代码里，不受本模块的实现牵制。

### 增加「对全部端登记同一层」的登记方法

`Router` 上增加一个方法，对每个已声明的端各登记一次传入的层。

**否决**：它要在 `Use` 之外再开一条登记路径，那条路径要同样守登记闸门、同样校验层的声明，登记路径此后各自演化。按清单收窄的模块仍要按名取端，读全集的办法也仍然要有。一个读方法同时满足对全部端登记与按清单收窄：对全部端登记的模块遍历返回的名单，逐个取端，按清单收窄的模块照旧。

### 不改，由模块要求宿主逐个写端名

模块只能在自己的配置里要求宿主列出端名。

**否决**：覆盖面靠宿主记得，端的集合增长时每个这样的模块的清单都要回头补，补漏的信号只有 `Serve` 组装时写出的链清单，需要人去读。

### 列出端名，但不保留任何名字

`Router` 返回端名，清单里的「全部」另由各模块自选写法。

**否决**：各模块的写法互不相同，其中任何一种都可能与一个真实端名重合；重合之后清单里的一项既可视为那个端，也可视为全部，读法不同，行为也不同，而配置里看不出写的是哪一种。

### 列出端名，并保留 `*` 为端名

**采纳**，见决策。

## 决策

采纳：`Router` 增加 `Endpoints() []string`，返回本次装配已声明的全部端名；`*` 保留为端名，配置里取这个名字的端在 `Prepare` 阶段被拒绝。

## 后果

需要对全部已声明的端登记同一层的模块与按清单收窄的模块可以用同一个读方法：对全部端登记的模块遍历 `Endpoints` 的结果，按清单收窄的模块照旧按名取端。

模块能把自己的端名清单与全集对照，也能在清单里用 `*` 指代全部已声明的端而不与任何真实端名重合。

返回值按升序排列，每次调用返回一份新切片，调用方改动它不影响 `Router`。

**接受的代价：**

- `Router` 的所有实现新增一个方法。宿主自己预置的 `Router` 同样要补，这是不兼容变更，在编译期暴露。
- `*` 成为保留端名。配置里已有以 `*` 命名的端必须改名，否则 `Prepare` 失败。保留的是一个字符串，编译器不参与，靠启动期校验建立。
- 列出端名不会让漏写自动失败。一个模块只要仍以自己的清单工作，漏写一个端的结果不变：那个端上没有它的层，启动期不失败，也没有诊断。枚举让模块有了对照全集的可能，是否对照、对照之后是否失败由模块决定；察觉途径仍是 `Serve` 组装时写出的链清单。

## 失效条件

本记录假定端的集合在装配期间不变，名单读到的就是全集。若入口模块出现能在运行期增减端的实现，一次读取的名单不再是全集，`Endpoints` 需要另配变更通知，或改为不承诺全集。
