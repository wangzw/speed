# 采样、批处理、导出周期、停机上界与采集面清单归配置，输入项不接受命令行来源

## 状态

已接受

## 背景

配置与设置的划界判据是：一个值属于配置，当且仅当它在数据库可用之前就被需要（[ADR-config-scope-2026-09-13](adr-config-scope-2026-09-13.md)）。配置是启动时的快照，启动期间读入一次，此后在进程生命周期内不再变化，变更配置需要重启进程（[ADR-config-lifecycle-2026-09-13](adr-config-lifecycle-2026-09-13.md)）。

本模块的 provider 在构造期就需要服务身份、采样器与一组构造选项，采集层挂载的监听端与订阅的事件类型同样在装配期被读到（取值清单见 [设计正文](../design/modules/design-observability.md) 的核心数据结构）。构造发生在 `New` 阶段，迁移发生在 `Migrate` 阶段（见 [core](../design/modules/design-core.md) 的阶段表）：`New` 整体早于 `Migrate`，而设置表由迁移集建立、由数据库模块在 `Migrate` 施加，这些取值在被需要时落在设置够不到的一侧。

输入项的来源不是任意的。配置库的命令行名处于一个全局平铺的命名空间：分处不同命名空间的两个输入项仍可能给出同名的命令行参数，重名按完整清单判定，与两者是否被同一条命令纳入无关（见 [config](../design/modules/design-config.md) 的输入项清单）。声明命令行来源的每一项因此要给出一个不与他人冲突的 `FlagName`。同一份清单受一条安全边界约束：配置定位符会出现在命令行、进程列表与诊断输出中，因而不得承载凭据（见 [architecture](../design/architecture.md) 的安全边界）。

## 考虑过的选项

### 把采样率放进设置，支持不重启地改采样

**否决**：改采样要重建 provider，而 provider 是一次装配的产物。支持它等于给本模块加一套运行期换手机制，与「配置是启动时的快照」和 provider 的一次装配相冲。

### 为各项声明命令行来源

**否决**：承载凭据的项一进命令行就会出现在进程列表里，而安全边界正是不让凭据走这一层；其余项描述的是部署形态，为其声明命令行来源要在全局平铺的命名空间里为每一项起一个带前缀的长名。

### 按租户取不同的采样率或端点

**否决**：同样要重建 provider；且服务身份与导出目的地是进程级事实，按租户取不同值会让同一个进程向不同目的地报告两条身份不同的流。

### 全部输入项归配置，来源限主配置源与环境变量，不声明命令行来源，凭据项标注敏感

**采纳** — 见决策。

## 决策

采纳：本模块的全部输入项都是配置，不声明任何设置项。输入项的来源限主配置源与环境变量，不声明命令行来源。承载凭据的项在配置里标注为敏感。

## 后果

输入项的取值随配置在启动时一次读入，此后不再变化，调试与调整都经部署流程。

**接受的代价：**

- 改动这些取值一律要重启进程。采样率、批处理参数、导出周期与停机上界的调整各走一次部署，运行期改不动。
- 不能按租户调整采样与导出。采样率与导出目的地是进程级取值，高流量租户与低流量租户共用同一个采样率，一个租户的采样需求压不到别的租户头上。
- 不声明命令行来源意味着命令行上无法临时覆盖任何一项，调试时只能用环境变量，而改动环境变量同样要重启。
- **上游库的标准变量只对本模块不配置的设置起作用。** 上游对没有显式给出的设置读取自己的 `OTEL_*` 变量；本模块把配置声明的每一项与文档写明的线上形态都显式交给上游，这些变量对它们不起作用。留给库的那些——导出的压缩、单次请求的超时、重试与退避，SDK 的跨度上限、样例筛选与基数上限，以及资源上本模块给出的两个属性之外的那些——仍受这些变量影响，而它们不在本模块的配置面、未认领变量的诊断与敏感标注之内。撞上它的是在部署环境里统一设置了这些变量的运维者：它们对端点、头部与 TLS 不再起作用，对上面列出的那些仍然起作用。
- 敏感标注只覆盖配置模块自己的输出。`Decode` 之后取值是普通结构体字段，此后去了哪里由拿到它的模块负责（见 [architecture](../design/architecture.md) 的安全边界）。
