# 社交登录提供方的端点与出站信任作为部署配置，缺省不变

## 状态

已接受

## 背景

Google 与 GitHub 两个登录方式把提供方地址写死在代码里：Google 的 issuer 是 `https://accounts.google.com`，GitHub 的授权、令牌与 API 端点取自 `x/oauth2` 的 `endpoints.GitHub` 与 `https://api.github.com`；两者的受限出站客户端一律拒绝回环地址并用系统根证书。这个形状堵住两件事：

- 自动化端到端测试无法走完一次真实的社交登录回跳，因为没有回调能到达本地提供方。
- 指向 GitHub Enterprise 或自建 OIDC 提供方的部署没有配置入口，只能改代码。

约束：

- 缺省行为必须与当前逐字相同：回环仍拒绝，系统根仍是 TLS 信任来源，公网 https 仍是唯一可到达的出站形状。
- 企业 SSO 已有按租户登记 IdP 的路径（[ADR-authn-sso-2026-10-10](adr-authn-sso-2026-10-10.md)），社交方式不属于它，不引入第二套 IdP 表。
- 受限出站客户端的规则（只许 https、不跟随重定向、连接时判目的地址）不变。

## 考虑过的选项

### 只给测试留构建标记或可注入客户端

测试把方法构造到本地服务端，生产路径不暴露配置。

**否决**：这是隐藏的测试专用路径，部署侧没有同一能力；端到端测试要驱动产品的真实装配，不是测试里另拼的一份。

### 通用 IdP 登记表，社交方式也按行装配

把 Google 与 GitHub 当成企业 SSO 的提供方行。

**否决**：企业 SSO 的 issuer 与凭据按租户在运行期出现，社交方式的凭据是启动期配置；合并会让社交方式依赖租户与设置存储，并把按租户的 IdP 表扩成两用。

### 每个方法一组可选覆盖项，缺省即内置值

Google 接受 issuer 覆盖，GitHub 接受授权、令牌与 API 基址覆盖；两者各接受回环开关与替换系统根的 PEM 文件。

**采纳** — 见决策。

## 决策

Adopt：Google 与 GitHub 各自接受一组可选的提供方覆盖项与出站信任项，缺省值就是当前的常量、端点表与系统根；受限出站客户端接受回环开关与根证书文件。

- **缺省不变。** issuer、授权端点、令牌端点与 API 基址为空时取当前值；回环开关缺省关；根证书文件缺省为空即系统根。
- **校验只增不减。** 显式 issuer 必须是 https，回环主机的 http issuer 仅在该方法的回环开关为真时接受；GitHub 的端点覆盖必须是绝对 https 地址；根证书文件在启动时读取，读不到或没有证书即启动失败。缺省路径上的校验与当前一致。
- **自定义端点是部署方的信任。** 部署把方法指向自己的提供方时，自行承担对该端点身份、其证书链与网络路径的信任。产品不判断该端点是否可信，只保证传输仍只走 https、证书始终校验、回环仍由显式开关控制。

## 后果

- 端到端测试可以用一个本地 TLS 身份提供方走完真实回跳；部署可以把 Google 或 GitHub 指向自建提供方或 GitHub Enterprise。
- 配置面增加一组可选的提供方覆盖项与出站信任项，缺省值与当前相同。
- 根证书文件替换系统根，而不是追加：配置它的部署必须把提供方证书链需要的根全部放进该文件。这与受限出站客户端现有的根证书语义一致。

**接受的代价：**

- 指向自定义端点的部署自行承担端点与证书的信任，产品不做白名单。
- 覆盖项写错只在启动期报错，运行期不会修正。
- 本地提供方仍须提供 TLS 证书；回环开关只放开地址判断，不放开明文 http 的传输。

## 失效条件

- 若社交方式需要按租户切换提供方，这套启动期配置不够，应由企业 SSO 的路径承接或另写记录。
- 若受限出站客户端不再只许 https，端点覆盖的 scheme 校验要随之重评。
