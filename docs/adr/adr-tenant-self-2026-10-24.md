# 调用方本人的租户读取由 tenant 目录新增的只挂路由的模块承担，挂在账户端的普通面

## 状态

已接受

## 背景

租户切换控件要列出账户持有有效成员关系的全部租户，当前租户也在其中（REQ-tenancy-035），个人租户那一项显示个人空间的文案而不是别名（REQ-tenancy-050）。平台没有接口返回调用方本人的成员关系，示范宿主只能用一份硬编码的占位清单。

成员关系在认证（`Memberships.Tenants` 列出账户跨租户的全部成员关系），租户的状态与别名在名册（`Catalog.Get`）。名册是平台域的数据，读名册的管理路由要求平台域的 `tenant.read`，普通成员不持有它。

个人租户是宿主策略：名册不记录租户种类，平台自己的名册视图也不带种类；宿主的个人租户服务端按固定前缀从账户标识派生标识与别名，宿主的 ensure 应答另带它自己的 `kind`。

路由路径的归属由作用域决定：`tenants` 是租户管理作用域的保留段，普通面不带作用域段（[ADR-http-api-path-scopes-2026-10-19](adr-http-api-path-scopes-2026-10-19.md)）。

## 考虑过的选项

### 由平台名册读取承担（`GET /api/v1/system/tenants`）

成员读同一个管理面，自己筛出所属的租户。

**否决**：它要求平台域的 `tenant.read`，而这份权限正是普通成员没有的；把它开放给成员等于把全平台的租户名单交给每一个成员，名单里包括它们不属于的租户与其他账户的个人空间。

### 由 `GET /api/v1/auth/me` 的档案视图携带

档案视图加一个 `tenants` 成员，前端在已有的本人读取里一次拿到。

**否决**：档案视图归认证，认证不 import `pkg/tenant`；有效状态要读名册，只能让认证依赖租户目录。档案视图还登记为可冒充，冒充者会读到被冒充账户在其他组织的成员关系，那超出了冒充授予的那一个租户。把列表放进一个可冒充的读面，等于给冒充者一条枚举目标账户所属组织的路径。

### 在 `tenant.catalog` 或 `tenant.admission` 里加这条路由

**否决**：名册模块的非职责是不读身份，准入层的非职责是不读名册、只读已解析的租户上下文；两者都会把一条与调用方身份相关、又不带租户的读面塞进一个只做一件事的模块。准入层还只在它所守的端上工作，而这条读取必须挂在它不守的账户端上。

### 由宿主自己提供，像个人租户那样

每个产品的服务端各挂一条自己的读取。

**否决**：两个事实都是平台数据，组合规则对每个产品相同；宿主各自实现会让平台 SDK 缺这条读取，并让每个产品的成员列表口径各自漂移。个人租户进宿主是因为它是宿主的策略，这条读取不是。

### 新增 `pkg/tenant/self` 模块，挂 `GET /api/v1/auth/me/tenants`

只挂路由、不交付功能，组合认证的成员关系与名册的状态。

**采纳**，见决策。

### 路径放在 `/api/v1/tenants/me`

**否决**：`tenants` 是租户管理作用域的保留段，该作用域的每条路径必须以 `/{tenant}/` 开头；`me` 会被读成一个租户名，地址上分不清管理面与普通面。

### 路径放在 `/api/v1/tenant/me/tenants`

**否决**：与保留段 `tenants` 只差一个字母，普通面的其他能力段也不用单数；这个相似性会让读者与管理面的路径混起来，而作用域段的存在正是为了在地址上分开两类面。

### 应答带 `kind`

平台读取返回 `kind: personal`，前端按它渲染个人空间的文案。

**否决**：个人租户是宿主的策略（[ADR-starters-personal-tenant-2026-10-18](adr-starters-personal-tenant-2026-10-18.md)），名册不记录它，平台也无法为别的宿主定义"个人租户"是什么；把一个宿主概念写进平台应答，会让每个宿主继承一套它可能并不使用的词汇。宿主已经按固定前缀派生个人租户的标识，按标识逐字相等即可判定。

### 应答带 `status`

每项带租户状态，前端据此决定可不可选。

**否决**：状态是过滤条件，不是字段。不进列表的正是状态不是在册的那些，每一行都读作在册；这个字段是过滤条件的第二条陈述，会与它各自漂移。

## 决策

采纳：新增 `pkg/tenant/self`，模块名 `tenant.self`，不交付功能接口、不声明特性。它只挂一条路由 `GET /api/v1/auth/me/tenants`，落在账户端（不解析租户），要求已认证、不要求任何权限、不登记为可冒充。

**组合。** 经 `authn.Memberships.Tenants` 取出账户的全部成员关系，逐条经 `tenant.Catalog.Get` 取名册里的状态与别名。一条成员关系进入应答，当且仅当它自身是启用的，且名册里那个租户的状态是在册。

**应答。** `tenants` 数组，每项只有标识与别名，按标识升序；空结果写 `[]` 而不是 `null`。应答不带种类、不带状态、不带展示名。

**失败。** 没有身份答 401；成员关系或名册读不出答 503，成因只进日志。路由集里没有 403 与 404。

**个人租户留在宿主。** 平台应答不带个人租户这个概念；宿主按它派生的标识判定并渲染自己的文案。

## 后果

- **成员有了可用的切换器，占位清单退役。** 占位清单唯一能保证的事实是它写下的那个名字，而它写下的名字只在一个装配里成立。
- **读取跨成员关系与名册两份事实，两者没有一致的时点。** 成员关系是一次表读，状态与别名来自名册快照；清单会落后于名册的刷新周期，也可能漏掉另一个副本刚登记或刚改名的租户。清单不是授权判定：切换之后准入层仍按请求判定，一个已撤销的入口在切换时答 404。
- **平台 API 不认识个人租户。** 每个有个人租户策略的宿主自己维护标识前缀与文案，两处拼写靠人保持一致；平台不为它提供第二个来源。
- **路由住在 `/api/v1/auth` 前缀下，模块却归租户目录。** 路径按调用方面归类，不按模块目录归类；读者要把这两个事实分开读。
- **暂停的成员关系被排除。** 需求把有效成员关系写成"成员关系存在且租户处于启用状态"；平台在 `Memberships` 的读法与准入层里都把暂停读作非成员，列表必须与之一致，否则它会列出一个准入层答 404 的租户。
- **平台员工经决策接缝进入自己不是成员的租户时，清单里没有这个租户。** 触发器要能命名当前租户，宿主须从平台名册补那一行；这一条是宿主装配的代价，平台读取不替它补。
- **应答不分页。** 切换器要列出全部有效租户，截断会静默漏掉一个；上限由账户的成员关系条数给出。

## 失效条件

若名册开始记录租户种类，或成员关系带上每个租户的展示名，应答不带种类与展示名的理由不再成立，要与把它们放进应答重新比较。若产品要求切换器列出调用方能进入、但不是其成员的那些租户，这条读取不再是列表的来源，平台员工那一档要另立。
