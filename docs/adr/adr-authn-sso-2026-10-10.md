# 企业 SSO：IdP 作表里的数据，SAML 用 gosaml2 加补充校验，企业 OIDC 共用桥

## 状态

已接受

## 背景

企业租户要用自己的 IdP 登录，协议为 SAML 2.0 或 OIDC。这件事带来以下彼此牵连的约束。

**IdP 的配置是运行期才出现、数量不定、带秘密的数据。** 每个租户有自己的 IdP，租户管理员在运行期创建、修改与删除；OIDC 的 `client_secret` 属于它。设置的键必须在启动前静态声明，类型封闭、没有容器，值明文落库，读取接口照常交出敏感项（[settings](../design/modules/design-settings.md)）；配置的容器叶子只能来自主配置源，整体替换，键不进清单（[config](../design/modules/design-config.md)）。两者都不是为这种数据设计的。

**回调到达时没有租户上下文。** 校验后端在租户解析之前运行，看不到租户（[ADR-tenant-ordering-2026-09-21](adr-tenant-ordering-2026-09-21.md)）。IdP 把浏览器送回回调地址时，处理器要知道这次登录属于哪一个 IdP，而请求面上没有租户可读。租户插件对「没有租户上下文的受约束语句」直接拒绝，IdP 表要在没有租户上下文的路径上被读取。

**URL 来自租户管理员的输入。** OIDC 的发现文档与 JWKS、SAML 的元数据都由服务端按管理员给出的地址发起请求。租户管理员不是平台运营方，这些请求是服务端请求伪造的入口。

**邮箱域是一种登录入口，也是一种接管入口。** 按邮箱域把用户引向某个 IdP，要求「这个域属于这个租户」。该事实若可以被租户管理员自行声明，则声明 `gmail.com` 或竞争对手的域，就能劫持其登录入口，并借自己 IdP 的断言接管该域名下的账户。

**SAML 的现成库不替调用方做完校验。** 对源码的核读结果，列出与本决策相关的缺口，是例举，不是库缺陷的全集：

- gosaml2 的 `RetrieveAssertionInfo` 只取第一条断言，不检查 `InResponseTo`，`IdentityProviderIssuer` 为空时跳过颁发者比较，`Destination` 为空时跳过目的地比较。
- 断言条件不满足时，库不返回错误，只在 `WarningInfo` 里置位；没有受众限制的断言库放行。
- 库的时间比较没有容差字段。
- goxmldsig 的 `ValidationContext` 只有证书库、标识属性与时钟这几个字段，没有拒绝签名算法的开关，验签面接受 SHA-1。
- gosaml2 没有 IdP 元数据的解析助手，没有断言标识的去重。
- 签名包装类缺陷在 crewjam/saml、gosaml2 与 goxmldsig 的历史记录里都出现过：被验签的元素与被使用的元素不是同一个。goxmldsig 在 v1.6.0 之前存在同一 `SignedInfo` 含多个引用时的签名绕过（CVE-2026-33487），crewjam/saml 默认解析到的 goxmldsig 版本落在受影响范围内。

**IdP 侧的状态变化不会通知 speed。** 员工在 IdP 被停用后，speed 的会话不会因此终止，登出与停用都没有回传通道，除非另做单点登出。

模块边界与取用方式见 [ADR-authn-packaging-2026-10-10](adr-authn-packaging-2026-10-10.md)，状态放置的判据见 [ADR-authn-state-placement-2026-10-10](adr-authn-state-placement-2026-10-10.md)，登录引擎对方法接缝的约定见 [ADR-authn-login-flow-2026-10-10](adr-authn-login-flow-2026-10-10.md)。

## 考虑过的选项

### IdP 配置放进 settings 或 config 容器叶子

每个 IdP 是设置里的一个 JSON 字符串项，或配置里的一个容器叶子。

**否决**：

- 设置的值明文落库，读取接口交出敏感项，`client_secret` 因此不能放进去；设置项有大小上限，且全部设置载入每个副本的内存。
- 设置没有逐项的类型校验，也就没有针对 IdP 形状的写入校验、变更事件与敏感标记；整张 IdP 表被压成一个字符串项，改一个租户的 IdP 要整体读写。
- 配置只来自主配置源、整体替换，改一个租户的 IdP 要重启进程；租户管理员无从在运行期自助维护。

### IdP 表内嵌租户模型

`authn_idps` 与域表携带 `tenant.Model`，由租户插件自动按租户过滤。

**否决**：域名发现与回调路由没有租户上下文，租户插件对无上下文的受约束语句直接拒绝；要读到行只能走跨租户读取，而跨租户读取不判权限。租户列是普通列。

### 在校验后端里按租户挑选 IdP

校验后端识别请求所属租户，再选该租户的 IdP。

**否决**：校验后端看不到租户，这是平台的既有约束。改它要求认证获得「先解析、后校验」的分段形态，而 [ADR-tenant-ordering-2026-09-21](adr-tenant-ordering-2026-09-21.md) 把这一形态列为它自己的失效条件。把提供方标识放进回调路径，则租户由提供方行得出，不需要改动这条约束。

### SAML 选 crewjam/saml

以 crewjam/saml 作 SP，验签、`InResponseTo`、IdP 元数据解析与 Artifact 绑定使用库自带的实现。

**否决**：

- 默认解析到带 CVE-2026-33487 的 goxmldsig v1.4.0，调用方要在自己的 `go.mod` 里抬高版本，并持续满足这条约束；库不自带这条保证。
- 验签后丢弃 `Validate` 返回的元素，后续仍从原元素解析，被验与被用不是同一个元素，正是签名包装类缺陷的根源。gosaml2 用验过签返回的元素解码。
- 没有接收 IdP 登出请求的实现。
- 容差是包级变量（`MaxIssueDelay`、`MaxClockSkew`、`Clock`），不能按 IdP 设置。
- 它的优点，IdP 元数据解析、`InResponseTo` 与 Artifact 绑定，补在 gosaml2 上并不比修补 crewjam/saml 的缺陷更难；Artifact 绑定没有需求。

### 不在进程内做 SAML，由前置的身份代理承担

SAML 交给独立部署的身份代理（Dex、Keycloak 一类），speed 只做企业 OIDC。

**否决**：企业 SSO 的范围包含 SAML，部署形态不应成为是否支持 SAML 的前提；宿主要为此另部署并运维一个服务。这一路线仍然可用：`authn.sso.oidc` 能接任何 OIDC 代理，宿主愿意前置代理时，代理作为一个企业 OIDC 的 IdP 登记即可（[ADR-authn-scope-2026-10-10](adr-authn-scope-2026-10-10.md)）。

### 用邮箱域匹配代替域所有权证明

租户声明一个邮箱域，声明即生效。

**否决**：任一租户管理员可声明任意域，劫持该域的登录入口，并借自己 IdP 的断言接管该域名下的账户。

### 自己实现一遍带容差的 Conditions 时间比较

在库的校验之外另写一个带容差的 `NotBefore` 与 `NotOnOrAfter` 比较，以容忍时钟偏差。

**否决**：库的比较没有容差字段，另造的版本要么重复库已做的校验，要么绕开它。「严格」与「宽松」两种说法并存，行为取决于走了哪一条路径。时间同步是部署的前提，不是代码可以补偿的缺陷。

### 每租户一对 SAML SP 密钥，服务端生成并双钥轮换

SP 的私钥与证书成为按租户的数据，附带生成与轮换流程。

**否决**：一组 PEM 文件变成按租户的数据与轮换流程，范围随之扩大。默认不请求加密断言，签名 AuthnRequest 本就是可选，SP 私钥只在 IdP 要求时才用到。需要时可在 IdP 记录上加可选的密钥覆盖，不改变接缝。

### 把断言重放行加进 SSOProviders 的方法集，或另立一个根包能力接口

`SSOProviders` 增加一个写入断言标识的方法，或把它拆成一个独立的根包接口、在 `authn.sso` 与 `authn.sso.saml` 之间传递。

**否决**：`SSOProviders` 的方法集是对宿主与协议模块的稳定承诺（[authn-sso](../design/modules/authn/design-authn-sso.md)）；把一条只为 SAML 服务、只为内部去重而存在的写入塞进它，会让每个自写实现的提供方登记都被迫交付一个与登记职责无关的方法。另立一个根包接口则要在根包里新增一个只被一个协议模块用到的能力。做法是：写入由持有表的 `authn.sso` 交付一个 `RememberAssertion`，`authn.sso.saml` 在构造期把它取到的 `SSOProviders` 值断言到这个扩展形状上，断不上即构造失败（fail-closed）；公开方法集不变，这个扩展是登记方必须额外满足的形状。

### authn 在后台自动刷新 IdP 元数据与周期性复验域

常驻协程定期取元数据、定期重查域的 DNS TXT 记录。

**否决**：

- 多一个常驻协程与一套失败策略；后台无界地发 DNS 与 HTTP 请求。
- 元数据刷新失败时保留旧证书，等于继续接受可能已被撤销的证书，与「失败时拒绝」的方向相反；证书的轮换由管理员触发，与这个方向一致。

### 支持 SLO，IdP 发起登录缺省开启

实现 SAML 单点登出与 OIDC 背向通道登出，IdP 发起登录缺省允许。

**否决**：

- SLO 没有需求，表面积大于收益；gosaml2 的登出请求校验在 v0.11.0 之前曾接受未签名的请求（GHSA-pcgw-qcv5-h8ch）。会话的绝对期限给出上界。
- IdP 发起的断言没有可比对的流程，没有 `InResponseTo`，登录 CSRF（攻击者把自己的断言投给受害者的浏览器）无解。能收窄的只有断言的新鲜度、标识唯一、受众与接收者，残余风险无解，所以缺省关闭。

### 出站目的地用黑名单，在解析阶段检查

拒绝私网、回环与链路本地等地址，对 URL 解析出的地址检查一次，通过后交给默认客户端连接。

**否决**：

- 黑名单挡不住不在名单里的特殊用途段，也挡不住内嵌写法：IPv4 映射的 IPv6、NAT64、6to4 与 Teredo 地址都能把内网目的地写成一个看似全局的 IPv6 地址。
- 解析阶段检查的地址与实际连接的地址可以不同，DNS 重绑定与多记录的应答因此绕得过去。检查要落在每次连接尝试的实际地址上。

### 只放行标准库判为全局单播的地址

以 `netip.Addr.IsGlobalUnicast` 为准：为真即放行，不再维护特殊用途段。

**否决**：该判据对不可全球访问的地址也答真：内嵌 `169.254.169.254` 的 NAT64 与 6to4 写法、Teredo 地址，IPv4 的 `100.64.0.0/10`、`192.0.0.0/24`、`198.18.0.0/15` 与 `240.0.0.0/4`，以及 `2000::/3` 之外、除组播、链路本地、回环与未指定地址之外的全部 IPv6 地址，`fec0::/10` 与 `::/96` 在其中。只拒私网、回环与链路本地挡不住服务端请求伪造。放行条件因此取全局单播加两处补充：IPv6 须落在已分配给全球单播的 `2000::/3` 之内，且不落在特殊用途段。

### 以出站代理或网络层隔离代替对端地址检查

由宿主把 authn 的出站流量交给代理，或用网络策略挡住内网，进程内不再判断目的地址。

**否决**：经代理时进程看到的对端是代理地址，目的地判断失效，租户管理员输入的地址能否到达内网完全取决于部署；authn 作为库不能假定宿主做了隔离。网络层隔离可以作为宿主的纵深防御叠加，不能作为进程内检查的替代。

### provisioning 缺省为 JIT

创建提供方时不要求显式选择开户方式，缺省按首次登录自动开户。

**否决**：缺省方向是放行：租户管理员创建一个 IdP，该 IdP 签出的任何断言就能在全局账户表里开户。开户方式没有无风险的缺省值，要求创建时显式选择，把这个决定留给做出它的人。

### 把 IdP 的组声明映射为角色

IdP 断言里的组或角色声明，按租户管理员配置的对照表转成账户的角色。

**否决**：角色归授权，authn 只回答「是谁」。组声明由租户管理员控制的 IdP 签发，映射使租户管理员能经自己的 IdP 为全局账户授予权限，而账户并不属于这个租户。IdP 属性只作为该次登录的只读属性交给宿主，不转成角色。

### IdP 作 authn 表里的数据，SAML 用 gosaml2 加补充校验，企业 OIDC 共用桥

**采纳**，见决策。

## 决策

采纳：企业 IdP 是 authn 自己表里的数据；SAML 用 gosaml2 与 goxmldsig，在库之上补充校验；企业 OIDC 与社交 OIDC 共用 go-oidc 加 x/oauth2 的校验桥；邮箱域发现要求域所有权证明；由外部输入决定目的地的出站请求走受限客户端；开户方式无缺省值，角色与组不映射。各项的条目、表与接口见 [authn-sso](../design/modules/authn/design-authn-sso.md)，本节只写判据。

### IdP 是表里的数据

判据：**运行期才出现、数量不定、带秘密的配置是数据，进 authn 自己的表；键在启动前可静态声明的有限开关才是设置。** 按租户的 IdP 落在 `authn_idps` 与 `authn_idp_domains`，不进设置，也不进配置。租户级策略开关，即要求 MFA 与要求 SSO，是静态键，属于 `tenant.admission`（[ADR-tenant-admission-2026-10-10](adr-tenant-admission-2026-10-10.md)）。

- 提供方标识是不透明的 UUID，出现在回调路径与 SP 元数据地址里。租户由提供方行得出，不由请求面得出，校验后端因此不需要看到租户，[ADR-tenant-ordering-2026-09-21](adr-tenant-ordering-2026-09-21.md) 的失效条件不被触发。
- OIDC 的 `client_secret` 存在 `authn_idps` 的加密列里，读取接口与日志里不出现它，应答只带「是否已设置」。IdP 的签名证书是公钥，不加密。SAML 的 SP 私钥与证书是整个部署共用的一组文件，不属于 IdP 行。秘密的存放规则见 [ADR-authn-settings-and-secrets-2026-10-10](adr-authn-settings-and-secrets-2026-10-10.md)。
- 提供方行带 `version`，变更使各副本缓存的 `Provider` 与 `ServiceProvider` 失效。提供方行的读写接口、表结构与 `config` 的校验规则见 [authn-sso](../design/modules/authn/design-authn-sso.md)。

### 协议与库

- SAML 用 gosaml2 与 goxmldsig，goxmldsig 须不低于 v1.6.1，版本要求写在 `pkg/go.mod` 里。
- 企业 OIDC 用 go-oidc 加 x/oauth2，与 Google 走同一条代码路径，差别只在配置来源：Google 来自配置，企业 IdP 来自表。`state`、PKCE 与 `nonce` 自做，细节见 [ADR-authn-oauth-flow-2026-10-10](adr-authn-oauth-flow-2026-10-10.md)。
- 每个 IdP 一个缓存的库实例，库不认识租户。构造失败只影响这一个 IdP。

### SAML 的补充校验

判据：**库不检查、对空值默认放行、或只置位不报错的项，由 authn 在库调用的前后补上；补充校验的任一失败都拒绝，对外统一为 `login-failed`，成因只进日志与指标。** 背景一节列出的缺口是例举，不是封闭集；补充校验的条目、判定顺序与错误映射见 [authn-sso](../design/modules/authn/design-authn-sso.md)。

- 被验签的元素与被使用的元素必须是同一个：验签与取用基于一次解析，使用验过签返回的元素。
- 时间条件严格判、不设容差，部署要求各副本与 IdP 时间同步。
- 断言标识的去重放在 db 的唯一约束上，不放 kv：这类丢失会放宽校验的状态的判据见 [ADR-authn-state-placement-2026-10-10](adr-authn-state-placement-2026-10-10.md)。写这一行的是持有表的 `authn.sso`，它向 `authn.sso.saml` 交付一个 `RememberAssertion`，方法与登记之间以构造期要求的扩展形状相接，公开的 `SSOProviders` 方法集不变。

### 域发现与域所有权

- 邮箱域发现只在已验证且提供方已启用的域里查找；它只返回入口，不决定登录，应答不泄露账户存在性。
- 租户声明邮箱域必须通过 DNS TXT 证明拥有该域；已验证的域全局唯一，未验证的声明可以并存，抢注占不了名额。
- 已验证的域不做周期性复验，IdP 元数据不做后台刷新。复验与刷新是由宿主调度或由管理员经管理面触发的动作，authn 自己不在后台运行它们。
- 邮箱域不匹配时不并入账户；JIT 缺省只新建、不并入，并入的条件与成员关系的创建规则见 [ADR-authn-external-binding-2026-10-10](adr-authn-external-binding-2026-10-10.md)。

### 受限出站客户端

判据：**凡目的地址由外部输入决定的服务端请求，一律经 `internal/egress` 的受限客户端发出。** 外部输入指租户管理员填写的 URL，以及由它引出的发现文档里的地址。发现文档、密钥集、令牌端点、元数据与 userinfo 是例举，不是封闭集；新增的出站请求先按这条判据归类。

- 目的地址用白名单判定，只放行全局单播且不落在特殊用途段的地址，IPv6 另须落在已分配给全球单播的 `2000::/3` 之内；并且在每次连接尝试的实际连接地址上判，不在解析阶段判。内嵌了 IPv4 的 IPv6 写法还原后按 IPv4 判，隧道类写法无法还原的拒绝。地址段与规则见设计文档。
- 注入方式与库侧的约定见 [ADR-authn-oauth-flow-2026-10-10](adr-authn-oauth-flow-2026-10-10.md)，那里不另列出站范围，以本条的判据为准。

### 开户方式与授权的边界

- `provisioning` 没有默认值，创建提供方时必须显式选择。
- IdP 的组声明不转成任何角色或属性；`attr.<名>` 只是给宿主读的只读属性，只在该次登录的会话上。

### 不做的事与会话上界

- 不做 SLO，不做每租户的 SP 密钥。IdP 发起登录缺省关闭，开启是提供方行上的显式选择，管理应答与启动诊断以警告呈现。
- IdP 侧的停用与登出没有回传通道，speed 的会话不会因此终止。上界由会话自己的期限给出：由企业 SSO 建立的会话，不论种类，其绝对期限受 SSO 专用的绝对期限限制，规则与计算见 [ADR-authn-session-2026-10-10](adr-authn-session-2026-10-10.md)，缺省值见 [design-authn-config](../design/modules/authn/design-authn-config.md)。

## 后果

- 租户管理员可以在运行期自助维护 IdP，改一个租户的 IdP 不需要重启进程，也不影响别的租户。
- 回调处理器不依赖租户解析，校验后端的既有约束保持不变。
- 域所有权证明使租户管理员无法声明他人的域；已验证域全局唯一使同一个域至多属于一个 IdP。
- 库的每一处默认放行都有对应的补充校验，签名包装类缺陷的根源，即被验与被用不同，由单次解析验签消除。
- 外部输入决定的出站请求只有一个出口，目的地判断不会因某条调用路径漏注入而缺席。

**接受的代价：**

- gosaml2 在 v0.11.0 之前披露过 CBC 解密越界、未签名 LogoutRequest 与 goxmldsig 签名绕过，攻击面包含 XML 签名校验与解密；补充校验的每一条都要有负向测试，漏一条就是静默放行。版本固定，升级走专门变更。
- IdP 发起登录与 SLO 缺省关，一部分企业的开箱即用体验变差。员工在 IdP 被停用后，其 authn 会话要到空闲或绝对期限才失效，SSO 专用的绝对期限只是缓解，不是消除。
- JIT 缺省不并入现有账户：已有账户的员工第一次企业 SSO 登录得到 `link-required`，要先用原方式登录再关联。租户 IdP 对跨租户全局账户的权限边界划在这里。
- 创建提供方时多一个必填项；租户若要按 IdP 的组授权，只能在授权一侧另行配置，IdP 的组声明不会自动生效。
- 域所有权转手后，旧认领继续有效，直到管理者移除或重验失败；DNS TXT 验证不要求 DNSSEC，解析器被投毒时验证可被骗过。
- 证书轮换靠管理员更新，或触发元数据刷新。IdP 换了证书而管理员没有跟上，该 IdP 的登录全部失败；这是失败时拒绝的方向。
- 时间条件严格判、没有容差：副本与 IdP 的时钟偏差超过几秒就会零星拒掉合法断言，部署必须保证时间同步。
- 整个部署共用一组 SP 密钥对；租户的 IdP 要登记统一 `public-url` 下的 ACS 与 `redirect_uri`，不支持按租户子域名的回调，不支持经出站代理访问 IdP。
- 受限出站客户端是自写的安全部件，要有专门测试，覆盖私有地址、DNS 重绑定与重定向；每个 IdP 在进程内缓存一个库实例，租户很多时内存随之增长。
- 特殊用途段表是登记表在某一时点的复刻，不自动更新：登记表之后新增的不可全球访问的整块，只要落在 IPv4 的全局单播或 IPv6 的 `2000::/3` 之内，不进表就不被拒。守住表的是逐段的测试向量，与登记表的一致靠改表时逐条对照，包内不保留登记表的副本。
- SHA-1 预扫描靠扫描 XML 文本，可能误拒，要有测试向量守住。
- 写入 `authn_idps` 的 `config` 要在写入时校验形状并拒绝未知键，校验规则随协议增长而增长。

## 失效条件

下列断言依赖尚未用代码或测试核实的行为。每一条写成假设，并配有守住它的测试；测试失败即说明本记录的相应判断需要重新比较。名单是例举，不是封闭集：

- **假设：goxmldsig 没有别的途径拒绝 SHA-1 签名。** 守住它的测试：用 SHA-1 签名的样本做负向测试，预扫描必须拒绝。若库提供了按算法拒绝的开关，预扫描与库的开关择一保留，不并存。
- **假设：gosaml2 的 `ValidateEncodedResponse` 返回验过签的响应，且调用不要求对同一字节再解析。** 守住它的测试：以签名包装样本（被签名的元素与被取用的元素不是同一个）调用，断言结果要么被拒，要么取得的主体与属性全部来自被签名的元素；返回类型不再是验过签的响应时，测试无法编译。与假设不符，则「单次解析验签」的做法要调整。
- **假设：gosaml2 对 NameID 中夹带 XML 注释的截断攻击已有防护。** 守住它的测试：构造含注释的 NameID，断言取得的主体不被截断。
- **假设：gosaml2 的 `SPKeyStore` 不同时接受两把解密密钥。** 守住它的测试：用旧钥加密的断言，在 `SPKeyStore` 只交出新钥时必须解密失败而被拒绝。库升级后该测试失败，说明库已支持双钥，SP 证书的轮换步骤可以简化；在假设成立期间，SP 证书的轮换要在 IdP 元数据刷新的重叠期内完成。
- **假设：特殊用途地址段的清单与 IANA 登记表一致。** 守住它的测试：逐段的向量，每一整块与每一种嵌入写法（NAT64、6to4、Teredo）各一条，以及十六进制、八进制与十进制写法的 IPv4 字面量，断言被拒；向量是改表时逐条对照登记表的记录。向量不比较登记表本身，包内也不保留登记表的副本，所以登记表新增整块之后这条假设会漂移，对照要在改表时重做。

若认证获得「先解析、后校验」的分段形态，使校验后端能在判决之前读到租户，则提供方标识放进回调路径所绕开的约束不再存在，路径形态要按 [ADR-tenant-ordering-2026-09-21](adr-tenant-ordering-2026-09-21.md) 的失效条件重新比较。

若需求出现 SLO、按租户子域名的回调、或按租户的 SP 密钥，则对应的否决理由不再成立，这些项分别要在新的记录里重新裁定。

若 goxmldsig 或 gosaml2 再次披露签名校验层面的缺陷，且补充校验无法单独封堵，则「在 gosaml2 之上补校验」的路线要与前置身份代理一并重新比较。
