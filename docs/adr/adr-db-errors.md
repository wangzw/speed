# 约束拒绝以 GORM 的两个哨兵错误识别，驱动的原始错误留在错误链上

## 背景

本模块封装 GORM（[REF-gorm](../references.md)）而不抽象它，接口就是 `*gorm.DB`（[ADR-module-packaging](adr-module-packaging.md)）。本模块的哨兵表只给启动期的失败分类，运行期的错误由 GORM 带回发出语句的那一处。

一条语句被唯一约束或外键拒绝时，调用点拿到的是驱动的原始错误，两个引擎的形态互不相同：SQLite 的驱动报扩展结果码，唯一约束、主键、rowid 与外键各有一个；PostgreSQL 的驱动报 SQLSTATE。宿主要把业务唯一键的冲突返回为冲突应答，就得对两种驱动错误各写一遍判断，并 import 两个驱动，而驱动按设计只出现在绑定它的实现子包里。

GORM 自带一组哨兵错误，其中 `gorm.ErrDuplicatedKey` 与 `gorm.ErrForeignKeyViolated` 正是这两类拒绝。打开句柄时设 `TranslateError`，GORM 就把每个报回语句的错误交给方言的 `Translate`，由它把驱动错误换成哨兵。两个方言驱动自带的 `Translate` 映射的集合不同：PostgreSQL 的另外映射未定义列与检查约束，SQLite 的漏掉了 rowid 重复。

PostgreSQL 的驱动在打开结果集时就执行语句并读第一行，以 `Raw` 写的 `INSERT … RETURNING` 被唯一约束拒绝时，拒绝在那一步报出；GORM 在这一步直接给语句的错误赋值，不经 `Translate`。SQLite 的驱动在读第一行时才报，那一步经过 `Translate`。

## 考虑过的选项

### 维持现状，宿主按方言判驱动错误

**否决**：宿主代码为此要 import 两个驱动，驱动只在实现子包里的边界被迫打破；每个宿主各写一遍判法，两个方言上的判法各自漂移，漏掉一个结果码的那个引擎上，冲突就返回了服务端错误。

### 本模块另立哨兵错误

例如 `db.ErrUniqueViolation`，由本模块把驱动错误映射过去。

**否决**：本模块的哨兵表只给启动期的失败分类，运行期错误属于发出语句的代码。更根本的是本模块不在 GORM 之上另加一层，而 GORM 已有同义的哨兵：另立一套，宿主要在两套之间选，按 GORM 语义写的第三方代码也认不出本模块的那一套。

### 打开句柄时开 GORM 的 `TranslateError`，用驱动自带的 `Translate`

**否决**：驱动错误被整个换成裸哨兵，约束名与引擎给出的细节随之丢失——宿主分不出是哪一个唯一键冲突，日志里只剩一句 `duplicated key not allowed`。两个驱动映射的集合不同，同一种拒绝在两个引擎上分类不同。结果集打开时报出的拒绝在 PostgreSQL 上根本不经翻译。

### 以 GORM 的两个哨兵为契约，本模块在每个句柄上附加分类，驱动错误留在链上

**采纳**，见决策。

## 决策

采纳：本模块打开的每个句柄——交付的与 `Open` 自建的——把被唯一约束（主键在内）拒绝的语句错误标上 `gorm.ErrDuplicatedKey`，被外键拒绝的标上 `gorm.ErrForeignKeyViolated`，宿主用 `errors.Is` 识别。标注是附加而不是替换：驱动的原始错误留在同一条错误链上，错误文本仍是驱动的原文。

只分类这两类。其余拒绝在两个引擎上都保持驱动错误原样。

哪些驱动错误属于这两类由方言判断，实现子包经 `Spec` 交给本模块，这一项必填。

## 后果

宿主一处判断在两个引擎上成立，且不 import 驱动。`errors.As` 仍取得到驱动错误，约束名在它上面。新增的方言必须给出这项判断才注册得了模块。

**接受的代价：**

- 检查约束、非空约束、未定义列这些拒绝不分类，宿主要区分它们仍得判驱动错误。
- 经 `Row` 的 `Scan` 以及宿主自己迭代 `Rows` 时由 `rows.Err()` 报出的错误来自 database/sql，不经 GORM，不带分类；要分类就用由 GORM 收尾的方法读结果。
- 句柄上的方言成了一层包装。GORM 在方言上查找的可选接口由包装逐一转发，驱动升级新增的方法要随之补上。
- `Spec` 多了一个必填字段，仓库之外实现方言的代码要补上它。
- 分类跟着错误链走。插件以 `%w` 把自己那条语句的失败交给调用方时，那条语句若被唯一约束拒绝，调用方的错误上同样认得出 `gorm.ErrDuplicatedKey`。

## 失效条件

若宿主普遍需要按同一种方式区分检查约束或非空约束的拒绝，只分类两类的范围就不够用，要重新决定分类的集合。
