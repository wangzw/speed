# 键值模块交付原语，不交付缓存语义

## 背景

键值模块的交付范围需要一个判据：只服务"把结果存一阵"的缓存，还是同时服务需要原子性与过期语义的其他消费方。已知的消费方如下，名单为例举：

- 限流的计数需要原子自增，且计数器要在滚动窗口里自然过期。
- 分布式锁需要一次条件写入，写入是否发生要能读出来，且锁在持有者停下之后要自行失效。
- 幂等键与去重标记要在键不存在时写下一个会自行过期的标记，同一请求的多个副本同时到达时只有一个写成。
- 登录流程状态（回跳类登录的一次性校验串与流程记录）要带过期时间写入，多副本共享，每一步用比较并交换推进；丢失的后果是流程失败、用户重来。
- 业务缓存要存一段不透明字节，过期时间由调用方给定。

方法集合另受一条纪律约束：接口按最弱后端设计，不暴露服务端脚本、管道、发布订阅或超出不透明字节之外的数据类型。原子性只由自增、带过期的自增、比较并交换与带过期的不存在则写入表达，需要读改写循环的调用方用它们拼，而不是用"读一次再写一次"。限流算法因此只能是滑动窗口计数器的近似，不能是滑动窗口日志，因为滑动窗口日志需要有序集合。

## 考虑过的选项

### 只交付缓存语义

接口面收敛为读、写、删，外带一个过期时间。

**否决**：限流的原子自增与锁的比较并交换被排除在外，而它们都是真实消费方。堵在模块之外不会让需求消失，只会让每个消费方各自实现一遍，或在键值之上再叠一层——两层之间还要处理过期时间的语义衔接。名字与"缓存"一致，代价是消费方拿到的能力比它们需要的小。

### 缓存语义与键值原语各成一个模块

**否决**：两种功能的实现后端是同一批（内存、Redis、PostgreSQL、Memcached、NATS），拆分意味着两套实现子包、两份一致性套件、两次连接构造。它们的差别只是方法集合的子集关系，不是两种功能，拆开换来的是两份互相不知道对方的代码。

### 交付键值原语

**采纳**，见决策。

## 决策

采纳：**模块交付键值原语。** 键与值都是不透明字节，模块不解释其中任何一个，唯一的例外是自增操作读写的数值编码。接口面的构成、哨兵错误与各操作的语义见 design-kv。

**纳入接口的判据**：消费方侧用两步调用拼出的组合，若两步之间存在会丢失更新或留下永不失效状态的缺口，该组合做成接口上的单次调用，由实现以单次原子操作完成。带过期时间的原子自增与带过期时间的不存在则写入按这条判据进入接口，缺口的具体论证见 design-kv 的同名小节。原子自增虽能由带过期时间的自增以零过期时间表达，仍与它同在接口上。

**比较并交换在键不存在时把空值视为匹配**，因而它同时是不带过期时间的"不存在则写入"。带过期时间的版本不能由它派生，因为交换从不附着也不改动过期时间。

带过期时间的不存在则写入不违背按最弱后端设计的纪律：比较并交换靠的是后端的条件写入，能实现比较并交换的后端都能以同一种条件写入实现它。

## 后果

限流、分布式锁、幂等与去重、登录流程状态、缓存都建在同一个接口上，不需要各自实现键值存取。

登录会话的撤销标记不是本模块的消费方。撤销要求标记丢失时校验不放宽，而本模块不承诺这一点：各实现是否持久取决于后端与部署，模块不检查，接口上也没有声明「需要持久」的入口，各实现声明的部署前提见 design-kv 的部署前提的判断。丢失会放宽校验的状态放在数据库，依据见 [ADR-authn-state-placement](adr-authn-state-placement.md)。

**接受的代价：**

- 接口不暴露有序集合、脚本与管道，需要它们的算法做不了。这是按最弱后端设计的直接结果，且不可通过换后端解决——换一个更强的后端，接口面不变。
- 值是不透明字节，序列化由调用方负责。同一个键在不同调用方之间没有共享的结构约定，模式演进不在本模块的职责内。
- 模块不提供键的命名空间、前缀或分区。两个消费方用同一个键名即互相覆盖，而本模块看不见这件事。
- 比较并交换的成功与否不携带失败原因。调用方区分不了"值不匹配"与"键不存在"，两者都返回交换未发生。
- 不存在则写入报未写入时不交出键上现有的值。调用方要知道占着这个键的是什么，得另读一次，而两次调用之间它可能已经变了。

## 失效条件

若出现一种消费方，它需要的原子性明显超出自增、比较并交换与不存在则写入的表达能力（例如需要在一次往返里对多个键做条件更新），而按最弱后端设计的接口拒绝扩展，则该消费方需要在键值之外另有一处落点，本记录不预设它是什么。

若某一天所有目标后端都能提供有序结构，而限流确实需要滑动窗口日志的精度，则"接口以最弱后端为准"这条纪律的取值需要重新检验。
