# 失败语义：依赖不可用时拒绝，有界放宽逐项列出

## 状态

已接受

## 背景

`pkg/authn` 在请求路径上的判决就是这次请求的访问结果：通过则放行，不通过则请求到不了业务处理器。判决依赖的东西随范围扩大而变多：`pkg/db`（账户、会话、成员关系、失败退避）、`pkg/kv`（登录流程记录）、签名密钥、短信发送方、企业 IdP、设置、事件、审计，以及宿主交付的 `Decider`、`Provisioner`、`ClaimsContributor`。每一个都可能在某个时刻答不出来，而认证要在答不出来时给出一个方向。

**相邻模块在同一问题上取了与认证不同的方向，判据各自成立。** 限流在计数后端不可达时放行，理由是它是防滥用面而不是数据越权面（[ADR-ratelimit-failure-2026-09-22](adr-ratelimit-failure-2026-09-22.md)）；审计的请求级与事件级写失败时放行，理由是记录与业务不是一件工作（[ADR-audit-failure-2026-09-21](adr-audit-failure-2026-09-21.md)）。认证的判决不具备这两条理由：它不是防滥用面，而是数据越权面；它的放行也不是记录的缺失，而是请求本身越过身份边界，代价是未经证明的请求到达受保护的数据。

**失败可以被诱发。** 耗尽连接池、打满 kv、让 IdP 超时，都是攻击者能做的事。把「依赖答不出来」读作「没有凭据」或读作「通过」，等于把制造故障变成绕开认证的手段。

**客户端对状态码有固定的反应。** 对 401，令牌与会话的持有方通常把凭据当作无效而丢弃，或让用户重新登录；对 503，持有方保留凭据并重试。依赖故障答 401，会把一次后端抖动放大成全体已登录用户的登出。

**校验缓存是唯一让判决不来自实时读取的地方。** 会话与成员关系的校验每个请求都要读 db，缓存摊薄这笔读取，同时让撤销、停用与成员变更在其他副本上延迟生效。延迟必须有数字。

**库的默认值不等于本模块的要求。** SAML 与 JWT 的库对签名范围、哈希算法、算法与密钥的对应各有默认行为，其中哪些默认放行了本模块要拒绝的输入，没有逐条核实。库返回成功时，补充校验若不同意，需要一条优先级规则。

**多副本的时钟互相不可见。** 令牌的 `exp`、SAML 的时间条件、会话与流程记录的期限、kv 值里的写入时刻都用到时间。没有手段让一个副本可靠地判断另一个副本的时钟是否偏了。

**架构的错误模型对哨兵有既定规则**：每一层为自己产生的失败提供哨兵，哨兵表对该层自己判出的失败封闭，不为经它返回的外部失败发明名字；启动期的失败终止启动（见 [architecture](../design/architecture.md) 的错误模型一节）。认证的失败面覆盖登录、会话、令牌、多因素、企业 SSO 与冒充，这条规则要落到启动期与运行期各自的哨兵表上。

## 考虑过的选项

### 依赖不可用时放行，沿用限流与审计的取向

db 或 kv 答不出来时，按缓存或按「没有证据表明被撤销」放行，并报一个信号。

**否决**：限流的放行成立，是因为限流失效的后果是额度失准，而这在放行期间与「请求都在额度之内」不可区分且不越权；认证失效的后果是越权，且发生在被攻击者诱发的故障窗口里。信号不改变请求已经到达了业务处理器。

### 出错时继续服务过期的缓存条目；撤销检查失败时放行

校验缓存读库失败时，沿用已过期的条目；撤销与账户状态的检查读不出来时按未撤销处理。

**否决**：已撤销的会话、已停用的账户在整个故障期间继续可用，期限没有上界，故障越久放宽越大。放宽必须有明确的数字且可调；校验缓存有效期已经提供一个带上限的、可调的放宽，再加一条出错时的放宽只会让上界失效。

### 依赖不可用时答 401

后端读不出来时按「凭据不成立」收口。

**否决**：客户端据此丢弃令牌与会话，用户被迫重新登录，而重新登录同样依赖那个不可用的后端。503 让持有方保留凭据并重试。

### 对外区分是哪个依赖不可用

应答里标明 db、kv、IdP 或发送方，便于调用方与运维定位。

**否决**：应答成因会告诉攻击者部署的形态与此刻哪一条路径可攻击。成因进日志，供有权限读日志的一方使用。

### 依赖故障时跳过退避层

kv 故障时整体跳过失败退避，以保登录可用。

**否决**：权威的退避状态在 db，不依赖 kv，kv 故障时没有可跳过的东西；跳过的只能是 kv 上追加的粗粒度来源地址层，那一层丢失之后界仍由 db 里的退避给出（[ADR-authn-state-placement-2026-10-10](adr-authn-state-placement-2026-10-10.md)、[ADR-authn-throttling-2026-10-10](adr-authn-throttling-2026-10-10.md)）。把「整体跳过」写成规则，会把 db 退避不可用时的「拒绝」一并带成放行。

### 所有审计失败都拦业务

审计写失败一律令动作失败。

**否决**：审计的可用性变成登录的可用性。审计写失败只在动作属于强制档时拦业务；其余动作的审计缺失是明说的缺口（[ADR-authn-events-and-audit-2026-10-10](adr-authn-events-and-audit-2026-10-10.md)）。

### 一个总的 `ErrUnavailable` 取代全部哨兵

运行期失败收成一条哨兵，调用方只区分「可用」与「不可用」。

**否决**：调用方需要区分配置缺陷、被拒绝与后端故障，这几类的补救动作不同。`ErrUnavailable` 只用于外部依赖不可用这一类。

### 启动期失败降级运行

缺校验后端、缺路由功能、配置不合法时记 Warn 并继续启动，缺失的部分按拒绝或按放行处理。

**否决**：降级把部署错误变成请求期的行为差异，由用户先于运维发现。按拒绝降级时，该路径永远 503；按放行降级时，被配置的守护面静默缺席。启动终止并点名缺的那一项，错误在部署时暴露。

### 服务端检测时钟偏差并拒绝服务

副本互相比对或与外部时间源比对，偏差超过阈值时拒绝认证。

**否决**：副本之间互相不可见，没有可靠的检测手段；本机时钟与外部时间源的比对要引入新的依赖与新的故障面，误判时会把正常副本拉出服务。时钟偏差用部署前提与各处的容差处理。

### 自写带容差的 SAML 时间条件

在库的 `NotOnOrAfter` 判定之外，由 authn 实现一份带容差的版本。

**否决**：库已经判定，自写等于绕过库的校验，并让容差成为本模块要维护的另一套语义。时间同步由部署层保证。

### 请求期默认拒绝、有界放宽逐项列出、哨兵表对自己判出的失败封闭

**采纳**，见决策。

## 决策

采纳：**请求期依赖不可用时，对应路径拒绝；放宽只有一个封闭的清单，清单里每一项带上界，或带结束它的动作；对外不区分成因；没答与答了拒绝分开处理；哨兵表对本模块自己判出的失败封闭。**

**默认方向是拒绝。** 请求期 db、kv、签名密钥、短信发送方、IdP 或宿主交付的接缝（`Decider`、`Provisioner`、`ClaimsContributor`）答不出来时，依赖它的路径答 503，不答 200，也不答 401。接缝返回 error 时不带着半份结果放行。登录引擎对每个方法与因素的 panic 做 `recover`，按该路径的故障处理，同样答 503。

**放宽的清单是封闭集，每项带上界，或带结束它的动作。** 放宽的判据：按权威状态（db 里的账户、会话、撤销、退避，以及已生效的配置）本应拒绝的请求，因缓存、显式开关、传播延迟或依赖失败而被放行。满足判据的只有下列各项，不在清单里的情形按默认拒绝：

- **会话与成员关系的校验缓存**：缓存命中时按缓存放行，上界是 `check-ttl`，该设置自身有上限（取值域见 [design-authn-config](../design/modules/design-authn-config.md)）；`tenant.admission` 的成员检查与会话校验各用一份，数值各自可调。命中缓存而 db 不可用，与命中缓存而 db 可用，对撤销的滞后是同一个上界。
- **`check-session` 的显式放宽**：访问令牌校验不核对会话是否有效，撤销最晚到令牌到期才生效。它是放宽开关，缺省关闭，只取主配置源，开启时在启动诊断里单独一行 Warn；它只放宽会话有效性这一项，账户状态、`valid_after` 与冒充记录的核对照常执行（[ADR-authn-settings-and-secrets-2026-10-10](adr-authn-settings-and-secrets-2026-10-10.md)）。
- **设置变更的传播**：读设置读内存快照，不会失败；变更在各副本上的生效最晚到刷新间隔，租户刚开启强制策略时个别副本仍按旧值放行。凡安全上需要立刻生效的变更不走设置，走 db 的撤销面。
- **IdP 元数据的证书陈旧**：元数据不自动刷新；管理员触发的刷新失败时保留上一份有效配置并记 Warn，被 IdP 撤销的旧证书继续被接受，直到管理员更新成功（[ADR-authn-sso-2026-10-10](adr-authn-sso-2026-10-10.md)）。这一项没有时间上界，结束它的动作是管理员的更新成功，不会自动到期。

**不越过权威状态的缺口另列，各自声明方向，不算放宽。** 事件发布失败记 Warn、不阻塞业务；尽力档动作的审计写失败记 Error 与失败计数、业务继续；kv 上按来源地址的前置减负层不可用时跳过该层，界仍由 db 里的退避给出。强制档的动作先写审计、写成功才动作，写失败 503。账户停用、删除与撤销服务密钥之后的清理钩子失败时，状态已在本模块事务里生效，调用返回 503、重试幂等，由 `valid_after` 与账户状态检查兜底（[ADR-authn-account-lifecycle-2026-10-10](adr-authn-account-lifecycle-2026-10-10.md)）。

**对外不区分是哪个依赖不可用。** 503 的应答体不携带依赖种类，令牌端点按 OAuth 的约定答同类的暂时不可用；成因只进日志与指标。应答的具体形状见 [design-authn-failure](../design/modules/design-authn-failure.md)，入口模块的错误形状见 [ADR-http-errors-2026-10-10](adr-http-errors-2026-10-10.md)。

**没答与答了拒绝不混。** 校验后端交回零值判决是没答：网关收口 401，单独计入 `unspoken`，记 Error（[ADR-authn-verdict-2026-10-10](adr-authn-verdict-2026-10-10.md)）。凭据存在而后端答不出来是 503，不是匿名；可选认证的路由上也如此，因为把服务故障读作没有凭据，攻击者靠制造故障就能得到匿名放行。

**库返回成功而补充校验失败，按失败。** 凡本模块在库的校验之外另加的检查，任何一项不通过，结果都是失败，并记一条 Error，说明库的某条默认放行被补上了。补充检查的结论不由库的结论覆盖。

**会话与 kv 解耦。** 已建立的会话、访问令牌与刷新令牌的认证只读 db，kv 不可用时已登录的用户照常使用，只是不能开始或继续登录流程与 WebAuthn 仪式。db 不可用时，缓存未命中的 cookie 与令牌认证、登录、刷新、因素校验、管理面与冒充都答 503；不依赖 db 的口令表（`authn.static` 的 Basic）不受影响。放置的依据见 [ADR-authn-state-placement-2026-10-10](adr-authn-state-placement-2026-10-10.md)。

**时钟：不检测，撤销不依赖，前提写明。** 本模块不检查本机时钟，也不检测副本间的偏差。撤销以会话行的撤销标记为准、不比较时间；账户级 `valid_after` 的比较发生在同一个库写下的时间戳之间。时钟偏差因此不会让撤销失效，只让期限类判断偏移。令牌的时间校验带有容差，容差有上限；SAML 的时间条件全部由库严格判定，本模块不另设容差，只在库的判定之外补充校验断言的签发时刻。各处的容差取值与取值域在设计文档。认证检不出、只能由部署满足的条件，写成设计文档里的部署前提，并写明违反时的症状；它们不在运行期被检查，也不被读作保证。

**哨兵表：对本模块自己判出的失败封闭，启动期与运行期分表。** 启动期的失败一律终止启动，错误点名缺的那一项且不带秘密；运行期哨兵由根包的能力接口返回，处理器据此映射应答。新判出一类确定的失败，要么并入补救动作相同的既有哨兵，要么补一条；本模块自己造出而说不出名字的失败不允许存在。经本模块返回的外部库的错误不在表内，本模块不替它们命名，调用方用 `errors.Is` 判别，错误链保持完整。`ErrUnavailable` 只指外部依赖不可用这一类。取不到配置读取面时，`core` 的 `ErrMissingProvider` 原样外传，不另立哨兵。

启动期与运行期的哨兵表、503 的应答形状、每条路径的方向、时钟容差与部署前提的全文在 [design-authn-failure](../design/modules/design-authn-failure.md)；配置键、取值域与上限在 [design-authn-config](../design/modules/design-authn-config.md)。

## 后果

每个依赖的故障都有一个事先写明的方向：拒绝，或清单里的某一项放宽。新增一个依赖或一条路径，要在设计文档里声明它不可用时的方向；声明为放宽的，要满足清单的判据并带上界或结束它的动作，否则这条路径按拒绝。

**接受的代价：**

- 清单里的放宽是明说的放宽，不是缺陷。校验缓存有效期内、`check-session` 开启后、设置传播窗口内、管理员更新证书之前，被撤销或被收紧的状态仍有请求通过。
- db 不可用时，除口令表之外的全部认证都答 503，缓存命中的除外，最长 `check-ttl`。kv 不可用时不能开始新的登录流程，已有会话与令牌照常。
- 凭据存在而后端答不出来时答 503，包括可选认证的路由：本来允许匿名访问的页面，对带着凭据的用户也在故障期间不可用，而不是降级为匿名视图。
- 对外不区分成因，排障只能靠日志与指标；日志与指标因此要能承受按成因检索。
- 零值判决收口 401，一个有缺陷的后端会让合法用户被拒绝，直到缺陷被修；该后端被计入 `unspoken` 并写 Error，是发现它的唯一信号。
- 补充校验不由库覆盖，库升级之后某条默认行为变化时，补充校验与库同时判定的结果可能不再逐条可解释，Error 日志的数量随之变化。
- 时钟漂移的后果分散在令牌、SAML、会话期限与 kv 值的写入时刻几处，没有统一的检测；SAML 的时间条件无容差，要求部署做时间同步，违反时表现为零星地拒绝合法断言。
- 口令表在多副本下的失败退避每副本各算一份（[ADR-authn-guarantees-2026-10-10](adr-authn-guarantees-2026-10-10.md)）。
- 证书陈旧这一项没有按时间的上界，只有管理员的更新动作能结束它；它不会自行到期。
- 启动期终止使每一类配置缺陷都阻止进程启动，在宿主把配置交给运维之前才被发现的缺陷要在部署时修。

## 失效条件

- **依赖的可用性要求高于 db。** 部署要求认证在 db 不可用时对已登录用户继续服务的时间超过 `check-ttl` 的上限。此时「缓存加默认拒绝」不够，需要一份新的、带数字上界的读降级设计，并重新判定撤销在降级期间的语义；沿用出错继续服务过期条目的写法不满足清单的判据。
- **客户端在 503 上的行为与假设不符。** 假设用于本模块令牌与会话的客户端在 503 上保留凭据并重试，没有对具体客户端逐一核实；这些客户端若对 503 同样丢弃凭据，503 与 401 的区别消失，「持有方保留凭据重试」这条理由失效。守住它的测试：向令牌端点与受保护路由在依赖故障下发请求，应答须是 503 且不含依赖种类，不得是 200 或 401。
- **补充校验的有效性是假设。** 假设库的某些默认行为会放行本模块要拒绝的输入，而补充校验补上了它们，这一点没有对库的每个版本逐条核实：SAML 的响应与断言都未签名时的错误、签名包装、SHA-1 签名，以及 JWT 头里的算法与密钥所配算法的对应。守住它的测试：用签名包装向量、全部未签名向量、SHA-1 签名向量与算法不符的令牌做表驱动测试，每一条无论库自身是否拒绝，最终结果都必须是失败；库放行而补充校验拒绝的向量要产生那条 Error 日志。向量任何一条通过，补充校验就要补。
- **「没有补救动作不同的新失败」的假设被打破。** 出现一类本模块自己判出、而既有哨兵与新哨兵都装不下的失败，说明哨兵的划分按补救动作切得太粗或太细，需要重新划分。守住它的测试：装配测试断言根包能力接口返回的每个错误都能用 `errors.Is` 归到一条运行期哨兵，或是被包裹的外部错误。
- **时钟前提不成立。** 副本间的偏差接近流程记录的最短有效期，或超过令牌容差的上限，零星的 401 与流程失败成为常态。此时部署前提不再是可靠的假设，要在认证之外加偏差检测，或把受影响的期限判断改为只读同一个库的时间。
- **清单被绕过。** 出现一条路径在依赖不可用时放行、而它不在清单里，或清单里的一项既没有上界也没有结束它的动作。守住它的测试：对每个依赖逐一注入故障，断言每条路径的结果与设计文档里写明的方向一致，且放行只出现在清单所列的路径上；带时间上界的项，放行的持续时间不超过声明的上界；证书陈旧一项，刷新失败后保留上一份有效配置并写 Warn，管理员更新成功后旧证书不再被接受。
