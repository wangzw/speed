# 速率限制按责任键计数，取不到身份即放行

## 背景

限流是链上的一层，位置由它声明的功能标识定。认证网关交付 `(*authn.Gate)(nil)` 作为链上的定序锚点，限流用 `After` 指向它，落在认证之内。

认证交付的身份带一把责任键，由 `Identity.Key()` 给出，定义见 [ADR-authn-identity](adr-authn-identity.md) 与 design-authn。本层不透明地使用它。

认证模块同时声明：豁免路由上带着正确凭据也取不到身份；可选认证的路由上没带凭据的请求取不到身份；链上没有认证层时全部请求都取不到身份，宿主既没有纳入认证模块、也没有为它预置实例，或为网关预置的实例不是网关模块的产物，都是这种装配（[ADR-authn-guarantees](adr-authn-guarantees.md)）；下游必须自己处置取不到的那一档。

## 考虑过的选项

### 按租户计数

**否决**：一个租户内的用户共享一份额度，其中一个用户的异常行为会压掉同租户其他用户的正常调用。租户是可用的最粗维度，而限流要拦的恰是个体行为。

### 按客户端地址计数

**否决**：网络地址转换与反向代理之后，多个调用方共享同一个地址，额度被无关的人互相挤占。转发头只在配置了可信代理时才可信，取键的语义随部署而变，而本模块读不到部署。

### 按生效账户计数

**否决**：冒充时生效账户是被冒充者，额度于是算到被冒充者头上。管理员借冒充许多个账户取得许多份额度，绕开自己的额度；被冒充账户的额度被管理员的请求耗掉，它自己的正常调用被压。限流要拦的是实际操作者，而生效账户在冒充时不是实际操作者。冒充时实际操作者是发起冒充的管理员，责任键取实际操作者。

### 按责任键计数，取不到身份时记在一个固定的匿名键上

**否决**：一个客户端能打满那个共享的键，把其他匿名流量一并挡掉。这条把「没有身份」读成了一个可被利用的身份。

### 按责任键计数，取不到身份即放行

**采纳**，见决策。

## 决策

采纳：**额度按认证交付的责任键计，键取 `Identity.Key()` 的值，并在它前面加上请求的租户段。取不到身份时本层放行，该请求不计入任何计数。**

**键取实际操作者，不取生效账户。** 冒充期间的请求计在管理员名下：冒充不占用被冒充者的额度，管理员也借不到多份额度。本层只读 `Key()`，不解析它，也不区分请求是否在冒充；同一个人经任何后端到达同一个账户，得到同一个键。

**租户段留在键里的理由是额度按租户取。** 限流的额度归设置一侧，而设置的取值按租户回落；把计数键做成纯粹的主体维度，会让同一个主体在租户 A 打满之后连带限制它在租户 B 的调用，而它在那里本该按 B 的额度计。租户段使计数的作用域与额度的作用域一致。

认证既已豁免一条路由，限流不在这条路由上另设一道需要身份的闸门。

## 后果

限流与认证的强弱一致：认证覆盖到的请求，限流也覆盖到。

**接受的代价：**

- 豁免路由上、可选认证路由上没带凭据的请求，以及链上没有认证层的装配上，限流不生效。链上没有认证层的装配包括宿主既没有纳入认证模块、也没有为它预置实例，以及为网关预置的实例不是网关模块的产物。这些情形与「本层不存在」在外部不可区分。
- 取不到租户的请求共用同一个不含租户段的键，因而彼此挤占同一份计数，并按全局层的额度判定。
- 一个主体对它自己在一个租户内全部路由的调用共用一个额度，一个慢接口会吃掉它其余调用的份额。
- 管理员在冒充期间发出的请求与它自己直接发出的请求共用同一份额度。

## 失效条件

假设责任键只有一个正确答案，即实际操作者。若出现按被当作请求方的账户计数才合理的下游消费者，或认证模块让 `Key()` 的取值带上第二个维度，本记录对键取值的结论要重新检验。守住这个假设的是认证模块里一条断言 `Key()` 等于 `string(Actor())` 的测试（[ADR-authn-identity](adr-authn-identity.md)）。

若某个部署要求同一用户在多个租户下共用一份额度，租户段要从键里去掉，本记录随之重新检验。
