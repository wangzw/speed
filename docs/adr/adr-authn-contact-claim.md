# 邮箱地址的占用由联系方式预留的唯一约束原子仲裁，未验证预占被接受

## 背景

邮箱在账户持有并经持有人选作登录方式时是口令登录的登录名（REQ-signin-006）。标识表 `authn_identifiers` 只承载已写下的标识，没有待验证的行（`verified_at` 非空），`UNIQUE (kind, value)` 在写入标识时仲裁占用；但邮箱在验证之前先以一条待验证预留落在 `authn_pending_contacts`，这张表没有全局唯一约束，同一地址可以被多个账户同时列为验证目标。注册本身也不检查地址占用，占用只在验证码证明控制之后、写标识的那一步以唯一约束冲突暴露。

由此产生的状态：

- **地址的占用判定不是原子的。** 两个并发注册可以都成功；先完成验证的账户拿到标识，后完成验证的账户在写标识时失败，而它的账户、用户名与口令已经建成，且这个邮箱永远不能成为该账户的一条标识。
- **抑制不产生归属。** 自助添加邮箱对已被其他账户持有的地址按相同的应答处理，不发送验证码；调用方拿不到证明该地址的机会，这条请求没有完成路径。抑制隐藏了冲突，但没有回答“这个地址属于谁”。
- **注册时收集的邮箱没有仲裁点。** 注册成功与邮箱可用是两件事，客户端在注册阶段无法知道地址已被占用。

决定要在下列约束内成立：

- 邮箱地址的占用必须由数据库唯一约束保证原子性，不靠先读后写。
- `authn_identifiers` 继续只承载已写下的标识，不引入待验证的标识行。
- `authn_pending_contacts` 表已经存在，承载注册收集的邮箱；同一份数据可以改造成预留表。
- 不做数据迁移；部署可以清理重建，Fly.io（[REF-fly-io](../references.md)）的卷与数据库可以丢弃重建。
- 接受未验证预占：地址的第一个注册者取得占用，不要求它在取得时证明控制该地址。
- 账户已有的标识、注册验证状态与口令登录的读取路径不变。

## 考虑过的选项

### 保持无全局唯一，发码阶段抑制已占用地址

注册不检查邮箱占用，同一地址可被多个账户列为待验证目标；自助添加邮箱对已被其他账户持有的地址答相同的 `pending`、不发码、不花预算。

**否决**：注册阶段没有仲裁点，地址的占用不是原子的；后验证的账户会在写标识时失败，而它的注册已经成功。抑制只是把冲突藏起来，不解决归属，也不给被抑制的调用方任何完成路径。

### 唯一预留，真正的所有者凭证明接管

`authn_pending_contacts` 设全局唯一，第一个注册者取得预留；真正的所有者用邮箱验证码证明控制之后，预留与账户归属一起转到证明者名下，原预占账户的预留被释放。

**否决**：接管要在验证码回路里跨账户改写预留与归属，涉及原账户是否保留、并发接管与证明窗口的竞态；当前产品阶段不需要这条路径，先接受预占与清理释放。

### 唯一预留、接受未验证预占、按 TTL 清理

`authn_pending_contacts` 成为联系方式预留表，`(kind, value)` 全局唯一；注册在同一事务里插入未证明预留，唯一索引是唯一仲裁点；未证明预留被接受为占用，随该地址被证明转为已持有，随账户删除或未验证账户的清理释放。

**采纳**，见决策。

## 决策

采纳：**`authn_pending_contacts` 是联系方式预留表，`(kind, value)` 全局唯一；预留只仲裁地址归属，不记录该地址是否作登录方式或默认联系地址；注册插入预留即原子仲裁地址归属，未验证预留被接受为占用；未证明预留随该地址被证明转为已持有、随账户删除或未验证账户的清理释放，已持有预留随邮箱标识的删除或账户删除释放；不做数据迁移，旧库重建。**

- 预留行以 `verified_at` 区分：为空是注册写下的未证明预留，非空是该地址已被账户占用（证明写入或管理员写入）；预留行不记录该地址是否作登录方式，也不承载默认联系地址。
- `Signups.Register` 在开户事务里插入一条邮箱预留。唯一索引是地址的唯一仲裁点：插入失败即 `authn.ErrContactTaken`，整个事务回滚，账户、用户名标识与口令凭据都不留下。注册不在插入之前读邮箱占用。
- `AccountAdmin.Create` 与 `AccountAdmin.AddIdentifier` 写邮箱标识时，在同一事务里写入或提升该地址的预留；预留属于别的账户即 `ErrContactTaken`。
- `AccountAdmin.RemoveIdentifier` 删除邮箱标识时删除该地址的预留，地址释放给其他账户。
- 手机不写预留。证明手机标识时删除同值的待验证目标；手机的唯一性仍只由 `authn_identifiers` 的 `(kind, value)` 约束仲裁。
- 未证明预留随该地址被证明置为已持有；已持有预留随对应邮箱标识的删除或账户删除释放；未证明预留随账户删除或未验证账户的清理释放。没有单独针对预留行的期限。
- `ErrContactTaken` 在注册、自助添加邮箱（发码与写标识两步）、管理面的账户创建与标识添加上一律映射为 409 `email-taken`。
- 旧库不迁移：已有行违反新的唯一索引时，数据库重建而不是对账。Fly.io 部署丢弃卷与数据库后重新部署。
- 表结构与各写入接口的契约细节由 [authn-account](../design/modules/authn/design-authn-account.md) 与 [authn-login](../design/modules/authn/design-authn-login.md) 给出，本记录不重述。

## 后果

邮箱地址的占用在注册事务里一次确定，并发注册只有一个能拿到地址；标识表仍只承载已写下的标识；删除标识释放地址，未验证账户的清理释放地址。

**接受的代价：**

- **匿名注册可以探测地址占用。** 409 `email-taken` 与 409 `username-taken` 一样对匿名调用方可见；注册不再隐藏邮箱是否已被预留或持有。自助添加邮箱的发码请求也从相同的应答改为显式的 409，并因此不再占用重发窗口与预算。
- **未验证的预占会挡住真正的所有者。** 先用某地址注册的账户取得占用，即使它从未证明控制该地址；真正的所有者不能仅凭验证码接管，只能等预占账户被删除或经未验证账户清理释放。
- **持续活动的未验证账户长期占用地址。** 清理只删长期未活动的未验证账户；一直登录但不验证邮箱的账户保持预留，地址对它一直不可用。
- **更换验证目标不释放旧预留。** 未验证账户把验证目标换成另一个地址并证明之后，注册时写下的旧地址预留不在这次写入里删除，仍占用旧地址直到账户被删除；界面上的“更换邮箱”因此不能把原地址立即还给其他账户。
- **没有所有者接管路径。** 预占账户存在且活动时，地址只能经管理面删除该账户后重新注册，或等清理；本决定不提供经证明迁移归属的操作。
- **每个邮箱写入多一行。** 标识与预留在同一事务里成对写入；直接写库可以绕过预留，造成两份记录不一致，此后从预留表与标识表读到的该地址归属可能不同。
- **全部写入接口受约束。** 管理面的账户创建与标识添加、导入与自助添加都受 `ErrContactTaken` 约束；运维脚本对已被预占的地址会收到 409，需要先处理预占账户。
- **旧库需要重建。** 不做数据迁移；已有数据库里重复的联系方式预留使唯一索引无法建立。Fly.io 部署删除卷与数据库后重建。
- **错误码新增进入发布对账。** 409 `email-taken` 是宿主可见的问题码，前后端的错误文案与白名单随之扩展。

## 失效条件

产品要求真正的所有者凭邮箱证明接管已被预占的地址，或要求未验证账户不得占用地址，或要求注册不暴露地址是否已被占用；任何一条成立时本决定的前提不再成立。
