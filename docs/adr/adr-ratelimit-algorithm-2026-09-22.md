# 限流以两个固定窗口加权近似滑动窗口

## 状态

已接受

## 背景

键值原语的接口按最弱后端设计，不暴露有序结构、脚本与管道，需要它们的算法在那套原语之外表达不了。原子操作都只作用于单个键——自增、带过期时间的自增、比较并交换、带过期时间的不存在则写入——没有跨键或按范围的原子能力。精确的滑动窗口要记下窗口内每一次请求的时刻，落在这条界外。

判定的键由本模块自己拼。原语不划分前缀、不保证租户隔离，两个消费方用同一个键即互相覆盖。

## 考虑过的选项

### 滑动窗口日志

**否决**：要为每次请求写入一条带时刻的记录，按时间范围读取并计数，需要有序结构。原语的接口不提供它，而接口以最弱后端为准这条纪律不因换后端而解除。

### 单个固定窗口

一个键，以窗口编号切分，自增即计数。

**否决**：窗口边界处会出现双倍突发——调用方在两个相邻窗口的末尾与开头各发满一份额度，跨过边界的那一小段时间里实际速率是额度的两倍。这恰是限流要抹平的那一类。

### 令牌桶

**否决**：要存上次补充的时刻与当前令牌数两个量，并以比较并交换拼一个读改写循环。循环在竞争下要重试，而原语的比较并交换不携带失败原因，调用方分不出值不匹配与键不存在，重试的终止条件因此含糊。

### 两个固定窗口加权求和

**采纳**，见决策。

## 决策

采纳：**估计值取「当前窗口的计数 ＋ 前一窗口的计数 × 权重」**，权重是窗口内尚未走过的那一段占窗口长度的比例。判定以估计值和额度比较。计数走带过期时间的原子自增，**过期时间取两倍窗口长度**。

**过期时间必须覆盖两个窗口。** 键的过期时刻由它首次写入的那一刻起算，其后的自增不续命，而键名含窗口编号——上一个窗口的键由那个窗口内的首次请求创建。过期时间若只取一个窗口，那个键的存活终点就是「上一窗口内首次请求的时刻 ＋ 一个窗口」，一个在窗口一开始就有请求的主体，它的键在当前窗口开始的那一刻即已过期，前一窗口计数恒为零，估计值退化成只有当前窗口计数。取两倍窗口，使任一窗口的键在它自己那个窗口与紧接的下一窗口内都读得到。

**自增发生在判定之前**，被判超限的请求也计入当前窗口。只对放行的请求计数，会让被拒的请求不消耗任何额度，同一窗口的后半段于是随着权重下降提前放行——限制的严格程度取决于权重曲线，而不是调用方实际发了多少。

## 后果

一次判定恒为两次后端调用与一次比较，复杂度 O(1)。

**接受的代价：**

- 边界附近的估计值与精确的滑动窗口有偏差，可能更宽松也可能更严格，偏差幅度随窗口长度与流量分布而定。
- 每个主体在任一时刻占用两个计数键，一个属于当前窗口，一个属于前一窗口。
- 键的字符集与格式是本模块自己的一份约定。别的消费方读不懂它，也不该读它。

## 失效条件

若所有目标后端都能提供有序结构，而部署确实需要精确的窗口计数，则接口以最弱后端为准这条纪律的取值需要重新检验。
