# 租户列存不可变标识，请求面出现的名字是名册上的可改别名

## 状态

已接受

## 背景

受租户约束的每一张表都有一列记住这一行属于哪个租户（[ADR-tenant-isolation-2026-09-21](adr-tenant-isolation-2026-09-21.md)）。那一列里存什么，与请求面上出现什么，此前没有出处。

两个位置上的约束不同。请求面上出现的是取法读到的那个串：子域名的合法字符集、路径段的合法字符集与请求头的取值三者并不相同，而用哪一种由配置选定（[ADR-tenant-resolution-2026-09-21](adr-tenant-resolution-2026-09-21.md)）。库里那一列的取值不在任何 URL 的语法之下，它的读者只有本模块、日志与排查的人。

改名是租户生命周期上必然发生的动作：换一个子域名、公司改名、与另一个系统对接时统一命名。它必须在租户已经在服务之后仍然可做，而那时受约束表里已经有行。

标识还要出现在日志、启动诊断与错误文本里。这些场合的读者是人，读到的东西要能直接认出是哪个租户。

## 考虑过的选项

### 请求面上那个串直接入列

取法读到的名字就是库里那个取值，一次解析省掉。

**否决**：改名等于重写每一张受约束表的每一行，而改名是必然要支持的动作。它还把取法的字符集变成库的约束：换一种取法就换一套合法字符，而已入库的取值不跟着变——同一份数据在两次部署之间可用的名字不同。URL 的语法约束因此变成库的约束，而两者管辖的范围本不相同。

### 数值自增主键入列

名册用一个自增整数做主键，受约束表存那个整数。

**否决**：跨库搬迁与合并时撞号，而这两个动作在多租户系统里是常规运维。它在日志、启动诊断与错误文本里读不出是谁，每次排查都要回查名册；认证对身份的字符串形式坚持带归属限定，理由是同一件事（[ADR-authn-ownership-2026-09-20](adr-authn-ownership-2026-09-20.md)）。

### 不可变标识入列，请求面的名字是名册上的可改别名

名册的一行携带一个不可变标识与一个可改的别名，受约束表存标识，请求面出现别名，解析即别名换标识。

**采纳**，见决策。

## 决策

采纳：租户列存不可变标识；请求面出现的名字是名册上的别名，别名唯一、可改，改名不动任何受约束表。

```go
// ID 是一个租户的不可变标识。
type ID string
```

**标识是一个字符串，由建立租户的一方给出，本模块不生成它。** 生成它要求一个全局唯一的生成器，而宿主已有自己的身份体系：从既有系统迁移时，那里的租户号就是标识，另造一个只会让两套编号长期并存。本模块校验它的形状——非空、不含空白与控制字符、长度不超过 36 个字节（UUID 的规范写法，也是既有编号各形态中最长的那个）——不校验它的来源。

**别名由建立租户的一方一并给出，唯一，可改。** 别名的字符集由取法约束，不由本模块规定：子域名取法下它是一个 DNS 标签，路径前缀取法下它是一个路径段。同一个别名在名册上只对应一个租户，两个租户抢同一个别名是启动期与写入期都判得出的一类失败。

**解析是别名到标识的一次换名**，写进请求上下文的是标识。日志、启动诊断与错误文本一概写标识，需要人能认出来的场合另外带上别名——别名可改，因而它不承担任何判定。

## 后果

改名是一次名册写入，受约束表一行都不用动。跨库搬迁与合并时标识保持原样，合并的冲突落在别名上，而那是人读得出的一类冲突。

受约束表的那一列与请求面上出现的东西从此是两个概念，链条是：取法读出别名 → 名册换成标识 → 上下文携带标识 → 插件按标识加条件 → 日志与诊断写标识。

**接受的代价：**

- **每个请求要把别名换成标识，因而必须读名册。** 换名的结果要有缓存与失效途径，租户名册从此位于请求的关键路径上；它答不了时请求收口而不是放行。
- **标识与别名两个概念并存，两个场合各写哪一个要各自明确。** 写错一处的形态是排查时对不上号：日志里是标识，而操作者手上是别名。
- **别名可改意味着别名可被回收。** 一个被释放的别名指向新租户之后，旧的书签、缓存与客户端里的地址会把请求带到新租户。回收策略是宿主的事，本模块只保证别名在任一时刻唯一，不保证它指过的东西保持不变。
- **标识不可变，因而它不能承担任何随租户而变的信息。** 把区域、分级一类东西编进标识的宿主，改它们时要面对一次数据迁移，而本模块不提供。
- **长度上界把长于 UUID 的既有编号挡在门外。** 从既有系统迁移时把那里的租户号原样带过来是本条的出发点，而一个超过 36 字节的编号要么在迁移时改写，要么这条上界重新比较。原样带过来的前提是它落在上界之内。

## 失效条件

若出现一种部署形态，其中同一个租户在不同监听端上必须由不同的名字到达，且这些名字不能同时是别名，则"别名唯一"这一条不再够用，名册的键要重新裁定。

若宿主普遍需要本模块生成标识，则"不生成"这条要重新比较：多一套生成器与长期并存两套编号之间，权衡的结论可能相反。
