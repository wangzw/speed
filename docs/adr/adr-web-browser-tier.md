# 前端的版面与可聚焦性由真实浏览器层的用例守住，不进提交门禁

## 背景

前端的单元层跑在 jsdom（[REF-jsdom](../references.md)）里。jsdom 不求值媒体查询与容器查询，不做布局，也不判定一个节点是否可被键盘聚焦。下列性质因此在单元层里测不出，只有真实布局才能判定：

- **占位与偏移。** 外壳里的占位元素用主题工具条的高度写法时，主题的断点规则会盖过组件自己声明的最小高度；jsdom 里 `toHaveStyle` 读到的是声明值，断言通过，而真实渲染里占位偏小、内容被顶部栏盖住。
- **可聚焦性。** 视觉隐藏的播报区里若含带 `overflow: auto` 的节点，真实浏览器会把它当作可滚动、可聚焦的停靠点；jsdom 与路由级的无障碍扫描都没有布局，看不到。
- **数据表各档的宽度。** 每个断点档的可见列宽度之和是否不超过该档下限，只有真实字体与真实布局能量出来。
- **焦点顺序。** 跳转链接是否仍是第一个可聚焦元素，取决于渲染顺序与定位，不取决于组件树里的声明。

这些性质的测量目前只有临时的 Chromium 运行，不可重复。

提交门禁要求在任何装了 `.mise.toml`（[REF-mise](../references.md)）所列工具链的机器上跑到绿（见 ADR-test-tiers）；Chromium 不在那份工具链里。

## 考虑过的选项

### 保持单元层加偶发的人工测量

**否决**：版面类缺陷在重构里静默回归，没有人知道下一次改动前该去量；测量不可重复，同一个宽度、同一种横幅高度下的结论无法在两次运行之间比较。

### 把浏览器用例放进提交门禁

**否决**：每台跑提交门禁的机器都要有 Chromium，违背「提交门禁只要求工具链」；用例比 jsdom 慢一个量级，且对机器负载敏感，门禁会因时钟而不是断言失败。

### 用截图做视觉回归

**否决**：像素差异与字体、平台相关，判不出「占位等于横幅与顶部栏之和」这类性质，反而在无关的渲染差异上报红；要判定的是几何关系、焦点顺序与可聚焦性，不是像素。

### 浏览器层作为独立的一层，由定时任务与手动入口运行

**采纳**，见决策。

## 决策

采纳：**前端新增一层浏览器用例，在真实 Chromium 里断言版面与可聚焦性的不变量，不断言像素；它与单元层分开，由 `make web-browser` 与定时的 CI 任务运行，不进 `make check`。**

- 用例断言的是不变量：几何关系（占位等于横幅与顶部栏高度之和、某点命中的是内容自身、表格 `scrollWidth` 不超过 `clientWidth`）、焦点顺序（跳转链接第一）、可聚焦性（无障碍规则 `scrollable-region-focusable` 为零）。
- 第一批覆盖：外壳的偏移与占位（三个宽度、三种横幅高度、常驻与临时抽屉与窄栏）、跳转链接的 Tab 序、冒充横幅的播报区、表格单元格的内容宽度上限、各列表页在 `sm`、`md`、`lg` 下限宽度下的横向溢出（用固定的假数据）。
- 运行器与 Chromium 的供给方式由工程方按「复用现有组件测试的主题与 i18n 夹具、依赖族最少」选定；CI 里安装 Chromium，本地一条命令安装。
- 用例以事件等待而非固定睡眠写成，宿主负载下不因时钟判红。

## 后果

版面类缺陷由定时任务拦下，不再等下一次人工测量；跨宽度、跨语言的几何不变量有了可重复的判据。

**接受的代价：**

- **提交门禁不覆盖版面。** 一个破坏版面的提交在当天的定时任务之前不会红。
- **多一个依赖族与一份 Chromium 安装。**
- **浏览器用例比单元层慢一个量级，且依赖机器的字体。** 几何断言要对字体差异留出可解释的余量，或把字体固定在夹具里。

## 失效条件

- 若提交门禁机器都能稳定提供 Chromium，且浏览器层的耗时降到与单元层同量级，应并入提交门禁。
