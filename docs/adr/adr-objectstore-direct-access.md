# 业务前端经直连地址读写对象字节，铸址归元数据面，后端把能否铸址声明为可选能力

## 背景

objectstore 是给业务后端用的能力，不是给终端用户用的功能。业务后端在进程内经 `Objects` 声明、上传、完成、取址、列举、删除；业务前端必须以一条 URL 直接读写字节（例如 `<img src>`），从不调用对象存储自己的结构化 API。以下事实约束着取址与字节投递：

- **通用对象权限不在本能力内。** 一条取到的 URL 是否允许某个终端用户访问，是业务后端的判断；能力不拥有通用对象权限。
- **URL 只因到期而死。** 轮换是再要一条，没有撤销 API。
- **内部键不出现在对外可见之处。** 内部键不出现在任何结构化应答、错误文本与日志里。
- **预签名地址必然携带后端对象键。** `s3` 的预签名地址在路径里带后端对象键，这是后端自身的寻址方式。
- **入口模块的访问日志无条件记录路径。** `pkg/http` 的访问日志记录 `r.URL.Path` 而不记录查询串，路径里的凭据会进日志。
- **`fs` 只依赖标准库与根包。** `fs` 不 import `pkg/http`、不认识 URL、不持有任何密钥。
- **能力在装配期按声明取用。** 模块在 `Provides` 里声明交付的功能接口，`core.Resolve` 按声明取；`pkg/sms`、`pkg/authz/policy` 与 `pkg/audit/journal` 已有“一模块一实例多 token”的形态。
- **通用对象 CRUD 与对象页把对象存储当成终端用户功能。** `/api/v1/objects` 与前端对象页与上述定位冲突。
- **到期由平台统一约束。** 一条地址的有效期要由平台策略给出，调用方只能缩短。

模块划分见 [ADR-objectstore-packaging](adr-objectstore-packaging.md)，三步写入见 [ADR-objectstore-lifecycle](adr-objectstore-lifecycle.md)。

## 考虑过的选项

### `fs` 自挂路由、自持签名密钥（AES-GCM 令牌）

让 `fs` 后端自己挂内容路由，并在字节根目录下持久化一枚密钥，用它封装令牌。

**否决**：把 `pkg/http` 与 gin（[REF-gin](../references.md)）拉进一个只该依赖标准库与根包的字节后端；模块在字节根目录下自造持久密钥，违背“造钥是宿主的事”的先例；令牌若放在路径段会被访问日志原文记录。

### HMAC 签名令牌（含明文载荷）

令牌由 HMAC 签名，载荷里放租户与对象标识，每次使用验签还原。

**否决**：载荷把内部键的两段放进浏览器可见的 URL；默认的进程内随机密钥会让重启作废在途 URL，与“URL 只因到期而死”冲突。

### 统一的 307 重定向层

每个后端先由应用回一条 307，把客户端跳到真正的字节地址。

**否决**：每张图多一跳应用往返，且不消除桶的 CORS（[REF-whatwg-fetch](../references.md)）前提；应用仍然要参与每一次读取。

### 所有后端的字节都由应用代理

不区分 `fs` 与 `s3`，字节一律经本进程中转。

**否决**：`s3` 的价值正在于字节不经本进程；代理让带宽与应用连接承担全部读取流量。

### `PresignedPostPolicy` 绑定尺寸与类型

`s3` 的写址用 POST policy，把声明尺寸与类型签进凭据。

**否决**：请求结构变成 multipart 表单，与 `fs` 的 PUT 不同；同一请求结构是两种后端共用一条代码路径的前提。

### 撤销表 / 每条 URL 绑定终端用户

记录每条已签发的 URL 及其主体，提供撤销，并在每次使用时校验主体。

**否决**：与“URL 只因到期而死、没有撤销 API”冲突；绑定主体会把通用 ACL 重新拉回能力里，而某终端用户能否访问是业务后端的判断。

### 保留通用 `/api/v1/objects` 与对象页，只加直连 URL

保留既有的对象 CRUD 接口与前端对象页，在它旁边加一条直连地址。

**否决**：要删的正是“对象存储作为终端用户功能”这一层；留着它意味着能力继续拥有通用对象权限，与“业务前端从不调用对象存储自己的结构化 API”冲突。

### 把内容路由并进 `api` 端点

把内容路由挂在既有的 `api` 端点上，与其他业务路由共用端点。

**否决**：租户解析与认证网关都是端点级、没有按路由豁免；匿名的 `<img>` 请求必被拒。

### 按调用传任意 TTL

取址方法接受调用方给出的任意有效期，直到后端上限。

**否决**：调用方能把有效期放到后端上限，破坏“一个平台策略、一条到期语义”。

### 铸址归元数据面，能铸址的后端声明 `DirectURL`，本地目录后端用不透明令牌加授权行

`Objects.URL` 在元数据面铸址；能铸址的后端在交付字节接口的同时声明 `DirectURL` 能力并返回后端铸出的地址；不能铸址的本地目录后端由元数据面挂一条匿名内容路由，凭随机不透明令牌加一行授权记录放行。

**采纳**，见决策。

## 决策

采纳：**业务前端经直连地址读写对象字节，铸址归元数据面；“能否铸址”是可声明的可选能力 `DirectURL`，不是字节接口的必选方法。**

- **铸址归元数据面。** 只有 `objectstore.metadata` 同时知道对象标识、租户、状态、声明尺寸与 MIME；读址与写址是同一请求结构、同一到期语义的两个分支。
- **直连是声明的可选能力。** 能铸址的后端让 `Open` 返回的同一个值同时实现 `Store` 与 `DirectURL`，并在 `Provides` 里排他声明 `DirectURL`；装配按声明取用，构造期逐一校验。不能铸址的后端不声明它，元数据面因此改挂内容路由。
- **本地目录后端用不透明令牌加授权行。** 它的地址是“随机令牌 + 一行授权记录”，不签名、不引入任何密钥；每次使用重读对象状态，删除对象即令地址失效。
- **令牌固定在查询串。** 入口模块的访问日志记录路径而不记录查询串，令牌放路径会进日志。
- **`s3` 直接给预签名地址。** 内容路由只服务本地目录后端，不为 `s3` 设 307 跳转。
- **`url-ttl` 归设置，`public-url` 归配置。** 调用方只能在平台值、上传窗口剩余时间与对象剩余寿命之内缩短，不能放大。
- **内部键改为随机不透明串，直连地址是不透明地址。** 键不含租户与对象标识；一条直连地址只能整体使用，调用方不得解析其内部结构。
- **内容路由不进 OpenAPI（[REF-openapi](../references.md)）。** 它是签名 URL 一侧，不是客户端 API。

## 后果

业务后端只需要声明对象并取址，业务前端用一条 URL 读写字节；宿主无需实现签名、令牌或路由。`fs` 与 `s3` 两种后端对调用方呈现同一个取址方法，区别只在于地址由谁铸出、字节经不经本进程。

**接受的代价：**

- **URL 即能力。** 泄露一条 URL 即到期前对该对象的读或写；转发即授权；没有撤销 API。缓解是短 TTL 且被窗口与寿命夹紧，业务在铸址之前判定。
- **上游代理仍可能记下令牌。** 令牌在查询串里绕开本进程的访问日志，但记录完整请求行的反向代理或负载均衡会记下它。部署前提是不记查询串，或接受一个 TTL 长度的窗口。
- **`s3` 预签名写址不能约束长度。** 过量的上传花掉带宽，完成时比对长度才发现不符并删字节，中间存在一段占用。
- **`s3` 直连上传没有校验和。** 字节不经进程，`checksum_sha256` 留空，声明的校验和无法核对；需要内容级保证的业务走进程内上传或自行下载复算。
- **本地目录后端的媒体热路径依赖数据库。** 每次字节请求一次授权行查询加一次对象行读取；数据库不可用时图片不可用。
- **每次铸本地目录地址写一行授权记录。** 写入放大与签发率同阶；业务应缓存已铸的地址直到临近到期。
- **本地目录后端多副本不成立。** 共享卷不在承诺内；内容地址指向的进程必须能读到字节。多副本必须用 `s3`。
- **装配是配置正确性依赖。** 内容端点必须匿名且不设请求体上限，没有编译期护栏；缓解是启动诊断与迁移清单。
- **完成语义放宽。** “未上传就完成即状态冲突”的既有断言失效，改为“字节不在”；补偿是完成步骤真的去看后端字节。
- **删除通用对象这一层是宿主可见的破坏性变更。** 配置键、权限点、特性名、路由、OpenAPI 片段、生成客户端与前端对象包全部消失。
- **`public-url` 留空只适合同源部署。** 跨源部署忘了配置会得到根相对地址，前端请求打到自己的源。

## 失效条件

- **若多数部署要求对每条地址可撤销或绑定终端用户**（例如合规要求逐次授权），则“URL 只因到期而死”的前提失效，令牌加授权行的设计要重议。
- **若上游代理普遍必须记录完整请求行**，则令牌放查询串这条决定失效，令牌的位置要重议。
- **若跨源部署成为常态且桶的 CORS 无法配置**，则“`s3` 直接给预签名地址、不设跳转”失去可行性。
