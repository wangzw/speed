# 模态弹层打开期间背景设为 inert，由 ui-kit 的共用 hook 在 layout 阶段施加与撤除

## 背景

前端全部模态弹层都经 MUI 的 Modal 渲染：`Dialog`、`Drawer`、`Menu`、`Popover`，以及 `Select` 与 TextField select 展开的菜单。MUI 的模态管理器（[REF-mui](../references.md)）在弹层打开时给背景设 `aria-hidden`，让整页对辅助技术隐藏，却不设 `inert`。背景因此仍留在 Tab 顺序里：焦点陷阱之外第一次按 Tab，焦点落到背景里打开弹层的那个控件上，这一步没有可见焦点，读屏通常也不播报，从第二次按键起焦点才回到弹层内并保持。菜单不同：MUI 9.5 的菜单按 Tab 直接关闭并把焦点交还触发控件，空档出现在对话框与抽屉这类把 Tab 循环留在弹层内的浮层。

`inert` 是 HTML 的一个属性，带它的元素及其子树不可聚焦、不被辅助技术读到（[REF-whatwg-html](../references.md)）。axe-core 把位于 `inert` 子树内的元素算作不可聚焦（[REF-axe-core](../references.md)），背景带上 `inert` 后，`aria-hidden-focus` 规则在 jsdom 与 Chromium 两档都直接判通过。

焦点归还的时机决定了施加与撤除必须落在哪一阶段。MUI 的焦点陷阱在被动效果阶段的清理里把焦点还给打开弹层的控件；`aria-hidden` 要等弹层的退出过渡结束才撤，晚于焦点归还。撤除 `inert` 若跟随 `aria-hidden` 的节奏，归还的那一刻目标仍带 `inert`，`focus()` 静默失败，焦点落到文档正文。

## 考虑过的选项

### 维持现状，容忍第一次按键落到背景

**否决**：背景对键盘可达，与模态弹层的语义相违，弹层打开期间背景本不应可交互。测试对 `aria-hidden-focus` 只能报告、无法判定为失败，缺陷因此在每一份打开态的扫描日志里反复出现，却从不阻断合并。

### 扫描时把背景排除在检查之外

扫描打开态的弹层时，不把背景节点交给 axe 判定。

**否决**：这只让违规不被报告，背景仍对键盘可达。缺陷还在，门禁反而失去发现它的能力。

### 只改测试压掉这条诊断

保留背景原样，把 `aria-hidden-focus` 从判定的规则集中移除或降级。

**否决**：改动落在报告层，使用者面对的行为不变，缺陷仍留。

### 用 `MutationObserver` 镜像 MUI 的 `aria-hidden`

监听 `aria-hidden` 的变化，在它出现时加 `inert`、在它撤除时撤 `inert`。

**否决**：`aria-hidden` 在关闭时等退出过渡结束才撤，晚于焦点归还，镜像它就把撤除推迟到同一时刻，归还目标带 `inert`，归还静默失败。观察器也无法区分 MUI 设的 `aria-hidden` 与宿主自己设的。

### 以 MUI 的 `disableEnforceFocus` 一类选项替代

**否决**：这类选项只放松或关闭弹层的焦点陷阱，不让背景不可达，键盘焦点因此更容易跑进背景，与要解决的问题相反。

### ui-kit 的共用 hook 在 layout 阶段计数施加与撤除

ui-kit 导出一个 hook，在打开提交的 layout 阶段给背景加 `inert`，在关闭或卸载提交的 layout 清理里撤除；每个直接用 MUI 模态弹层的调用点接入它。

**采纳**，见决策。

## 决策

采纳：**由 ui-kit 导出共用 hook `useInertBackground(open, overlayRef)`，在打开弹层的那次提交的 layout 阶段给背景加 `inert`，在关闭或卸载的那次提交的 layout 清理里撤除，撤除早于 MUI 的焦点归还；每个直接用 MUI 模态弹层的调用点接入它，选择框经 `useInertSelectMenu` 接线。**

按元素计数持有：同一元素被几层弹层保护就记几次，计数归零才移除 `inert`，层叠与乱序关闭因此只撤各自的那一份。hook 从不读写 `aria-hidden`，与 MUI 的模态管理器并存。选择框自持打开状态，把 `Select` 或 TextField select 改为受控打开。

焦点归还也由这个 hook 承担。打开提交里记录当时持焦点的元素，但该元素若位于同一提交里正在关闭的弹层内，它即将离开文档，不记为归还目标。关闭时若记录仍在文档中，hook 把焦点交还它；没有记录、或记录已离开文档时 hook 不动焦点，交给 MUI 焦点陷阱的归还或宿主的安排。门户比打开晚一次提交：同一提交里没有别的弹层在退场时 hook 当场施加；有弹层仍在退场时，hook 以有限次定时重试等本次的门户挂上，避免把退场弹层仍要归还焦点的元素设为 `inert`。

接口签名、施加范围与层叠规则由 ui-kit 的设计文档给出，本记录不重述。测试工具要求弹层打开时背景同时带 `aria-hidden` 与 `inert`，`aria-hidden-focus` 违规一律判定为失败。

设计文档不再接受该空档，见“模态弹层的背景”。

## 后果

弹层打开期间背景既对辅助技术隐藏又不可聚焦，第一次 Tab 不会落到背后；对话框、面板、菜单与层叠对话框关闭后，焦点回到发起控件。发起控件仍在文档中时焦点交还它；发起控件已随弹层一起离开文档时 hook 不动焦点，落点由 MUI 的焦点陷阱或宿主决定。模态语义在键盘与读屏上成立，`aria-hidden-focus` 在 jsdom 与 Chromium 两档都判通过，测试对这条规则按违规判定。

**接受的代价：**

- **每个直接用 MUI 模态弹层的调用点都要接 hook。** 漏接由测试的背景断言兜住，但断言只覆盖有打开态扫描的弹层；没有扫描的弹层仍可能漏接。
- **选择框改为受控打开。** `Select` 与 TextField select 的调用点改用 `useInertSelectMenu` 自持的打开状态；循环里渲染的选择框要抽成小组件，因为 hook 不能在 `.map` 里调用。
- **打开期间新插入 `body` 的节点不受保护。** 与 MUI 的 `aria-hidden` 一致，打开之后才插入 `body` 的节点不会补 `inert`；测试的背景断言会把这样的节点报为违规。
- **背景里的实时区域随背景一起不可达。** 共享播报区与页面各自的 live region 在弹层打开期间进入 `inert`，与弹层打开时已有的 `aria-hidden` 效果一致；关闭的同一次提交撤除，关闭后的播报不受影响。
- **另一个弹层仍在退场时，新的弹层晚几拍才把背景设为 `inert`。** hook 要等本次的门户挂上才知道背景范围，定时重试次数有上限；等不到时回落到整页算背景。
- **退出过渡窗口背景仍 `aria-hidden` 而 `inert` 已撤。** MUI 要等过渡结束才撤 `aria-hidden`，hook 在关闭提交就撤 `inert` 以便归还焦点。这段时间背景对辅助技术隐藏却可聚焦，扫描测试不能把仍在退场的弹层当作打开中的弹层，测试工具因此区分这两种状态。
- **测试工具趋严。** 背景缺 `inert` 或 `aria-hidden-focus` 违规都让扫描失败；自建裸 MUI 弹层的测试夹具要补 `inert` 或改用 hook。

## 失效条件

- MUI 的模态管理器提供原生的 `inert` 选项，打开弹层时自己设 `inert`：共用 hook 可以退役，调用点回到只传 props。
- 支持矩阵出现不支持 `inert` 的目标浏览器，而背景必须对它可交互：需要另一种让背景不可达的机制。
