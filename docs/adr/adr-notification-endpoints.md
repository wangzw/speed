# 通知偏好路由按端名清单挂载，不挂在入口模块声明的每一个端上

## 背景

`notification.preferences` 在 `Init` 里遍历入口模块登记接口报出的端名，在**每一个**端上挂 `/api/v1/notifications` 下的三条路由。当时的依据是 i18n 一侧的先例：`pkg/i18n/http` 同样遍历 `Router.Endpoints()`，在每个端上登记本地化层。

这条先例不适用，因为两者登记的东西不同。i18n 登记的是**中间件**（`Endpoint.Use`）：中间件不占路径空间，挂在哪条路由旁边都不冲突。preferences 登记的是**路由**，而同一个端上不能既有一条通配路由又有一条具体路由——gin（[REF-gin](../references.md)）在同一个方法树上拒绝 `/*path` 与具名路径共存，入口模块在组装链时以路由冲突终止启动，错误形如 `endpoint "web": the routes "GET /api/v1/notifications/types" and "GET /*path" cannot both be mounted`。

冲突是硬的，且落在一条既定拓扑上。入口模块只要声明了 `web` 端，`pkg/webui` 就在那个端上挂一条覆盖整个路径空间的通配路由（`GET /*path` 与其 `HEAD` 一条），做深链接回退；preferences 的路由随之落在同一个端上，进程启动失败。**一个同时服务前端的进程因此装不了偏好矩阵**，而「前端 + API 同进程」是本框架的两种既定拓扑之一。

同族的两个兄弟已经点名端点：`notification.inbox` 读 `notification.inbox.endpoints`，`notification.stream` 读 `notification.stream.endpoints`，两者都在路由能力在场时把清单当必填项。三个模块的路由落在同样的路径空间上，只有 preferences 一个不点名端。

## 考虑过的选项

### 保持现状：挂在入口模块声明的每一个端上

**否决**：一个服务前端的进程装不了本模块。这不是「配错了才出现」的失败，而是拓扑本身的冲突：前端模块必须覆盖它那个端的整个路径空间才能把深链接交回单页，而本模块的三条路由必须在该端上是具体路径。两者在同一方法树上互斥，没有配置能把它们调和。

### 让前端模块改用 `NoRoute` 兜底，不再占用整个路径空间

**否决**：那是改另一个模块的既有契约，且只针对路由引擎这一种冲突形态。路由落在不该落的端上，是 preferences 自己该收窄的事；把代价转嫁给前端模块，等于让每一个与前端模块同端的模块都来重议通配路由。

### 给本模块加端名清单，照同族两个兄弟的写法

**采纳**，见决策。

## 决策

采纳：**本模块声明配置命名空间 `notification.preferences`，读端名清单 `notification.preferences.endpoints`，只在点名的端上挂本模块的路由。**

- 清单照两个兄弟的形态：路由能力（`(*http.Router)(nil)`）在场而清单为空即以 `notification.ErrInvalidConfig` 终止启动，以完整路径 `notification.preferences.endpoints` 点名这一项；入口模块缺席时清单不被读取，空清单合法。
- 清单是一组具体端名（封闭判据）：保留端名 `*`、空名与写了两遍的端名都被拒绝并点名这一项。`*` 被拒绝的理由与两个兄弟一致：把路由挂到入口模块声明的每一个端上，公共端也一并挂上。
- 入口模块没有声明点名的端时，启动以该端的错误终止，不留部分挂载。
- 该项只取主来源（`config.OriginPrimary`）：它决定路由落在哪里，环境变量或命令行参数若能改写它，就等于可以从配置文件之外移动这些路由。

## 后果

本模块可以与一个服务前端的端共存于同一个进程：宿主把前端与 API 放在不同的端上，并在清单里点名 API 那一个，通配路由与具体路由各归其端。

三个通知模块的端名清单同名且一致，宿主只需知道一条规则，模块之间也不必各自发明一套端名约定。

**接受的代价：**

- **宿主多一个必填项。** 只有一个端，或本来就想让偏好路由落在所有端上的宿主，现在也要写出 `notification.preferences.endpoints`；漏写即启动失败。这是把「路由落在哪里」从隐式约定变成显式声明所付的价。
- **配置项是宿主可见的接口。** `notification.preferences.endpoints` 的路径与语义是宿主可见的接口，改动它是破坏性变更。
- **端名是字符串，本模块的配置与入口模块的配置之间的对应靠启动期校验建立，编译器不参与**——与端名参数本身同源（[ADR-http-endpoints](adr-http-endpoints.md)）。

## 失效条件

- 若前端不再与 API 同进程（宿主用反向代理把两者分到不同的监听，或前端由独立进程服务），清单对「同进程」这一档不再必填，只余下「路由落在哪个端由宿主说了算」这一条。
- 若入口模块的登记接口改为按路径前缀分派而不是按方法树组装，通配路由与具体路由的互斥不复存在，这条决定的前提随之消失。
