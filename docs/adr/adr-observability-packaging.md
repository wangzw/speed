# 根包是接口包且不登记模块，装配器排他、导出后端非排他

## 背景

`pkg` 是一个 Go module，功能在其中按包划分：功能目录的根包承载接口与公共逻辑，实现位于子包；模块名由实现子包导出，形如 `observability.otel`（[ADR-module-layout](adr-module-layout.md)，常量见 `pkg/observability/otel` 的 `ModuleName`）。

同一横切能力的多条通路同属一个登记单元，判据是它们共用一份数据形状与一份写入面，拆开会让这份共用变成跨模块的契约（[ADR-audit-packaging](adr-audit-packaging.md)）。

本功能目录要容纳三种形态不同的东西：不绑定实现的类型面、构造 provider 的装配器、以及各绑自己传输库的导出后端。多个导出目的地并存是部署形态：一路推送采集端、一路落标准输出。

## 考虑过的选项

### 根包即实现，登记一个模块

根包自己实现采集层与 provider 的构造，登记一个模块，导出后端作为它的子包。

**否决**：导出后端各自需要按自己的配置构造，共用一个模块就没有位置放它们各自的命名空间与生命周期；根包登记模块还意味着取用它的人一并带上实现子包的依赖，而接口包定义类型而不绑定实现的价值随之取消。

### 拆成 pkg/trace 与 pkg/metric 两个功能目录

追踪与指标各自成为功能目录，各自登记模块，各自持有导出后端的收集点。

**否决**：追踪与指标共享服务身份与导出端点，两个功能目录各写一份而没有强制一致的机制，二者同开时给出两条身份对不上的流且不报错。

### 导出后端做成资源声明，由装配器按类型收集

每个导出后端声明一条资源，装配器按类型把资源收齐后构造导出器。

**否决**：资源在 `init` 期随描述符冻结，拿不到配置，而导出器必须按自己的配置构造；走非排他的功能即可，且不产生一个按类型收集资源的消费点。

### 根包是接口包，装配器与导出后端各登记模块

**采纳**，见决策。

## 决策

采纳：`pkg/observability` 是接口包，**不登记任何模块**；`pkg/observability/otel` 登记装配器，**排他**交付追踪与指标的 provider 功能；每个导出后端是一个实现子包，登记一个模块，**非排他**交付导出器功能。

## 后果

宿主按目的地取用：接口包与装配器不绑定任何导出后端，新增一种目的地是新增一个模块（依赖闭包与扩展点的机制见本模块的设计文档）。

**接受的代价：**

- **排他交付让两条信号的成败耦合。** 装配器对追踪与指标分别声明排他并表态 `StateEnabled`，消解的退让只落在「声明排他且表态 `StateAuto`」的提供者身上，装配器因此不会被消解禁用。任一条信号上出现第二个仍然启用的提供者时，由裁决判 `ErrExclusiveViolated` 并终止整次启动：竞争者出现在指标一侧时，追踪一侧即使自身没有竞争者也随之无法启动（[ADR-module-enablement](adr-module-enablement.md)）。
- **点名装配器即承受上游 SDK 的闭包。** 只 import 接口包的宿主同样带上上游的追踪 API、指标 API 与两个 SDK 导出接口所在的包（别名必须写出被别名的包），但不带任何导出后端所绑的传输库。装配器另绑上游 gin（[REF-gin](../references.md)）采集库，它的闭包随装配器进入宿主（[ADR-observability-request-layer](adr-observability-request-layer.md)）。`go.sum` 与整图读取的那部分代价另见 [ADR-module-layout](adr-module-layout.md)。
- **每个导出后端是一个模块，宿主在命令树上逐个点名，或为它预置实例。** 既没点名也没有预置实例的后端，那条目的地没有数据，启动期不失败，也不进启动诊断。

## 失效条件

本决策依赖「追踪与指标总是被同一个宿主一并取用、且两者共享服务身份与导出端点」这一前提。若出现只取其中一种信号、把另一种交给别的提供者的形态，或两者不再共享身份与端点，则把两个 provider 绑在同一个排他装配器上、并把导出后端分成各自模块的判据要重新检验。
