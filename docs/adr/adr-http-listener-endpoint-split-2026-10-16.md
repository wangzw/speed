# 把监听与端点拆成两层

## 状态

已接受

## 背景

入口模块此前把「一个端点（endpoint）＝一个监听套接字」写死：配置里每个端各给一个地址，`Serve` 对每个端各做一次 `net.Listen`。示范骨架因此有五个端就占五个端口，而前端 bundle 与 API 落在不同端口上，浏览器访问前端时对 API 属跨源，验收失败。

一个端点的本性是一条中间件链与一张路由表——认证、租户、限流、审计各按端登记——而不是一个地址。把地址绑在链上，使得共享同一地址的若干种流量无法并存，也使前端与 API 无法同源。

多个端点要共用一个地址，就需要一个显式的「监听」层来承载套接字，端点挂在它上面。

## 考虑过的选项

### 维持端点＝套接字，让多个端点监听同一地址

两个端点在同一地址上各做一次 `net.Listen`，靠 `SO_REUSEPORT` 之类的机制共享端口。

**否决**：同一地址上的连接由内核在套接字之间分发，落到哪个端点的链不可控，而本模块的端点链正是要按（方法，路径）精确选择的东西。共享端口还把两个 net/http.Server 堆在一起，排空与停机时序无法协调。

### 把示范的多个端点收成一个端点

前端 bundle 与 API 合成一个端点，用一条链、一张路由表承载。

**否决**：端点是产品自己划的流量边界，认证、租户、限流与审计各按端登记。收成一个端会把这些边界一并抹掉，把「哪些流量属哪个端」从配置里删掉，改由路由前缀决定，而这是本模块不认识的业务知识。

### 引入显式的监听层，端点挂在监听上

配置分监听与端点两组：一条监听是一个监听套接字（地址、四个超时、可选的 TLS 与排空时限），一个端点挂某条监听，带自己的链、请求体上限与可信代理设置。多条端点可挂在同一条监听上，共享它的套接字。

**采纳**，见决策。

## 决策

采纳：入口模块在配置中声明**监听**与**端点**两个封闭集合。

- 一条监听由一个 `net.Listen` 与一个 `net/http.Server` 承载，持有地址、四个超时、可选的 TLS 证书位置与排空时限。绑定、接受、排空与停机都按监听进行。
- 一个端点由本模块自建的一台 gin 引擎承载它的中间件链与路由表，带自己的请求体上限、可信代理网段与来源地址头名。它按名挂某条监听；指向一条未声明的监听即启动失败。
- 每条监听持有一个分派 handler：按静态前缀选出占有该请求路径的端点，把请求交给它的引擎，端点自己的引擎再匹配一次并跑它的链。一个端点的静态前缀由它各已登记路由派生，路由从根起、到首个动态段为止的字面段即是前缀。
- 分派没有端点占有该路径时，交给该监听的**兜底端点**——覆盖整个路径空间的端点，其路由含一个 `*` 通配、或登记根路由 `/`；一条监听至多一个兜底端点，且只挂一个端点的监听，那个端点即是兜底端点。没有兜底端点则答 404。
- 同一条监听上两个端点占有同一静态前缀、两个端点登记同一（方法，路径）、一个端点没有可据以被选出的静态前缀、或挂两条兜底端点，都归入既有 `ErrRouteConflict` 语义，点名该监听与相关端点。
- `Accepting` 仍是逐端点的读面，但其状态取自该端点所属的监听：同一条监听上的端点报同一个值。

## 后果

前端与 API 可以落在同一个监听上，因而同源；示范骨架的五个端点占两条监听而不是五个端口。

服务器级设置（地址、超时、TLS、排空时限）取自监听，链级设置（请求体上限、可信代理）取自端点，一处设置只在一个地方声明。

一个监听上的多个端点逐端点自建引擎、自组装链，逐端点的中间件与路由互不影响。

**接受的代价：**

- **配置键是破坏性变更。** 端点的 `endpoints.<名>.address` 变为 `listeners.<名>.address` 加 `endpoints.<名>.listener`；`read-header-timeout`、`read-timeout`、`write-timeout`、`idle-timeout`、`drain-timeout`、`tls-cert-file`、`tls-key-file` 七项从端点移到监听。没有向后兼容垫片。
- **一条监听载多个端点时，请求经过的链由分派按静态前缀选定，不取决于哪个端点登记了这个路径。** 端点引擎收到请求时它的全部登记层照常运行；分派把落在某端点静态前缀之下的请求归该端点，因而一个没有登记该路径、却落在该端点前缀之下的请求由该端点以其自己的 404 作答、跑该端点的链，只有不被任何前缀占有的请求才交给兜底端点、跑兜底端点的链。端点独占一条监听（这是多数装配的形态）时，分派把每个请求都交给那一个端点，这些差异不出现。
- **一条监听上的两个端点不能共享静态前缀，也不能共享（方法，路径），也不能都是兜底端点。** 分派按静态前缀选择端点，同一前缀无从二选一；同一（方法，路径）落在同一前缀之下，同样无从二选一；gin 里一个 `*` 通配不能与任何具体路由同处一棵方法树。
- 分派多一层 gin 引擎与一次再匹配：每个请求在监听层面匹配一次、在端点引擎再匹配一次。这是一次启动期建一次、请求期常数级的额外开销。
