# 对象存储本轮交付核心面、字节接缝与 `fs`/`s3` 后端，复验净化与缩略图派生后置

## 背景

对象存储能力目录是 `pkg/objectstore`，实测范围如下：

- **元数据入表。** 早期实现的 `objects` 表记一个对象的全程——上传方在任何字节到达之前声明的尺寸、媒体类型与校验和，复验流水线在字节到位之后确立的最终尺寸、检测出的 MIME 与 SHA-256，以及对象所处的生命周期状态；派生另占 `object_derivatives` 表，一行一个缩略图。
- **字节经宿主接缝。** 对象的字节不落模块的表，落在宿主的 `pkgcore.ObjectStore` 接缝上，键由模块按租户 id、对象 id 与固定后缀构造，从不经 API 暴露。
- **复验净化与派生。** 早期实现的 `Complete` 对刚到的字节跑一条复验流水线；净化步骤按载体类型结构化剥离图片里承载位置与作者一类的元数据容器，像素数据原样穿透；派生步骤把已完成的图片对象降采样成缩略图，经宿主的作业队列异步派生。

本轮的范围由几条约束决定：

- **复验净化与派生都要引入图像解码与净化库。** 早期实现用纯标准库做结构化剥离与降采样，但那组代码只在图片对象上生效，且带像素上限、编码器选择与按载体类型的剥离规则。一条只在某一类媒体上生效、并带成套图像规则的流水线，不是每个拷贝方都要。
- **模块面要求「可直接拷贝即用」。** 交付物是一个可装配的默认实现——宿主写配置、点模块名即得一个能用的对象存储，不是一组只有接缝、业务面全留给宿主的接口。
- **框架要交付对象存储本身。** 旧的字节接缝 `pkgcore.ObjectStore` 由宿主提供；新架构里一个只声明接缝、不交付任何后端的对象存储能力，等于没有交付对象存储。

## 考虑过的选项

### 全量照旧，一并交付复验净化与派生

把 `go/storage` 的整批范围搬进 `pkg/objectstore`：元数据面、生命周期、复验净化流水线与缩略图派生一起做。

**否决**：复验净化与派生要引入图像解码与净化库，把这一组库带进框架的默认面——每一个拷贝对象存储的宿主都因此背上图像处理依赖，而多数拷贝方存的是文本、压缩包或音视频，用不到这条流水线。

### 只做接缝，不做业务面

只交付 `Store` 字节接缝与根包类型，元数据面、生命周期状态机、上传窗口、过期清扫与 HTTP 面一概不做，全部留给宿主。

**否决**：交付物接近空壳，不符合「可直接拷贝即用」。宿主拿到一个只有接缝的能力目录，仍要自己写元数据表、状态机、上传窗口、过期清扫与 HTTP 面，本能力因此没有消掉任何重复——接缝是框架要交付的东西的一部分，不是它的全部。

### 核心面加字节接缝加 `fs`/`s3` 后端，复验净化与派生后置

交付对象元数据、生命周期状态机、上传窗口、读取、键集游标列表、删除、过期清扫与 HTTP 面，加字节接缝与 `fs`、`s3` 实现后端；内容复验净化流水线与缩略图派生刻意后置。

**采纳**，见决策。

## 决策

采纳：**本轮做核心面、字节接缝与 `fs`/`s3` 后端，内容复验净化流水线与缩略图派生刻意后置。**

- **做。** 对象元数据与生命周期状态机（`pending → uploaded → completed → deleted`）、上传窗口、读取、键集游标列表、删除、过期清扫、HTTP 面；`Store` 字节接缝与 `fs`、`s3` 实现子包。
- **刻意后置。** 内容复验净化流水线与缩略图派生不在本轮。两者都要引入图像解码与净化库，且不是每个拷贝方都要；后置是刻意的，不是漏项。完成（`Complete`）只把对象行翻入可用态，不读字节内容、不核对声明、不剥离元数据、不生成派生。

## 后果

上传与读取的一个完整可用闭环在本轮成立：调用方声明一个对象、上传字节、完成它，此后可按 id 读取、列表与删除。复验净化与缩略图派生由消费方自己承接或等后续批次补齐。

**接受的代价：**

- **复验与净化不在本轮。** 完成后的对象不被核对宣告的尺寸、类型与校验和，也不被剥离图片里的位置与作者元数据。要这条保证的消费方要自己在字节落库之前跑一遍，或等后续批次。由此「对象的内容与其声明一致」「对外提供的图片不含内嵌元数据」不再由本能力保证。
- **缩略图派生不在本轮。** 需要缩略图的消费方要自己降采样并另存，或等后续批次。旧实现里派生经宿主的作业队列异步跑（`go/storage/derive.go`），本轮不引入这条流水线，也不引入它对作业队列的依赖。
- **复验净化与派生将来补上时新增宿主可见面。** 两者若在后续批次纳入，会新增配置项（像素上限、派生边长一类）与可能是新的模块面，宿主的配置文件与命令树要随之改写。
- **字节后端在本轮是能力目录自己的封闭面。** `fs` 与 `s3` 由本能力交付；新增一种后端是新增一个实现子包，不是宿主注入一个实现。

## 失效条件

- **若多数拷贝方都要复验净化或缩略图派生**，则把它们留在框架之外的价值下降，应把它们纳入核心面。判据是同时用到复验净化与缩略图派生的拷贝方在数量与权重上成为多数。
- **若图像解码与净化库成为可接受的框架默认依赖**（例如本仓的其它能力已经引入同一组库），则「不把图像库带进默认面」这条否决理由失效，全量照旧一并做重新成为可选。
