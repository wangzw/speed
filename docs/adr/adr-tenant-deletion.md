# 已删除的租户是名册上的终态行，标识与别名不再复用

## 背景

账户删除要结束它的个人租户，此后以那个租户标识发起的请求与不存在的租户得到同一结果，标识也不得被重新使用（REQ-tenancy-045、REQ-tenancy-046、REQ-tenancy-049）。租户模块没有删除动作，停用是可逆的：账户恢复会撤销一次由账户造成的停用，运营者也能随时把停用的租户重新启用（[ADR-tenant-directory](adr-tenant-directory.md)）。停用因而不表达「这个租户到此为止」。

受约束表里带那个标识的行仍在。库里的一个标识指不出它的租户还在不在：名册上那一行没了，行的来历也就没了，任何按标识排查的动作都找不到它属于谁。

名册的登记判据是表本身：`Create` 插入时撞上标识即拒绝，因而一个仍在表里的标识拿不到第二次登记（[ADR-tenant-directory](adr-tenant-directory.md)）。标识不被复用这件事，因而只需要那一行还在。

请求侧对「这个租户不存在」与「这个租户已停用」答同一个状态码，不向进程外的调用方暴露名册（见 [tenant](../design/modules/tenant/design-tenant.md) 的请求期的收口）。

## 考虑过的选项

### 删除名册上的一行

`Delete` 删掉那一行，标识随之空闲。

**否决**：受约束表里那个租户的行失去来历，成为库中看不出来的无主行；标识一旦空闲，新租户可以登记同一个标识，把旧租户的数据读成自己的。停用不删数据正是为了避开这一形态（[ADR-tenant-directory](adr-tenant-directory.md)）。

### 已删除的租户复用 `StatusDisabled`

删除只把状态写成停用，不新增取值。

**否决**：停用按定义可逆。账户恢复会撤销一次由账户造成的停用，运营者也能把停用的租户重新启用；一个已删除的租户混在停用里，就会被账户恢复或运营者的启用复活，而「标识不得复用」随之失效。

### 名册之外另立一张墓碑表

删除把那一行搬进另一张表，名册只剩在册与停用的租户。

**否决**：「这个标识是否已被占用」会有两个答案，分别落在两张表里，而 `Create` 的判据是一条插入的唯一约束——一次插入只能撞一张表，判断占用要先读另一张表，快照与表之间的窗口也随之出现在这里。别名唯一同样只能是单张表上的唯一约束，跨两张表的唯一性数据库不提供。请求侧的别名索引与名册快照要各读两张表。

### 名册行上一个新的终态取值

状态集合新增「已删除」，一行写进这个取值即不再被服务，行留在原处。

**采纳**，见决策。

## 决策

采纳：租户的删除是名册行上的一个终态取值 `StatusDeleted`，`Catalog.Delete` 写这个状态；行、标识与别名都留在原处。

**取值是封闭集合的一个新成员**，排在 `StatusActive` 之后：零值仍视为停用，本版本不认识的取值也视为停用。已删除不落在宽松的一侧，也不落在停用那一侧——它与停用在任何一处按状态分支的地方都分开判定。

**`Catalog.Delete` 只写状态。** 标识、别名与行本身不动；对已经删除的行重复调用什么也不写；名册上没有这一行，或标识不在取值域内，报 `ErrInvalidTenant`。

**终态对每一条写路径成立。** `SetStatus`、`SetStatusByAccount` 与 `Put` 遇到一个已删除的行一律以 `ErrTenantDeleted` 拒绝，什么也不写；`Create` 对表里已有的标识照旧以 `ErrTenantExists` 拒绝。标识因而在任何一条路径上都拿不到第二次登记，别名随行保留，同样不再可用。

**请求侧把已删除当作不存在。** 解析层按别名取到那一行后，只要状态不是在册就不放行，与停用、与名册上没有这个名字收口同一个 404。状态不泄漏给进程外的调用方，存在性预言机因而不存在。

**不经请求侧的路径按状态分开处置。** `Enter` 对一个已删除的租户以 `ErrTenantDeleted` 拒绝——它不是停用，等不到恢复，调用方据以丢弃那件工作；`EnterRegistered` 不论状态，仍按这一行进入，这是清除或导出残留数据的唯一途径（[ADR-tenant-suspension-access](adr-tenant-suspension-access.md)）。

**名册照常列出墓碑。** `Get` 与 `List` 交出它，管理面的视图把它渲染成已删除。

**墓碑不清理。** 本记录不设保留期，也不提供把行搬走或删掉的路径。

## 后果

- **状态集合的增长没有编译器的帮助。** 按状态分支的代码散在解析层、名册、管理面与前端，新增一个取值编译器一处也拦不住，每一处都要按新取值重读一遍（[ADR-tenant-directory](adr-tenant-directory.md) 记着同一条代价）。
- **名册只增不减。** 删除的租户永远留在名册与快照里；一个反复做租户登记与删除的部署，名册的规模是它服务过的租户总量，不是当前在服务的租户数量。
- **删除不可撤销。** 一个建错的租户在删除之后既不能恢复，也不能以同一个标识重建；要重来只能换一个标识。运营者因而要把删除与停用当成两件轻重不同的事。
- **受约束表里那个租户的行在删除之后仍在。** 框架不收集它们，名册也不再服务它们；清除归声明那些表的模块，本模块与宿主都不替它做。
- **旧版本读到这个取值会读成停用。** 一个还在跑的旧副本把状态 2 视为停用，因而不服务那个租户，安全的一侧成立；它只是在管理面上看不出已删除。

## 失效条件

若名册的规模在实践中必须按保留期裁剪，或产品后来要求复用已删除租户的标识，这条决策要与「另立墓碑表」重新比较。判据是标识在受约束表里是否仍然承担指认那些行的作用：一旦它不再指认，行可以删；一旦要复用，墓碑必须搬出名册。
