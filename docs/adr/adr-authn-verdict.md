# 判决带事实、不可字面构造，网关校验后盖章

## 背景

校验后端是独立的模块，认证网关不拥有它的代码。网关拿到的只有一个接口，以及后端交回的那一份判决；后端说得对不对，网关无从核实。网关能决定的是：判决这份数据长什么样，后端什么都没说时按什么读，后端交出的事实在什么条件下才被写成请求的身份。

一次校验的结果穷尽为凭据有效、凭据无效、答不上来。有效与无效是关于这条凭据的正面知识，答不上来是关于后端自身的。对外，无效收口成 401，答不上来收口成 503。

401 与 503 的差别不止在数字上。以 401 为键的那些设施，失败计数与账号锁定、限速、应用防火墙的规则、安全事件平台的告警线都在其列，只认 401，503 不进它们的任何一条计数。一段时间里所有拒绝都以 503 出去，这些机制在那段时间里一次都不触发：后端不可用期间，针对同一账号的连续口令猜测全部得到 503，拒绝计数为零，锁定与限速都没有动作。

在 Go 里，失败的原因放进 error 返回值，查不到记录返回的是 `sql: no rows in result set` 这一类错误。后端把这个 error 原样填进判决的诊断字段、不再另外表态，是这门语言里常见的写法，不是疏忽才会出现的写法。判决的读法若把「没有表态」归到故障那一档，这种写法就把每一次拒绝都报成了后端故障。

漏写落在哪一格由零值决定：结构体字面量省略掉的字段、没有赋值的返回值、枚举的第一个常量，都落在零值上。

判决由后端构造。字段导出就意味着包外能拼出任意组合，包括「认证通过并且带着失败原因」和「只有原因没有结论」这种自相矛盾的组合。

通过的判决还带着事实：账户、实际操作者、登录会话、认证方式、保障等级、认证时刻、冒充的租户范围、企业 SSO 提供方与一组只读属性。这些事实由后端声明，而下游（授权、限流、审计、租户准入）把身份当作已核实的输入使用。身份的写入口不导出，请求链上只有网关能写，使「请求上下文里的身份」成为网关作出过决定的证据；于是后端声明与身份之间需要一道由网关把守的关口。关口能依据的只有后端交出的值本身、网关自己的时钟与常量、后端在装配期声明的载体与账户命名空间（[ADR-authn-credential-dispatch](adr-authn-credential-dispatch.md)）。

## 考虑过的选项

### 判决用 `(Identity, error)`，结果靠哨兵错误区分

后端返回身份与一个 error：`nil` 表示认证通过，拒绝与故障各由一个哨兵错误表示。

**否决**：error 槽的零值是 `nil`，而 `nil` 在这个结构里就是成功。一个漏了表态的后端返回 `(Identity{}, nil)`，网关读成认证通过，放行一个账户为空的身份。漏写落在放行那一格上：写错的方向是放行，不是拒绝。

### 判决是字段导出的结构体，未表态视为故障

后端用结构体字面量填判决，诊断原因放在导出的字段上，结论的零值视为故障。

**否决**：字面构造让「只填原因、不填结论」成为能编译、看着也完整的写法，而那恰好是把 error 原样搬过来的写法。这样的后端在口令错误与查无此人的情形下都收口成 503，正确口令仍旧通过：功能上看不出问题，而拒绝这一档在它身上整体消失，键在 401 上的设施随之全部失灵。同一结构还让故障计数失去意义，健康后端上的日常口令错误全部记进故障桶，基于它的告警只剩噪声。

### 判决不可字面构造，未表态与显式拒绝同属一格

结论枚举的零值就是「拒绝」，漏写与后端明确拒绝落在同一个结论上。

**否决**：收口方向对，但运行期没有任何信号指出某个后端根本没在表态。后端的缺陷与调用方的错口令混进同一个计数，只能靠人读代码发现。

### 判决不可字面构造，未表态收口为 500

零值视为网关自身出错。

**否决**：500 告诉调用方这次失败与它的凭据无关、原样重试也许能成，而事实是它没有认证上。它还把某个后端的缺陷说成网关的故障，归因指向错误的一方。

### 后端自己盖章：通过时直接交出身份

`Verify` 在通过时返回已构造好的 `Identity`，网关只负责放进请求上下文。

**否决**：身份的写入口得对每个后端导出，「上下文里的身份由网关作出过决定」这一性质随之消失，任何后端的缺陷或宿主自写的后端都能铸出任意账户、任意保障等级。`Backend()` 无法保证等于 `Verifier.Name()`，账户命名空间的边界无处执行。网关在这个结构里从决策者退化为搬运者，后端对身份的每一项声明都不再有一个能核对它的位置。

### 属性塞进袋子里，类型化字段也放进去

判决只带一个字符串映射，认证方式、保障等级、会话标识、冒充范围、提供方都以保留键放在其中。

**否决**：授权与网关要按类型取这些值，放进袋子就得靠保留键防伪造，每个读取点各自解析字符串；保留键的写入权限还要另外约束，而「后端交出、网关盖章」恰要避免这种带特殊含义的保留键。袋子里的键也无法由编译器检查，拼写错误成为静默的缺值，缺值又落在放宽的一侧（缺保障等级视为单因素，缺冒充范围视为未冒充）。

### 属性映射的值取任意类型

属性集用 `map[string]any`，让后端交出结构化的属性。

**否决**：值无法限制大小与格式，进日志与跨度时无法保证不带结构化的秘密。

### `Principal` 也走构造器，字段不导出

后端交出事实的那份数据同样只能经构造器产生，构造器内部校验。

**否决**：构造器只能核对与后端无关的结构，认证方式闭集与账户格式属于此类；账户命名空间与能力声明要对照该后端的 `Accepts`，只有网关持有。构造器里的检查与网关的出口检查是同一件事的两份实现，网关仍须逐项复核，两份实现还要保持一致。`Principal` 是后端的声明而不是身份，字面构造它不破坏任何由类型保证的性质。

### 判决与步骤的读取函数也限定 importer

`internal/verdict` 与 `internal/step` 的读取函数像 `internal/identity` 的注入口一样，只许一份名单内的包 import。

**否决**：名单要拦的是铸造。判决与步骤的构造函数经根包公开给宿主的校验后端与登录方法，限定读取函数的 importer 拦不住任何伪造；读取函数只读，读取者做不出构造器做不出的判决与步骤。身份不同：它的注入口不经根包公开，限定 importer 才限得住铸造，写入方名单因此只管 `internal/identity`。读取函数的使用方是网关、登录引擎与测试夹具，名单随使用方增减，每次改名单换不来任何防护。

### 属性键的保留前缀由网关在盖章处拒绝

`idp.` 前缀只许声明了 SSO 能力的后端交出，`authn.` 前缀对所有后端一律拒绝，出口检查据此判属性键。

**否决**：网关判的是后端自报的值，分不出 authn 自带的后端与宿主自写的后端：后端名是代码里的常量，装配只校验格式与唯一，不校验它与后端的来历一致。宿主自写的后端取了 authn 自带后端的名字（例如顶替自带的会话后端），网关无从区分。声明了 SSO 能力的后端交出的任何 `idp.*` 键，网关也无从知道它是否真出自映射。这样的检查只挡得住没有声明 SSO 能力的后端，读起来却像一条对 `idp.*` 来源的保证。键空间的保证落在写属性的一方：登录引擎写 `idp.*`，账户的写入接口拒绝宿主与管理员使用保留前缀。

### 网关自判的拒绝用普通挑战

出口检查不符与冒充范围不符是网关自己作出的判定，后端没有拒绝凭据，所以回应与没有凭据的 401 一样，带各后端的普通挑战。

**否决**：出口检查不符与冒充范围不符发生时，请求带着的仍是某个后端认领的凭据。普通挑战让调用方去出示一份凭据，而它刚出示过；带着该后端的「凭据被拒」挑战，调用方才读得出是它出示的那份凭据没有通过。

### 判决不可字面构造，未表态视为拒绝并单独计一类缺陷；通过时由网关校验事实后盖章

**采纳**，见决策。

## 决策

采纳：判决的字段一律不导出，只能经构造器产生，通过的判决携带后端声明的 `Principal`；结论枚举的零值是「未表态」，网关把它收口成 401，同时单独计入 `unspoken` 并记一条错误日志；网关在写入身份之前逐项复核 `Principal`，复核全部通过才盖章，任何一项不符都是一次网关自产的拒绝。

**判决的结构**

- 构造器按结论分开，各自只收该结论用得上的东西：`Authenticated` 只收 `Principal`，`Denied` 与 `Unavailable` 各只收一个诊断原因。「既认证通过又带着失败原因」与「只有原因没有结论」在包外不是能写出来的程序。
- `Principal` 承载的事实：账户、实际操作者、会话、认证方式集、保障等级、`IDPAssured`、认证时刻、冒充的租户范围、企业 SSO 提供方、属性集。它是后端的声明，字段导出，字面构造合法；它不是身份。
- 诊断原因只进日志，不进响应。
- 未表态对调用方收口成拒绝：这个调用方确实没有认证上，401 与事实相符。零值判决同时是后端的缺陷信号，单独计数并单独记一条错误日志，不与正常拒绝混在一个桶里。
- 凭据不成立（`Denied`）收口为 401，后端不可用（`Unavailable`）收口为 503；凭据不成立与后端不可用的收口及计数名不因 `Principal` 而改变。

**网关盖章**

- `Identity` 的写入口不导出，请求链上的身份只有网关写入；写入口在 authn 树内的可达范围是一份封闭名单，由依赖测试断言，名单与理由见 [ADR-authn-identity](adr-authn-identity.md)。
- 判决与步骤的读取函数不在名单之内，对 authn 树内的 importer 不设限：构造函数经根包公开，读取函数只读，限定它们拦不住任何伪造。
- 认证后端名取自 `Verifier.Name()`，重新认证用的挑战方案名取自凭据载体，二者都不经过后端交出的任何值。
- 网关在写入身份之前，对 `Principal` 逐项复核，复核的对象是结构与后端声明的出口检查，是一个封闭集。复核只依据网关自己持有的事实（时钟与常量）与装配期的声明（后端的载体、账户命名空间与能力），不信任后端自报的任何一项。检查项、界限数值与各自的取值由 design-authn-gate 的出口检查承载，本记录只定判据。
- 出口检查任一项不符，是网关自产的拒绝：401，Error 级日志，计入 `denied`，记在网关名下，不计入任何后端的缺陷计数。检查依据的是网关自己持有的事实与装配期的声明，作出拒绝的是网关，不论它发生在问后端之前还是之后。
- 盖章前还有冒充身份的范围核对，依据是路由登记与 `ScopeGuard.Covers`，不属于出口检查：它记在后端名下，Info 级，同样计入 `denied`。核对的规则见 [ADR-authn-impersonation](adr-authn-impersonation.md) 与 `design-authn-gate`。
- 网关自判的拒绝，即出口检查不符与冒充范围不符，按「请求带着某后端认领的凭据而被拒」设挑战头：请求带着的仍是该后端认领的凭据，调用方要读出的是这份凭据没有通过，不是它没有出示凭据。挑战的构造见设计文档。

**属性集**

- 属性集只读：网关盖章时深拷贝，读取返回副本，没有写入口。
- 属性集的键不得与类型化字段竞争：认证方式、等级、会话、冒充范围、提供方等事实只经类型化字段传递，不经属性集。
- 属性集的键空间按写入方划分：登录引擎写入的属性与账户上由管理员或宿主设置的属性不会撞键。前缀与分项上限由 `design-authn-gate` 承载。
- 网关在盖章处检查键的格式、条数与大小，不检查保留前缀 `idp.` 与 `authn.`：前缀由写属性的一方保证，网关分不出 authn 自带的后端与宿主自写的后端。

身份的结构见 [ADR-authn-identity](adr-authn-identity.md)；账户命名空间取代归属的理由见 [ADR-authn-credential-dispatch](adr-authn-credential-dispatch.md)；保障等级只在一处合成，见 [ADR-authn-mfa](adr-authn-mfa.md)。

## 后果

把 error 原样搬进判决的写法不再是能编译的程序，这一类错误落在编译期。

故障这一档的来源穷尽为后端自报与网关自证：网关自证的判据是这件事由网关亲历，网关掐断一个超出预算的调用、网关接住后端的 panic 都在其中。后端漏答不再能伪装成故障，故障计数因此可以拿来告警：健康后端上的日常口令错误全部记进拒绝，故障计数保持为零。

凭据不成立的拒绝落在 401 上，以 401 为键的下游设施在后端健康时按预期触发。

请求上下文里的身份只有一个来源：经过出口检查的网关盖章。后端不能为不属于自己命名空间的账户盖章，不能交出自己没有声明能力的冒充与 SSO 事实，不能把格式不合的认证时刻、属性或方式集带进下游。authn 自己的后端也在这道关口之内。

**接受的代价：**

- 保障等级由后端自报。网关只做格式、界限与账户命名空间的校验，不能独立证明「确实用了两个因素」；信任边界是进程内的代码：宿主选择哪些校验后端，就是在选择信任谁来自报。authn 自带的后端经同一个多因素能力得出等级，会话与令牌后端读会话行里已记录的等级，使自报的来源收敛在一处；命名空间之内的标识真伪仍由后端负责。
- 未表态收口成拒绝，代价落在调用方身上：一个有缺陷的后端会把自家用户的请求全部变成 401，而 401 正是上游锁定与防火墙规则计数的键，后端的一个缺陷因此升级成账号锁定事件。出口检查不符同样收口成 401 并计入 `denied`，同样会进入这些上游计数；它与普通拒绝的区别只在日志级别与归因，不在状态码，也不在计数桶。
- 后端把自己的宕机写成拒绝，运行期无法与真拒绝区分。网关没有后端的错误分类，它看到的只是一个结论。这类误标只能由后端自己的测试挡住，挡不住不写测试的后端。
- 宕机分支漏了表态的后端，在真故障期间一个 503 都不产生：带正确口令的请求全部收口成 401，未表态计数上涨而故障计数为零。缺陷信号在计数与日志里，不在状态码里。
- 判决在包外不可字面构造，后端自己的测试也只能用构造器给出的组合。要造一份违反契约的判决去测网关的收口，只能在 `pkg/authn` 包内做；其他模块的测试经测试构造口得到已盖章的身份。
- `Principal` 可以字面构造，格式错误的 `Principal` 能通过编译，只在运行期被出口检查拦下并记 Error 日志；编译期保证的只有判决的结论。
- 出口检查是网关的一份固定义务：认证方式闭集或界限数值每变一次，网关与引入变化的后端必须同时升级。
- 判决与步骤的读取函数对 authn 树内的全部包可用，没有 importer 名单；树内的包读得到判决的诊断原因与 `Principal`。防住的是伪造，不是窥视。
- 保留前缀不在盖章处判。宿主自写的校验后端能交出任意 `idp.*` 与 `authn.*` 键，网关拦不住；授权读到的 `idp.*` 是否出自 IdP 映射，取决于交出身份的后端，信任这些键就是信任该后端（[ADR-authn-guarantees](adr-authn-guarantees.md)）。
- 网关自判的拒绝带「凭据被拒」的挑战，令牌后端因此对一个签名有效、被出口检查或冒充范围核对拒绝的令牌答 `error="invalid_token"`（[REF-rfc6750](../references.md)）：调用方据此丢弃或刷新一个并无损坏的令牌，成因要读日志才知道。
- 「未表态」是可观测信号中的一类新计数，它的名字一旦被宿主的看板与告警引用就改不动。

## 失效条件

- 若 Go 提供一种使「结论未被赋值」无法表达的类型，未表态这一格随之消失，本记录中关于零值读法的部分不再有对象。
- 假设校验后端与网关在同一进程、同一时钟之内运行：认证时刻的上限取固定常量，保障等级自报的信任边界取进程内代码。若出现进程外的校验后端，这两项都失去依据，需要后端对事实作可验证的声明（签名的断言）才能继续把等级当作输入。守住它的是装配期对校验后端声明的核对与网关的出口检查测试，以及断言身份写入口只在写入方名单内的包里可达的依赖测试。
- 假设保留前缀只由写属性的一方保证就足够：下游把 `idp.*` 视为「出自 IdP 映射」，只在装配里的校验后端都可信时成立。若出现要求网关替它保证这一点的下游，保留前缀的判定要改由网关承担，并先解决网关分不出自带后端与宿主自写后端的问题。
- 假设命名空间声明与出口检查足以防住一个有缺陷的 authn 自带后端越权。若实际出现自带后端经合法声明交出了不属于自己的账户，命名空间核对的判据需要重写，而不是在后端内打补丁。
