# 调用方本人的租户读取由 tenant 目录新增的只挂路由的模块承担，挂在账户端的普通接口

## 背景

租户切换控件要列出账户持有有效成员关系的全部租户，当前租户也在其中（REQ-tenancy-035），个人租户那一项显示组织的文案而不是别名（REQ-tenancy-050）。平台没有接口返回调用方本人的成员关系，示范宿主只能用一份硬编码的占位清单。

成员关系在认证（`Memberships.Tenants` 列出账户跨租户的全部成员关系），租户的状态与别名在名册（`Catalog.Get`）。名册是平台域的数据，读名册的管理路由要求平台域的 `tenant.read`，普通成员不持有它。

个人租户是宿主策略：名册不记录租户种类，平台自己的名册视图也不带种类。宿主在自己的装配里知道哪一类租户是个人租户；平台需要一个扩展点把这份判断读过来，而不把宿主的策略写进平台。

路由路径的归属由作用域决定：`tenants` 是租户管理作用域的保留段，普通接口不带作用域段（[ADR-http-api-path-scopes](adr-http-api-path-scopes.md)）。

## 考虑过的选项

### 由平台名册读取承担（`GET /api/v1/system/tenants`）

成员读同一个管理面，自己筛出所属的租户。

**否决**：它要求平台域的 `tenant.read`，而这份权限正是普通成员没有的；把它开放给成员等于把全平台的租户名单交给每一个成员，名单里包括他们不属于的租户与其他账户的个人组织。

### 由 `GET /api/v1/auth/me` 的档案视图携带

档案视图加一个 `tenants` 成员，前端在已有的本人读取里一次拿到。

**否决**：档案视图归认证，认证不 import `pkg/tenant`；有效状态要读名册，只能让认证依赖租户目录。冒充者读到被冒充账户在其他组织的成员关系会超出冒充授予的那一个租户；本条否决的其余理由与冒充无关，而冒充那一处的暴露由 `tenant.self` 自己在 handler 里按授予租户收窄应答来消除（见决策的「冒充」）。

### 在 `tenant.catalog` 或 `tenant.admission` 里加这条路由

**否决**：名册模块的非职责是不读身份，准入层的非职责是不读名册、只读已解析的租户上下文；两者都会把一条与调用方身份相关、又不带租户的读取接口塞进一个只做一件事的模块。准入层还只在它所守的端上工作，而这条读取必须挂在它不守的账户端上。

### 由宿主自己提供，像个人租户那样

每个产品的服务端各挂一条自己的读取。

**否决**：两个事实都是平台数据，组合规则对每个产品相同；宿主各自实现会让平台 SDK 缺这条读取，并让每个产品的成员列表口径各自漂移。个人租户进宿主是因为它是宿主的策略，这条读取不是。

### 新增 `pkg/tenant/self` 模块，挂 `GET /api/v1/auth/me/tenants`

只挂路由、不交付功能，组合认证的成员关系与名册的状态。

**采纳**，见决策。

### 路径放在 `/api/v1/tenants/me`

**否决**：`tenants` 是租户管理作用域的保留段，该作用域的每条路径必须以 `/{tenant}/` 开头；`me` 会被读成一个租户名，地址上分不清管理面与普通接口。

### 路径放在 `/api/v1/tenant/me/tenants`

**否决**：与保留段 `tenants` 只差一个字母，普通接口的其他能力段也不用单数；这个相似性会让读者把它与管理面的路径混起来，而作用域段的存在正是为了在地址上分开两类接口。

### 应答不带 `kind`，宿主按固定前缀派生

平台读取只返回标识与别名，宿主按自己派生的个人租户标识与应答里的 `id` 逐字相等来判定。

**否决**：这条判定把宿主的标识派生规则变成前端与平台读取之间的隐式契约。每个宿主都要再实现一次前缀规则，两处拼写靠人保持一致；标识派生规则一改，前端与宿主服务端要同时改。一个不从账户标识派生个人租户标识的宿主无法表达自己的种类，平台读取也没有位置承载它。

### 应答带 `kind`，由宿主注入的解析器给出

平台读取的每项带 `kind`，取值是平台定义的封闭集 `business|personal`，由宿主在装配时注入的 `KindResolver` 给出。

**采纳**，见决策。

### 应答带 `status`

每项带租户状态，前端据此决定可不可选。

**否决**：状态是过滤条件，不是字段。不进列表的正是状态不是在册的那些，每一行都视为在册；这个字段是过滤条件的第二条陈述，两者会各自漂移。

## 决策

采纳：新增 `pkg/tenant/self`，模块名 `tenant.self`，不交付功能接口、不声明特性。它只挂一条路由 `GET /api/v1/auth/me/tenants`，落在账户端（不解析租户），要求已认证、不要求任何权限、登记为可冒充；冒充身份的应答收窄到授予的那个租户。

**组合。** 经 `authn.Memberships.Tenants` 取出账户的全部成员关系，逐条经 `tenant.Catalog.Get` 取名册里的状态与别名。一条成员关系进入应答，当且仅当它自身是启用的，且名册里那个租户的状态是在册。

**应答。** `tenants` 数组，每项有标识、别名与 `kind`，按标识升序；空结果写 `[]` 而不是 `null`。`kind` 的取值是封闭集 `business|personal`，词汇由平台定义。应答不带状态、不带展示名。

**种类由宿主解析。** 平台不记录租户种类，也不在名册里存它。`KindResolver` 是宿主实现的接口：给定一个租户标识，回答 `business` 或 `personal`。没有个人租户策略的宿主可以不给解析器，此时每个租户都视为 `business`；装配了个人租户特性（例如 `org.personal`）的宿主必须提供解析器，缺席即终止启动。失败点是启动期拒绝，不是逐条列表的错误。解析器在逐条读取时失败，整条读取答 503，不按 `business` 兜底。

**契约。** `kind` 的封闭取值进 OpenAPI 的 enum 与生成的 SDK 联合类型。宿主把 `kind` 映射为组织文案；租户切换控件不读取也不判断 `kind`，不再按标识前缀派生。

**失败。** 没有身份答 401；成员关系或名册读不出答 503，成因只进日志。路由集里没有 403 与 404。

**冒充。** 路由登记为可冒充，好让宿主在整页重载后仍能命名冒充授予的租户：名册属平台管理面，冒充期间不可达，宿主此前只能靠内存里的名册别名缓存，重载即丢失，租户作用域的读随之由准入层答 404。handler 按身份的 `Scope()` 收窄应答，只保留授予的那个租户那一条，被冒充账户在其他租户的成员关系仍不交给冒充者；没有范围的冒充身份（网关的出口检查不会放行）应答空列表。授予租户的标识、别名与种类本来就由冒充状态读与横幅陈述，这里只是把别名与种类的来源补齐。

**个人租户留在宿主。** 平台不记录哪种租户是个人租户；它只把宿主给出的 `kind` 带进应答，并保证词汇是封闭的。

## 后果

- **成员有了可用的切换器，占位清单退役。** 占位清单唯一能保证的事实是它写下的那个名字，而它写下的名字只在一个装配里成立。
- **读取跨成员关系与名册两份事实，两者没有一致的时点。** 成员关系是一次表读，状态与别名来自名册快照；清单会落后于名册的刷新周期，也可能漏掉另一个副本刚登记或刚改名的租户。清单不是授权判定：切换之后准入层仍按请求判定，一个已撤销的入口在切换时答 404。
- **平台不记录租户种类，种类由宿主在启动时注入。** 每个有个人租户策略的宿主实现一个 `KindResolver`；平台读取只带值，不存值。词汇由平台封闭为 `business|personal`，一个需要这份词汇之外的其他种类的宿主无法表达，要扩展这份词汇。
- **装配个人租户特性的宿主多一个必填扩展点。** 解析器缺席即启动失败；解析器对某个租户回答错误时，宿主会把商业租户渲染成组织的文案，平台不替它校验。
- **应答多一个字段是宿主可见的契约变更。** 生成的 SDK 的联合类型随之变化，映射文案的宿主代码要处理 `business` 与 `personal` 两种。
- **路由住在 `/api/v1/auth` 前缀下，模块却归租户目录。** 路径按调用方一侧归类，不按模块目录归类；读者要把这两个事实分开读。
- **暂停的成员关系被排除。** 需求把有效成员关系写成「成员关系存在且租户处于启用状态」；平台在 `Memberships` 的读法与准入层里都把暂停视为非成员，列表必须与之一致，否则它会列出一个准入层答 404 的租户。
- **平台员工经决策接口进入自己不是成员的租户时，清单里没有这个租户。** 触发器要能命名当前租户，宿主须从平台名册补那一行；这一条是宿主装配的代价，平台读取不替它补。
- **应答不分页。** 切换器要列出全部有效租户，截断会静默漏掉一个；上限由账户的成员关系条数给出。
- **冒充身份可读这条路由，但只看到授予的租户。** 整页重载后宿主仍能宣告请求侧的别名与种类；暴露范围是授予租户那一项，不含目标账户的其他成员关系。

## 失效条件

若宿主需要 `business|personal` 之外的种类，封闭词汇要重开。若平台开始自己记录租户种类，`KindResolver` 与它的启动规则成为第二来源，要收回平台一侧。若名册或成员关系开始带每个租户的展示名，应答不带展示名的理由不再成立。若产品要求切换器列出调用方能进入、但不是其成员的那些租户，这条读取不再是列表的来源，平台员工那一档要另立。
