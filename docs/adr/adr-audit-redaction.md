# 审计的敏感键名取一个闭集，与日志共用一份登记

## 背景

审计行带明细：设置变更的旧值与新值、请求参数、对象标识。这些位置会出现凭据与个人数据。

明细的键名由调用点自选，语句级通路则没有调用点可问——它的明细由本模块自己按语句填。因此「哪些键名算敏感」这件事，本模块要么自己定，要么从别处取。

日志模块已有一套脱敏：规则由各模块经它的登记面登记，判定发生在处理链内，作用对象是每一条日志记录的属性。**该判定面不导出**——登记面只有登记的方法，没有任何入口能把规则集施加到一个任意值上。

## 考虑过的选项

### 由调用点在写出明细时自行遮蔽

**否决**：语句级通路没有调用点，它的明细由本模块填，这条途径覆盖不到它；同一条明细分经两条通路时，遮蔽与否还会不一致。

### 不遮蔽，明细原样落库

**否决**：审计表会存下凭据与个人数据，而审计表的读者通常比业务表更多，且它的留存期更长。

### 回改日志模块，导出可复用的判定入口

**否决**：这要动一个已落地模块的公共接口面，而审计明细的需要不足以让它承担一个新导出面；把判定逻辑从处理链里提出来还会改变日志链的内部结构。这条途径在本仓没有先例。

### 审计自带一套遮蔽规则，独立于日志

**否决**：两套规则可以独立漂移，而「日志里遮了、审计里没遮」这个缺口没有任何一层会报出来。

### 本模块固定一组扁平键名，登记进日志模块的规则集，写表前按同一组遮蔽

**采纳**，见决策。

## 决策

采纳：**本模块固定一组敏感键名，它是一个闭集，且每个键名都是不带分组路径的扁平拼写。**

- 实现子包在构造时把这一组登记进日志模块的脱敏规则集，使本模块自己写出的日志受同一份规则约束；
- 写审计表之前，本模块按同一组键名遮蔽明细中对应的值。

**键名逐字比较。** 日志侧按分组路径逐段比对，本模块按扁平键比对；把这一组限定为不含点的拼写，两种语义在它上面重合。

**值形状规则不作用于审计表。** 别的模块经值形状规则登记的匹配器只在日志链上生效。

**别的模块登记的键名也不作用于审计表。** 日志模块的规则集是进程级的、只可追加，但本模块读不到它，因此两处的覆盖集合不同。

## 后果

这一组键名在两处一致地被遮蔽，登记只有一处。

**接受的代价：**

- **覆盖的是一个闭集。** 明细里其余键名原样落库；一个由形状识别的秘密（会话令牌、卡号）在日志里被遮蔽，在审计表里原样落库；别的模块登记进日志规则集的键名同理。两者都写入非保证。
- **登记是全进程生效且不可移除的。** 日志模块的规则集跨注册表、跨命令共享，规则只可追加；本模块登记的键名因而会遮蔽**别的模块**写出的、恰好同名的日志属性，而这一处影响无法撤回。
- **审计对日志模块产生一条构造期依赖。** 只想要审计、不想要结构化日志的宿主仍然要装配日志模块；接口包不导入它，实现子包导入并声明依赖。
- **遮蔽依赖值以独立键写出。** 塞进一个包装值或不具名映射里的敏感值两处都漏，与日志模块的同一条边界一致。

## 失效条件

若日志模块导出可复用的判定入口，或出现第三个需要同一份规则的消费点，则「两处应用」应改为「一处判定、多处取用」，闭集这条限定也随之失去必要。
