# 事务发件箱是事件功能目录里的另一项功能，接口包是子包

## 背景

事务发件箱的接口要表达“在调用方的事务里暂存一个事件”（[ADR-outbox-scope](adr-outbox-scope.md)）：它的参数是一个 GORM（[REF-gorm](../references.md)）会话与一个事件，接口上因此有 `*gorm.DB`。它的实现依赖数据库功能（表在交付的库里，迁移由数据库模块施加），也依赖事件总线。

事件根包被每一个发布方 import，它放进来的每一条边都落进每一个发布方的闭包，因而它与键值功能同处依赖图的底层，不依赖任何别的功能（[ADR-event-scope](adr-event-scope.md)）；它也不引第三方的后端客户端，`pkg/event` 的依赖面检查守着这一条。要暂存事件的模块则本来就经数据库功能写库、经总线发布，GORM 与事件根包两者它都已承受。

实现要与各总线实现共用两件事：发布方留空的标识在事件离开调用之前赋予，以及订阅方收到的载荷是传输的结构（数保留为十进制文本）。这两件事住在事件目录的内部单元 `pkg/event/internal/dispatch` 里，Go 的 `internal` 规则只让 `pkg/event` 之下的包取用它。

功能目录的根包承载该功能的接口，实现位于子包（[ADR-module-layout](adr-module-layout.md)）；模块在 `init` 里登记，import 一个登记模块的包就把它带进可用集（[ADR-module-registration](adr-module-registration.md)）。

## 考虑过的选项

### 放进事件根包

`Bus` 旁边增加暂存的函数或接口。

**否决**：GORM 随之进入每一个发布方的闭包，包括从不暂存事件的那些；根包的依赖面检查正是为挡住这一条而设。

### 独立的功能目录 `pkg/outbox`

**否决**：它取用不了 `pkg/event/internal/dispatch`，只能另写一份标识的赋予与载荷的解码。订阅方收到的载荷结构于是在两处定义，一处改了另一处不会跟着改，经发件箱发布的事件与直接发布的事件在订阅方看来就不再一样。暂存也是发布事件的一种途径，它与总线的关系是事件目录内部的事。

### 一个子包既声明接口又登记模块

**否决**：暂存事件的模块 import 这个包来取得接口，登记写在 `init` 里，import 它就把中继带进了可用集，宿主没有写下的 import 决定了一个模块在不在二进制里。实现所需的 import（内部单元、日志、嵌入的迁移文件）也随之进入每一个暂存方的闭包。

### 接口包 `pkg/event/outbox`，实现子包 `pkg/event/outbox/relay`

**采纳**，见决策。

## 决策

采纳：**事务发件箱是事件功能目录里的另一项功能。** 接口包 `pkg/event/outbox` 声明功能接口与哨兵错误，只 import 事件根包与 GORM，不登记模块；实现子包 `pkg/event/outbox/relay` 登记模块 `event.outbox.relay`，排他地交付它。事件根包不 import 二者。

## 后果

不暂存事件的发布方的闭包不变，GORM 只进入 import 接口包的模块；实现与各总线实现共用标识的赋予与载荷的解码，订阅方从两条途径收到的事件形式一致。

**接受的代价：**

- **功能目录不再等于一项功能。** `pkg/event` 之下有两项功能，第二项的接口包是子包，功能标识 `(*outbox.Outbox)(nil)` 也在子包里；按“根包即接口”读目录的读者会漏掉它，要从设计文档或目录说明里得知。
- **接口包带着 GORM。** 暂存方承受它，也承受 GORM 的不兼容升级直达接口，与数据库功能的依赖方相同（[ADR-module-packaging](adr-module-packaging.md)）；接口包没有编译期的约束挡住它引入更多，守着的是它自己的依赖面检查。
- **实现与事件目录的内部单元绑在一起。** 内部单元的一次改动同时落到各总线实现与中继上，改动方要一并顾及。

## 失效条件

若事务发件箱的实现不再需要事件目录的内部单元，或出现了不依赖数据库功能的实现，它归在事件目录之下的理由就不再成立，应拆为独立的功能目录。
