# 作业进入终态时发事件，发布义务记在作业行自己身上，事件总线因此是可选依赖

## 背景

作业进入终态（`succeeded`、`dead_letter`、`cancelled`）时，订阅方要能得知一件作业完成了、死了或被取消了，据此推进后续的事。

发布与作业行的写入不是一回事：执行返回后，终态先写进作业行（`completed_at`、`result` 或 `error`），再想发一条事件。若发布失败即永久丢失——作业行已经落库，没有第二次机会去补。

环境有两处相关事实。事件总线没有发布登记，`Publish` 是至少一次，订阅方按事件标识自行去重（[ADR-event-identity](adr-event-identity.md)）。事务发件箱在写入的事务里暂存事件、提交之后发布，发布失败即一再重发（[ADR-outbox-scope](adr-outbox-scope.md)）。

一个只跑作业、不发布任何领域事件的装配存在：作业表是它的能力，事件总线不是。

## 考虑过的选项

### 把发事件放在执行完成的那一刻

执行返回、终态写进作业行之后立即调 `event.Bus.Publish`，失败即记一条日志。

**否决**：发布失败即永久丢失。作业行已经落库，一次发布失败之后没有任何一处会再尝试，一条「作业完成」的事件就此消失，订阅方无从知道它发生过。反过来先发布再写终态，订阅方得知的写入可能随后回滚。

### 强制依赖事件总线

`jobs.db` 构造期必需 `(*event.Bus)(nil)`，没有总线即启动失败。

**否决**：只跑作业、不发布领域事件的装配不该被迫装总线。作业能力的存在理由是分摊与执行，发布终态事件是它的附加能力；一个不发布任何领域事件的部署（作业结果只由调用方经 `jobs.Queue.Get` 轮询）应当能只纳入 `jobs.db` 而不引入事件总线。强依赖还会让每个用作业的宿主都背上对总线的依赖。

### 进入终态时发事件，发布义务记在作业行自己身上

**采纳**，见决策。

## 决策

采纳：**作业进入终态时向事件总线发事件；发布义务记在作业行自己身上（`terminal_published_at` 为空即补发），因此对 `pkg/event` 是可选依赖。**

- 事件类型：`jobs.job.succeeded`、`jobs.job.dead_letter`、`jobs.job.cancelled`。类型名常量由 `pkg/jobs/db` 声明，在作业进入相应终态时发上总线。
- 发布义务在作业行上：作业进入终态时 `terminal_published_at` 为空即表示「待发布」，一次发布成功后写下 `terminal_published_at`。已进入终态而 `terminal_published_at` 仍为空的作业，由执行循环在后续轮次补发，直到发布成功为止。发布因此是至少一次，订阅方按事件标识去重。
- 可选依赖：`jobs.db` 构造期可选取用 `(*event.Bus)(nil)`。总线在场即发布并记录发布时刻；总线缺席即不做任何发布尝试，作业照常执行、照常进入终态，`terminal_published_at` 保持为空而不触发补发。一个没有总线的装配不因缺事件而失败。
- 发布在事务之外：终态与 `terminal_published_at` 的写入在作业行所在的事务里完成，发布在事务之外、提交之后进行。发布失败不撤销终态的写入，只让补发在下一轮发生。

## 后果

终态事件不会因一次发布失败而丢失：作业行记着发布义务，补发到成功为止。只跑作业的装配不装事件总线。

**接受的代价：**

- **发布是至少一次。** 一次发布成功而写 `terminal_published_at` 失败，或副本在这次成功与写下发布时刻之间中断，下一轮会再发一次，订阅方按事件标识去重。
- **作业表多一列 `terminal_published_at`，执行循环多一段补发逻辑**：每一轮除认领到期作业外，还要找已进入终态而未发布的作业补发。
- **补发有延迟。** 一次发布失败到下一轮补发之间有一段时间；`terminal_published_at` 为空是「待发」的标记，不是「已发」。
- **总线在场与否改变可见行为。** 同一个作业能力，装了总线的装配发终态事件，没装的什么都不发，而作业本身的行为不变；「作业完成」这一事实对订阅方的可见性因此在两种装配下不同。
- **可选依赖不满足即静默跳过。** 一次装配忘了装总线不会报错，只是没有终态事件。

## 失效条件

若终态事件成为装配正确性的一部分——某项下游只有在收到终态事件后才推进——则「可选依赖、缺席即不发」要重议：一个缺了总线的装配会静默地少推进一项下游。

若发布改为恰好一次或需要顺序，作业行上的发布义务这一形态要重做。
