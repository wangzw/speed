# 装配层面的性质写成非保证，不为它们改动别的模块

## 状态

已接受

## 背景

认证的否决力是 HTTP 中间件链上的一层，由认证网关在 `Init` 登记。这条链的登记面对 `Init` 期的任何模块开放，且拿不到登记方的身份：`Endpoint` 不带它，`core` 不提供「当前正在 `Init` 的模块」这样的查询，登记又允许发生在模块自己起的协程里。入口模块因此不校验一层声称代表的功能与它所属模块交付的功能是否一致，一层可以声称代表认证而它所属模块并不交付认证。

层与层的先后由指向功能标识的硬约束决定，`Order` 只在硬约束未定的自由度内起作用。「位于最外层」这个诉求与任何具体功能都无关，只能用 `Order` 表达，而两个都要求位于最外层的层之间互相不知道对方取了什么值（[ADR-http-middleware-2026-09-14](adr-http-middleware-2026-09-14.md)）。「链上没有任何一层在认证之外」因此不是链上任何一方能单独声明出来的性质。

认证网关是否在场由宿主的命令树决定，模块不声明、也无从知道自己出现在哪条命令下（[ADR-command-tree-2026-09-20](adr-command-tree-2026-09-20.md)）。未被本次命令纳入的模块连 `Prepare` 都不执行。启动诊断的义务写的是：启动成功时，未进入启用集的模块必须在诊断中列出，并给出它表态禁用或消解落选的原因。未被纳入的模块字面上也未进入启用集，条文没有把它单独排除；本记录据此推断它不落在这条义务里，理由是义务要求的原因它一个都写不出——`Prepare` 都没执行，既没有表态禁用，也没有参与消解。这是本记录的推断，不是引自架构文档的条文。按名查询启用结果也没有为「在可用集里但不在参与集里」定义取值。

想要而拿不到的是这样一类性质：成立与否取决于本次装配里还有哪些层、它们各自怎么写，而认证既不认识它们，也没有任何声明位能约束它们。链上没有任何一层能绕过认证层、凭据不向认证层以内泄漏、认证层以内的缓存或合并层不把一个主体的应答交给另一个主体，都属于这一类。要把其中任何一条变成入口模块强制的性质，落点都在 `pkg/http` 的接口面上——那是认证不拥有的模块，它的接口被每一个贡献路由的模块使用，新增的代价落在每一个宿主头上，与这个宿主是否纳入认证无关。

架构的错误模型在这里既给了义务也给了边界：每一层为自己产生的失败提供哨兵，不允许留下它自己造出却说不出名字的失败；而这条约束不延伸到经由这一层返回的一切失败。哪些失败必须配哨兵、哪些才谈得上写成非保证，判据由此而来。

## 考虑过的选项

### 在入口模块上增开接缝，把性质变成强制

为认证判定在 `pkg/http` 上开一个专属位置：每端唯一的守卫席位、可读回的已登记模式清单、向路由引擎问「这条请求会分发到哪条路由」的接缝，以及一个「本端只在守卫之后服务」的配置键。链的组装把守卫包在全部登记层之外，席位的唯一性在组装时校验。

**否决**：每一道接缝把可被绕过的点挪到别处，不消掉它。把判定从登记层挪到最里侧插槽这一形态修掉了「认证之后有层重写路径」，换来的是网关与插槽之间的任何一层只要自己应答就完全绕过认证——同一套装配上的对照：无凭据的 `GET /admin/secret` 在这个形态下得 200 且短路的缓存层应答一次，判定位于全部登记层之外时得 401 且该层与受保护 handler 各零次。暴露面比它修掉的那一条更大。守卫席位这一形态同样不闭合：席位的名字由占座者自报，一个注册名为别的东西的模块把名字填成认证的名字，冲突文本读作同一个名字两次，单独占座时启动行印出的守卫名也是它；认证不在装配里时，占座者靠占住席位就满足了「本端只在守卫之后服务」这条数据声明而什么都不做。这些残余项都落在「装配里已经有一个坏模块」这一类，接缝换掉的只是哪个坏模块得手。而想要的性质里有一条接缝根本够不着：席位之内的流量是已认证的，按路由核对分发的接缝对身份不作断言——装一个按 URL 合并并发请求的层，两个调用方各带自己的正确凭据并发请求同一条路由，两人都得 200 且两份应答带的是同一个主体，handler 只跑一次，核对点没有报出任何不符，计数桶里也没有异常。

### 缩小认证的职责，只交付校验能力

认证不在链上占位，只交付校验后端；由宿主或各 API 模块在自己的 handler 里调用校验。「链上没有任何一层能绕过认证」不再是这个发布单元的主张。

**否决**：它把一处集中判定摊成每条路由各自的动作，漏掉一条就是无认证放行，而漏掉本身不产生任何信号——同一个失效形态从装配层搬到了路由层，并且变密。想要的性质一条也没有因此成立：凭据仍然穿过整条链到达 handler，缓存层仍然按方法加路径做键。它还与入口模块的分工相悖：入口模块把「哪些路由免于认证」划在自己的非职责里，并指明路由的认证策略归实现认证的那个模块、以中间件的形式接入。

### 写成非保证，不为它们改动别的模块

认证的收口止于它自己产生的失败；装配层面的性质作为非保证载入文档，每条附可观察的失效形态。

**采纳**，见决策。

## 决策

采纳：装配层面的性质写成非保证，不为它们在 `pkg/http` 或任何别的模块上增开接缝。

落在哪一侧由判据决定，判据覆盖认证的每一种失败：

- 认证在启动期自己判得出来的确定失败，配哨兵与修复动作，不得写成非保证。
- 成立与否取决于本次装配里还有哪些层、它们各自怎么写的性质，写成非保证，每条写清可观察到什么、哪一层不报错。

按「取决于装配」这一侧落在非保证、本记录直接指名的性质：链上没有任何一层能绕过认证层、凭据不向认证层以内泄漏、认证层以内的缓存或合并层不把一个主体的应答交给另一个主体。判据管到的不止这些指名的性质，符合判据的新情形归入非保证，不为此修订一份列举。

认证为此所立的防线不需要改动别的模块：启动的成功路径上无条件写出冻结后的豁免表，以及本次实际接上的校验后端名单。它们只用认证自己的信息，不向别的模块要任何接缝。

## 后果

收口口径与架构的错误模型一致：认证为自己产生的失败提供哨兵，不为发生在它之外、或经由它返回的失败发明名字。

`pkg/http` 的接口面不因认证而变：`Endpoint` 的方法集不扩，配置面不新增键，监听端的构造不为认证改写。不纳入认证的宿主不为它付任何代价。

认证层在链上与别的横切层同形：它的位置用 `Order` 表达，它对外的锚点是它在链上声明的功能标识，要排在认证之内的层用指向该标识的硬约束表达。

非保证是文档承诺的一部分，不是省略：每一条都要写出可观察的失效形态，以及宿主据此自己该做什么。

**接受的代价：**

- **链上没有任何一层能绕过认证层不成立。** `Order` 小于认证层的任何一层都在认证层之外，它自己应答的请求认证层一次都看不到；链上还可以有第二层认证，也可以有一层声称代表认证功能而它所属模块并不交付认证，登记面不知道登记方是谁，第二层认证与冒名的那一层都拦不住。宿主自己要做的是核对组装出的链——它在启动时是确定的、可以逐层列出（[ADR-http-middleware-2026-09-14](adr-http-middleware-2026-09-14.md)），认证层之外还有谁在那上面看得见；把一层排在认证之内的正当写法是指向认证功能标识的硬约束，不是取一个更大的数值。
- **凭据不向认证层以内泄漏不成立，失效形态不止一种。** 豁免路由上认证层不读 `Authorization` 头也不问任何后端，头里的内容因此原样到达 handler，而网关对它一个字都没校验过；一个把入站头当可信输入转发到上游的 handler 会被它驱动。脱敏这一侧同理：凭据的脱敏规则由认证在自己的 `Init` 里向日志模块登记，时机比日志模块给出的那条更弱。日志模块给的写法是模块在自己的 `New` 中、取得 logger 之前登记，它保住的是「自己的规则早于自己的 logger 绑定」，跨模块的覆盖本就没有时机保证（[ADR-log-redaction-2026-09-13](adr-log-redaction-2026-09-13.md)）；网关的 `Requires` 为空（[ADR-authn-wiring-2026-09-20](adr-authn-wiring-2026-09-20.md)），在 `New` 里取 `Logger` 实例要么声明对日志功能的依赖、要么赌构造顺序，登记因此只能落在 `Init`，而 `Init` 整体跑在全部 `New` 之后。日志模块那条保证靠的是「登记与取用同在自己的 `New` 里、登记在先」这个顺序，网关排不进这个顺序，连「自己的规则早于自己的 logger 绑定」都不保证；别的模块在 `New` 期绑好属性的 logger 同样落在这条规则之前。日志模块不在这条命令的参与集里时规则根本登记不上，失效形态是认证层在而规则集空。架构的安全边界已把脱敏的覆盖面定性为装配的结果，不是日志模块的承诺。宿主自己要做的是不让认证层以内的转发面与日志面原样复制入站头。
- **认证层以内的缓存或合并层不把一个主体的应答交给另一个主体不成立。** 认证层放行之后，同一条路由上的两个请求在它看来等价：装一个按 URL 合并并发请求的层，两个调用方各带自己的正确凭据并发请求同一条路由，两人都得 200，两份应答带的是同一个主体，handler 只跑了一次，没有任何计数异常。应答缓存、批处理、流量镜像、重放式重试都是这个写法，键通常取方法加路径，写这些层的人无需恶意。宿主自己要做的是：认证层以内任何按请求做键的缓存或合并层，键里必须含主体标识。
- **一条没有纳入认证网关的命令完全静默。** 链上没有认证层，网关连 `Prepare` 都不执行，净效果是该端全部路由无认证放行：缺席的后果落在放行那一侧，不落在拒绝那一侧。「完全静默」依赖背景给出的那条推断——未被纳入的模块不落在启动诊断的义务覆盖面里，是推断，不是架构文档的条文。豁免登记随认证层一同缺席，这一点不改变净效果——没有门的端不因为没有豁免项而变得安全。宿主自己要做的是：纳入认证的命令逐个写出网关与所选后端的名字，不用「纳入全部可用模块」——它让参与集重新成为 import 图的函数（[ADR-command-tree-2026-09-20](adr-command-tree-2026-09-20.md) 已把这一项记为代价），而对认证而言多一个后端等于多一条能登录进来的路，模块没有任何「拒绝被它纳入」的表达位；也不要把网关放进根命令，根命令纳入的模块对每条子命令都有效，认证会随之进入迁移一类命令的参与集。
- **驱动深度浅于 `StageServe` 时，运行期的收口语义整段不适用。** `StagePrepare` 是 `Stage` 的零值，一条忘了写深度的命令会跑完表态就退出、退出码为零，而认证层从未存在过。
- **别的层用指向认证功能标识的硬约束把自己排在认证之内，认证不在本次装配里时这条边不存在、约束自动满足**，那一层照常运行在没有认证的链上。本端有层点名过认证功能时，启动诊断里有一行「该功能在本端无人代表」，它分不出成因是未纳入、未启用，还是在场却漏写了声明；没有任何层点名过认证功能时——新装的进程，或只有日志与追踪的最小链——一行都不打印。
- **这些性质将来若要变成硬保证，代价不再落在认证内部**：落点在入口模块的接口面上，届时是一次宿主可见的破坏性变更。

## 失效条件

入口模块若出于本决策之外的理由获得一个每端唯一、位于全部登记层之外的位置——例如恢复层要求这样的位置——「链上没有任何一层能绕过认证层」不再需要为认证单独增开接缝，这一条应当从非保证转为保证。

`core` 若为「在可用集里但不在参与集里」定义出可查询的取值，或启动诊断的义务明确覆盖到未被纳入的模块（背景里的那条推断就此被推翻），「一条没有纳入认证网关的命令完全静默」不再成立，宿主的自检也就有了可用的判据。
