# 租户作用域的 query key 由框架提供工厂与逐出辅助函数

## 背景

多租户下，切换租户后不得再展示离开的租户的数据（REQ-tenancy-023）：前一个租户的缓存必须逐出，否则新租户的界面会显示旧租户的数据。

生成产物刻意与租户无关。`@speed/api-sdk` 是 orval（[REF-orval](../references.md)）生成的（`web/packages/api-sdk/src/index.ts`），它的 query key 是裸的 spec 路径，不带租户维度；`web/packages/api-sdk/AGENTS.md` 记下这条——生成代码里没有租户头、没有租户 query key，`tenant_id` 只在认证片段的类型里出现。租户由传输层统一挂在请求上：`@speed/api-client` 的 `tenantProvider` 的值接成 `X-Tenant` 头，不经任一生成操作，生成产物因而仍与租户无关。

今天的租户分域是宿主壳的纪律，不是框架能力：`web/packages/tenancy-ui/README.md` 把 `queryClient.removeQueries({ queryKey: ['tenant', oldId] })`（[REF-tanstack-query](../references.md)）写成宿主在 `TenantSwitcher` 的 `onSwitched` 里的工作，参考应用里是宿主自己写的一份键结构加逐出。键结构与逐出时机因而会按宿主数各写一遍。

## 考虑过的选项

### 把租户维度放进 api-sdk 生成的 query key

**否决**：生成产物必须保持与租户无关。做到这一条要么手改生成产物（破 `src/index.ts` 的 DO-NOT-EDIT 头），要么让 orval 持有一个它不认识、也无法在生成期取得的运行期维度。且生成的裸 spec 路径键是跨租户稳定的资源标识；把租户段塞进生成键会让每一处生成的 hook 都多背一个运行期维度，而多数操作与租户无关。

### 让每个宿主壳自定义键结构与逐出辅助函数

**否决**：键结构与逐出时机是会出缺陷的地方——把键当成跨租户稳定、或漏逐某一个前缀，都会让上一个租户的数据留在新租户下。让每个宿主复制这套纪律，等于把这类缺陷按宿主数复制，而它们本可以定在一处。

### 由框架提供租户作用域的 query key 工厂与逐出辅助函数，生成产物保持租户无关

**采纳**，见决策。

## 决策

采纳：**租户作用域的 query key 由框架提供工厂与逐出辅助函数，`api-sdk` 的生成产物保持与租户无关。**

- 工厂把租户标识作为最外层段拼在生成的裸 spec 键之上，一个租户下的全部读操作共用一个前缀。
- 逐出辅助函数在租户切换提交后按该前缀逐出前一个租户的键。
- `@speed/api-sdk` 的生成产物不变：query key 仍是裸 spec 路径，无租户头、无租户 query key；租户由传输层统一挂在请求上（`X-Tenant`，`@speed/api-client` 的 `tenantProvider` 接），不经生成产物。
- 会话结束的整棵逐出（`web/packages/product-shell/src/bootstrap.tsx` 的 `bootstrapSpeedApp` 会话结束默认）与租户逐出并存：租户切换逐出租户段，会话结束逐出整棵缓存。

## 后果

宿主不再自定义键结构与逐出时机，一处定义；切换租户后旧租户的数据不再残留。生成产物继续与租户无关。

**接受的代价：**

- **框架包背上一个与 react-query 键结构绑定的约定。** 键的最外层段保留给租户，业务自定义的键要服从这一约定；绕过它、自造一个顶层键，就失去逐出辅助函数的覆盖，这类键只能靠会话结束的整棵逐出来兜底。
- **约定在类型系统里无强制。** 一个生成的裸键与一个租户前缀键类型相同，编译器不阻止直接使用一个裸键；纪律靠工厂的默认路径与代码审查守住。
- **逐出以租户段为界。** 一个在租户段之外缓存的键——身份域的行——逐出辅助函数够不到；这类键的正确性是「租户切换逐出租户段」与「会话结束逐出整棵」合起来的结果，只看其中一条会漏。

## 失效条件

- 若 orval 或其继任者原生支持 query key 前缀或 transformer，工厂可以退回生成层，本决策要重新评估。
- 若租户标识成为生成产物的**逐操作参数**（而非由传输层统一挂在请求上）——生成产物与租户无关这一前提不再成立。
