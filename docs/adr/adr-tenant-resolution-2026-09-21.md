# 租户标识由请求面解析得到，取法由配置选定，不从认证身份派生

## 状态

已接受

## 背景

租户标识从哪里取，此前全仓没有出处。文档只说它产生于依赖图上层的模块、被随 context 传递（[ADR-db-scope-2026-09-14](adr-db-scope-2026-09-14.md)、[ADR-log-context-2026-09-13](adr-log-context-2026-09-13.md)、[ADR-tenant-ordering-2026-09-21](adr-tenant-ordering-2026-09-21.md)），没有一处说过取值途径。主体空间、请求头、子域名、路径前缀、配置映射都是可能的来源，一种都没有被提及过。

认证这一侧关闭了其中一条。身份只有主体、归属与键三个只读方法，字段不导出、只能由判决盖章产生，主体是裸字符串、自身不含归属信息（[ADR-authn-packaging-2026-09-20](adr-authn-packaging-2026-09-20.md)）。身份是 `pkg/authn` 明列的跨模块契约，在它上面加一个租户字段等于要求每一个校验后端回答租户问题。豁免路由上没有身份，而登录、注册、探活这些最需要知道租户的路由恰恰走在豁免上（[ADR-authn-scope-2026-09-20](adr-authn-scope-2026-09-20.md)）。

租户与主体的基数关系不是一对一：同一个人可以在两个租户下各有一个主体，一个租户下可以有多个主体。从主体派生租户因而要求一份映射，而那份映射就是一份名册，与请求面的取法相比不多出任何信息。

请求面的取法是同一批宿主并存的部署形态：子域名与路径前缀各自成片，写死一种等于替宿主决定对外 URL 的形状，而那是 API 的形状，不是装配的自由度（[ADR-authn-scope-2026-09-20](adr-authn-scope-2026-09-20.md) 为"免认证的路由分到另一个监听端"记下的同一条理由）。

## 考虑过的选项

### 从认证身份派生

租户是主体的一个属性，从 `Identity` 上读出租户，或者在 `Identity` 上加一个租户字段。

**否决**：`Identity` 的字段不导出、构造函数在内部包里，链上任何一层都写不进去，加字段要改一个已发布的接口包；豁免路由上没有身份，而最需要租户的路由都在豁免上；租户与主体不是一对一，从主体派生要求一份映射，而那份映射就是名册——绕开请求面不多得到任何东西，只多出一条依赖。

### 取法写死为一种

本模块内建一种取法，宿主按它组织对外 URL。

**否决**：子域名与路径前缀是并存的两片部署形态，写死一种等于替宿主决定 API 的对外形状。它还会把取法的字符集约束变成库的约束（见 [ADR-tenant-identifier-2026-09-21](adr-tenant-identifier-2026-09-21.md)）：换一种取法就换一套合法字符，而已经入库的标识不跟着变。

### 只做扩展点，本模块不内建任何取法

本模块只定义取法的接口，每一种取法由宿主自己写。

**否决**：每个宿主各写一遍同一段解析，而写错的形态是静默地把另一个租户的名字读出来。取法还要与名册上别名的字符集对得上，那是本模块的事实，推出去就没人对得上了。

### 由宿主在 handler 里自己解析并写进上下文

本模块不占链上的位置，把解析摊给每一条需要租户的路由。

**否决**：把一处集中判定摊成每条路由各自的动作，漏掉一条就是无租户或错租户，而漏掉本身不产生任何信号。认证为"缩小职责只交付校验能力"记下的否决理由同源（[ADR-authn-guarantees-2026-09-20](adr-authn-guarantees-2026-09-20.md)）。

### 取法由设置给出

取法作为运行期可变的参数，存放于数据库。

**否决**：自举失败。读设置的租户层要先知道租户（[ADR-config-scope-2026-09-13](adr-config-scope-2026-09-13.md) 的推论正是这条）；取法在运行中改变还会让同一个请求头在两个瞬间解析出不同的租户。

### 内建一组取法由配置选定，另留取法的扩展点

**采纳**，见决策。

## 决策

采纳：租户标识由请求面解析得到；取法由本模块的内建实现提供、由配置选定，另留一个取法的扩展点。**不从认证身份派生，本模块不改动 `Identity`。**

判据是取值途径与判定所需的输入：认定一个请求属于哪个租户只需要请求面，不需要凭据，也不需要主体。

取法的接缝与登记面的确切形状写在设计文档的外部接口契约里。**登记面拿不到登记方的身份**，因而重名冲突点得到那个名字与两处登记的实现类型，点不到模块名——与认证的豁免登记同形（[ADR-authn-guarantees-2026-09-20](adr-authn-guarantees-2026-09-20.md)）。

**取到的名字是名册上的别名，不是最终标识**：解析层把它交给名册，换回不可变标识，写进请求上下文的是标识（[ADR-tenant-identifier-2026-09-21](adr-tenant-identifier-2026-09-21.md)）。

**一次请求只由一种取法解析。** 允许多种并存时，任何优先级都意味着一条请求可以用两种方式声称自己是某个租户，而两条途径得出的结论可能不同。迁移期需要同时支持两种 URL 形态的，形态是把它们放进两个进程——取法配在模块自己的命名空间下，作用于它登记中间件的全部监听端，一个二进制里并存两种取法表达不出来（[ADR-tenant-packaging-2026-09-21](adr-tenant-packaging-2026-09-21.md)）。

**注入口不导出，`FromContext` 不回落**，与认证的身份同形（[ADR-authn-packaging-2026-09-20](adr-authn-packaging-2026-09-20.md)）：回落等于把一条没有租户的请求读成某个租户，导出注入口等于让链上任何一层改写租户。

**解析层守护哪些监听端由配置列举**，与认证网关同形。未被列举的监听端上不登记这一层，那条链上的请求没有租户，受约束模型的语句一律拒绝。

## 后果

取值途径有了出处，`ADR-tenant-scope`、`ADR-tenant-ordering` 与 `ADR-tenant-isolation` 里"租户标识产生于上层"这句话有了落点。

主体与租户之间没有强绑定：一个已认证的调用方可以在请求面声称它是另一个租户，而认证不参与这个判定。这一条与 [ADR-tenant-scoping-2026-09-21](adr-tenant-scoping-2026-09-21.md) 的零值防线是同一条设计的两面——租户的作用域由装配与配置划定，不由身份划定。

**接受的代价：**

- **取法是启动期配置，改它要重启。** 按租户取值的参数一律归设置侧（[ADR-config-scope-2026-09-13](adr-config-scope-2026-09-13.md)），而取法在数据库可用之前就被需要，两条件把它钉在配置一侧。
- **请求面在反向代理之后可被伪造。** `Host` 与 `X-Forwarded-*` 由前置代理写入，本模块信任它读到的东西；把入站头当作可信输入转发，或让一个不受信的客户端直接够到本进程，都能让调用方选定自己要读哪个租户的数据。前置代理的净化是宿主的事，这一条写进非保证。
- **一个进程里只能有一种取法生效**，它作用于解析层守护的全部监听端；迁移期同时支持两种 URL 形态要靠两个进程，分成两个监听端做不到。
- **下游必须处理"取不到租户"这一档。** 未被本模块守护的监听端，以及本模块不在参与集里或未启用的进程，上下文里都没有租户；宿主为解析模块预置的实例不是该模块的产物时，解析层不登记，经请求面到达的请求同样没有租户（[ADR-supplied-instance-2026-10-08](adr-supplied-instance-2026-10-08.md)）。**豁免路由不在此列**：解析层排在认证之内，认证层放行的豁免请求照常经过它（[ADR-tenant-ordering-2026-09-21](adr-tenant-ordering-2026-09-21.md)）。
- **一个不需要租户的路由不能与需要它的路由共处一个被守护的监听端。** 探活、诊断这类路由要放到另一个监听端：解析层在 handler 之前就以 404 收口，注入口又不导出，宿主没有位置替这样一条请求给出一个租户。解析层按监听端守护，没有按路由的例外，这一条是守护粒度换来的。

## 失效条件

若认证的身份面获得一种承载应用自定义属性的方式，且该属性对每一个校验后端都是必答项，则"租户与主体一对多"不再是拒绝从身份派生的理由，本记录的取值途径要与它重新比较。

若出现一种入口不经中间件链——本仓已有的形态只有 HTTP——则"解析占链上一层"这一形态不再覆盖它，本模块的交付面需要重新裁定。
