# 刷出落在关闭阶段，以配置的上界为界

## 状态

已接受

## 背景

一次驱动的关闭分两拍：`Stop` 停止接收新工作，`Close` 释放资源，两拍收到的 context 去掉取消、保留值。注册表不对停机施加超时，回调必须自己保证有界，而刷出的上界在上下文里表达不出来——它只能来自本模块自己的配置（见 `core` 设计文档的阶段一节、[ADR-observability-config-2026-09-22](adr-observability-config-2026-09-22.md)）。

关停会把上游 SDK 的批处理器与读数器里的在途数据刷出（见本模块设计文档的关停时的刷出）。刷出落在关闭路径的哪一拍，是本记录要定的。

上游批处理器的每一次导出，关停时的末批也在内，跑在它自己以 `batch.export-timeout` 为界的上下文上，不随关停收到的上下文取消；gRPC 导出器对 `Unavailable` 默认重试，一次导出在重试里等到它的上下文结束、导出器自身的超时与重试的总时长中先到的一个，默认值下它们都不短于 `shutdown-timeout`；http 导出器只对拨号超时这类暂时性错误重试，连接被拒、主机名解析失败这类错误立即放弃，拨号超时或采集端不应答时，一次导出同样等到它的上下文结束。刷出的上界要约束到导出本身，只能由本模块在转发导出的地方做到。

`Stop` 先走遍入口——声明了 `Serve` 的模块——再走遍其余模块，两组各按逆构造序；`Close` 在全部 `Stop` 返回之后按逆构造序推进（[ADR-lifecycle-stages-2026-09-28](adr-lifecycle-stages-2026-09-28.md)）。本模块不声明 `Serve`，它的 `Stop` 落在每个入口的 `Stop` 之后；它与其余模块之间的先后由逆构造序给出，与事件总线之间没有构造期依赖。

入口模块的排空在它自己的 `Stop` 里走完，界由它的排空时限给出（[ADR-http-shutdown-2026-09-14](adr-http-shutdown-2026-09-14.md)），排空期间在途请求照常结束、照常产生跨度。`Stop` 这一拍里其余模块也还在收尾：事件总线在自己的 `Stop` 里把已取到的条目交给订阅者，本模块从事件派生的跨度就产生在那时。

## 考虑过的选项

### 在停止阶段刷出

采纳它意味着 `Stop` 里就关停 provider。

**否决**：`Stop` 这一拍里仍有跨度产生。入口的排空排在本模块之前，但排在本模块之后停止的模块还在收尾——事件总线在宽限期内交出已取到的条目即是；在本模块的 `Stop` 里关停 provider，这些跨度落在刷出之后，而关闭时已经没有东西可以接住它们。

### 让入口模块反过来依赖本模块

采纳它意味着入口模块的 `Requires` 里出现本模块的功能，关闭次序由这条依赖声明给出。

**否决**：入口的排空已经排在一切 `Close` 之前，一条反向依赖换不来任何先后；它只会要求入口模块认识遥测，并把一个纯粹的后台命令也拖进一次它不需要的装配。

### 在关闭阶段不设上界，一直等到刷完

采纳它意味着 `Close` 无限等一个不肯结束的导出。

**否决**：注册表要求回调自身有界，而刷出的上界无处可来；没有第二个东西能在重启与停机路径上兜住一个不肯结束的关闭。

### 导出器的释放沿用刷出的上下文

采纳它意味着两个 provider 与导出器的释放共用 `shutdown-timeout` 这一个截止时刻。

**否决**：上游的导出器在已经结束的上下文上照常关闭连接，并把该上下文的错误作为结果返回。导出拖到截断点时，刷出之后那一份上下文至多剩下截断余量；一个 provider 的关停用满上界时，它已经过期；释放沿用它，就只能在这点余量里关闭，或者拿到一个已经过期的上下文而返回错误，`Close` 随之失败，与导出本身成败无关。

### 导出器释放的上界做成设置项

采纳它意味着配置里与 `shutdown-timeout` 并列多一项释放的时限。

**否决**：这个上界只负责让一个等待上下文结束的关闭不能把停机无限挂住，没有部署事实可据以取值，取值不随部署变化，设置项只会多出一个无处取值的旋钮；采用固定值，代价列入后果。

### 关闭开始之后的导出不受刷出的上界约束

采纳它意味着关闭开始之后的导出照旧只以 `batch.export-timeout` 或刷出的上下文为界。

**否决**：采集端不可达时，追踪一侧的末批或关闭开始时仍在途的那次导出在重试里拖过 `shutdown-timeout`，追踪 provider 的关停以超时错误返回；真实服务只要有追踪流量，每一次这样的停机都以非零状态退出，与导出本身成败无关。

### 导出截断在截止时刻上

采纳它意味着导出与 provider 的关停在同一时刻到期。

**否决**：导出被截断之后，provider 还要走完自己的收尾才能返回，而它等待的上下文在同一时刻结束，关停于是仍以超时错误返回；截断必须早于截止时刻，留出 provider 返回所用的时间。

### 停止阶段无动作，关闭阶段以配置的上界依次关停两个 provider

采纳它意味着刷出落在关闭拍上，排在全部 `Stop` 之后，上界由 `shutdown-timeout` 给出，关闭开始之后的导出截断在上界之内的截断点上；导出器的释放另有一个固定的短上界。

**采纳** — 见决策。

## 决策

采纳：**停止阶段无动作，关闭阶段以配置的上界依次关停两个 provider。** 刷出因而排在全部 `Stop` 之后：入口的排空与其余模块在 `Stop` 里的收尾都先于它结束。导出也受这份上界约束：关闭开始之后，转发包装把每一次导出——开始时仍在途的，以及期间的末批与末次导出——截断在截止时刻之前上界的十分之一处的截断点上；被截断的导出按转发包装的首次与恢复规则写行并吸收，provider 的关停在上界之内返回；截断余量随上界成比例，不是设置项。导出器的释放是同一个关闭拍的后半，不在这份上界之内，在两个 provider 关停之后以一个固定的短上界另行进行，不是设置项。

## 后果

事件总线在 `Stop` 里交出的条目，其跨度与指标都产生在刷出之前，照常导出；入口模块的实例是它自己的产物时，入口在排空时限之内走完的请求同样如此。

**接受的代价：**

- **追踪 provider 的关停超过上界时，剩余的在途数据被丢弃，丢了什么不产生信号。** 截断够不着的跨度导出落在这里，例如跨度导出器无视上下文。`Close` 以超时错误返回，驱动以失败结束，宿主看得到这一次停机没有在上界内完成；被丢弃的是哪些跨度与指标，本模块不为它写日志行，这部分观测面缺口与「本来就没有数据」从外部看不出区别。
- **指标导出器无视上下文时，关闭不受上界约束。** 读数器在指标 provider 的关停里同步做末次导出，截断够不着这样的导出，关停等到它返回为止，关闭耗时随那次导出拉长。它是最后一个读数器时，关停随后返回成功，`Close` 不因此失败；排在它后面的读数器拿到已经过期的上下文，不做末次导出，以超时错误使 `Close` 失败。
- **采集端不可达时，关闭对导出的等待至多到截断点，截断点上仍未送达的跨度与指标被丢弃。** 在截断点之前结束的导出按 `batch.export-timeout`、`metric.timeout` 与导出器自己的重试和超时进行，截断点不影响它们；http 导出器遇到连接被拒、主机名解析失败这类不重试的错误时不经这段等待。被截断的导出只经转发包装的日志行报出，`Close` 不因它失败。
- **截断余量是上界的固定比例。** 一次本可以在截断点与截止时刻之间完成的导出被截断，配置改不动这一比例。
- **释放的上界是固定值。** 一个等待上下文、关闭得比它久的导出器使 `Close` 以超时错误返回，配置改不动这一点；无视上下文的关闭不受这个上界约束。
- **在本模块之后关闭的模块，它在自己的 `Close` 里产生的记录不被导出。** 关闭拍按逆构造序推进，构造在本模块之前的模块在它之后关闭；那些模块在 `Close` 里记下的跨度与指标落在刷出之后。
- **入口排空超时之后仍在运行的处理函数，此后产生的跨度同样可能落在刷出之后。** 排空时限到期时入口的 `Stop` 返回，停机照常推进，而入口切不断一个已经接管连接的处理函数（见 `http` 设计文档的排空的界）。
- **宿主为入口模块预置的实例不是它的产物时，那个实例放进来的请求产生的跨度同样可能落在刷出之后。** 入口模块对这样的实例不排空，它的 `Stop` 随即返回，请求仍在运行时停机照常推进（[ADR-supplied-instance-2026-10-08](adr-supplied-instance-2026-10-08.md)）。

## 失效条件

若某个模块在自己的 `Close` 里产生必须导出的记录，关闭拍上的任何一个位置都覆盖不了它，把刷出放在关闭拍的判据随之不再成立。
