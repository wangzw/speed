# 刷出落在关闭阶段，以配置的上界为界

## 状态

已接受

## 背景

一次驱动的关闭分两拍：`Stop` 停止接收新工作，`Close` 释放资源，两拍收到的 context 去掉取消、保留值。注册表不对停机施加超时，回调必须自己保证有界，而上界在上下文里表达不出来——它只能来自本模块自己的配置（见 `core` 设计文档的阶段一节、[ADR-observability-config-2026-09-22](adr-observability-config-2026-09-22.md)）。

关停会把上游 SDK 的批处理器与读数器里的在途数据刷出（见本模块设计文档的关停时的刷出）。刷出落在关闭路径的哪一拍，是本记录要定的。

`Stop` 先走遍入口——声明了 `Serve` 的模块——再走遍其余模块，两组各按逆构造序；`Close` 在全部 `Stop` 返回之后按逆构造序推进（[ADR-lifecycle-stages-2026-09-28](adr-lifecycle-stages-2026-09-28.md)）。本模块不声明 `Serve`，它的 `Stop` 落在每个入口的 `Stop` 之后；它与其余模块之间的先后由逆构造序给出，与事件总线之间没有构造期依赖。

入口模块的排空在它自己的 `Stop` 里走完，界由它的排空时限给出（[ADR-http-shutdown-2026-09-14](adr-http-shutdown-2026-09-14.md)），排空期间在途请求照常结束、照常产生跨度。`Stop` 这一拍里其余模块也还在收尾：事件总线在自己的 `Stop` 里把已取到的条目交给订阅者，本模块从事件派生的跨度就产生在那时。

## 考虑过的选项

### 在停止阶段刷出

采纳它意味着 `Stop` 里就关停 provider。

**否决**：`Stop` 这一拍里仍有跨度产生。入口的排空排在本模块之前，但排在本模块之后停止的模块还在收尾——事件总线在宽限期内交出已取到的条目即是；在本模块的 `Stop` 里关停 provider，这些跨度落在刷出之后，而关闭时已经没有东西可以接住它们。

### 让入口模块反过来依赖本模块

采纳它意味着入口模块的 `Requires` 里出现本模块的功能，关闭次序由这条依赖声明给出。

**否决**：入口的排空已经排在一切 `Close` 之前，一条反向依赖换不来任何先后；它只会要求入口模块认识遥测，并把一个纯粹的后台命令也拖进一次它不需要的装配。

### 在关闭阶段不设上界，一直等到刷完

采纳它意味着 `Close` 无限等一个不肯结束的导出。

**否决**：注册表要求回调自身有界，而上界无处可来；没有第二个东西能在重启与停机路径上兜住一个不肯结束的关闭。

### 停止阶段无动作，关闭阶段以配置的上界依次关停两个 provider

采纳它意味着刷出落在关闭拍上，排在全部 `Stop` 之后，上界由 `shutdown-timeout` 给出。

**采纳** — 见决策。

## 决策

采纳：**停止阶段无动作，关闭阶段以配置的上界依次关停两个 provider。** 刷出因而排在全部 `Stop` 之后：入口的排空与其余模块在 `Stop` 里的收尾都先于它结束。

## 后果

入口在排空时限之内走完的请求，以及事件总线在 `Stop` 里交出的条目，其跨度与指标都产生在刷出之前，照常导出。

**接受的代价：**

- **刷出超时后剩余的在途数据被丢弃，丢了什么不产生信号。** `Close` 以超时错误返回，驱动以失败结束，宿主看得到这一次停机没有在上界内完成；被丢弃的是哪些跨度与指标，本模块不为它写日志行，这部分观测面缺口与「本来就没有数据」从外部看不出区别。
- **在本模块之后关闭的模块，它在自己的 `Close` 里产生的记录不被导出。** 关闭拍按逆构造序推进，构造在本模块之前的模块在它之后关闭；那些模块在 `Close` 里记下的跨度与指标落在刷出之后。
- **入口排空超时之后仍在运行的处理函数，此后产生的跨度同样可能落在刷出之后。** 排空时限到期时入口的 `Stop` 返回，停机照常推进，而入口切不断一个已经接管连接的处理函数（见 `http` 设计文档的排空的界）。

## 失效条件

若某个模块在自己的 `Close` 里产生必须导出的记录，关闭拍上的任何一个位置都覆盖不了它，把刷出放在关闭拍的判据随之不再成立。
