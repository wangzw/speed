# 网关不声明构造期依赖，入口与校验后端都在 Init 取

## 状态

已接受

## 背景

认证网关是 `pkg/authn` 中登记为模块的那一层：它向 HTTP 监听端登记一道中间件，请求到达时取出凭据交给在场的校验后端判定。校验后端是同一发布单元下的另一批模块，非排他地交付同一个功能，多个可以并存（[ADR-authn-packaging-2026-09-20](adr-authn-packaging-2026-09-20.md)）。

网关要用到的东西是入口模块的登记面与全部校验后端，而它们在构造期都还用不上：

- 登记面只在 `Init` 阶段接受写入，此外的写入一律失败（[ADR-http-routing-2026-09-14](adr-http-routing-2026-09-14.md)）。
- 校验后端在请求到达时才被问到，那发生在 `Serve` 之后。

`Init` 运行时全部实例均已构造完毕，相互引用在此成立（[ADR-lifecycle-stages-2026-09-13](adr-lifecycle-stages-2026-09-13.md)）。

`Requires` 的作用是决定构造顺序，并在任何模块构造之前完成校验（[ADR-dependency-resolution-2026-09-13](adr-dependency-resolution-2026-09-13.md)）。

参与集是命令路径上各层运行级纳入的模块，连同它们在 `Requires` 中声明的功能的提供者（不写命令树的调用方走 `Run` 入口时，它是注册表里已登记的每一个模块，见 [ADR-drive-entry-2026-09-21](adr-drive-entry-2026-09-21.md)）。纳入只给予表态的资格，不决定启用（[ADR-module-enablement-2026-09-13](adr-module-enablement-2026-09-13.md)），但它是宿主表达"这条命令要哪些校验后端"的唯一途径：后端彼此不排他，多个并存不构成冲突，命令树上的列举是它们之间仅有的取舍点。

这些事实合起来给出一个后果：网关一旦把校验后端的功能写进 `Requires`，命令上只列举网关，与同时列举网关和某个后端，得到的参与集相同——闭包按该功能的提供者展开，凡被 import 进来的后端都会进来。宿主在命令树上的列举因而不再有效果，参与集重新成为 import 图的函数（[ADR-command-tree-2026-09-20](adr-command-tree-2026-09-20.md)），而参与集决定这一层命令行上有哪些参数、帮助输出列出哪些参数、哪些模块的必填项会被判到。

另一件与之相关的事实是时机。依赖校验发生在叶子节点，在任何模块构造之前完成，此时尚无实例存在，无须回滚。同一处缺失若改由 `Init` 里的取用发现，`New` 与 `Migrate` 都已执行完毕，而 `Migrate` 已经施加的数据变更不在回滚范围内，也无法回滚。

## 考虑过的选项

### 入口与校验后端都写进 Requires

网关声明它需要路由登记面与校验后端。任一缺失都在任何实例构造之前报出提供者缺失，错误文本点名声明该依赖的模块以及登记它的包。

**否决**：后端这一侧，依赖闭包把校验后端功能的提供者一并纳入参与集——后端非排他交付，闭包照常展开——凡被 import 进来的后端都会进来，宿主在命令树上的列举随之失效，选不了这次要哪些后端，"这次装配了哪些后端"不再能从宿主代码上读出。入口这一侧不构成理由：入口排他交付，依赖闭包不为它自动纳入提供者，只取命令树上已点名的实现，未点名的入口模块不会进来（[ADR-dependency-resolution-2026-09-13](adr-dependency-resolution-2026-09-13.md)）。

### 声明为可选依赖

同样写进 `Requires`，但标注 `Optional`，缺席不构成错误，网关照常构造。

**否决**：`Optional` 表达的是缺席为一种合法配置，而这里的缺席都不合法——没有任何 HTTP 入口时认证层无处可挂，一个校验后端都没有时无人能判定凭据；这样声明等于让描述符陈述一件与事实相反的事。它也换不到想要的那个便利：`Optional` 落在 `Requires` 里，参与集按 `Requires` 所声明功能的提供者展开，不区分声明是否可选，架空显式列举这一条不受影响。

### 由宿主把入口与后端直接交给网关

宿主在 `main` 里写出它要的后端，经构造参数或预置产物交给网关，不经模块机制取用。

**否决**：后端要读自己那个配置命名空间、要依据配置表态、自带凭据表的还要声明迁移，这些时机都因它是模块才存在。绕开模块机制交进来的实例没有这些时机，宿主要为它用的每个后端自行重写一遍这些事。入口这一侧同样不成立：登记面出自入口模块的实例，宿主取得它的途径也只有模块机制。

### 不声明构造期依赖，入口与校验后端都在 Init 取

网关的 `Requires` 为空，`Init` 阶段按功能取用登记面、整体取出全部到场的校验后端，取不到即启动失败。

**采纳**，见决策。

## 决策

采纳：认证网关不声明任何构造期依赖，路由登记面与校验后端都在 `Init` 阶段取得。

- 网关的 `New` 里登记面与校验后端都用不上，因此没有需要排的次序，`Requires` 的定序作用在这里落不到实处。配置读取面是预置产物，取用它本来就不需要声明（[ADR-assembly-bootstrap-2026-09-20](adr-assembly-bootstrap-2026-09-20.md)）。
- 参与集因此只含宿主在命令树上运行级纳入的模块及其自身的依赖闭包。这条命令下有哪些校验后端、认证挂在哪个 HTTP 入口上，是宿主写下的选择，不是 import 图的结果。
- **取不到登记面、取出的校验后端为空，都由认证自己的启动期哨兵拦下，都在 `Init` 中判定，都是启动失败，都不降级为放行。** 取不到登记面时错误文本点明纳入了认证却没有纳入任何 HTTP 入口；校验后端为空时点明一个校验后端都没有纳入。

## 后果

宿主在命令树上运行级纳入哪些校验后端，就只有那些后端进入参与集、有资格表态、出现在帮助输出与必填判定里。被 import 而未被列举的后端不参与这次运行。

纳入认证不会连带纳入一个 HTTP 入口，推进到 `Serve` 的命令不会因此绑定宿主没有列举过的监听端。

网关与入口模块、与校验后端的关系不出现在描述符里，只能从 `Init` 的代码中读出。这与环上的引用改在 `Init` 动态取得所付出的代价同类（[ADR-lifecycle-stages-2026-09-13](adr-lifecycle-stages-2026-09-13.md)）。

**接受的代价：**

- **失败点被推到 `Migrate` 之后，而迁移不可回滚。** 声明依赖时这些缺失在任何实例构造之前就报出；改在 `Init` 判定，发作时 `New` 与 `Migrate` 都已执行完毕，`Migrate` 施加的数据变更无法回滚。一条漏列入口或漏列后端的服务命令，会先把库结构改掉再失败。
- 漏列一个校验后端而另有后端在场时，没有任何失败信号。哨兵只在后端全空时触发，"少了一个"与"本来就只有这些"区分不开。该后端权威认领的主体（[ADR-authn-ownership-2026-09-20](adr-authn-ownership-2026-09-20.md)）在这次运行中无人认领，表现为这些主体一律被拒。
- 这种漏列在模块机制那一侧不主动告知：未被本次命令纳入的模块不进启动诊断，架构文档已写明这一点，理由是诊断要写的原因——消解落选——在一个连表态都没有的模块身上无从写起；而启用结果查询要主动去问才答，它对这种模块给出禁用并写明原因是不在参与集里，注册表不会自己说。"宿主 import 了某个校验后端却没有在命令树上列举它"因而只有认证自己的判空能主动抓到，而判空说得出"一个都没有"，说不出"少了哪一个"。
- 收益取决于宿主逐一列举。一条纳入全部可用模块的命令，或在根命令上纳入后端——根命令纳入的模块对每条子命令都有效——都让参与集重新成为 import 图的函数，这道闸自行让开。

## 失效条件

若参与集的展开规则改为不按 `Requires` 所声明功能的提供者展开——例如按启用结果展开，或让依赖声明可以指向具体模块——架空显式列举这条否决理由不再成立，届时声明依赖可以在不牺牲宿主选择的前提下，把这些缺失重新提前到任何实例构造之前。

**该条件已触发。** 依赖闭包为一个必需功能展开时，排他交付的提供者不再自动纳入，展开规则因此不再对全部提供者一视同仁（[ADR-dependency-resolution-2026-09-13](adr-dependency-resolution-2026-09-13.md)）。本记录中据此修订的是「考虑过的选项」里否决「入口与校验后端都写进 Requires」的理由：入口这一半不再成立——入口排他交付，闭包不为它自动纳入提供者；否决由后端这一半承担——后端非排他，闭包照常展开，宿主在命令树上的列举仍会失效。决策与后果不受影响：网关仍不声明构造期依赖，入口与校验后端都在 `Init` 取。
