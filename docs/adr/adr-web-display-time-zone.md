# 全部界面按同一显示时区渲染时间：账户设定优先，其次浏览器时区，环境给不出才用 UTC

## 背景

同一个时刻在管理后台与账户页读作同一个小时，操作者在两者之间对照记录不需要换算。账户的时区偏好存于账户属性集（[ADR-i18n-preferences-storage](adr-i18n-preferences-storage.md)），随账户到达每一台设备（REQ-account-033）。

需求要求全部页面的时间按显示时区呈现，包括管理后台（REQ-presentation-009）。约束有三条：账户没有存过时区时界面仍要能渲染；运行环境可能给不出浏览器时区；接口里的时间格式、导出文件名与导出内容、邮件与短信属于传输格式，不在界面显示的范围内。

## 考虑过的选项

### 保持固定 UTC

界面时间一律按 UTC 呈现，管理后台与账户页一致。

**否决**：固定 UTC 要求每个读者自行换算，已存的时区偏好对显示无效，而界面本可据它直接呈现。

### 只按浏览器时区

所有页面读取运行环境的时区，不读账户偏好。

**否决**：账户偏好换设备会失效，同一账户在不同设备上看到不同的时刻；已存的偏好成为无人使用的数据。

### 各组件包各自决定时区与兜底

每个组件包自行选择时区来源，命中无效值时各自回退。

**否决**：解析链的层级与顺序会在各包之间漂移，同一时刻在不同页面可能落在不同时区；某个包漏掉回退就会显示错误时区或隐藏整行时间。

### 账户设定优先，其次浏览器时区，环境给不出才用 UTC，由一个入口解析

**采纳**，见决策。

## 决策

采纳：全部界面的时间按显示时区渲染。显示时区由一条三级链解析：宿主交来的账户存值（空或全空白视为未选）、浏览器时区、`UTC`；每一级都经 Intl 校验，拒绝的值按空值跳过，第一个被接受的值胜出。冒充期间宿主交来的是被冒充账户的存值：横幅本身呈现被冒充者的视角，横幅与其余页面因此同按被冒充账户的时区渲染。

界面渲染时间只经一个已解析的显示时区入口，组件包不自带格式化器，也不固定时区。解析链只在一处实现。

## 后果

- 同一时刻在全站读作同一显示时区的值，管理后台与账户页对同一时刻的读数一致，操作者在两者之间对照记录不需要人工换算。
- 账户未设偏好时按浏览器时区呈现，换设备会看到该设备的时区；写偏好之前这是唯一的设备相关行为。
- 浏览器时区也取不到时以 UTC 收尾，界面仍渲染，不退化为隐藏时间行。
- `@speed/ui-kit` 公开显示时区的解析与格式化入口，组件包经它渲染；这是可交付包公开接口的新增。
- 每个组件包的时间渲染只经统一入口。web 包的非测试源码不得自带时区格式化器，也不得固定时区字面量，由源码守卫拒绝；审计导出文件名这类传输格式用 `toISOString` 生成，不经时区格式选项，也不调用被守卫拦截的接口，因此不属于守卫的拦截对象，无需豁免项。
- 审计页的起止时间按显示时区解释，筛选边界因此随显示时区改变。
- 站内信正文与标题里的时间由前端按查看者的显示时区渲染：服务端写标记，客户端用消息参数解析（[ADR-notification-inbox-time-render](adr-notification-inbox-time-render.md)）。
- 邮件、短信、接口时间格式、导出内容与导出文件名不随之改变，是这条规则的例外：它们不经过界面渲染。邮件仍在服务端按收件人存下的时区定格，短信参数按 UTC 秒级字符串化。
- 显示时区与主题、语言各有自己的 provider 与解析链，取值互不依赖；宿主按外壳层级挂载它们，挂载顺序不改变各自的取值。

## 失效条件

- 需要同一页面同时呈现多个时区，或读者要选择与账户偏好不同的临时时区：单一显示时区上下文不再够用。
- 没有浏览器的消费者要读站内信正文：时间以标记存放，只有界面能解析它，这类消费者需要另行决定自己的解析方式。
- 账户偏好要在没有浏览器的宿主里生效：三级链中的浏览器时区一级不存在，链要重新定义。
