# 请求的语言按 context、账户偏好、默认三级解析，两层中间件分居观测与鉴别阶段

## 背景

一次请求的语言按优先级取来源：请求自己声明的语言偏好最高，账户保存的偏好次之，都没有时用默认语言。

请求头的协商不需要身份，账户偏好需要已鉴别的身份。链的分阶段定位把这两件事分到不同的阶段：观测阶段在最外，看到每一个请求但不写响应，鉴别阶段确定调用者是谁，其内的拒绝是 401、404、503；认证网关落在鉴别阶段内（[ADR-http-stages](adr-http-stages.md)）。

鉴别之前的拒绝——认证网关的 401、方法不允许的 405、无匹配路由的 404——也要带语言，否则客户端在最早的一类失败上拿不到本地化文本。

既有的登录引擎有一个把 `Accept-Language` 映射到短信闭集的函数。它只看头部里第一个非空标签的主子标签：命中 `en` 或 `zh` 即返回，遇到不认识的主子标签返回空，完全忽略 `q` 值。`fr, en;q=0.9` 这类头部因此得到空而不是 `en`，`en;q=0.1, zh;q=0.9` 得到 `en` 而不是偏好更高的 `zh`。

## 考虑过的选项

### 一层中间件同时做协商与读账户偏好

一个 `StageIdentify` 内的层，先协商请求头，再在身份就绪后读账户偏好。

**否决**：读账户偏好必须在鉴别之后，一层之内两头兼顾就把协商也拖到鉴别之后，鉴别之前的 401、405、404 便没有语言，而这正是要靠最外层解决的窗口。

### 不给中间件，各使用方自己解析

不提供层，每个写出用户可见文本的地方自己读头、读偏好、回退。

**否决**：协商规则与三级回退会在每处重写，且互不知道对方怎么写，「默认」散落多处；一处改了另一处不跟。

### 沿用既有只看第一个标签的映射

`Accept-Language` 到语言仍按第一个非空标签的主子标签判定。

**否决**：它忽略 `q` 值，对 `fr, en;q=0.9` 与 `en;q=0.1, zh;q=0.9` 给出与客户端偏好相反或为空的结论；这与「按客户端声明的偏好挑选最合适的受支持语言」相悖，且它把「取不到」读成空值而非一次协商结果。

### 三级解析链，两层中间件分居观测与鉴别阶段

**采纳**，见决策。

## 决策

采纳解析链 `context → 账户 profile → 配置的默认语言`，由两层中间件落位。

`i18n:accept-language` 落在观测阶段、取 `Order: -100`，位于观测采集层之内、把 `Order` 留在零值的各层之外，对每一个请求生效，只读 `Accept-Language` 并按 `q` 值协商出受支持语言中最合适的一个，写进请求的 context；它不依赖身份，鉴别阶段的拒绝也经它带上语言。取不到受支持语言时它不写值。

`i18n:profile-locale` 落在鉴别阶段之内、认证网关之后，在 context 尚无语言时读账户保存的偏好并写进 context。

解析的优先序是 context 已有的值、账户 profile、配置的默认语言。协商按 `Accept-Language` 的 `q` 值在受支持语言集合（各模块声明的目录与配置指定的覆盖目录所覆盖的语言，见 [ADR-i18n-catalogs](adr-i18n-catalogs.md)）中挑选，而不是只看第一个标签。既有的只看第一个标签的映射被它取代。

## 后果

鉴别之前的拒绝与鉴别之后的响应共用同一套语言解析，客户端在最早的一类失败上也能拿到本地化文本。这一条由产生拒绝的模块渲染它自己的文本来满足：入口模块 `pkg/http` 自己写出的无匹配路由 404、方法不允许 405、请求体超限 413 与兜底 500，从它自己声明的目录取文本，读的正是 `i18n:accept-language` 写进上下文的那一层语言，因而在这些拒绝上也有语言（[ADR-i18n-error-rendering](adr-i18n-error-rendering.md)）。一个只发机器字段、不带文本的拒绝（例如认证网关的 401）不承载语言，按状态码回退到 `net/http` 的标准状态文本。

账户偏好只对已鉴别的请求生效，匿名请求走协商与默认。

**接受的代价：**

- 两层之间有一段窗口：鉴别阶段的拒绝发生时，账户偏好还未读取，语言只到协商结果一层。这一段不影响正确性（账户偏好本就要求身份），但排错时要意识到语言来自两级中的哪一级。
- 协商与偏好分居两处，一处改动不会提示另一处；两处都写 context 时以后写者为准与否取决于实现，需要读实现才能确定。
- 既有只看第一个标签的映射被替换，行为随之变化：以前被读成空的头部现在能得到一种受支持的语言。
- 常用宿主里，读账户偏好的那一层（`i18n:profile-locale`）依赖认证模块交付的账户偏好实现（[ADR-i18n-preferences-storage](adr-i18n-preferences-storage.md)）；该实现缺席时它不写值，账户偏好这一级不存在，而这不产生失败信号。

## 失效条件

若语言的事实来源移到本进程之前——例如网关已完成协商并把结果放进一个请求头——则协商不再由本层独占，本记录要改为读那个头而不自己协商。

若出现必须在鉴别之前就读到账户偏好的场景（不存在的身份），则两层的划分不成立，需要另找承载。
