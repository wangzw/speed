# 前端一次构建产出两件制品

## 背景

部署的拓扑是合一与分离（[ADR-web-static-hosting](adr-web-static-hosting.md)）：合一拓扑里前端产物内嵌进 Go 二进制，一个二进制搬迁即可运行；分离拓扑里前端另由静态主机（CDN、反向代理）托管，后端只做 API。

合一拓扑要求二进制内嵌 `server/dist`，而 `server/dist` 是构建输出、不进版本库。Go 的 `go:embed` 要求被内嵌的文件在编译它之前已经存在。

若合一与分离各自构建一次前端，就是两份可能漂移的产物：一个部署跑了某次构建的前端，另一个跑了另一次。

## 考虑过的选项

### 合一与分离各构建一次前端

**否决**：两份产物会漂移——两个部署跑着不同次构建的前端；且只想要其中一条拓扑时也付出另一份构建。

### 只产出前端静态包，合一拓扑也从不内嵌

合一拓扑改为从磁盘读产物，不内嵌。

**否决**：合一拓扑的意义是单产物部署——一个二进制搬迁即可；从磁盘读要求部署时另带一份前端目录与一条路径配置，丢掉这一收益。参考应用正是从磁盘读的一条实现，那是一条拓扑的选择，不是全部。

### 一次构建产出两件，合一与分离拓扑共用同一份 server/dist

**采纳**，见决策。

## 决策

采纳：**前端一次构建产出一份 `server/dist`，它既被内嵌进 Go 二进制，也作为静态包交付；合一与分离两条拓扑共用这份产物；构建顺序固定为先前端后 Go。**

- 合一拓扑：Go 构建把 `server/dist` 内嵌进二进制。
- 分离拓扑：同一份 `server/dist` 交静态主机。
- 顺序是硬约束：`go:embed` 要求产物在编译 Go 之前存在。

## 后果

两条拓扑共用一份产物，不会漂移；只想要一条拓扑也只需一次前端构建。构建与部署的形态落在一处。

**接受的代价：**

- **构建顺序固定为先前端后 Go。** 改一次前端要重编一次 Go；一次单独的 Go 构建——前端产物尚未生成时——在内嵌拓扑下以缺文件失败，而不是产出一份只做 API 的二进制。
- **前端产物成为 Go 构建的输入。** CI 与发布流水线要保证前端腿在前；缺一条腿的构建会失败，一处失败同时挡下两条拓扑的制品。
- **内嵌把产物大小加进二进制。** 一份较大的前端产物让二进制随之变大。

## 失效条件

- 若合一拓扑被弃用——部署一律分离——内嵌与顺序约束随之消失，本决策退回「只产出前端静态包」。
- 若前端构建时长相对 Go 构建增长到每次合一发布都为一次前端重建付出不成比例的等待，应重新评估是否按拓扑拆分构建，那要同时接受两份产物漂移的风险。
