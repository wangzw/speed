# 订阅事件总线取领域事实，类型名由配置点名且只转成短跨度

## 状态

已接受

## 背景

横切能力取得领域事实的通路只有事件总线，可观测性与审计并列为它的消费方。这条通路成立的前提是横切能力不必耦合每一个产生事实的业务模块：发布方按类型名发布，订阅方按类型名订阅，发布方与订阅方之间没有静态类型的共享（[ADR-event-scope-2026-09-21](adr-event-scope-2026-09-21.md)）。

总线的投递承诺是各实现都能满足的下界：`Publish` 返回成功只表示事件已被总线接受，不表示任何订阅者收到；总线不承诺投递次数与顺序，「某条事件丢了」不可判定（[ADR-event-delivery-2026-09-21](adr-event-delivery-2026-09-21.md)）。

`pkg/event` 的 `Event` 字段是 `Type`、`TenantID` 与 `Payload`，没有时间戳；`Bus.Subscribe` 的匹配是精确字符串比较，无通配与前缀。

覆盖面的形态在审计上已经立定：事件类型名由配置逐项点名、默认空，点名了而对应功能的模块取不到即启动失败（[ADR-audit-reach-2026-09-21](adr-audit-reach-2026-09-21.md)）。

## 考虑过的选项

### 不订阅，域事实由各模块自己的仪表与请求级跨度承载

每个业务模块自己产出它关心的指标与跨度，本模块只交付 provider 与请求路径的采集。

**否决**：租户维度只有经总线才拿得到——租户标识由事件携带，请求级采集不带它，而按租户切分正是 [ADR-event-scope-2026-09-21](adr-event-scope-2026-09-21.md) 为可观测性写下的用途。把这件事推回各业务模块，等于要求每个模块都认识可观测性，与总线存在的理由相悖。

### 订阅全部事件，不做点名

本模块向总线订阅每一类事件，覆盖面不必写进配置。

**否决**：事件类型名与发布方之间没有编译期联系，总线也不提供类型名的注册面，全订会把不受控的类型基数直接带进信号。点名的形态与审计的捕获面同源（[ADR-audit-reach-2026-09-21](adr-audit-reach-2026-09-21.md)），覆盖面对宿主是一份可读的清单。

### 把事件转成计数

订阅回调把每个事件累加进一个计数器。

**否决**：计数的目录与命名归产生该信号的模块。本模块替业务模块决定指标的形态与名字，会让名字的稳定性承诺落在一个不认识那些语义的模块上：事件只是字段名与不透明载荷，本模块读不出一个名字该是什么。

### 订阅点名的类型，回调把事件转成短跨度

**采纳** — 见决策。

## 决策

采纳：**配置点名的每一个事件类型，装配器在 `Init` 向总线订阅一次，回调把事件转成一个短跨度；不把事件转成计数。**

## 后果

观测面来自配置点名的类型，宿主不必改动产生事实的业务模块。

**接受的代价：**

- **事实来源是下界承诺，观测面看起来完整而可能缺样。** 一条事件在投递中丢失时本模块收不到，也报不出来；缺样不可判定，点名的类型越多，这个面越大。撞上它的是把该观测面当作事实全集的宿主。
- **事件不带时间戳，派生的跨度只落在消费时刻。** 它与本模块在请求路径上起的服务端跨度、与产生该事实的业务跨度都不对齐；需要按发生时间排序的宿主从短跨度上读不到。撞上它的是把事件派生跨度与业务跨度拼成一条链的宿主。
- **类型名写错时订阅静默不中。** 名与发布方之间没有编译期联系，匹配是精确字符串比较，本模块不做启动期校验；写入一个不存在的类型名，与发布方改名，表现相同——不报错，也不进诊断。撞上它的是维护点名清单的配置作者。
