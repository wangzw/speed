# 应用内导航与认证翻转后焦点交给新页面的一级标题，首屏不移

## 背景

应用内导航使旧页面卸载，旧页面持有的焦点随之丢失，浏览器按焦点修正规则把焦点放到文档正文（[REF-whatwg-html](../references.md)）。认证状态翻转同样整页替换内容，而翻转不改 URL，任何按 URL 判断换页的机制都看不到它。两种情形之后，键盘使用者要从页首重新按 Tab，读屏使用者要重新找起。写入落定后发起控件卸载时的焦点去向由 [ADR-web-write-feedback](adr-web-write-feedback.md) 规定，那管的是同一页内的控件替换；本记录管整页切换后的焦点。

页面的一级标题在本项目中来源分散：ui-kit 的 `PageHeader` 与 `PageLayout`、auth-ui 的各屏、layout-kit 的 `RouteGuard` 缺省拒绝态、org-create-ui、admin-ui 与 demo 的若干页面各自渲染标题。应用的 `document.title` 只按语言设一个固定的应用名，不随页面变化。route-kit 的包规则禁止 import 同族包，也不渲染任何文字，因此落点不能依赖一个页面标题组件，也不能由本包播报页面名。

## 考虑过的选项

### 焦点交给新页面的 `main` 地标

焦点移到 `main`，读屏立即报出“主要内容”地标，键盘使用者从地标内的第一个控件开始。

**否决**：读屏只报地标，部分读屏还会把地标内容从头读起；键盘起点停在地标而不是页面标题，落点不精确。

### 焦点交给路由或分支的外层容器

焦点移到包住整个页面的容器上，任何页面结构都无需改动。

**否决**：容器没有名字，读屏要么什么都不报，要么把整块内容读一遍；键盘使用者仍要穿过容器开头的 chrome，与修复前的问题相同。

### 路由播报区播报页面名，焦点重置到文档正文

换页后由实时区域播报新页面的名字，焦点回到正文由使用者自己重新开始。

**否决**：播报区要播报的是页面名，而本项目的 `document.title` 不随页面变化，它只能读出同一个应用名；改为播报一级标题时，读屏从播报里听到一遍，焦点却被重置到文档正文，使用者要再从页首经过 chrome 读到同一标题。它也不解决键盘起点：焦点回到正文，键盘使用者仍要从页首重新按 Tab。

### 每个页面组件各自聚焦自己的标题

每屏在挂载时把自己的标题设为焦点。

**否决**：标题来源分散在多个包与页面，每个页面都要记得接线，新增页面默认遗漏，落点覆盖不全。

### 落点由宿主经回调接线，route-kit 缺省不做

route-kit 只提供钩子，宿主在每次导航后自己调用落点。

**否决**：每个宿主都要记得接线，漏接时行为退回本决策要修的那一态；缺省即缺陷。

### 一级标题，回落 `main`，route-kit 缺省开启，认证翻转同规则，首屏不移

应用内导航换了页面后，焦点交给新页面 `main` 地标里的第一个一级标题，没有标题时交给该 `main`；首屏与加载期的替换跳转不移，新页面已把焦点放进自己的 `main` 或模态对话框持有焦点时不移。route-kit 的 `RouteProvider` 缺省执行这条落点，认证翻转用同一条规则。

**采纳**，见决策。

## 决策

采纳：应用内导航或认证翻转换了页面之后，焦点交给新页面 `main` 地标里的第一个一级标题，没有标题时交给该 `main`；首屏与加载期的替换跳转不移，新页面已把焦点放进自己的 `main` 或模态对话框持有焦点时不移。`RouteProvider` 缺省执行这条规则，`navigationFocus: 'none'` 关闭；product-shell 的认证翻转用同一条规则。

## 后果

**接受的代价：**

- 同一规则有两份实现。route-kit 不能 import 同族包，`navigation-focus.tsx` 与 ui-kit 的 `focusPageLanding` 各自实现，改动一处必须同时审视另一处。
- 落点时刻只渲染了等待态的新页面没有一级标题，焦点落在 `main`；标题稍后出现时不再上移。
- 一级标题本身不可聚焦，落点要落在它上面，必须临时加 `tabindex="-1"`；该属性在目标第一次失焦时移除，落点完成后标题不会继续是 Tab 序列的一站，鼠标点击也不会落在它上面。
- `RouteProvider` 的缺省行为改变。既有宿主不传 `navigationFocus` 也会在导航后落点；不需要的宿主传 `'none'`。
- 只有路径变化算换页。查询串或 hash 变化不移动焦点。

## 失效条件

- `document.title` 改为随页面变化时，重新评估用播报区代替移焦。
- 路由层换成带滚动恢复的数据路由器时，后退与前进的落点改为不滚动。
