# 默认语言由 zh-CN 改为 en-US，i18n 与 authn 取同一个默认

## 状态

已接受

## 背景

认证模块已有一个语言默认：`LocaleOf` 把一个不含语言的值读作 `zh-CN`，`zh-CN` 与 `en-US` 是短信模板的封闭集。本能力目录引入后要有唯一的默认语言，它是协商取不到、账户偏好也没有时的兜底（[ADR-i18n-locale-resolution-2026-10-13](adr-i18n-locale-resolution-2026-10-13.md)）。

登录引擎把协商结果映射进短信的封闭集，再交给发送路径；未协商到时用哪个语言，就是这里的默认。因此默认语言不只决定错误文本，也决定未声明语言时短信发的是哪种模板。

## 考虑过的选项

### 改默认，`i18n` 与 `authn` 取同一个值

`i18n.Default` 是 `en-US`，`authn.LocaleOf` 把空值也读作 `en-US`。

**采纳**，见决策。

### 两套默认并存

`i18n` 用 `en-US`，`authn` 仍以 `zh-CN` 为默认。

**否决**：同一个请求在错误响应与短信两处得到不同语言，除非每一处都显式传语言；两个默认的边界不在任何一处显现，改动其一会让两处悄悄分叉。

### `i18n` 缺席时保留 `zh-CN` 兜底

装配了本能力目录用 `en-US`，没有它时认证模块退回 `zh-CN`。

**否决**：默认随装配是否存在而变化，同一份请求在两个装配里得到不同语言；一份二进制在有无本能力目录时有不同行为，而这一差异不产生任何信号。

## 决策

采纳：默认语言改为 `en-US`。`i18n.Default` 是 `LocaleEN`；认证模块的 `LocaleOf` 把一个不含语言的值读作 `LocaleEN`，`LocaleZH` 仍是短信封闭集的成员，但不再是默认。

登录引擎优先取本能力目录协商后的 locale，再把它映射进短信的封闭集（`zh-CN`、`en-US`）；协商取不到时用 `en-US`。

## 后果

未协商、无账户偏好的请求，其错误文本与通知类文本是英文；登录短信在未协商到语言时按 `en-US` 模板。

错误响应与短信的默认是同一个值，改它只有一处。

**接受的代价：**

- 短信的默认模板语言随之变为英文。这是有意接受的产品后果：面向中文用户的部署必须让厂商侧提供 `en-US` 模板，否则构造期对（用途，语言）覆盖的核对会失败。以前默认发中文短信的部署在升级后默认发英文，除非请求协商到 `zh-CN` 或账户偏好是 `zh-CN`。
- 认证模块的行为发生可见变化：一个以前被读作 `zh-CN` 的空语言，现在读作 `en-US`。以空语言调用短信发送、期望中文模板的调用方需显式传 `zh-CN`。
- 默认语言的改动会连带改变任何依赖默认的错误文本与通知文本，影响面不止一处。

## 失效条件

若产品的目标用户以中文为主且明确要求中文为默认，则 `en-US` 为默认不再符合产品定位，需要重定，或另立一个由配置给出的默认；由配置给出的默认会把默认从编译期常量变成配置项，是另一条决策。
