# 状态按丢失的方向放置：丢失会放宽校验的进 db，丢失只会让流程失败的进 kv

## 背景

`pkg/authn` 在逐请求校验之外持有登录、会话、令牌、多因素、企业 SSO 与冒充的状态。每一份状态都有三处可放：`pkg/db`、`pkg/kv`、进程内存。放置不影响接口形状，影响的是这份状态丢失、过期或被并发改写时认证的结果朝哪个方向偏。

**kv 的既有性质**（[ADR-kv-scope](adr-kv-scope.md)、`design-kv` 的部署前提一节）：

- 接口面是读、写、删、原子自增、带过期时间的原子自增、比较并交换、带过期时间的不存在则写入。没有键枚举与前缀扫描，没有「取并删」，比较并交换不交出失败原因。
- 过期时间只能由 `Set` 改写。`Set` 续期与并发的 `Delete` 之间没有原子性，续期的写可以把刚删除的键写回来。
- 持久性按实现各自声明：内存实现重启即丢；Memcached 在重启与淘汰时无声丢弃；Redis 与 NATS 是否持久取决于服务器配置，模块不检查。没有一项对所有实现统一的「需要持久」声明。
- kv 与 db 是两个存储，其间没有共同事务。

**认证状态的两种丢失。**

- 撤销标记、失败退避计数、验证码尝试计数、断言标识去重集一旦丢失，校验放宽：被撤销的会话复活，暴力破解的次数上限归零，已用过的断言在有效期内可重放。这些状态的存活期长短与丢失的后果无关。
- OAuth 的 `state`、PKCE 校验串、`nonce`、SAML 的请求标识、WebAuthn 的仪式数据这类登录流程记录，丢失之后回跳找不到记录，流程失败，用户重新开始。

**需求。** 管理面要能按账户列出登录会话并批量撤销（踢下线）；刷新令牌的轮换要原子；账户停用与撤销之间不能留下可用的会话。

## 考虑过的选项

### 登录会话放 kv

会话记录与撤销标记存在 kv，键为会话标识，`Set` 续期空闲期限。按账户批量撤销改用每个账户一个撤销纪元键，校验时读它与会话比较。

**否决**：

- kv 没有键枚举，「列出一个账户的会话」无从实现；撤销纪元键能批量撤销整个账户，不能列出，也不能只撤销其中一个会话。
- 撤销必须可靠，而 kv 的内存与 Memcached 实现会无声丢键，Redis 与 NATS 的持久性不被检查。丢失的方向是撤销失效、会话复活，纪元键丢失则整个账户的撤销一并失效。
- 续期用的 `Set` 与并发撤销用的 `Delete` 之间没有原子性，续期可以把刚撤销的会话写回。
- 没有「取并删」，会话令牌与刷新令牌的轮换做不到原子。
- 账户停用、成员变更与撤销写入落在两个存储，没有共同事务。
- 要让这条路成立，kv 必须不淘汰键、不丢键；这个前提一旦成立，退避计数、验证码尝试计数与断言去重集也只能放在 kv，全部认证的安全属性都押在部署配置上。

### 在 kv 上叠账户到会话的二级索引

会话记录放 kv，再维护一个「账户到会话标识集合」的索引键，靠比较并交换循环增删，补上枚举与批量撤销。

**否决**：

- 比较并交换不交出失败原因，败者分不清「值已被改」与「键不存在」，循环无法安全地决定重试还是放弃。
- 索引键与会话键是两个键，两次写之间没有原子性；中断留下指向不存在会话的索引项，或存在而不在索引里的会话，后者在批量撤销时被漏掉。
- 索引键本身会丢，丢失的结果是「列不全、撤不全」，方向仍是放宽。
- 续期与撤销的竞争、轮换的非原子、跨存储无事务这几处缺口一处也没有补上，补上的只是枚举。

### 先让 kv 增加持久性声明与枚举

扩展 kv 的接口与各实现：加一个对所有实现统一的「需要持久」声明项，不满足即启动失败；加键枚举或前缀扫描；会话随后放 kv。

**否决**：

- 键枚举要求后端提供可扫描的有序结构，与 kv「接口按最弱后端设计」的纪律冲突（[ADR-kv-scope](adr-kv-scope.md)）；对 Memcached 这类后端只能声明不支持。
- 统一的持久性声明要求每个实现回答自己是否持久，Redis 与 NATS 的回答取决于模块不检查的服务器配置，声明只能是部署方的自述。
- 改动面落在 kv 的全部实现与一致性套件上，由一次认证设计推动，而 kv 的消费方并不只有认证。
- 即便补齐，续期与撤销的原子性、取并删仍是缺口。

### 按状态的存活时长放置

存活期短的状态（验证码、退避计数、断言去重集、登录流程记录）放 kv，存活期长的（账户、会话、令牌）放 db。

**否决**：存活时长与丢失方向无关。验证码尝试计数与断言标识去重集的存活期以验证码或断言的有效期为界，短于会话，丢失后却放宽校验；这个判据把它们放进了会静默丢失它们的存储。

### 按丢失的方向放置

判据是：这份状态丢了，校验会不会变宽。

**采纳**，见决策。

## 决策

采纳：**状态放置只依据一个判据：这份状态丢失之后，校验会不会比没有它时变宽。**

- 丢失会放宽校验的状态进 db。db 是权威存储，不会无声丢键，撤销、列出与批量操作都能表达。
- 丢失只会让流程失败的状态进 kv，并带有界的有效期。丢键的方向是拒绝，用户重新开始。
- 丢失只让一次计算或一次读取重做的状态进进程内存，只作缓存，不作依据。
- 一份状态若只是权威状态之上追加的一层，丢失之后校验退回权威状态给出的界，则它本身不是校验依据，可以进 kv。按来源地址的粗粒度洪泛计数属此：丢失之后的界仍由 db 里的退避给出。

判据对 authn 状态的应用，下面每个方向只取代表性的例子（例举，非封闭集）；完整的放置表与各项丢失后果在 `design-authn` 的状态放置一节，不在例子里的状态按判据归位：

- **db**：撤销标记所在的登录会话，失败退避计数，验证码尝试计数。
- **kv**：登录流程记录。
- **进程内存**：口令校验缓存。

**登录会话的权威存放在 db（`authn_sessions`），不在 kv。** 刷新令牌与冒充记录挂在会话上，撤销会话即撤销它们；撤销以会话行的撤销标记为准，不比较时间（[ADR-authn-session](adr-authn-session.md)）。

**kv 只承载登录流程记录与洪泛计数。** 流程记录的推进与一次性消费由引擎以比较并交换完成（[ADR-authn-login-flow](adr-authn-login-flow.md)）。

## 后果

会话、退避、验证码与断言去重各在 db 里有表，撤销、按账户列出与批量撤销是 db 上的查询与更新；会话行与账户行同在一个存储，会话校验对账户状态与 `valid_after` 的核对不跨存储。跨模块的清理在此之上仍是非原子的，兜底由账户的 `valid_after` 与账户状态检查承担（[ADR-authn-account-lifecycle](adr-authn-account-lifecycle.md)）。

kv 上没有任何一项状态的丢失会放宽校验。kv 的任一实现都可承载登录流程记录，丢键的结果是流程失败，不要求部署方为认证另配持久化。

只有口令表的部署（网关加 `authn.static`）不需要 db 与 kv：失败退避在进程内，多副本时每个副本各算一份，写进非保证（[ADR-authn-throttling](adr-authn-throttling.md)、[ADR-authn-guarantees](adr-authn-guarantees.md)）。

**接受的代价：**

- 登录会话要求宿主有 db。只有 kv 的部署没有登录会话这条路。
- 缓存未命中时，每个 cookie 请求一次读库；进程内的会话校验缓存摊薄这笔读取，同时让撤销在缓存期限内、在其他副本上延迟生效，延迟的上界由设置给出，列入有界放宽（[ADR-authn-failure](adr-authn-failure.md)）。
- 每次失败尝试与每次验证码校验是一次 db 写入，认证路径上的写入量随失败尝试数线性增长，退避与挑战的高频写落在权威库上。
- 登录引擎要求宿主有 kv。
- 判据只衡量丢失的方向，不衡量成本。db 为安全属性提供的可靠性，以写入量与对宿主存储的硬依赖换来。

## 失效条件

- kv 增加对所有实现统一的持久性声明与键枚举，并补上「取并删」与续期、撤销之间的原子性。此时会话与撤销放 kv 的否决理由消失，登录会话的放置需要按新的 kv 重新检验；其余按判据放在 db 的状态不因此移动，除非逐项重新判定方向。
- 登录流程记录里存在一个字段，其丢失使某一步成功而没有它时会被拒绝。此时承载该字段的状态不满足「丢失只让流程失败」，要移入 db。守住这条假设的测试：删除流程记录之后，该流程的每一步（提交、回跳、完成）一律被拒绝，且不产生登录会话与令牌。
- 会话校验缓存摊薄之后，cookie 请求的库读仍占请求路径延迟的主要部分。此时需要重新权衡缓存期限与撤销延迟的取值，放置本身仍以丢失方向为准。
