# 本模块的句柄装上自己的 GORM logger，写出的内容里不带语句的值

## 状态

已接受

## 背景

本模块打开的每个句柄都携带一个 GORM logger，交付的与 `Open` 自建的都是。GORM 的默认 logger 在一条语句失败、或慢于 200 毫秒时，经标准库 `log` 往标准输出写一行：语句的文本，绑定值按方言的引号规则填进占位符，失败时再加上语句的错误文本。一次被拒的插入因此把口令哈希、邮箱、联系人姓名这类值原样写到标准输出；`First` 查不到行也按失败写出，连同查找用的值；`Debug` 派生的会话写出每一条语句连同它的值。

错误文本同样可能带着值。PostgreSQL 拒绝一个格式不对的输入时，把输入写进消息：`invalid input syntax for type integer: "…"`。database/sql 扫描不了读出的一个值时，把那个值写进消息：`converting driver.Value type string ("…") to a int`。

句柄上的 logger 由每个模块的语句共用。宿主可以在自己发出的语句上以 `Session(&gorm.Session{Logger: …})` 换掉它；别的模块在同一个句柄上发出的语句——名册、设置、审计写的行——不经宿主，照样写出它们的值。交付之后改句柄上的 `Logger` 会与在途的语句竞争，本模块不支持。

GORM 给 logger 留了两个接缝：`ParamsFilter` 在它把值填进文本之前问 logger 要哪些值，`Trace` 拿到填好的文本与语句的错误。GORM 的 logger 报出的调用点是调用栈上第一个不在 GORM 源码里的帧。

GORM 的终结方法 `DB.Scan` 是个例外。它在语句执行期间把句柄的 logger 换成 GORM 的记录器，记录器对 `ParamsFilter` 把值全数交回，方言于是把值填进文本，`Scan` 在语句执行完之后才把这段文本经 `Trace` 交给句柄原来的 logger：句柄上的 logger 在这条路上不被问到有哪些值要交，文本到手时值已在里面。

## 考虑过的选项

### 维持 GORM 的默认 logger，写明它把值写到标准输出

**否决**：凭据与个人数据随每一次失败的写入落到标准输出，别的模块发出的语句宿主管不到；写明代价不给宿主任何避开它的途径。

### 用 GORM 自带 logger 的 `ParameterizedQueries`

语句不带值，其余照默认 logger。

**否决**：错误文本照样写出，PostgreSQL 与 database/sql 消息里的值跟着出去。在它外面包一层替换错误，调用点就报成包装层：包装层是第一个不在 GORM 源码里的帧，每一行都指向本模块的同一个文件。

### 接到日志模块，由它的脱敏遮蔽

**否决**：脱敏按登记的敏感键名与值形状改写（[ADR-log-redaction-2026-09-13](adr-log-redaction-2026-09-13.md)），一条填了值的语句是一整段文本，里面的邮箱、姓名不在任何键下，也不是哪一种登记过的形状；值要遮得住，就不能先填进文本。这条路还要给本模块加一条对日志模块的依赖，每个带数据库的装配都要带上日志模块。

### 什么都不写

**否决**：失败与慢的语句在调用方之外不再留下痕迹，慢语句那一行是宿主看得到一条语句慢的唯一途径。

### 把 logger 作为一项配置交出去

**否决**：默认值仍须不写值，旋钮只会多出一条把值写出去的路，要去掉的正是这条路。

### 一次性设置 GORM 的包级变量 `logger.RecorderParamsFilter`

GORM 的记录器问包级变量 `logger.RecorderParamsFilter` 里的函数要值，默认的函数把值原样交回；本模块打开句柄时把它换成不交回值的函数，`Scan` 的文本里便没有值，本模块的 logger 不必认出 `Scan`。

**否决**：包级变量对进程里的每个 GORM 句柄生效，宿主自己的句柄也在内，它们的 `Scan` 日志从此不再带值；宿主也设置同一个变量时，后设置的覆盖先设置的，本模块的保证无声地失效。

### 维持 `Scan` 这条路的现状，把缺口写明

本模块的 logger 只处理 `ParamsFilter` 问到的语句，`DB.Scan` 执行的语句连值写出，缺口写在后果里。

**否决**：本记录要给的保证在一条常用的路上不成立：`pkg/settings` 与 `pkg/tenant/catalog` 的语句就经 `Scan` 发出。

### 本模块装上自己的 logger：何时写、写到哪里照 GORM 的默认 logger，文本不带值，错误只写类别

**采纳**，见决策。

## 决策

采纳：本模块打开的每个句柄装上本模块自己的 GORM logger。它在 GORM 的默认 logger 写的时候写、写到同一个地方：失败的语句，慢于 200 毫秒的语句，`LogMode(logger.Info)` 下——`Debug` 即是——的每一条语句，经标准库 `log` 写标准输出。它对 `ParamsFilter` 不交回任何值，语句照 GORM 为日志渲染的文本写出，占位符不填；GORM 的终结方法 `DB.Scan` 执行的语句除外，它不带文本写出。失败的语句不写错误文本，只写错误带着的、文本固定的类别：GORM 的查不到行与两个约束哨兵，上下文的取消与到期，引擎给这次失败的代码——PostgreSQL 的 SQLSTATE、SQLite 的结果码；一个也不带时只写语句失败。每一行报出发出语句的调用点，与 GORM 的默认 logger 报的相同。

`Trace` 认出调用它的是 `DB.Scan`，这条路上的每一行——失败的、慢的、`Debug` 会话里的——照写错误的类别、耗时、行数与调用点，语句的位置写一段固定的说明：语句因 GORM 在 logger 看到它之前已填入值而不写出。语句没有构造出来时，不写这段说明。认出在 `Trace` 之内完成，不设置 `logger.RecorderParamsFilter` 或 GORM 别的包级变量。只有这个终结方法在此列：`Row` 与 `Rows` 不换 logger，泛型接口 `gorm.G[T]` 的 `Scan` 方法是另一个函数，它们的语句经句柄的 logger 渲染，仍带占位符的文本写出。

## 后果

每个引擎上，本模块的 logger 写出的内容里没有一条语句绑定的或读出的值，接受的代价里写明的转手路径除外。错误原样交给调用方，记不记、怎样脱敏由调用方决定。

**接受的代价：**

- 失败语句的错误文本不在日志里，被违反的约束名、表名也不在；诊断要看调用方拿到的错误，日志里只有类别，例如 `duplicated key not allowed, result code 2067`。
- `DB.Scan` 执行的语句不带文本写出：失败的、慢的与 `Debug` 会话里的那一行只有类别、耗时、行数与调用点，语句要到调用点指的那一行去看。
- 转手的 logger 在保证之外。GORM 的迁移器在 `DryRun` 下为一次迁移装上的 logger（`printSQLLogger`）内嵌 `logger.Interface`，不露出 `ParamsFilter`，再把 `Trace` 转给原来的 logger；宿主以 `Session(&gorm.Session{Logger: …})` 在自己的语句上装的包装，内嵌 `logger.Interface` 而不露出 `ParamsFilter` 的，也是这样。GORM 为这样的 logger 转手的每一条语句——不止 `Scan` 的——都先把值填进文本，本模块的 logger 收到的文本里就有值，`Scan` 之外的语句照写；转手若经包装自己定义的 `Trace`，`Scan` 的语句也认不出，同样连值写出。本仓库的代码不走这些路径。
- 语句文本里本来就有的东西——调用方写进 SQL 的字面量、拼进文本的值、迁移文件的正文——照写，`DB.Scan` 执行的语句除外：它整条不带文本。这些东西不是绑定值，本模块不解析 SQL，分不出文本里哪一段是值。
- GORM 自己的消息——回调的增删、迁移器解析不了的模型——照 GORM 的格式写出，迁移器那一条带着它解析不了的那个模型值。
- 写出的格式与 GORM 的默认 logger 不同：一条一行，不带颜色控制符，PostgreSQL 的占位符照 GORM 的渲染写作 `$1$`。按 GORM 默认格式解析标准输出的宿主要跟着改。
- 日志仍绕过日志模块、写标准输出；`First`、`Take`、`Last` 查不到行仍按失败写出，连同整条语句。
- GORM 对 `logger.Interface` 或 `ParamsFilter` 的不兼容改动直达本模块。

## 失效条件

若 GORM 不再在把值填进文本之前询问 `ParamsFilter`，或把绑定值另经别的途径交给 logger，文本里的值要由本模块另想办法去掉。`DB.Scan` 就是这样一条途径，本模块认它靠的是调用 `Trace` 的函数名：GORM 把 `Scan` 改名或挪到别处，这条路上的语句就连值一起写出，除日志用例外没有哪一处报错；每个引擎上的日志用例经 `Scan` 发出绑定了值的语句，守着这个认出。GORM 让 `Scan` 也经 logger 的 `ParamsFilter` 渲染语句时，这个例外不再需要。
