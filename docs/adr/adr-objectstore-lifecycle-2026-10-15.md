# 对象以声明、上传、完成三步写入，内部键从不经 API 暴露

## 状态

已接受

## 背景

对象的字节可能很大——一段视频、一个数据包——且不落本能力的表，经 `Store` 接缝进出（[ADR-objectstore-packaging-2026-10-15](adr-objectstore-packaging-2026-10-15.md)）。写入路径要回答的是：声明与字节何时进入系统，对象何时算可用，字节落在哪个键上，以及一个迟迟不完成的声明如何收场。

几条事实约束着这条路径：

- **声明要先校验并预留 id 与键。** 对象的 id 与内部键在字节到达之前就要定下，因为键是字节落地的地址。一次校验失败的声明不该已经吃掉一个对象 id。
- **键的语法是实现的自由。** `fs` 后端用文件系统路径，`s3` 后端用对象键，两者的键形式不同；键由元数据面构造并记在对象行上。
- **上传不等于可用。** 字节到达不意味着对象可用：一个已上传但未完成的对象不应被读取。上传窗口给「声明了但字节一直不到」一个出口。
- **调用方按 id 寻址。** 一个对象对内是一个 id、一行元数据与一个内部键，对外只有 id。

## 考虑过的选项

### 一步直传，一次调用同时声明与上传字节

`POST /objects` 在一次请求里带上声明与字节体，同时完成声明与上传，对象随即可用。

**否决**：声明要先校验并预留 id 与键，校验失败时不该已经吃掉一个对象 id。声明与字节在同一次调用里到达，意味着一次因声明不合法而失败的请求可能已经写进了字节、占用了键；把两者分开，校验失败的声明什么都不留。

### 把字节入库

对象字节存进 `objects` 表的一列（BLOB），元数据与字节同表。

**否决**：大对象会把数据库连接与备份拖垮——一次读取要占住一条连接直到字节传完，一次备份要整块搬走所有对象；而接缝本来就允许换成 S3，把字节固定在数据库里使这一换失去意义。

### 把内部键暴露给调用方

`Object.Key` 进 API 应答，调用方按键寻址或自行构造键。

**否决**：键的语法是实现的自由（`fs` 是路径、`s3` 是对象键），暴露即冻结，后端一换键的形态就变；且调用方本不该知道字节落在哪里——按 id 寻址就够，键是内部实现细节。

### 声明、上传、完成三步，键不外露

对象按声明、上传、完成三步写入；字节经 `Store` 接缝以内部键存取，键从不经 API 暴露；上传窗口过期即不可上传，过期清扫按间隔跑。

**采纳**，见决策。

## 决策

采纳：**对象按声明、上传、完成三步写入，字节经 `Store` 接缝以内部键存取，内部键从不经 API 暴露，上传窗口过期即不可上传，过期清扫按间隔跑。**

- **声明。** `POST /objects` 校验声明（尺寸、类型、校验和的形状），预留对象 id 与内部键，落一行 `pending`，写 `upload_expires_at`（声明时刻加 `objectstore.metadata.upload-window`）。
- **上传。** `PUT /objects/:id/content` 把字节经 `Store.Put` 写进内部键，行转 `uploaded`；窗口已过即拒绝上传。
- **完成。** `POST /objects/:id/complete` 把行转 `completed`，此后对象可用于读取；`expires_at`（完成时刻加 `objectstore.metadata.object-ttl`）在这一刻定下。
- **读取与列表按 id。** 读取与列表按对象 id 寻址；`Object.Key` 是内部字段，不出现在任何 API 应答里。
- **过期清扫。** 按 `objectstore.metadata.sweep-interval` 的间隔跑：上传窗口已过仍为 `pending` 的行与 `expires_at` 已过的 `completed` 行，都置 `deleted` 墓碑并删字节——`pending` 行的字节不能假定没有，一次 `Put` 成功而置行失败的上传会让字节暂留在后端。`deleted` 是墓碑，元数据行保留。

## 后果

写入路径把「声明什么」与「交什么字节」分开，校验失败的声明不占用对象 id，字节落在后端自己的键上，可用性由完成这一步显式给出。

**接受的代价：**

- **写一个对象要三次调用。** 声明、上传、完成各一次请求，调用方要在三步之间持有对象 id；两次调用之间对象处于 `pending` 或 `uploaded`，不是可用态。
- **未完成的对象占一行与一个键。** 声明先行，一个从不完成的对象在清扫之前一直占着一行 `pending` 与它预留的键；上传了字节却不完成的对象，字节也留在后端。
- **上传窗口是时限，不是担保。** 窗口一过即不可上传，一个迟到的上传要重新声明，吃一个新的对象 id 与键。清扫按间隔跑，过期行在被清扫到之前一直占着一行与它的字节。
- **键不外露使调用方只能按 id 寻址。** 换一个字节后端时，既有行的 `key` 列记的是旧后端的键；内部键随后端改变，既有对象在新的后端上不必然读得到。键的不可见换来的是实现的自由，代价是键不能当作跨后端的稳定地址。

## 失效条件

- **若多数调用方需要一个「一次调用即得可用对象」的接口**（例如普遍上传小文件、要求低延迟），则三步分离的价值下降，可另加一条直传的快路径。
- **若上传窗口这一约束不成立**（例如上层从不在声明与上传之间中断），则「窗口过期即不可上传」与随之的过期清扫失去意义，可去掉窗口。
