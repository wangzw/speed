# 停用期间仍属于一个租户的工作，经名册的另一个进入方法进入那个租户

## 背景

停用使租户不再被服务且不删除数据（REQ-tenancy-003、REQ-tenancy-004；[ADR-tenant-directory](adr-tenant-directory.md)）。停用在写进标识的那一步生效：请求侧把停用的租户答成 404，名册的 `Enter` 以 `ErrTenantDisabled` 拒绝它（[ADR-tenant-scoping-jobs](adr-tenant-scoping-jobs.md)）；插件不读名册，语句级不另拦（[ADR-tenant-isolation](adr-tenant-isolation.md)）。跨租户是为横跨多个租户的工作保留的途径（[ADR-tenant-scoping](adr-tenant-scoping.md)）。

停用之后仍有只属于那一个租户的工作：查看它的审计轨迹、下线之前导出它的数据、清除它的数据。导出、删除与搬迁本身是应用的领域动作，不由本模块提供（见设计文档的非职责）；本模块要回答的是这类工作以什么形态进入那个租户。在已有的途径下它只剩跨租户一条：过滤、填列与核对在那里一概不生效，一次漏写条件的清除删到每一个租户的行，审计行也记不下这件事是为哪个租户做的：为只属于一个租户的后台工作设 `Enter` 时否决的正是这个形态。

几条事实约束了可选的方案：

- **停用要继续挡住请求侧与 `Enter`**：一个停用的租户不因为多出一条途径而在它们那里重新被服务。
- **进入一个停用的租户要在调用点上认得出来**：它的权力大于 `Enter`，理由与跨租户要在调用点字面写出相同。
- **读租户的各方都读上下文**：审计补全租户列、限流按租户分桶、日志的关联字段，读的都是 `FromContext` 与上下文里的 logger。

## 考虑过的选项

### 维持现状，停用租户上的工作跨租户

不增加任何途径，这类工作整段跨租户，自己在每一条语句上写租户条件与租户列。

**否决**：过滤在那条路径上完全不生效，而清除恰恰是最需要它兜底的工作：漏写一处条件，删到的是每一个租户的行。审计行也不属于任何租户。

### 给 `Enter` 加一个选项

`Enter` 多一个布尔参数或变长选项，允许进入停用的租户。

**否决**：`Enter` 的每一个调用点都跟着改签名，而“连停用的也进”成了一个取值，随复制粘贴在调用点之间流转，评审里认不出它与普通的进入有什么不同。跨租户选择具名函数而不是布尔参数或字符串键，理由在这里原样成立（[ADR-tenant-scoping](adr-tenant-scoping.md)）。

### 上下文里的一个标记，放行随后对停用租户的进入

调用点在上下文里建立一个标记，此后在它之下的 `Enter` 连停用的租户也进入。

**否决**：标记随上下文传进与这件工作无关的代码，那里的每一次 `Enter` 都连停用的租户一并放行；它的作用范围由上下文怎么传递决定，而不由写出它的调用点决定。

### 临时重新启用那个租户，做完再停用

**否决**：重新启用的那段时间里，那个租户在请求侧重新被服务，它自己的用户可以照常读写；多副本部署下启用与停用各按所在副本的刷新相位生效，这个窗口比工作本身还长。

### 名册功能上另设一个进入方法，不论状态

名册功能交付第二个进入方法：名册上有那个标识的一行即进入，不论它停用与否。

**采纳**，见决策。

## 决策

采纳：名册功能交付第二个进入方法 `EnterRegistered`，名册上有这个标识的一行即进入那个租户，不论状态。

- **与 `Enter` 只差一处：停用的租户也进入。** 名册上没有那一行，或标识不在取值域内，照样以 `ErrInvalidTenant` 拒绝；读名册的方式、进入之后的上下文、拒绝时交回的上下文与 `Enter` 相同。
- **它是一个单独的具名方法**，名字说出它进入的是登记过的租户，而不只是被服务的租户。
- **`Enter` 不变**：停用的租户照样以 `ErrTenantDisabled` 拒绝。
- **它不带身份**：身份与租户的成员关系由租户准入层在请求侧判定，这个方法的调用点不经过它。

方法签名写在设计文档的外部接口契约里。

## 后果

停用期间仍属于一个租户的工作，与被服务的租户上的后台工作相同：过滤、填列与核对作用于那个租户，一次漏写条件的清除只删得到那个租户的行，审计与日志读到的也是它。停用照样挡住请求侧与 `Enter`。

**接受的代价：**

- **停用不再意味着本进程里没有途径把这个租户写进上下文。** 持有名册功能的代码能经这个方法把一个停用的租户写进上下文，请求路径上的 handler 也不例外。这个方法不判定调用方能不能代表那个租户，与 `Enter` 和跨租户同理。请求侧“这个身份属不属于这个租户”由租户准入层判定（[ADR-tenant-admission](adr-tenant-admission.md)），而准入层核对的是请求命中的租户：调用点经这个方法写进上下文的另一个租户不在它的核对之内。
- **语句级没有第二道拦截这一点多了一条被有意用到的路径**：经这个方法进入之后，语句照常作用于那个停用的租户（[ADR-tenant-isolation](adr-tenant-isolation.md)）。
- **名册功能的接口再多一个方法**，这是一次接口的变更：实现这个接口的每一个替身都要补上它。

## 失效条件

授权落地后，若要按身份判定谁能进入一个停用的租户，需要重新比较：`EnterRegistered` 是否要带上身份，与准入层承担的成员判定如何分工。
