# 平台设置与授权

## 问题陈述

平台运营者需要在不重启进程的前提下调整运行期参数、管理短信模板与企业身份提供方、维护角色与权限。这些写入必须受权限与账户状态约束，非法值必须被拒绝，改动要对后续请求生效。

## 范围

本能力覆盖运行期设置在全局层与租户层的查看、写入与移除；租户层经平台管理面按所选租户读写。设置值在租户、全局与声明默认值之间的回落次序，保存后对后续请求的生效，以及非法值的拒绝同属本能力；短信模板的登记、送审、启用、停用与移除，以及发送时对模板的准入判定；企业身份提供方的登记、启停、删除、邮箱域声明与验证，以及更新时的所属租户约束；角色与权限的查看、创建、删除、授予与撤销，以及账户与角色的绑定。

平台管理面保留角色绑定与按账户查询绑定的入口；组织管理面把成员与角色的绑定迁到成员管理页，角色的创建、描述改写、授权与使用情况留在角色页。两处各自服务自己的操作者，不共用页面。

### 不在范围内

- 管理后台入口、区域守卫、概览、租户名册、账户、会话、冒充与邀请的管理，归平台运营能力。
- 审计记录的检索与导出归平台运营能力；管理面写入留下何种审计记录由该能力定义，本能力不另行规定。
- 短信的发送通道、载体适配与号码登记；本能力只涉及模板的管理、启停、移除以及发送时对模板的准入判定。
- 社交登录与企业登录流程本身；本能力只涉及企业身份提供方的登记与启停。
- 设置项的声明、类型、取值域与默认值的定义；运营者只读取并改值。
- 部署配置的选择与生效，以及界面视觉、布局与响应式规格。

## 参与者

- **平台运营者**：已认证并持相应权限的员工。设置页的全局层读写需要 `settings.read` 与 `settings.write`，判定在平台域；设置页的租户层读写需要 `settings.tenant.read` 与 `settings.tenant.write`，判定在所选租户的域，平台员工须在该租户持有对应的租户码，通常经该租户的 `tenant-admin` 取得。短信模板页需要 `sms.template.read` 与 `sms.template.manage`；SSO 提供方页需要 `authn.idp.manage`；权限页需要 `authz.role.read` 与 `authz.role.manage`。短信模板是进程级资产，短信模板页的授权判定在平台域；权限页的判定也在平台域，所选租户只标识被操作的角色与绑定属于哪个租户。SSO 提供方页的授权判定在提供方所属的租户域——新建时即所选租户——运营者须在该租户持有 `authn.idp.manage`。
- **租户成员与终端用户**：不进入管理后台；感受有效设置值的变化，以及其经角色获得的权限随授予或撤销而变化。
- **部署方**：决定哪些能力随装配在场，以及短信载体与企业身份提供方的外部凭据；不是应用内角色，不登录。

平台运营者的管理面写入按平台运营能力规定的账户前提执行：设置页、权限页与 SSO 提供方页的写入以运营者的邮箱已证明为前提，未满足时的拒绝见 REQ-platform-admin-017；改变凭据、因素、账户的停用或删除、或冒充的写入，其会话强度要求见 REQ-platform-admin-114。

## 功能需求

### REQ-platform-config-001

系统必须在管理后台的设置页按命名空间分组列出全局层已声明的设置项，每项显示键、类型与当前有效值。全局层的读取需要 `settings.read`。

- **验收**：打开设置页后全局层的每个已声明项都出现，且分组与它所属的命名空间一致；重新加载后列表仍完整；任一项缺键、类型或当前值即不通过。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-operator-configuration.spec.ts` `operator-configuration: a switch is closed and reopened, and the audit trail carries both writes`

### REQ-platform-config-045

系统必须在管理后台的设置页按命名空间分组列出所选租户的租户层已声明的设置项，每项显示键、类型与当前有效值。租户层的读取需要 `settings.tenant.read`，且调用方须在所选租户持有该权限，通常经该租户的 `tenant-admin` 取得。

- **验收**：选定一个租户后，该租户的每个已声明项都出现，且分组与它所属的命名空间一致；切换所选租户后列表按新租户重读；只有全局层权限的调用方不能读取租户层，只有某租户层权限的调用方不能读取另一个租户层；任一项缺键、类型或当前值即不通过。

- **端到端测试**：未实现

- **验收**：每项设置的行内显示该项自己的说明与声明默认值；某一项没有显示说明或默认值，或显示了另一项的值即不通过。
- **状态**：已实现

### REQ-platform-config-002

系统必须按层解析一项设置的有效值：读取点名租户时，平台层与租户层各自按「显式行优先、否则声明默认值」求出；对声明为租户级的开关项，有效值是两层的逻辑或，平台层为真构成下限；对其余项，有效值按「该租户的行 > 全局行 > 声明默认值」回落。

- **验收**：从未写入过的键在所有租户读到声明默认值；写入一个全局值后，没有单独设置该项的租户在该项上读到全局值；某租户单独设置非租户级项后读到自己的值，其他租户仍读全局值；对租户级开关项，平台真、租户假时有效值为真，平台假、租户真时有效值为真，两者都假时为假。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-platform-config-049

平台设置页必须继续承载全部已声明设置项，含平台级项；组织管理面只承载声明为租户级的项。两个管理面不互相替代，可见集由声明回答，不由页面过滤或命名空间前缀推断。

- **验收**：平台设置页按层选列出全局层或所选租户层的全部已声明项，平台级项在其上可读可见；组织管理面对未声明为租户级的项的读、写、删都答 404（见 REQ-tenant-admin-019），全量读只返回租户级项（见 REQ-tenant-admin-016）。一面列出而另一面过滤同一项，或两面都不呈现它，即不通过。
- **状态**：已实现
- **端到端测试**：未实现

- **验收**：在全局层修改一项的当前值并保存，该项状态从「默认」变为「已覆盖」，当前值显示新值；该项的有效值按 REQ-platform-config-002 的回落次序解析；重新加载设置页后保持该状态与值。
- **状态**：已实现

### REQ-platform-config-007

系统必须让一次成功的设置写入在发起该写入的进程上立即生效：其后的请求取到新值，进程不重启。
