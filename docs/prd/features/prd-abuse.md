# 防滥用

## 问题陈述

平台会代表请求方向第三方邮箱与手机号发送验证消息，也会按业务要求投递邮件与短信。发送量没有约束时，攻击者可以让平台对任意邮箱或手机号反复发信：受害者收到大量并非自己请求的消息，平台的发信通道、号码与发信声誉被消耗，平台本身成为攻击的发起者。本能力规定平台在这些出站消息上的约束。

## 范围

本能力覆盖所有由请求方触发、收件人由请求方指定的出站消息：登录与注册流程中的验证短信、账户自助中验证邮箱与手机号的邮件与短信、以及业务通知的邮件与短信投递。它规定预算的层级、预算在并发下的一致性、按来源的约束、同一收件箱的别名归并、发送失败与预算耗尽时的可见结果，以及可开启的人机验证门槛。

### 不在范围内

- 站内信的列出、未读计数与偏好矩阵，归通知能力；本能力只规定其邮件与短信投递侧的预算。
- 管理面写入是否需要重新验证，归账户安全能力。
- 邮件与短信载体的选择、模板与注册，归相应的发送能力。

## 参与者

- **请求方**：触发一次发送的人。匿名访客在登录与注册流程中发码，已登录账户在自助验证中发码，业务模块按事件派发通知。
- **收件人**：接收消息的地址或号码的持有人。收件人没有请求该消息时，就是被攻击的一方。
- **平台运营者**：决定是否开启人机验证、并调整各项预算的人。

## 功能需求

### REQ-abuse-001

系统必须对验证消息按目标地址或号码、按账户（请求方已认证时）与全局分别计数，并在任一预算用尽时拒绝继续发送。

- **验收**：对同一目标连续请求直到预算用尽，后续请求不发送消息并得到可重试的拒绝；换一个目标仍在预算内时可以发送；全局预算用尽时任何请求都不再发送。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-abuse-002

并发请求不得越过本能力规定的任何一层预算。

- **验收**：对同一目标并发发起多于预算数量的请求，实际发出的消息数不超过预算；按账户与全局两层同样成立。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-abuse-003

系统必须按请求来源对验证消息计数，并在该来源的预算用尽后拒绝它的发送请求，即使它轮换目标。

- **验收**：同一来源对多个不同目标各请求一次，超过来源预算后不再发送；该来源被拒绝时，其他来源仍可在预算内发送。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-abuse-004

同一收件箱的不同地址写法必须共用同一份按目标预算。

- **验收**：对同一收件箱的加号别名与大小写不同的写法分别请求，累计超过预算后不再发送。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-abuse-005

一次没有发出的验证邮件不得永久消耗预算。

- **验收**：让一次邮件发送失败后重试，成功发送的次数仍可达到预算上限。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-abuse-006

预算用尽时，系统必须给出可重试的拒绝并标明建议的重试时间，不得报告服务不可用。

- **验收**：耗尽任一预算后，后续请求的应答带重试提示，且与发送后端故障的应答可区分。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-abuse-007

系统必须提供可开启的人机验证门槛，默认关闭。

- **验收**：默认配置下，发送请求不需要人机凭证；开启后，缺少或无效凭证的请求被拒绝且不发送消息，有效凭证的请求正常发送。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-abuse-008

开启人机验证后，验证消息的每一次发送请求都必须先提交一个有效的人机凭证。

- **验收**：逐个对登录、注册、账户自助验证的发送入口开启门槛，缺少或无效凭证时这些入口都不发送消息；同一凭证不得重复使用。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-abuse-009

业务通知的邮件与短信投递必须受按收件人与全局的预算约束，且收件地址必须属于该消息的收件人。

- **验收**：对同一收件人高频派发超过预算后不再投递；派发携带的收件地址不属于该收件人时，该次投递被拒绝。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-abuse-010

一次没有发出的验证短信不得永久消耗预算。

- **验收**：让一次短信发送失败后重试，成功发送的次数仍可达到预算上限。
- **状态**：未实现
- **端到端测试**：未实现

## 约束

- 开放匿名注册或放行可发送的短信号段之前，部署必须先具备 REQ-abuse-002 与 REQ-abuse-003 的预算。这两项未实现时，匿名者可以批量取得账户并轮换目标，平台可被用作轰炸的发起者。
