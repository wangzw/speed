# 租户管理

## 问题陈述

平台管理面面向平台员工，管理跨租户的平台资产：名册、账户、会话、冒充与审计。业务租户内部的成员、邀请、企业身份提供方、设置与角色只有平台员工可以管理；租户管理员因此依赖平台员工完成日常管理，而平台员工的权限跨越全部租户，不适合承担单个租户内的常规动作。

本能力为租户管理员提供组织管理面：入口、页面与服务端判定都限于当前业务租户。租户管理员在这条面上完成本租户的成员与邀请、企业身份提供方、组织资料、租户设置、角色与绑定的管理；组织所有者还在这条面上发起所有权转移请求与删除组织；被请求的成员在自己的账户级转移请求页确认或拒绝，所有权在确认后才改变。租户管理员不能借这条面取得平台权限、改写内建角色或越过租户边界。

## 范围

组织管理面的账户菜单分组与首页卡片；页面级判定与回退；当前租户的成员读取、搜索、停用、恢复与移除、邀请的读取、签发、重发与撤销；当前租户企业身份提供方的读取、登记、启停、删除与邮箱域验证；当前组织资料的读取与写入；所有权转移请求的发起与组织删除；当前租户设置层的读取、写入与移除；当前租户角色、授权与绑定的读取与写入；上述写入的防提权判定；租户切换时分组与卡片的撤下与恢复。

角色页与成员页按动作分工：角色页创建、改写描述与删除角色，授予与撤销权限，并只读地展示角色的使用情况；改变成员归属的绑定与解绑在成员页完成。角色页的成员数只计当前租户的 active 成员，成员页按角色筛选时列出全部持有该角色的成员（含已停用），两处数量可以不同，不视为缺陷。

平台的端点分为三类，作用域与判定域各不相同，不得互相代替：

- 平台资产在平台域的 `/api/v1/system/...` 下，由平台管理面读写。
- 平台管理面按租户寻址的邀请与成员、企业身份提供方页面在 `/api/v1/tenants/{tenant}/...` 下，判定在该租户域；只持平台管理员权限不构成放行，调用方须在该租户持有对应权限。
- 组织管理面在 `/api/v1/tenants/{tenant}/...` 下，作用域是当前租户，判定在该租户域。

### 不在范围内

- 平台管理面的入口、名册、账户、会话、冒充、审计、短信模板与全局设置管理。
- 平台域的 `platform-admin` 角色、平台域角色与全局层设置；本能力不改变平台管理员在平台域的权限集。
- 租户的创建、所有者转移请求、停用与删除；名称创建后不可改。这些动作属于平台运营与组织所有者。
- 个人租户的开通与个人组织本身；本能力在入口与页面排除个人租户，服务端拒绝其租户管理写入。
- 成员关系的准入判定与邀请接受流程；这些属于组织与成员能力。本能力经组织管理面停用、恢复与移除成员，这些写入本身的行为契约见 REQ-tenancy-054 与 REQ-tenancy-010。
- 账户的建立、停用与删除，以及第二因素、会话与服务密钥。
- 租户层级、租户树与租户数据导出。

## 参与者

- **租户管理员**：在当前业务租户持有 `tenant-admin`，或持有覆盖某个组织管理页面的权限。`tenant-admin` 在业务租户与 `system` 租户是完整治理集；在个人租户是治理集内的允许子集，且不是内建角色。平台域权限不属于其租户管理能力。
- **普通租户成员**：在当前租户持有成员关系，不持有覆盖任何组织管理页面的权限。看不到账户菜单里的组织分组与首页卡片；直达路径回到租户首页。
- **个人租户的租户管理员**：持有个人租户及其 `tenant-admin`。个人租户不出现账户菜单里的组织分组与首页卡片，服务端拒绝其租户管理写入。
- **平台运营者**：持有平台域管理权限。平台权限不使其通过组织管理面判定；要执行租户管理动作，须是当前租户的成员并在当前租户持有相应权限。
- **冒充中的运营者**：会话主体为被冒充账户并带冒充标记。组织管理面的账户菜单分组与首页卡片不出现。
- **受邀人**：持有邀请链接的访问者。接受邀请后成为租户成员，不因接受邀请本身取得租户管理权限。

## 术语表

`治理权限`、`治理集`、`平台管理面`、`组织管理面`、`业务租户` 与 `内建角色` 的含义见项目术语表 [docs/glossary.md](../../glossary.md)。以下术语的含义限于本文档。

| 术语 | 英文 | 适用范围 | 定义 |
|---|---|---|---|
| 租户级设置 | tenant-level setting | 本文档 | 由设置声明标记为对租户可见的设置项；本轮是两项准入策略 `tenant.admission.require-mfa` 与 `tenant.admission.require-sso`。未标记为租户级的项与不存在的键对租户是同一个答案。 |
| 设置来源层 | source layer | 本文档 | 一项设置当前有效值的出处，闭集为 `tenant`、`global` 与 `default`，分别对应当前租户层写下的行、全局层写下的行与声明默认值。平台强制一项策略时来源为 `global`。 |

本能力在入口与页面排除 `system` 租户与个人租户；其余业务租户是本能力的对象。服务端对这两个租户上的租户管理写入的拒绝，`system` 租户由 REQ-tenant-admin-037 要求，个人租户由 REQ-tenant-admin-044 要求。`tenant-admin` 在业务租户与 `system` 租户是内建角色，在个人租户不是内建角色；个人租户的 `tenant-admin` 授权集由宿主按个人租户的允许范围维护，不经治理集收敛。

## 功能需求

### REQ-tenant-admin-001

系统必须只在同时满足以下条件时，向已认证账户展示以可访问名称“组织管理”标识的组织管理面账户菜单分组与首页卡片：当前租户是业务租户、当前租户不是 `system` 租户、会话不在冒充中、本部署装配了至少一条组织管理页面、且账户在当前租户持有的权限覆盖至少一条组织管理页面。

- **验收**：以只持租户管理员权限、不持平台权限的账户进入业务租户，头像账户菜单与侧栏账户菜单都出现组织分组，首页出现卡片；分组以可访问名称“组织管理”被识别；同一账户切到个人租户或 `system` 租户，两者都不出现；同一会话进入冒充后，两者都不出现；一个权限都不覆盖任何组织管理页面的普通成员看不到两者。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-002

账户菜单分组中的首条链接与首页卡片必须指向同一个页面，且该页面是当前账户可进入的第一条组织管理页面；分组必须把当前账户可进入的组织管理页面逐条列为链接。

- **验收**：分别激活分组中的首条链接与卡片，落到相同路径，且该路径属于当前账户可进入的组织管理页面集合；分组列出的链接集合与该集合一致；改变权限集使可进入集合变化后，首条链接与卡片仍落到同一路径，分组列出的链接随之变化。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-003

切换租户必须在切换动作发生时撤下组织管理面的账户菜单分组与首页卡片，并在新租户的权限集落定后，按该集合重新决定它们是否出现。

- **验收**：从一个业务租户切到另一个业务租户时，分组与卡片在切换后立即消失；新权限集落定后，若新租户仍有可进入页面则重新出现，否则保持不出现；权限集落定之前两者都不出现。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-004

组织管理区域的页面必须按该页所需权限判定；当前账户缺少该页权限时，转到当前账户可进入的第一条组织管理页面，一条也没有时转到当前租户的首页。

- **验收**：以只覆盖部分页面的账户直达未覆盖页面，落到第一条可进入页面；以不覆盖任何组织管理页面的账户直达区域根或任一子路径，落到当前租户首页。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-005

普通成员在租户区内导航到任一组织管理路径时，必须静默回到当前租户首页，且不显示重定向说明。

- **验收**：以不持任何组织管理页权限的成员导航到区域根与任一子路径，落在租户首页；页面不出现组织管理页面标题、账户菜单里的组织分组名或页面内容，也没有重定向说明。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-006

个人租户与 `system` 租户必须不展示组织管理面的账户菜单分组与首页卡片；直达任一组织管理路径必须回到当前租户首页。

- **验收**：在个人租户与 `system` 租户中，分组与卡片都不出现；直达区域根与任一子路径都落在当前租户首页，页面不出现组织管理内容。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-007

本部署未装配任何组织管理页面时，系统必须不展示组织管理面的账户菜单分组与首页卡片，并让任一组织管理路径回到当前租户首页。

- **验收**：在未装配组织管理页面的部署中，分组与卡片都不出现；直达区域根与任一子路径都落在当前租户首页，且不发出组织管理页面的读取。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-008

组织管理面必须以当前租户为作用域列出成员，逐行给出用户名、显示名、成员关系启用状态、成员关系来源、加入时间与当前持有的角色名，角色名按升序且不重复，成员按服务端的稳定次序分页，界面不显示账户标识；成员列表必须支持文本搜索、按角色筛选与游标分页，这些读取本身的行为契约见 REQ-tenancy-008、REQ-tenancy-051、REQ-tenancy-052 与 REQ-tenancy-053。

- **验收**：第一页只含当前租户的成员，逐行显示用户名、显示名、成员关系启用状态、成员关系来源、加入时间与角色名，界面不出现账户标识，角色名按升序且无重复；持有多个角色的成员给出全部角色名，没有角色的成员给出空角色列表；继续翻页可遍历全部成员；租户没有成员时读取成功且列表为空；其他租户的成员不出现；文本搜索、角色筛选与游标翻页按各自引用的需求生效。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-tenant-admin.spec.ts` `tenant-admin: the administrator invites, governs and switches the organization`

### REQ-tenant-admin-009

组织管理面必须把签发邀请的租户固定为当前租户，并在签发应答中一次性交出接受链接；签发后系统必须自动向被邀请地址发送含接受链接的通知邮件，投递结果随签发应答报告，投递失败不撤销邀请。接受链接、地址校验、邮件投递与重新签发本身的行为契约见 REQ-tenancy-011、REQ-tenancy-012、REQ-tenancy-057 与 REQ-tenancy-058。

- **验收**：在组织管理面签发一条邀请后，邀请列表出现该地址的待接受邀请，且该邀请只出现在当前租户的列表中；接受链接只在此次应答中出现，此后任何读取都取不到明文；页面报告投递结果，配置了邮件的部署向该地址发出含同一链接的通知邮件，投递失败时邀请仍在列表中且链接仍可接受。地址校验、重新签发与链接失效的行为见 REQ-tenancy-011、REQ-tenancy-012、REQ-tenancy-057 与 REQ-tenancy-058。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-tenant-admin.spec.ts` `tenant-admin: the administrator invites, governs and switches the organization`

### REQ-tenant-admin-010

组织管理面的邀请读取与撤销必须以当前租户为作用域；读取可按状态筛选，取值为未过期待接受、已过期、已接受与已撤销，缺省列出全部状态。列出、筛选与撤销本身的行为契约见 REQ-tenancy-015、REQ-tenancy-056 与 REQ-tenancy-014。

- **验收**：未筛选的列表只含当前租户的邀请，逐行给出地址、状态、邀请人与有效期；按每个状态筛选时，列表只含该状态的邀请，已过期的待接受邀请显示为已过期；对其他租户的邀请发起撤销得到与不存在相同的结果。撤销与冲突判定的行为见 REQ-tenancy-014、REQ-tenancy-015 与 REQ-tenancy-056。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-tenant-admin.spec.ts` `tenant-admin: the administrator invites, governs and switches the organization`

### REQ-tenant-admin-011

组织管理面必须以当前租户为作用域列出企业身份提供方，逐项给出协议、名称与启用状态；读取本身的行为契约见 REQ-platform-config-048。

- **验收**：租户 A 的列表只含 A 的提供方，租户 B 的提供方不出现；A 没有提供方时列表为空；列表不包含平台域或其他租户的提供方。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-012

组织管理面必须允许租户管理员为当前租户登记一个企业身份提供方，指名协议、名称与协议配置；登记本身的行为契约见 REQ-platform-config-017 与 REQ-platform-config-037。

- **验收**：登记成功后该提供方出现在当前租户列表，不出现在其他租户的列表；缺少必填配置或协议不受支持时被拒绝，列表不发生改变；新提供方不能被写入其他租户。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-013

组织管理面必须允许租户管理员启用或停用当前租户的企业身份提供方；启停本身的行为契约见 REQ-platform-config-018。

- **验收**：停用一个已验证邮箱域的提供方后，该域的登录发现不再返回它；重新启用后再次返回；其他租户的提供方不受影响。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-014

组织管理面必须允许租户管理员删除当前租户的企业身份提供方，并连同它名下的邮箱域声明一并删除；删除本身的行为契约见 REQ-platform-config-019。

- **验收**：删除后该提供方不再出现在列表中，其邮箱域不再参与登录发现，其他提供方对这些域名的验证状态不变；其他租户的提供方不受影响。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-015

组织管理面必须允许租户管理员为当前租户的企业身份提供方声明一个邮箱域并取得验证令牌；域验证与冲突判定的行为契约见 REQ-platform-config-020、REQ-platform-config-038 与 REQ-platform-config-021。

- **验收**：声明后该域显示为未验证，用该域邮箱发起登录发现找不到该提供方；DNS 记录匹配后该域转为已验证并参与发现；记录不匹配时仍为未验证；已被另一个提供方验证的域被拒绝，双方的验证状态都不变；其他租户的提供方不受影响。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-tenant-admin-016

组织管理面的“安全与访问”页必须只呈现租户层真正拥有的设置项；本轮是“要求多因素认证”与“要求企业单点登录”两项准入策略。每项必须给出说明、当前状态、生效范围与关闭后的影响。受保护租户只渲染只读说明，不渲染开关。

- **验收**：页面只出现这两项，各自带标题、说明、状态、生效范围与关闭影响；不出现键值表、命名空间导航、搜索或批量保存；平台级设置的名称、值、来源与存在性都不出现；受保护租户只渲染只读说明，不渲染开关。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-tenant-admin.spec.ts` 的 `tenant-admin: the administrator invites, governs and switches the organization`（设置步：两项策略的呈现与平台级名称不出现）、`tenant-admin: a platform-enforced policy is read-only and cannot be turned off` 与 `tenant-admin: the protected organization renders no switch and its write is refused`；设置步的零可见 API 断言见 REQ-tenant-admin-019。

### REQ-tenant-admin-017

组织管理面必须允许租户管理员为当前租户开启或关闭一项准入策略；关闭必须先经一次说明影响的确认，开启即时保存。关闭在平台未强制时写入租户层 false，不删除租户层行。

- **验收**：开启后页面立即显示已启用，重新读取仍为已启用；关闭时先出现确认，确认后显示未启用；平台未强制时关闭写入成功，租户层写入 false 且有效值随之变为假；写入失败时开关回滚到原值并显示可读的拒绝原因；请求在途时同一开关不可再次提交。
- **状态**：已实现

### REQ-tenant-admin-063

- **验收**：选中一个角色后显示 active 成员数与成员列表；逐行显示显示名、用户名、成员状态与授予时间，持有多个角色的成员只按该角色出现一次；显示名读不出时该行以用户名显示，任何一行都不出现账户标识；成员状态不可用时显示为不可用，不显示为停用；列表超过一页时提供上一页与下一页，最后一页不提供下一页；只持 `authz.tenant.role.read` 的调用者读到完整的只读列表，页面上没有绑定与解绑控件；成员状态的读取失败时整个使用情况读显示依赖不可用。
