# 租户管理

## 问题陈述

平台已有面向平台员工的管理后台，负责跨租户的名册、账户、会话、冒充与审计；业务租户内部的成员、邀请、企业身份提供方、设置与角色，此前只有平台员工可以管理。租户管理员因此必须依赖平台员工完成日常管理，而平台员工的管理权限又跨越全部租户，不适合承担单个租户内的常规动作。

本能力为租户管理员提供租户区内的管理面：入口、页面与最终判定都限于当前业务租户，平台域权限不构成放行。租户管理员可以在这条面上完成本租户的成员与邀请、企业身份提供方、租户设置、角色与绑定的管理，同时不能借这条面取得平台权限、改写保留角色或越过租户边界。

## 范围

租户管理入口、导航父项与首页卡片；租户管理区域的页面判定与重定向；当前租户成员与邀请的读取、签发与撤销；当前租户企业身份提供方的登记、启停、删除与邮箱域验证；当前租户设置层的读取、写入与移除；当前租户角色、授权与绑定的读取与写入；上述写入的防提权判定；租户切换时租户管理入口的撤下与恢复。

### 不在范围内

- 平台管理面的入口、名册、账户、会话、冒充、审计、短信模板与全局设置管理。
- 平台域的 `platform-admin` 角色、平台域角色与全局层设置；本能力不改变平台管理员在平台域的权限集。
- 租户的创建、别名、停用与删除；这些动作属于平台运营。
- 个人租户的开通与个人空间本身；本能力在入口、页面与服务端都排除个人租户。
- 成员关系本身的准入判定、邀请接受流程与成员关系的存储语义；这些属于组织与成员能力，本能力只调用。
- 账户的建立、停用与删除，以及第二因素、会话与服务密钥。
- 租户层级、租户树与租户数据导出。

## 参与者

- **租户管理员**：在当前业务租户域持有 `tenant-admin` 角色，或持有该租户内足以覆盖某个租户管理页面的权限。其权限集只含治理权限；平台域权限不属于其租户管理能力。
- **普通租户成员**：在当前租户持有成员关系，但不持有任何覆盖租户管理页面的权限。看不到租户管理入口、导航父项与首页卡片，直达路径回到租户首页。
- **个人空间所有者**：持有个人租户及其所有者角色。个人租户不出现租户管理入口、导航父项与首页卡片。
- **平台运营者**：持有平台域管理权限。平台权限不使其通过租户管理判定；要执行租户管理动作，须是当前租户的成员并在当前租户持有相应权限。
- **冒充中的运营者**：会话主体为被冒充账户并带冒充标记。租户管理入口、导航父项与首页卡片不出现。
- **受邀人**：持有邀请链接的访问者。接受邀请后成为租户成员，不因接受邀请本身取得租户管理权限。

## 术语表

「治理权限」与「治理集」的含义见项目术语表 [docs/glossary.md](../../glossary.md)。本文档只登记自己的术语。

| 术语 | 定义 |
|---|---|
| 保留角色 | 由平台定义、租户管理面不得创建、改写或删除的角色：`tenant-admin`。`platform-admin` 只在平台域存在，不在任何租户域存在；租户管理面对它的创建、授予或绑定一律拒绝。租户管理面可以查看 `tenant-admin` 的授权，可以按约束绑定 `tenant-admin`，不能改写它的授权。 |

## 功能需求

### REQ-tenant-admin-001

系统必须只在同时满足以下条件时，向已认证账户展示租户管理入口与首页的租户管理卡片：当前租户是业务租户、会话不在冒充中、本部署装配了至少一条租户管理页面、且账户在当前租户持有的权限覆盖至少一条租户管理页面。

- **验收**：以只持租户管理员权限、不持平台权限的账户进入业务租户，入口与卡片都出现；同一账户切到个人租户或 `system` 租户，两者都不出现；同一会话进入冒充后，两者都不出现；一个权限都不覆盖任何租户管理页面的普通成员看不到两者。
- **状态**：未实现
- **端到端测试**：未实现
- **来源**：新增

### REQ-tenant-admin-002

租户管理入口与首页的租户管理卡片必须指向同一个页面，且该页面是当前账户可进入的第一条租户管理页面。

- **验收**：分别激活入口与卡片，落到相同路径，且该路径属于当前账户可进入的租户管理页面集合；改变权限集使可进入集合变化后再次激活，两者仍落到同一路径，且该路径属于新的可进入集合。
- **状态**：未实现
- **端到端测试**：未实现
