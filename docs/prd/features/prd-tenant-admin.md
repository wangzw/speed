# 租户管理

## 问题陈述

平台管理面面向平台员工，管理跨租户的平台资产：名册、账户、会话、冒充与审计。业务租户内部的成员、邀请、企业身份提供方、设置与角色只有平台员工可以管理；租户管理员因此依赖平台员工完成日常管理，而平台员工的权限跨越全部租户，不适合承担单个租户内的常规动作。

本能力为租户管理员提供工作区管理面：入口、页面与服务端判定都限于当前业务租户。租户管理员在这条面上完成本租户的成员与邀请、企业身份提供方、租户设置、角色与绑定的管理，不能借这条面取得平台权限、改写内建角色或越过租户边界。

## 范围

工作区管理面的入口、导航父项与首页卡片；页面级判定与回退；当前租户的成员读取与移除、邀请的读取、签发与撤销；当前租户企业身份提供方的读取、登记、启停、删除与邮箱域验证；当前租户设置层的读取、写入与移除；当前租户角色、授权与绑定的读取与写入；上述写入的防提权判定；租户切换时入口的撤下与恢复。

平台的端点分为三类，作用域与判定域各不相同，不得互相代替：

- 平台资产在平台域的 `/api/v1/system/...` 下，由平台管理面读写。
- 平台管理面按租户寻址的邀请与成员、企业身份提供方页面在 `/api/v1/tenants/{tenant}/...` 下，判定在该租户域；只持平台管理员权限不构成放行，调用方须在该租户持有对应权限。
- 工作区管理面在 `/api/v1/tenants/{tenant}/...` 下，作用域是当前租户，判定在该租户域。

### 不在范围内

- 平台管理面的入口、名册、账户、会话、冒充、审计、短信模板与全局设置管理。
- 平台域的 `platform-admin` 角色、平台域角色与全局层设置；本能力不改变平台管理员在平台域的权限集。
- 租户的创建、别名、停用与删除；这些动作属于平台运营。
- 个人租户的开通与个人空间本身；本能力在入口与页面排除个人租户，服务端拒绝其租户管理写入。
- 成员关系的准入判定与邀请接受流程；这些属于组织与成员能力。本能力经工作区管理面移除成员，移除本身的行为契约见 REQ-tenancy-010。
- 账户的建立、停用与删除，以及第二因素、会话与服务密钥。
- 租户层级、租户树与租户数据导出。

## 参与者

- **租户管理员**：在当前业务租户持有 `tenant-admin`，或持有覆盖某个工作区管理页面的权限。`tenant-admin` 在业务租户与 `system` 租户是完整治理集；在个人租户是治理集内的允许子集，且不是内建角色。平台域权限不属于其租户管理能力。
- **普通租户成员**：在当前租户持有成员关系，不持有覆盖任何工作区管理页面的权限。看不到入口、导航父项与首页卡片；直达路径回到租户首页。
- **个人租户的租户管理员**：持有个人租户及其 `tenant-admin`。个人租户不出现入口、导航父项与首页卡片，服务端拒绝其租户管理写入。
- **平台运营者**：持有平台域管理权限。平台权限不使其通过工作区管理面判定；要执行租户管理动作，须是当前租户的成员并在当前租户持有相应权限。
- **冒充中的运营者**：会话主体为被冒充账户并带冒充标记。工作区管理面的入口、导航父项与首页卡片不出现。
- **受邀人**：持有邀请链接的访问者。接受邀请后成为租户成员，不因接受邀请本身取得租户管理权限。

## 术语表

`治理权限`、`治理集`、`平台管理面`、`工作区管理面`、`业务租户` 与 `内建角色` 的含义见项目术语表 [docs/glossary.md](../../glossary.md)。以下术语的含义限于本文档。

| 术语 | 定义 |
|---|---|
| 平台专用命名空间 | 租户面不得读写的设置命名空间，封闭集为 `ratelimit.*`、`tenant.admission.*` 与 `authn.*`。不在集合里的命名空间默认可由租户读写。 |
| 设置来源层 | 一项设置当前有效值的出处，闭集为 `tenant`、`global` 与 `default`，分别对应当前租户层写下的行、全局层写下的行与声明默认值。 |

本能力在入口与页面排除 `system` 租户与个人租户，服务端拒绝在这两个租户上的租户管理写入；其余业务租户是本能力的对象。`tenant-admin` 在业务租户与 `system` 租户是内建角色，在个人租户不是内建角色；个人租户的 `tenant-admin` 授权集由宿主按个人租户的允许范围维护，不经治理集收敛。

## 功能需求

### REQ-tenant-admin-001

系统必须只在同时满足以下条件时，向已认证账户展示工作区管理面的入口、导航父项与首页卡片：当前租户是业务租户、当前租户不是 `system` 租户、会话不在冒充中、本部署装配了至少一条工作区管理页面、且账户在当前租户持有的权限覆盖至少一条工作区管理页面。

- **验收**：以只持租户管理员权限、不持平台权限的账户进入业务租户，入口、导航父项与卡片都出现；同一账户切到个人租户或 `system` 租户，三者都不出现；同一会话进入冒充后，三者都不出现；一个权限都不覆盖任何工作区管理页面的普通成员看不到三者。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-002

入口与首页卡片必须指向同一个页面，且该页面是当前账户可进入的第一条工作区管理页面；导航父项必须把当前账户可进入的工作区管理页面列为子项。

- **验收**：分别激活入口与卡片，落到相同路径，且该路径属于当前账户可进入的工作区管理页面集合；导航父项的子项集合与该集合一致；改变权限集使可进入集合变化后，入口与卡片仍落到同一路径，导航父项的子项随之变化。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-003

切换租户必须在切换动作发生时撤下工作区管理面的入口、导航父项与首页卡片，并在新租户的权限集落定后，按该集合重新决定它们是否出现。

- **验收**：从一个业务租户切到另一个业务租户时，入口、导航父项与卡片在切换后立即消失；新权限集落定后，若新租户仍有可进入页面则重新出现，否则保持不出现；权限集落定之前三者都不出现。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-004

工作区管理区域的页面必须按该页所需权限判定；当前账户缺少该页权限时，转到当前账户可进入的第一条工作区管理页面，一条也没有时转到当前租户的首页。

- **验收**：以只覆盖部分页面的账户直达未覆盖页面，落到第一条可进入页面；以不覆盖任何工作区管理页面的账户直达区域根或任一子路径，落到当前租户首页。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-005

普通成员在租户区内导航到任一工作区管理路径时，必须静默回到当前租户首页，且不显示重定向说明。

- **验收**：以不持任何工作区管理页权限的成员导航到区域根与任一子路径，落在租户首页；页面不出现工作区管理页面标题、导航分组名或页面内容，也没有重定向说明。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-006

个人租户与 `system` 租户必须不展示工作区管理面的入口、导航父项与首页卡片；直达任一工作区管理路径必须回到当前租户首页。

- **验收**：在个人租户与 `system` 租户中，入口、导航父项与卡片都不出现；直达区域根与任一子路径都落在当前租户首页，页面不出现工作区管理内容。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-007

本部署未装配任何工作区管理页面时，系统必须不展示工作区管理面的入口、导航父项与首页卡片，并让任一工作区管理路径回到当前租户首页。

- **验收**：在未装配工作区管理页面的部署中，入口、导航父项与卡片都不出现；直达区域根与任一子路径都落在当前租户首页，且不发出工作区管理页面的读取。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-008

工作区管理面必须以当前租户为作用域列出成员，逐行给出账户标识、显示名、成员关系启用状态与成员关系来源，按账户标识升序；分页、空列表与成员读取本身的行为契约见 REQ-tenancy-008。

- **验收**：第一页只含当前租户的成员，逐行显示账户标识、显示名、成员关系启用状态与成员关系来源，按账户标识升序；继续翻页可遍历全部成员；租户没有成员时读取成功且列表为空；其他租户的成员不出现。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-009

工作区管理面必须把签发邀请的租户固定为当前租户，并在签发应答中一次性交出接受链接；接受链接、重新签发与地址校验的行为契约见 REQ-tenancy-011 与 REQ-tenancy-012。

- **验收**：在工作区管理面签发一条邀请后，邀请列表出现该地址的待接受邀请，且该邀请只出现在当前租户的列表中；接受链接只在此次应答中出现，此后任何读取都取不到明文。地址校验、重新签发与链接失效的行为见 REQ-tenancy-011 与 REQ-tenancy-012。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-010

工作区管理面的邀请读取与撤销必须以当前租户为作用域；列出与撤销本身的行为契约见 REQ-tenancy-015 与 REQ-tenancy-014。

- **验收**：列表只含当前租户的邀请，逐行给出地址、状态、邀请人与有效期；对其他租户的邀请发起撤销得到与不存在相同的结果。撤销与冲突判定的行为见 REQ-tenancy-014 与 REQ-tenancy-015。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-011

工作区管理面必须以当前租户为作用域列出企业身份提供方，逐项给出协议、名称与启用状态；读取本身的行为契约见 REQ-platform-config-048。

- **验收**：租户 A 的列表只含 A 的提供方，租户 B 的提供方不出现；A 没有提供方时列表为空；列表不包含平台域或其他租户的提供方。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-012

工作区管理面必须允许租户管理员为当前租户登记一个企业身份提供方，指名协议、名称与协议配置；登记本身的行为契约见 REQ-platform-config-017 与 REQ-platform-config-037。

- **验收**：登记成功后该提供方出现在当前租户列表，不出现在其他租户的列表；缺少必填配置或协议不受支持时被拒绝，列表不发生改变；新提供方不能被写入其他租户。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-013

工作区管理面必须允许租户管理员启用或停用当前租户的企业身份提供方；启停本身的行为契约见 REQ-platform-config-018。

- **验收**：停用一个已验证邮箱域的提供方后，该域的登录发现不再返回它；重新启用后再次返回；其他租户的提供方不受影响。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-014

工作区管理面必须允许租户管理员删除当前租户的企业身份提供方，并连同它名下的邮箱域声明一并删除；删除本身的行为契约见 REQ-platform-config-019。

- **验收**：删除后该提供方不再出现在列表中，其邮箱域不再参与登录发现，其他提供方对这些域名的验证状态不变；其他租户的提供方不受影响。
- **状态**：未实现

### REQ-tenant-admin-015

工作区管理面必须允许租户管理员为当前租户的企业身份提供方声明一个邮箱域并取得验证令牌；域验证与冲突判定的行为契约见 REQ-platform-config-020、REQ-platform-config-038 与 REQ-platform-config-021。

- **验收**：声明后该域显示为未验证，用该域邮箱发起登录发现找不到该提供方；DNS 记录匹配后该域转为已验证并参与发现；记录不匹配时仍为未验证；已被另一个提供方验证的域被拒绝，双方的验证状态都不变；其他租户的提供方不受影响。
- **状态**：未实现
- **端到端测试**：未实现

### REQ-tenant-admin-016

系统必须经工作区管理面按命名空间分组列出当前租户可见的设置项，每项给出键、类型、当前有效值与当前值的来源层；来源层是闭集 `tenant`、`global` 与 `default`。有效值的解析次序见 REQ-platform-config-002。

- **验收**：每个已声明且租户可读的设置项都出现，分组与它所属的命名空间一致；有效值按「当前租户覆盖 > 全局值 > 声明默认值」解析；来源层是 `tenant` 当且仅当当前租户写下该键，是 `global` 当且仅当当前租户未写下而全局层写下该键，是 `default` 当且仅当两层都未写下该键；平台专用命名空间下的项不出现。
- **状态**：未实现
- **端到端测试**：未实现

- **验收**：写入后当前租户读到新值，其他租户仍读到原来的回落值；重新加载设置页后仍显示新值、已覆盖状态与 `tenant` 来源层。

- **验收**：移除后该项显示为未覆盖，有效值等于回落值；来源层为 `global` 或 `default`，与回落值实际来自的层一致；对没有租户层覆盖的项再次发起移除成功，且不改变任何值。

- **验收**：分别对 `ratelimit.*`、`tenant.admission.*` 与 `authn.*` 下的键发起写入，都得到拒绝，租户层值不变；对允许集内的键发起写入成功；新增一个不在封闭集里的命名空间默认可写。
