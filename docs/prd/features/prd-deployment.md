# 部署与运维

## 问题陈述

部署者需要把一个已装配完成的 SaaS 骨架作为可执行程序对外运行，并在重复部署、升级与排障时不破坏既有数据与运营者已经做出的决定。运行模式由部署者选择：单实例，或分布式（多实例、多活、同角色）。所装配的每个组件是否支持所选模式由部署者自行保证，本文档只规定系统在两种模式下必须表现的行为。

## 范围

本能力覆盖：单一可执行程序与单一对外 HTTP 端口、单实例与分布式两种运行模式、前端产物的内嵌与交付、进程生命周期信号、首次运行的签名密钥、`seed` 引导与 `migrate`、存活与就绪探针、合并后的 API 规格、反向代理后的客户端地址、部署所需的机密、匿名口令重置的短信渠道是否可投递，以及向外部系统发送请求时的记录。

### 不在范围内

- 业务域功能。
- 终端用户的登录、账户、租户与控制台日常操作。
- 界面视觉、布局与响应式规格。
- 容量、延迟、可用性与数据留存期指标。
- 构建流水线与发布审批的实现。
- 各模块内部的存储结构与 API 形状。

## 参与者

- **部署者**：持有部署机密，创建持久卷，选择对外来源，运行部署与运维命令；不是应用内角色，不登录。
- **监督进程**：读取存活与就绪探针，向进程发送终止信号。
- **反向代理**：转发外部请求并写入客户端地址头；部署者为它配置可信代理网段。
- **API 消费者与前端构建**：读取合并后的 API 规格与特性声明清单。
- **外部服务方**：邮件中继、短信服务商、身份提供方与对象存储服务方，接收系统发出的请求。
- **平台运营者**：由 `seed` 写入的初始账户中标记为平台管理员的账户，持有内置管理员角色。

## 功能需求

### REQ-deployment-001

系统必须以一个可执行程序承载全部运行能力：HTTP 入口、后台任务与消息投递、一次性运维命令。

- **验收**：只运行该程序的 `serve` 命令时，页面与 API 可访问，入队的一次消息投递由该进程取走并完成，日志中出现该次投递的记录。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-037

系统必须支持单实例与分布式两种运行模式；分布式模式下，每个实例承担相同角色。

- **验收**：以单实例运行时，一个进程即可应答页面与 API 请求；以分布式运行时，任一实例都能独立应答请求，且不存在只由部分实例承担的角色。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-002

系统必须以一个对外发布的服务端口同时交付前端页面与 API，使浏览器访问 API 时与页面同源。

- **验收**：从部署外部只能经该服务端口取得入口文档与 API 应答；部署中不存在第二条对外发布的服务端口；浏览器对 API 的请求与页面同源。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-003

系统必须把前端构建产物内嵌在可执行程序中并由程序交付，部署不需要额外的静态文件服务或静态文件目录。

- **验收**：只部署可执行程序、配置与持久卷时，访问根路径得到前端入口文档；部署中没有独立的前端文件服务。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-004

系统必须把末段不带扩展名、且不落在内容寻址子树或任何静态资源前缀下的未知路径回退为前端入口文档。

- **验收**：请求一条未知的无扩展名页面路径得到 200，响应正文是前端入口文档。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-030

系统必须把命名静态资源的未知路径答 404 而不回退为入口文档：末段带扩展名的路径，以及落在内容寻址子树或任何静态资源前缀下的路径。

- **验收**：请求一条带扩展名的未知路径，或一条落在内容寻址子树或静态资源前缀下的未知路径，得到 404，响应正文不是入口文档。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-005

系统必须在全部模块启动后写出一条就绪记录。

- **验收**：启动完成后标准输出出现就绪记录。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-031

系统必须在收到 SIGINT 或 SIGTERM 后写出一条停止记录，让在途请求得到应答，然后退出。

- **验收**：停止信号到达后标准输出出现停止记录；信号到达时正在处理的请求仍得到应答；该请求完成后进程退出。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-006

系统必须在签名密钥文件不存在时于首次运行生成一份签名密钥并写入该路径，此后沿用该文件。

- **验收**：删除密钥文件后启动会生成新文件；保留文件重启后，此前签发的令牌仍然有效。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-032

系统必须把生成的签名密钥文件写成只允许其属主读写的权限。

- **验收**：首次运行生成的密钥文件，其属主可读可写，同组用户与其他用户既不可读也不可写。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-007

`seed` 必须把配置点名的初始账户写入账户存储，凭据取每条账户给出的明文口令或口令哈希中的恰好一个。

- **验收**：配置点名一个仅带明文口令的账户与一个仅带口令哈希的账户，运行 `seed` 后两者都能经登录流程取得会话；不带 `@` 的标识按用户名种入，带 `@` 的按邮箱种入。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-008

`seed` 必须把配置点名的租户登记进名册。

- **验收**：运行后名册包含配置的每个租户，且每个租户处于可用状态。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-033

`seed` 必须给标记为平台管理员的账户一个内置角色，该角色带本进程声明的全部权限，且同时写在平台域与配置点名的每个租户域。

- **验收**：标记管理员的账户在平台域与每个租户域都持有 `platform-admin` 角色，该角色带进程声明的全部权限并被标记为内置；管理面不能改写或删除该角色，也不能改动其授权。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-009

`seed` 必须在创建账户之前写入配置点名的运行期设置，使随后写入的账户受这些设置约束。

- **验收**：配置把口令最小长度设为高于某账户口令的值时，该次 `seed` 在写入该账户时失败，该账户不存在；设置本身已按配置写入。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-010

`seed` 必须幂等：对已存在的账户、租户、角色、授权与绑定不重复写入，并逐项报告跳过。

- **验收**：对同一配置连续运行两次，第二次不创建或修改任何账户、租户、设置、角色或绑定，并对已存在的每项报告跳过。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-034

进程新声明的权限必须在 `seed` 下次运行时补入管理员角色。

- **验收**：进程新增一条权限后再次运行 `seed`，该条授权出现在管理员角色上，此前的授权保持不变。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-011

`seed` 必须不覆盖运营者经管理面做出的改动：运行期设置仅在全局层没有显式行时写入；配置中已删除的账户与租户既不停用也不删除；已有授权既不删除也不改写。

- **验收**：经设置面修改一个 `seed.settings` 键后重跑 `seed`，该键保持运营者给定的值；从配置中删除一个账户或租户后重跑，该账户或租户仍然存在且状态不变；进程不再声明某条权限后重跑，管理员角色上的该条授权仍然存在。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-038

`seed` 必须把配置声明的成员关系只供给本次运行新建的账户；既有账户的成员关系无论处于什么状态都不改写，也不重建已被移除的成员关系。

- **验收**：配置声明一个新账户属于某个已声明的租户，运行 `seed` 后该账户能进入该租户；把该成员移除后重跑 `seed`，成员关系不被重建；把成员关系停用后重跑，停用状态保持不变。成员指向未声明的租户或账户时，`seed` 在写入任何数据之前失败并点名该条声明。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-012

`seed` 必须一并施加迁移，使一个从未迁移过的数据库仅凭这一条命令即可就绪。

- **验收**：对一个空数据库直接运行 `seed`，随后运行 `serve` 不需要另跑 `migrate` 即可启动并完成登录。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-013

`seed` 必须在结构上非法的配置上失败，且失败前不写入任何数据，例如：账户缺少凭据或同时给出两种凭据、租户名使用保留的平台域名 `system`。

- **验收**：配置出现上述任一情形时，命令以非零状态退出且错误点名出错的条目；运行后账户、租户与设置的数量与运行前相同。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-014

`seed` 必须拒绝非法的运行期设置：设置键拼错或取值越出声明的域时，命令失败且不写入任何账户。

- **验收**：设置键拼错或取值越域时，命令以非零状态退出，且运行后账户数量与运行前相同。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-035

`seed` 必须拒绝不满足当时口令策略的账户：账户口令短于生效的最小长度时，该账户不被写入。

- **验收**：账户口令短于生效的最小长度时，命令以非零状态退出且该账户不存在。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-015

随附的部署装配必须在每次启动时先运行 `seed` 再启动服务，使重启在幂等契约下既补齐缺失项也不覆盖运营者改动。

- **验收**：容器重启后服务可用；重启前经设置面修改过的运行期设置在重启后保持运营者给定的值；重启前配置新增的账户或租户在重启后出现在系统中。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-016

`migrate` 必须只对数据库引擎施加各模块声明的全部表，不要求键值后端、事件后端或遥测导出后端可达。

- **验收**：在一个只有数据库可达、其余后端不可达的环境中运行 `migrate`，命令成功退出并建立各模块声明的全部表。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-017

系统必须在一条不对外发布的独立运维监听上提供存活探针：请求不需要认证，每次请求都答成功且不读取任何状态。

- **验收**：无凭据请求存活探针得到 200；数据库或任一后端不可达时，该探针仍答 200；该探针在一条独立的运维监听上，该监听不作为对外服务发布。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-018

系统必须提供就绪探针，仅当本次进程声明的每个端点都在接受请求且数据库应答时答成功，否则答失败并逐项点名失败项。

- **验收**：全部端点可用、数据库可达时探针答 200；停掉一个端点或数据库后探针答 503，正文逐项列出失败的那一项。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-019

系统必须在运维端点上提供一份合并后的 API 规格，覆盖该二进制所提供 API 的全部声明，而不只覆盖当前命令运行的那些模块。

- **验收**：规格包含一个不由任何命令运行的模块所声明的操作；该操作存在，而该模块不在任何命令的运行集中。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

### REQ-deployment-020

系统必须提供一条离线写出合并规格的命令，它不绑定端口、不连接所读的配置中声明的任何后端，并可同时写出特性声明清单。

- **验收**：在没有任何后端可达的环境中运行该命令，规格与特性清单被写出；命令不监听端口，也不连接配置中的后端；特性清单逐项给出特性名、声明模块、所有者与是否条件特性。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-021

系统必须在模块声明的规格片段互相冲突时拒绝启动，并点名冲突的来源。

- **验收**：两个模块声明同一路径的同一方法时，进程启动失败，错误同时点名这两个模块及各自的端点；两个模块声明同名但内容不同的共享定义时，启动失败并点名声明它的模块与定义名。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-022

系统必须默认不信任任何转发头：未指定可信代理网段时，客户端地址取连接的对端地址，客户端不能用请求头声明自己的地址。

- **验收**：默认配置下，带 `X-Forwarded-For` 或 `X-Real-IP` 的请求所记录的客户端地址等于连接对端地址，而不是头中的值。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-023

系统必须允许部署者按模块配置可信代理网段与客户端地址头名，每个端点默认继承，并在写出同名项时覆盖。

- **验收**：只有来自所列网段的连接才采信所列头名；端点写出自己的列表时以该列表为准，写出空列表时该端点回到不信任任何代理；网段书写非法时启动失败并点名该配置项；与代理同处一个可信代理网段的其他主机发出的转发头同样被采信。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-024

随附的部署装配必须把部署所需的机密作为部署输入读取，并在缺少任一必需机密时拒绝启动并点名缺失项。

- **验收**：缺少运营者邮箱、运营者口令、数据库加密根键、邮件中继主机、邮件中继发件人，或任一社交登录提供方的应用标识与密钥时，部署入口以非零状态退出并打印缺失的机密名；补齐后启动继续。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-025

随附的部署装配必须拒绝无法原样写入配置或越出允许范围的部署输入取值：含双引号、反斜杠、换行或控制字符的取值，非 https 的公开来源，没有主机或带路径、查询、空格的公开来源，非整数的端口，以及不属于 `starttls`、`implicit`、`none` 三者的 TLS 姿态。

- **验收**：上述任一取值出现时，部署入口以非零状态退出并说明该取值不可用，进程不启动。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-026

系统必须拒绝在缺少数据库加密根键时启动，并拒绝空白或短于 14 字节的根键；更换根键时，旧键必须仍被提供给系统，否则同一持久卷上已有的加密列不可读。

- **验收**：缺少该键时部署入口拒绝启动；键短于 14 字节或全为空白时启动失败并点名该配置项；只提供新键打开同一卷上已有的数据库时，既有加密列不可读；同时提供旧键与新键时，既有加密列可读。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-027

随附的部署装配必须在每次启动时把渲染后的配置写入持久卷。

- **验收**：容器启动后，渲染出的配置出现在持久卷上，并以该次启动的取值重写；镜像层中不存在这份渲染结果。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-036

编译进二进制的默认配置与部署镜像不得携带任何凭据。

- **验收**：编译进二进制的默认配置与部署镜像中都不存在运营者口令、数据库加密根键、邮件凭据或社交凭据。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-028

系统必须为每一次向外部系统发出的调用写一条记录，成功与失败各一条，记录包含结果、耗时、服务商给出的回执标识（若有）与失败分类。

- **验收**：分别触发一次成功的邮件发送与一次被服务商拒绝的发送，日志中各出现一条记录；成功记录含结果、耗时与服务商回执标识，失败记录含结果、耗时与失败分类。
- **状态**：已实现
- **端到端测试**：未实现

### REQ-deployment-029

系统必须在外部调用的记录中排除验证码、口令、邮件或短信正文、收件人地址、对象存储的内部键与凭据。

- **验收**：检查成功与失败两类记录，均不出现收件人地址、验证码、邮件或短信正文、对象存储内部键或凭据的原文；对象以键的摘要标识。
- **状态**：已实现

### REQ-deployment-039

部署在提供匿名口令重置的短信渠道时，必须确保短信载体能够投递该渠道的验证码；不能投递时，该渠道不得出现在可用的重置渠道中。

- **验收**：短信载体能够投递重置验证码时，重置面提供短信渠道；不能投递时，重置面不提供短信渠道，直接请求短信重置得到「本部署不提供该方式」的可见结果；邮箱重置渠道与短信登录不受影响。
- **状态**：已实现
- **端到端测试**：未实现

## 约束

组件的运行模式支持由组件自身决定：以单个进程内可达的存储与状态为后端的组件只支持单实例，以共享服务为后端的组件支持分布式。装配与所选运行模式的匹配由部署者保证；系统不因二者不匹配而拒绝启动。
