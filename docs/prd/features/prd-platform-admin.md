# 平台运营

## 问题陈述

平台需要一个只对持有平台管理权限的运营者开放的管理后台：运营者借此管理租户名册、账户、会话、冒充记录、审计记录与邀请，而无平台权限的账户既看不到入口，也得不到任何管理后台页面信息。

## 范围

覆盖管理后台入口与区域守卫、概览、租户名册与详情、账户管理、会话管理、冒充的发起与结束，以及审计检索、审计导出与邀请管理。

### 不在范围内

权限与角色的管理、SSO 提供方的管理、运行期设置、短信模板、成员关系的写入、邀请的受理、账户自助面，以及冒充期间的租户侧业务行为。

## 参与者

- **平台运营者**：持有平台管理权限的已认证账户。可进入管理后台，各页按其持有的权限开放。
- **普通成员**：只持有租户域权限，没有平台管理权限。看不到管理后台入口，也得不到任何管理后台信息。
- **冒充中的运营者**：会话主体为被冒充账户并带有冒充标记。以被冒充账户在该组织内的权限行事，发起者自己的权限不生效；被冒充的账户不持平台域权限，管理后台因此对冒充身份不可达；可结束冒充。
- **匿名访客**：没有会话。访问管理后台路径时先落到登录面。

## 功能需求

### REQ-platform-admin-001

系统必须只让持有平台管理权限的运营者看到账户菜单中的管理后台入口与首页的管理后台卡片，且两者只在当前组织是平台自身的 `system` 租户、生效账户的平台权限集非空、至少一条管理后台页面在该部署在场时出现。

- **验收**：当前组织不是 `system` 时，即便运营者持有平台管理权限，账户菜单也没有管理后台入口、首页也没有管理后台卡片；当前组织是 `system` 的运营者登录后，管理后台入口与首页的管理后台卡片都出现；普通成员登录后账户菜单没有管理后台入口、首页没有管理后台卡片；同一会话进入冒充后管理后台入口与首页的管理后台卡片同时消失。
- **状态**：已实现
- **端到端测试**：`starters/demo/web/e2e/specs/journey-deploy-and-operate.spec.ts` `deploy-and-operate: a deployment serves, seeds, and refuses an unproved operator write`

- **验收**：激活账户菜单中的管理后台入口与激活首页的管理后台卡片，落到的路径相同，且等于当前可进入的第一条管理后台页面的路径。

- **验收**：特性读取中，页面出现不带管理后台框架的进度指示且不重定向；特性读取失败，页面出现带重试动作的失败视图，触发重试后重新读取；权限集未落定，页面出现访问检查中的等待视图且不渲染管理后台框架、不重定向；权限集为空，页面静默回到租户区首页且不渲染管理后台框架；邮箱未证明，页面落到账户页的验证分节。
