# 系统概览

## 系统是什么

本系统是一份可运行、可拷走的 SaaS 骨架：一个 Go 程序加一棵前端应用树，把登录注册、账户与安全、组织与成员、平台运营、通知、界面偏好这些平台能力装配成一个可部署给终端用户的程序。使用者拷走这份骨架、换上自己的业务域，在其上长出产品。

骨架面向终端用户与部署者。终端用户经浏览器使用它：注册账户、登录、维护本人资料与安全设置、进入组织并接收其中的通知。部署者把它装成一个可执行程序对外提供服务：单一端口同时交付前端与 API，一份配置决定装配与行为。运行模式由部署者选择：单实例时一个进程承担全部角色；分布式时多个实例以同一份装配多活，每个实例承担相同角色。所选组件是否支持所选模式，由部署者自行保证。

骨架自身不带业务域，也不带样例数据。它交付的是平台基线——不需要外部凭据、外部账号或部署栈之外的服务即可启动的那部分能力——以及把其余能力接入装配的约定。需要外部账号的能力（社交登录、企业单点登录、短信、邮件投递）由使用者在取得相应凭据后自行接入。

## 能力

系统对外提供的能力构成一条从身份到组织、再到组织内数据面的链，各能力在这一链上衔接。

身份的起点是匿名访客取得会话。登录能力向匿名访客公布本部署实际提供的方式，并在其中任一种方式上完成第一因素。开户是一组并列的来源——口令自助注册、短信首登开户、社交与企业登录首登开户——它们在建立账户之后落到同一条邮箱验证门控上：账户在本人证明邮箱之前可以使用一个封闭集内的能力，依赖可信邮箱的能力在其后放开。

会话建立之后，账户自助与账户安全共同治理这个人本身：资料、语言与时区偏好、登录标识、口令、社交绑定，以及第二因素、会话撤销与敏感操作前的重新验证。账户证明邮箱之后，依赖可信邮箱的能力随之放开。

组织与成员能力把账户放进彼此隔离的组织。平台运营者登记组织，组织内的成员管理员签发邀请、增减成员，受邀人接受邀请后成为成员；每个用户账户在开户时得到一个个人组织，并在其中持有非内建 `tenant-admin` 角色，开户来源、邮箱是否已证明、是否已属于其他组织都不影响这个组织的存在。每一次进入组织都要经过按成员关系与权限的准入判定，不满足条件的请求得到与组织不存在相同的结果。

租户管理把组织内部的日常管理交给该组织自己的租户管理员。租户管理员经租户区内的组织管理区域管理当前组织的成员与邀请、企业身份提供方、租户设置与租户角色；入口、页面判定与写入判定都限于当前业务租户，平台域权限不构成放行，个人组织与平台域不出现这条面。

平台运营与平台设置是同一批平台数据的管理面：运营者经管理后台管理组织名册、账户、会话、冒充记录、审计检索与邀请，并在受权限与账户状态约束的前提下调整运行期设置、管理短信模板与企业身份提供方、维护角色与权限。平台运营与平台设置对终端用户不可见：不持相应权限的账户既看不到入口，也得不到任何管理后台内容。

通知是组织内的数据面能力：业务模块借通知向收件人投递站内信，并按收件人的类型偏好决定一条消息走站内信、邮件还是短信。骨架不种任何业务数据，这一面在裸部署上以空态呈现，数据由产品与它的用户产生。

防滥用能力约束平台可能对外发出的每一条消息。验证邮件与短信按目标、账户、来源与全局四层预算发送，预算在并发下不得被越过；同一收件箱的不同地址写法共用一份预算；人机验证按发送面默认开启，手机号面用自托管的人机验证码，其余面用自托管的工作量证明，部署可按面关闭或换用外部机制，而每次发码都必须先提交一份有效、一次性的证明。业务通知的邮件与短信投递同样受按收件人与全局的预算约束，收件地址必须属于该消息的收件人。这些约束使平台不会被请求方当作对第三方邮箱或号码的轰炸发起者。

界面偏好贯穿以上全部面：语言、时区、时间呈现、主题预设、外壳形态、窄视口降级与写操作的统一反馈。它在匿名访客与已登录账户上表现不同，管理后台与租户区共享同一套外观决定。

部署与运维能力把以上全部装进一个可执行程序：单一对外服务端口同时交付前端与 API，前端产物内嵌其中，进程以信号报告生命周期，探针供监督进程判定存活与就绪。首次运行写入签名密钥，种子命令写入初始运营者、组织与设置，迁移命令只对数据库施加各模块声明的表。

## 范围边界

系统负责平台基线所覆盖的外部可见行为：身份的建立与证明、账户的维护与安全、组织的隔离与成员关系、平台管理面、组织内的通知数据面、界面呈现的一致规则，以及把上述能力装成单一可部署程序的运行契约。使用者在骨架上增加的领域模块，其行为与数据不改变这些边界；平台能力为它们提供接缝。

### 不在范围内

- **业务域本身。** 骨架不携带订单、工单、内容或任何具体业务类型；业务模块住在产品自己的业务目录，由使用者编写。
- **业务数据与样例数据。** 骨架不种任何可展示的样例数据。通知收件箱，以及管理后台概览中除平台自身名册统计之外的面，在裸部署上为空；这份空态由产品与它的用户之后产生的数据填充。
- **组织数据的导出，以及组织层级与组织树。**
- **界面视觉规格、布局取值与响应式断点。** 需求只固定使用者可见的呈现规则，具体视觉取值属设计。
- **各模块内部的存储结构、API 形状与技术选型。** 这些是设计文档的内容，不是系统对外的责任。
- **容量、延迟、可用性与数据留存期指标。** 部署方自行选择运行环境与规模。

## 参与者

- **匿名访客**：不持有会话。可读登录方式与注册开关的匿名发现、发起任一已启用方式的登录、到达外部提供方的回跳落点、凭邀请链接到达接受页；不能访问任何组织资源。
- **终端用户（持有账户的个人）**：经任一方式登录、持有有效会话的账户持有人。只能读改本人账户。邮箱尚未证明时，其能力被限制在一个封闭集内，集合外的动作——邀请他人、组织创建与变更、管理面的人类写、外部身份绑定、发起冒充——被拒绝。
- **组织成员**：被授予某组织成员关系的账户。可进入该组织并使用其中资源；能做什么由其在组织内持有的权限决定。
- **租户管理员**：在某业务租户内持有管理权限的成员。经组织管理面管理本组织的成员与邀请、企业身份提供方、租户设置与租户角色；平台域权限不使其通过组织管理面的判定，个人组织与平台域不出现这条面。
- **个人组织的租户管理员**：每个用户账户在开户时即持有个人组织及其非内建 `tenant-admin` 角色，邮箱是否已证明、是否已属于其他组织都不影响这个组织的存在；该角色只授宿主声明的允许集，不覆盖组织的管理动作。
- **平台运营者**：持有平台域管理权限的已认证员工账户。可进入管理后台，各页按所持权限开放；管理面的人类写要求账户已证明邮箱；改动凭据、因素、账户的停用或删除与冒充的敏感动作还要求新鲜的多因素，发起冒充，以及重置他人口令或第二因素，另要求所用因素达到最小年龄；发起冒充不要求发起者属于目标组织。
- **冒充中的运营者**：会话主体为被冒充账户并带冒充标记。读写与该账户本人在该组织内相同，权限取自该账户，发起者自己的权限不生效；被冒充的账户不持平台域权限，因此管理后台入口与管理后台内容对冒充身份都不出现；唯一区别在留痕，审计把实际操作者记为运营者并标明被冒充账户、组织与会话；可结束冒充。
- **部署者**：不是应用内角色，不登录。持有部署机密、创建持久卷、选择对外来源、运行部署与运维命令，并决定装配哪些能力与外部提供方的凭据。
