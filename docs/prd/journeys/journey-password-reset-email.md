# 邮箱验证码重置口令

## 参与者

忘记口令的账户本人，持有该账户已证明邮箱的收件箱；不持有平台管理权限。

## 前置条件

- 账户已设置口令，并有一条本人用验证码证明过的邮箱登录标识。
- 部署提供匿名口令重置的邮箱渠道，登录面因此出现「忘记口令」入口。
- 参与者能读取该邮箱收到的邮件。
- 参与者在另一台设备上保持着一个活跃会话，用于观察重置后的会话结束。

## 步骤

1. 在未登录状态下打开产品，界面呈现登录面；口令渠道下出现「忘记口令」入口。
2. 点「忘记口令」进入口令重置面，选择邮箱，填入该账户的邮箱并提交。
3. 界面给出不点名账户是否存在的提示（若该邮箱属于一个启用中的账户，验证码已发送），并出现验证码、新口令与确认口令字段。
4. 读取邮箱收到的验证码，填入验证码、新口令与确认口令并提交。
5. 界面确认口令已重置，并提供回到登录面的出口。
6. 用该邮箱与新口令登录；登录成功，进入该账户的租户区。
7. 退出登录，再用旧口令登录；登录被拒，界面给出凭据无效的提示。
8. 在另一台设备上刷新页面；该设备的会话已结束，界面要求重新登录。

## 结果

- 新口令可以登录，旧口令不再可用。
- 另一台设备上重置前的会话已结束。
- 账户已登记的第二因素清单没有变化；若账户登记了第二因素，下一次登录仍停在第二因素。
- 重置过程没有让参与者进入账户区；重置完成后仍需在登录面登录。

## 备选路径

- 提交错误或过期的验证码：界面给出与「联系方式不属于任何账户」相同的拒绝提示，参与者可以重新获取验证码。
- 提交从未与本产品关联的邮箱：界面给出与合格邮箱相同的提示，但不会有邮件到达；任意验证码得到同一条拒绝提示。
- 账户登记了第二因素：第 6 步登录仍停在第二因素；重置没有解除、替换或重新登记任何因素。
