# 导出一批变更的审计记录

## 参与者

平台运营者：持平台域的 settings.read、settings.write 与 audit.read，账户邮箱已证明，控制台的设置页与审计页对其开放。

## 前置条件

- 操作者已登录，账户邮箱已证明，并在平台域持有 settings.read、settings.write 与 audit.read。
- 部署装配了设置管理面与审计面，控制台的设置页与审计页可以打开。
- 操作者知道一个设置项的至少两个合法取值，可以在其间来回切换。

## 步骤

1. 操作者进入设置页，把一个设置项的取值改成另一个合法取值并保存；在两个合法取值之间来回切换，重复保存，直到该运营者在本次操作时间窗内的 settings.set 记录超过审计列表的一页。每次保存成功后，设置页反馈区都告知设置已保存，该行显示新的当前值。
2. 操作者再对一个设置项填入一个不在其声明取值域内的取值并保存。保存被拒，该行按错误码显示取值不合格的说明，设置保持原值；这次被拒同样留下一条失败结果的审计记录。
3. 操作者打开审计页，把起始时间设为本次操作开始之前、结束时间设为当前时刻，动作填 settings.set，点「应用」。列表按时间由近及远列出这些记录，条数超过一页，页脚可以翻页；其中包含步骤 2 那次结果失败的写入。
4. 操作者停在列表的其中一页（不是第一页），点「导出」。浏览器下载一个文件，文件名带导出时刻。
5. 操作者打开导出文件，逐行读作一条审计记录。记录条数等于步骤 3 中筛选命中的全部记录条数，包含当前页之外的记录；每行的动作都是 settings.set、操作者都是本人，并含有那次失败的写入。
6. 操作者回到审计页，把结束时间提前到只覆盖前几次保存，再次「应用」并导出。第二次导出的文件只含新的筛选命中的记录，集合比第一次小。

## 结果

- 两次导出各得到一个文件，文件中的记录集合分别等于对应筛选命中的全部记录，不受列表当前页影响。
- 导出记录的动作、对象与操作者与检索结果一致；失败的那次写入以失败结果出现在第一次导出的文件里。
