# 术语表

本项目全部文档共用这一份术语表，它只收录在项目范围内处处成立的术语，已登记的术语在所有文档中用词一致。

通用技术词汇不登记。含义由某个模块界定的术语登记在该模块自己的文档里。

## 结构

| 术语 | 英文 | 定义 |
|---|---|---|
| 模块 | module | 向注册表登记一份描述符的单元：它参与生命周期，进出启用集，交付功能。它与承载它的 Go module 不是一回事：同一个 Go module 内可以登记多个模块。 |
| 功能目录 | capability directory | `pkg/` 下承载一个功能的顶层目录：根包是该功能的接口包，实现位于子包。依附于该功能的另一项功能也可以住在其中，它的接口包是目录下的一个子包。对照是共享单元。 |
| 子包 | subpackage | 功能目录或共享单元内部的一个目录。实现的拆分默认用子包，第三方依赖因此不进未 import 它的宿主的 `go.mod`；`go.sum` 与实际下载会经被 import 包的测试闭包带上这些库，只有读整图的操作会看到全部实现所绑的库。实现子包各自登记为一个模块。 |
| 接口包 | interface package | 功能目录的根包；功能目录里依附于该目录功能的另一项功能，其接口包是目录下的一个子包，事件目录里的事务发件箱即是。它定义功能的接口与数据类型，可以暴露本模块所封装的第三方库；绑定具体后端与驱动的实现一律位于子包。它通常不登记为模块，根包自身即实现的功能目录除外。 |
| 共享单元 | shared unit | `pkg/internal/` 下一个不承载功能的目录：它封装一个第三方客户端，供多个实现子包共用；或提供一份测试夹具，供多个模块的测试共用，功能目录根包的测试也在其内。服务于某个客户端的夹具就落在这个客户端的单元目录里。它登记零个模块。 |
| 宿主 | host | 使用 speed 的应用程序：它编写 `main`，import 所需模块，驱动装配。 |

## 装配

| 术语 | 英文 | 定义 |
|---|---|---|
| 描述符 | descriptor | 模块向注册表登记的不可变声明：名称、构造期依赖、所交付的功能、对外资源与各阶段回调。 |
| 资源 | resource | 模块对外声明的只读元数据，`Run` 之前确定，供其他模块与注册表按类型查询。类型由需要它的模块定义，注册表不解释其含义。 |
| 注册表 | registry | 模块机制的本体。描述符部分在 `Run` 之前写入，此后不可变；实例部分随注册表实例各自持有，由生命周期驱动逐阶段建立，预置实例则由宿主在驱动之前经 `Supply` 预置。 |
| 可用集 | available set | 已登记到注册表的模块集合。进程级注册表的登记主要发生在 `init`，凡被 import 进来的模块包都会执行，因此它不限于宿主直接 import 的模块，也包含依赖间接 import 的。 |
| 命令树 | command tree | 宿主在 `main` 中写出的子命令层级。每个节点列举该层纳入哪些模块，并指定这条命令驱动到哪个阶段、到达之后做什么。模块不参与这份声明，也无从知道自己出现在哪条命令下。 |
| 纳入 | include | 宿主在命令树的某个节点上列举某个模块，使它进入这条命令的声明集。分运行级与静态级两种。 |
| 运行级纳入 | run-level inclusion | 使模块进入参与集的纳入：它被构造与驱动，有资格表态，其输入项出现在这条命令的参数面上。只给予表态的资格，不决定启用。 |
| 静态级纳入 | declaration-level inclusion | 只使模块进入声明集的纳入：它不构造、不表态、不展开依赖闭包，其输入项默认不出现在参数面上且永不判必填，唯一的作用是让它声明的资源进入本次运行的收集范围。 |
| 声明集 | declaring set | 本次运行哪些模块的声明进入收集范围：参与集与静态级纳入的模块之并，因而含依赖闭包拉进来的与预置了实例的那些。必为可用集的子集，且必含参与集。 |
| 参与集 | participating set | 本次运行有资格表态的模块集合：命令路径上各层运行级纳入的模块，连同它们的构造期依赖（标注 `Optional` 的依赖不展开；声明排他的提供者不被依赖闭包自动纳入，宿主须在命令树上点名或为它预置实例）；或 `Run` 入口下的全部已登记模块；再加上预置了实例的模块，它们不看命令树是否纳入，表态固定为启用。必为声明集的子集。 |
| 启用集 | enabled set | 本次运行实际被驱动的模块集合：参与集中未被消解禁用的那些，实例由驱动构造或由宿主预置。模块没有表态禁用这一档，被纳入而不能启动即启动失败，因此消解是唯一让参与者退出的环节。必为参与集的子集。 |
| 取材域 | declaration domain | 一处收集声明或表态的机制据以取材的模块集合：可用集、声明集、参与集或启用集中的一个。资源消费点的取材域由消费点自行裁定，判据见架构不变量 15。 |
| 阶段 | stage | 生命周期中的一个固定时机。阶段集合是模块作者与注册表之间的稳定契约。 |
| 预置实例 | supplied instance | 宿主在驱动开始之前人工生成、经 `Supply` 预置的模块实例。它属于恰好一个已登记模块，满足该模块声明交付的全部功能。与普通实例的差别起于来源：普通实例由模块的 `New` 在构造阶段生成，预置实例由宿主生成，该模块的 `Prepare` 与 `New` 因而不执行；模块进入参与集不取决于命令树，驱动开始时并入的只是它本身，这次并入不为它展开依赖闭包，表态固定为启用；实例自驱动开始即视为已构造，驱动无论在哪一步结束都对它执行模块声明的 `Stop` 与 `Close`。配置读取面是 `config` 模块的预置实例。 |
| 驱动深度 | drive depth | 一次驱动推进到的最后一个阶段，取值是 `Prepare` 到 `Serve` 中的一个。写出命令树的宿主由这条命令指定；`Run` 钉在 `StageServe`。未被推进到的阶段其回调不执行；`Stop` 与 `Close` 不可选，任何一次驱动结束时都要执行。 |
| 功能 | capability | 模块之间相互取用的单位，以一个接口类型表达。声明与取用指代的都是功能，不是实例。 |
| 功能标识 | token | 功能在声明与取用中的写法：指向该功能接口的类型化空指针，例如 `(*KV)(nil)`。 |
| 排他交付 | exclusive provision | 交付声明中的标注，表示本模块独占该功能。它是提供方对自身的声明，不是对该功能的全局断言；消解之后本模块仍然启用时，该功能若还有其他启用的提供者，即启动失败。被禁用的提供者不再主张独占。声明排他的提供者不被依赖闭包自动纳入，宿主须在命令树上点名或为它预置实例。 |
| 构造期依赖 | construction dependency | 模块在描述符中声明的功能依赖，决定构造顺序，必须无环。相互引用不在此声明，改由接线阶段动态取得。 |

## 参数

| 术语 | 英文 | 定义 |
|---|---|---|
| 配置 | config | 启动所必须的参数。进程级，全局一份，启动时读取一次后不再变化，变更需重启。 |
| 设置 | settings | 运行期可变的参数，存放于数据库，可按租户取不同值。由独立模块承载，不属于配置。 |

## 模板

| 术语 | 英文 | 定义 |
|---|---|---|
| 模板注册表 | template registry | 短信模板的集合，由 `pkg/sms/registry`（模块名 `sms.registry`）承载：它持有在用的模板，并决定一条消息按哪个模板发出。两个来源合为一份集合——配置来源在装配期读入一次后冻结、只读，运行期来源存放于该模块自己的数据库表，可在运行期增删启停。它因此不落在「配置」与「设置」的二分里：配置来源那一半是配置，运行期来源那一半是运行期可变的持久数据。它与「设置」的差别在取材与形态：全局一份、不按租户，且一条模板记录是有序参数列表与「语言到厂商代码」的映射，不是设置树里的可设项。 |

## 信号

| 术语 | 英文 | 定义 |
|---|---|---|
| 遥测 | telemetry | 进程开始运行之后产生的追踪与指标两种信号，由 `pkg/observability` 承载。它与启动诊断分属两面：启动诊断是装配期由 `core` 与 `config` 写标准错误的输出，见架构的可观测性一节。 |

## 认证与授权

| 术语 | 英文 | 定义 |
|---|---|---|
| 授权 | authorization | 在认证认定的身份与已解析的租户之上，判定某个身份能否对某个资源做某个动作的独立功能目录，由 `pkg/authz` 交付。它与认证分属两个功能目录，之间只经判定接缝相连；别处写作「权限模型」的与它同义。 |
